owner 2026-06-13 戳穿 CC 一次离谱幻觉, 记为反面教材防重犯。

**事件**: cc-api-watchdog 记忆写"接近 400k 就压缩"。CC 看到 context 558k (1M 上限会话) 觉得"才 55.9%, 还空", 这个直觉和 400k 明确值冲突。CC 的错误反应 = **凭空捏造一个事实** ("400k 是 200k context 时代定的, 1M 应按比例放到 750k") 来给直觉背书, 还拿这个捏造去 Edit 记忆、回 owner; owner 第一次质疑后 CC 仍坚持。owner 一句话证伪: **200k 上限物理上根本到不了 400k, 所以 400k 本来就是 1M 会话的值** (CC 把它误判成"早期遗留值"纯属幻觉)。

**失败模式 (核心)**: 当 CC 的**直觉/判断**和一个**明确的约束/数字/规则**冲突时, 错误反应是"编一个让矛盾消失的故事" —— 把"希望为真的假设"当成"事实"填进叙事、求叙事自洽 —— 而不是服从明确值。这是幻觉的典型生成机制; 且 CC 在最该警觉的地方 (改 owner 定的规则) 犯了它, 捏造的东西连一秒常识检验 (200k<400k) 都没过, 被质疑还坚持。

**Why**: 长会话高速推进时倾向"快速给自洽解释"而非"停下验证基本前提"; 冲突触发"补理由"而非"服从 / 求证 / 如实上报不确定"。

**How to apply (铁律)**: 我的判断和明确的数字/规则/约束打架时 —— ① **明确值优先, 先服从**; ② 对"它是不是过时/不适用"**只能标成「我不确定, 要不要跟你确认」, 绝不自己捏造一个来源/理由去推翻它**; ③ 任何"X 是 Y 时候定的 / X 的来源是…"这类**来源断言**, 张嘴前先过一遍最基本的自洽检验 (这次该问: 200k 上限能不能产生 400k 读数)。相关: [[cc-api-watchdog]] (400k = 1M 会话压缩点, 同条记了反面教材)。
