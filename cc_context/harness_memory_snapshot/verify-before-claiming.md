2026-06-14 弹窗功能联调时 owner 当场抓出我三个反复犯的坑。**Why + How to apply:**

## 1. 同一现象能从多条路径来时, 先查工具/log 坐实, 别凭"现象出现了"抢答

弹窗 [立刻] 测试: "测试消息到达"这个现象, 既可能来自 **弹窗→[立刻]→清草稿→注入**(要验的路径), 也可能来自 **owner 没草稿 → `-SendNow` code=0 直接注入**(没验到弹窗)。我两次只看到"消息到达"就喊"立刻路径通过 / 顺序测试通过", log 一查全是 `code=0`(直接注入), 根本没走弹窗路径。
**How:** 当一个 observable 能由多条因果路径产生时, **断言"路径 X 通过"前必须查到 X 独有的证据**(这里 = log 里 `code=3` + `弹窗` + `cleared=True` + 注入 `code=0`), 不能拿"终态出现了"当 X 走过的证明。**抢答=premature, 比慢一点危害大。**

## 2. 能自己查的信息别张嘴问 owner

我问 owner"清空输入框是哪个键", owner 回"你不会自己查吗"。有 `keybindings-help` skill、可以直接自己试(双/三 ESC)、可以读配置 —— 这些我都能自查。
**How:** 张嘴问 owner 前先过一遍"这个我能不能自己查/试出来"(skill / 实验 / 读源/配置)。只有**确实只有 owner 知道、且做错代价大**的才问(如 owner 的私人偏好/裁决)。

## 3. 极简回复("开始"/"继续"等)别过度推理、别编理由跳到别处

owner 说"开始", 紧跟在我刚问的"要不要现在验[立刻测试]?"后面 —— 显然就是"验"。我却抓着上一条消息结尾的 P1.2 脚注瞎推, 还编了个错子推断("输入框空了所以不可能是立刻测试", 其实打个草稿就有)跳去 P1.2。owner: "你哪来的信息认为开始是继续主线的意思"。
**How:** 极简回复的指代, **默认是"我刚提议/正在做的那件事"**, 不是上下文里某个旧脚注。要跳到别处需要**明确依据**, 没有就按最近的那件事走。直觉撞"显而易见"时别编故事推翻它(同 [[hallucination-fabricated-rationale-to-override-rule]])。

**共性**: 这三条都是"少抢、多核、就近"。关联 [[precompact-and-self-inject-ui]](本轮联调上下文)。
