**决定一条知识该不该进记忆树,正确的价值尺是「丢了能不能重建」,不是「这知识重不重要」。重要 ≠ 该常驻记忆树。**

## 怎么用
- 记一条前先问:**它丢了能从哪重建?** repo docs / 代码 / 测试 / git 里有 → 留存价值低(随时能重读),记忆树里只存指针 + repo 没有的"何时用"元数据即可,**别抄正文**。repo **不记**的纯经验(踩了什么坑才这么做的**因果链**、排除了哪些别的做法、某个旗标 / exit code 背后的故事)→ 高价值,丢了真丢,该记该加固。
- 同一节点里**实现字面量(函数名 / 行号 / 旗标,易漂、可重建)** 和 **因果经验(金子,不可重建)** 混写时,前者会拖累后者——瘦掉前者(改指针 / 按符号名引用),保后者。
- 算法 / 数学知识只存指针摘要**不是缺陷**,是符合这把尺的正确做法(repo docs 有、能重读)。

## 为什么这条本身要写下来(以及它的局限)
**Why:** 这把尺是 2026-06-14 四路记忆树审查里涌现的;但有个反讽——连涌现它的那一路自己都**反复用错尺**(默认抓"内容重要性"当尺),被另一路拿 CLAUDE.md 当场抓了 3 次。这恰恰证明:**判断类的错,成文规则治不住**(被动文本,会被忘,包括被提出它的人忘)。这棵树自己的 [[memory-currency-protocol]] rule#7 早判过:没上锁的动作靠规则治不住、要强制函数。

**所以这条节点的定位 = 「对抗的引信」,不是「防错铁律」:**
- 它**焊不了** forcing function(stamp 引擎只焊可推导值 sha / 计数 / phase,焊不了"用哪把尺判断"这种纯判断)。
- 真正每次把判断拽回正轨的是**对抗**:有多个视角在场(team / 外审)时多路互抓;**单会话只有一个 CC 时,起不了多视角,就靠"对自己的价值尺判断主动停一拍、自己跟自己唱一次反调"**(涌现一个结论 → 立刻问"我是不是又用错尺了" → 回 repo 核)。
- 这条写下来,是在没有对抗的单会话里**留一个召回锚点 + 提醒"该自反驳 / 该起对抗"**,不是指望"写了就不犯"。别把它当成"声称能防错、实际没 forcing"的反面教材来用。
