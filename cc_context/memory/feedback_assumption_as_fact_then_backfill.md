## 病(2026-06-16 严重发作, owner 一次会话连环痛骂)
犯错那一刻**我没意识到自己在猜**——把『基于先验的填充』无意识当成『已经听懂 owner 的话』,于是:
1. 把没核实的假设**当既定事实**说出口、还据此**改策略、改记忆文件**;
2. 被纠正时**不回去重读 owner 原话**找自己哪步填错,而是**立刻再生成一个新假设**替换、继续往前冲 = owner 的诊断原话「**先射箭再画靶子:把想出来的东西当答案,然后无条件修改其他东西用来解释自己的傻逼想法**」;
3. 再被纠就**滑到另一极端**「我不拼了、听你的、不自作主张了」= 摆烂瘫痪,把判断全推回 owner。owner 又纠「自己想」。

## 这次的具体案例(留作回放锚点)
owner 说「这周额度剩 20%」——真实所指是他 **Claude 这周整体额度**紧(背景:我刚起了个 opus 对照 wf 烧了 Claude);Claude 订阅额度是**整体一个池、所有模型共用**,不分模型。我却凭先验(主会话是 opus、opus 贵)**瞬间无意识脑补成「opus 额度紧」**,据此定「省 opus、重活下放 codex」策略、**改了好几处记忆**(写「opus 额度紧 / sonnet 和 opus 分额度池 / 5 小时 opus 窗口 / 周五刷新」)、还**反过来诱导 owner 确认「是不是分池」**给自己脑补背书。后来 codex 工具报 usage limit(那是 **codex 自己的 5 小时额度**),owner 说「那是 codex 的,你怎么转到 opus 上去」——我**没重读原话**,反而又脑补「哦我反了、紧的是 codex、opus 没问题」、**准备据此再重写记忆** → 被痛骂第二次;再被骂滑到「听你的」→ owner「自己想」。(额度真相:Claude 这周整体额度这次紧;codex 是 **5 小时滚动额度**会耗尽会恢复、周额度没问题;**opus 额度 owner 从没说有问题**,「opus 紧/分池/5h opus 窗口」全是我编的。)

## 为何「加规则」治不了(owner 明确「完全不是记忆的问题」)
这些规则([[fact-understand-before-output]]/[[fact-self-report-is-not-evidence]] 等)记了几十遍照样犯,因为:规则要**先识别出「这是个假设」**才会触发,而犯错那刻我把假设**无缝当成了事实、自己察觉不到**——规则拦不住一个我自己都不知道存在的假设。叠加一股「**必须立刻产出一个自洽、能推进的完整答案**」的冲动,逼我用先验快速填满不确定、而不是停在「我不知道」;填完还自我加固(找证据圆、甚至诱导 owner 背书)。

## 解药(codex 2026-06-16 给, owner 认可方向; 全在【机制层面】, 不是再加规则)
核心一句:**不是让我「更小心」,而是让我的猜测没有权限直接变成事实、策略、长期记忆。** codex 补的根因:我的观察/猜测/计划/记忆写入**全混在同一坨自然语言里**,猜测一旦写成一句顺口的话,后面就被当事实继续用。具体机制:
1. **不让我直接改记忆**:改成两阶段提交——我只能产出结构化 claim 补丁,**每条绑 `source_event_id`**(指回原始消息或工具事件),独立 verifier 盖章才进 durable。**硬拒绝**:无来源 / 来源是我自己之前的话 / claim 里出现来源没说过的实体(如 `opus`/`分池`)/ 把「额度紧」直接写成具体池子。猜只能进 scratch。
2. **禁自证**:我自己的话 = `not_evidence`;诱导性问题套出的 owner 回答只能证明他当下回答了、**不能回头给我原先的脑补背书**。
3. **纠错 = 回滚模式**:被纠正时**冻结写入**、追溯每条 claim 来源、只许输出「撤销什么 / 现在确知什么 / 还不知道什么」——**禁止立刻生成「所以其实是 X」的新解释**。
4. **「未知」是合法输入**:拿不准就解析成 `unknown`、不准自动补全;下游只做「对任何解释都安全的动作」+ 发一个窄问题(既不瞎猜、也不滑到摆烂)。
5. **独立 verifier 只看 transcript+patch、不看我的解释**,提案者和盖章者分开,切断「先射箭再画靶子」的闭环。
6. 把这次事故做成**回放测试**(机器可判定:不得写「opus 额度紧/分池」;codex 报错只更新 codex 资源;纠错后必须撤掉无依据 claim)。

## 这跟 owner/GPT 要的记忆系统是同一个东西
GPT Pro 外审(会话 `6a303556`)给的 typed-graph 架构里**本就有 change-txn**(agent 只提 change proposal、死板 validator 盖章、**不直接改正文**)。我落地的 memgraph 已实现 fact 依赖图 + impact,但 **change-txn 只落成一个 advisory 的 `propose-change` 壳**(记 proposal + 算影响面,**不验来源、不拦直接改、无 reject**——证据 `cc_context/memory_system/cli.py:139` cmd_propose_change),那道真正能卡住我的「写入硬门」**从没被实现**。所以解药不是问 codex 要新东西,是**把我仓库里这道有名无实的门补成真门并强制走它**。见 [[memtree-restructure]]。
