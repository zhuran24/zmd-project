2026-06-01 一致体现的偏好: 动记忆树**分两档**, 别一股脑直接改。

## 规则

- **纯机械 / 安全的小改 → 直接做**, 不必问: 补一条索引、修死 link、同步快照、给 transient 断言补日期、append 一句缺失 nuance 到已有文件的天然落点。
- **结构性大改 → 先把方案给用户过**: 新增 / 删条目、重组分类、改 living 现状源的语义、MEMORY.md slim + 重排、一次落多条 (像这次 31 条 finding)。摆出"建哪些文件、改哪些、MEMORY.md 怎么腾空间", 用户点头再落。

## Why

记忆树是跨 session 的权威信息源, 结构性改动 (尤其 slim 既有条目、改 living 现状源) 一旦走偏会污染未来所有 session 的判断, 且不易察觉。小改可逆且低风险, 卡确认只是浪费。这条本身就是本 session 查出的漏记 —— 落它的那次正是一次结构性大改, 先过了方案才动手。

**How to apply**: 改 memory 前先归档"这是机械小改还是结构大改"; 后者先呈方案。跟 [[no-reply-means-agree]] 配合 (呈了方案不回 = 默认同意推进, 不可逆/高 stakes 例外)。关联 [[lazy-mode]] [[memory-currency-protocol]] [[memory-tree-structural-health]]。
