记忆树里经常把"一开始①、后来②、最后③"整段演变都记下来,但未来大多只需要终态③,①②是噪音,会让树越长越肥、有用信息被淹。owner 2026-06-14 反馈:不是禁止记历史,而是**记之前先过一道"这段过程对以后有没有用"的筛子**。

演变过程只在对未来有作用时才记:
- ✅ 值得记:旧方案**为什么被否**(防未来的我/别人重提已验证失败的方案)、某旧结论"现在不可信"的明确标记(防盲信)、踩过坑的**根因**(防重蹈覆辙)。
- ❌ 不值得记:纯实现迭代的中间态(早上写错下午改对、v1→v2→v3 的前两版细节)、被推翻后再无警示价值的临时假设、过程的时间线流水账。

默认动作:**只写终态 + 必要时一句"为什么不是旧态"**,不写完整演变史。

**Why:** 上下文有限会被压缩,记忆树是 handoff 核心;塞满无警示价值的过程流水账 = 真有用的信息被淹、每次加载浪费 token、树越长越难维护。
**How to apply:** 往树里写"X 改成了 Y"前先自问:未来的我光知道 Y 够不够?只有"知道曾经是 X、为什么离开 X"能防重蹈覆辙或防盲信时,才补那一句;否则只留 Y。与全局"知识持久化"里"不记中间假设"、memory-currency-protocol(在 cc_context 项目树)的 superseded 标记同源。
