# Slice A 对拍审查

**三道验收通过，正式求解入口有一处可复现的输入差异。** 42 份黄金、原交付的 200 份随机脚本和本次独立生成的 200 份脚本，都与实时 Lean 输出逐字节一致。差异发生在第一步之前。求解器直接把合法的 JSON 初态传给 `LegalBase::new`，有可能得到回放时没有的错误。

## 1. 正式入口的行为差异

空历史满足 `历史.合法`。给初态的仓库放一件源矿，把数量写作 JSON 数字 `1e0`。同一份文件得到以下结果。

| 入口 | 退出码 | 结果 |
|---|---:|---|
| `lake exe 对拍` | 0 | 第一步输出 `{"仓库":[["源矿",1]]}` |
| Rust 回放 CLI | 0 | 第一步输出完全相同 |
| Rust 库 `LegalBase::new` | 1（复现调用程序） | 构造返回 `Err("invalid number")`，无输出行 |

把同一库存的拼写改成 `1`，正式入口也能构造并输出上表中的快照。两个 Rust 入口都链接原交付的包。回放先经过 `json.rs::number`，将十进制尾数和指数还原为整数字面值。正式入口接收调用者用 `serde_json::from_str` 读出的 `Value`，通过 `Simulation::new` 直接进入 `State::load`。仓库行按 `usize` 解码时仍带指数。只用程序自己输出的整数快照往返会漏掉这处差异。空历史、一个库存行已足以触发，脚本中的一步用于观察成功端的输出。[最小 JSON](复现/指数库存.json) · [最小库调用](复现/正式入口.rs) · [正式构造函数](../../src/lib.rs#L32) · [回放数字解析](../../src/json.rs#L124) · [仓库行解码](../../src/snapshot.rs#L240)

## 3. 独立随机对拍

用 Python 的 MT19937，种子 `0xc4d5a17`，生成器独立于交付的 Python 代码。从有箱、有边、有期望行且至多 17 个单位的黄金段中，按**各单位种类及其数量**分桶。不同桶的图即使重编号也不同。为协议核心、仓库取货口分别保留抽样位置，再抽满 25 桶。每桶抽 8 份，本次来自 18 个黄金文件、涵盖 12 种单位。

每份随机抽取黄金段的一个操作后快照，跟到该行之前最近一次离线后的历史，保留运输来处、轮询记录、制造进度等已有状态。再随机换一格箱货，重抽 19 种库存及段策略。只以黄金行作为起点，后续每个输出都重新交给 Lean 计算。

每份有七轮混合操作。每轮打乱走步、离线、放收货、开关、模式、仓库等操作块，保留放货后随即收格 0 的局部顺序，以保证收到真实的货。离线历史含临时建成再拆除、随两端就绪穿插接通、最后重接。1,400 次离线中，1,399 次确实改变最终建成或接通先后，另一次仅改变事件历史。

| 走步 | 非走步 | 输出行 | Rust / Lean |
|---:|---:|---:|---|
| 200 × 300 = 60,000 | 11,144 | 71,144 | 两端全部成功，逐份核对行数和完整 stdout 字节，0 差异 |

离线、拨开关、放货、收货、入库、出库、设储存箱模式各 1,400 次。设准入口及重置计数各 616 次，设取货指向 112 次。按文件名顺序拼接生成输入的 SHA-256 为 `1acecd25a85c9a0ae7757368917f35d8e73ef58dc1764650b2959c6ddd8677ad`。[独立生成及比对脚本](独立对拍.py)

## 4. 规格书逐节对照

| 规格书 | 代码与权威规则的对照 |
|---|---|
| §1 目标、边界 | `Cargo.toml` 为单包，直接依赖仅 serde、serde_json。CLI 每步、每项操作后输出，错误时刷新已成功的前缀、写 stderr、非零退出。`settle` 顺扫到整趟无移动。 |
| §2 两类入口 | `LegalBase` 私有包装 `Simulation`。创建及离线重建经历史逐事件校验、每个历史前缀的端口检查、最终布局可达性检查。正式 `Parameters` 无旧说法字段，步进固定 `Twice`。待接箱次序函数、四种旧说法和额外的首选通道记录均位于 `oracle` 模块。两入口传入不同的建表函数，步进按规则类型分派。入口类型隔离符合要求，初态数字接受范围有第 1 节的差异。 |
| §3 严格 JSON 和规范状态 | 回放逐对象拒绝重复键，并核对解码后的值与原形状。十二张表按有限域消费和查剩余键，区分缺省、显式默认、非法非默认，按键排序并省略默认行。运输格用 `Option<Load>` 联合存物品、已停、来处。机器用 `Batch` 区分空闲、制造中、成品待转，制造中的缓存由配方唯一恢复。箱和机器各自持有开关，仓库取货设施没有开关。供电保存在段参数，断电仍保留面板开关。 |
| §4.1 常量 | 核对 `model.rs` 与 `单位.lean`、`配方.lean`、`合法基地.lean`。19 种物品顺序、17 种单位、格数与端口数、18 条配方和每 tick 8 步吻合。接口集另外逐配方检查原料与产物。 |
| §4.2 历史与建表 | `History::read` 保存从空布局到当前的每个前缀。`since` 逆查连续成立的起点。`rank` 先比终点时刻再比长度，`level` 分别检查次序全相等或取最大值。分组按通道表先后，稳定排序，缺级别的组不入表。与 `通道与移动.lean`、`拓扑与级别.lean`、`判定.lean` 的立表逻辑对应。 |
| §4.3 轮询、放货、计数 | 分流器上次及出货队列存通道，进货上次存下标。成功离线保留这些值，因通道集合和种类相同，进货表长度保持。制造机优先同种存货格，满则拒绝。准入口在相应上限存在时才累计或追加名额。 |
| §4.4 单步 | 对照 `判定.lean`、`物品格.lean`、`框架.lean`，Rust 依次步初整理、记录第一次输入判定、元件移动、记录第二次判定、非运输单位移动与箱传输、结束制造、开始制造、计时。成功移动立即整理，空箱也重置冷却，成品缓存进取货格独立于电与开关。已停封顶和拍取模在驻留状态中完成。 |
| §4.5 段内操作 | 十种非走步操作均有分支，按 `作用.lean` 校验。放货逐件找格，已满时提前结束，后续相同物品也放不入。离线先检查历史及单位、种类、边集合，再替换建表并处理计数，保留段参数。正式入口还检查新历史合法。 |
| §5 验收 | 上述三关实跑通过。三关的随机差分均走回放接口，正式入口只有独立的库测试，不能据此推出两个入口能读入完全相同的初态。 |

检查了缺省值和通配分支的用途。缺席的合法表行按格式恢复默认，有行但解码失败时传出错误。快照序列化的 `or_default()` 创建输出行向量。待接箱的“其他出通道数”返回无次序，是 Lean 已定义的结果。移动源、目的类型错配会触发内部一致性断言。在本次审查范围内，未发现未知输入落入默认分支并继续走步的实例。

### 规格文字与权威源码的三处差别

1. 格式文档以物品名字符串描述操作参数。Lean 段内操作也接受已知物品作键的单键对象，例如入库一件 `{"源矿":null}`。Rust 与 Lean 都成功，段首状态另受编码回检约束。[操作物品复现](复现/操作物品构造子.json) · [操作解码](../../../规则模型/对拍/编码.lean#L93)
2. 离线历史里的制造机种也可用单键构造子对象。举例中的研磨机能用对象写法重建。段首历史经编码回检，要求规范字符串。两端离线均输出 `{}`。[离线机种复现](复现/离线机种构造子.json) · [机种解码](../../../规则模型/对拍/编码.lean#L52)
3. §4.2 的“对分流器返回自身”须加上“已是末端元件”。仅建一台无出口分流器，其终点为 `none`。Lean 的 `#guard` 实跑通过，Rust 的 `endpoint` 先作相同判断。待接箱次序与终点是两个读数。[Lean 最小复现](复现/分流器终点.lean) · [终点定义](../../../规则模型/Endfield/拓扑与级别.lean#L67)

这三处与交付报告所列一致。另有两处内部写法不同而输出规则相同。Lean 的原始计时可以超过 8 或 3，快照分别封顶或取模。Lean 整理的扫描次数以单位数为上界，Rust 扫到不再移动。每件货移入运输格后已停归零，在本轮计时前至多移动一次，所以扫描上界足够。

## 5. 实测覆盖缺口

下表基于干净重跑的三关、独立随机集和正式入口复现。对 release CLI 和正式入口测试、示例程序一起取 LLVM 分支计数，按源文件及条件起止位置合并泛型实例。每个条件的真、假各算一个方向。`match` 分支另查 LCOV 零执行行，编译期常量初始化、断言和不可达防线需结合源码解释。以下几处直接影响对规则或接口的信心。

| 情形 | 证据与影响 |
|---|---|
| 货恰好会回到刚离开的格 | `movement.rs:154` 的相等条件真侧为零。黄金中已有“来处”，但在候选目的格可收且正好等于来处的瞬间，没有执行拒绝回移。 |
| 收制造机的存货格 | `action.rs:135` 的 `Slot::Stock` 收货分支为零。箱格和制造机取货格的成功收货不能检验这条路径。 |
| 制造恰好剩 0 时断电 | `state.rs:169` 的假侧为零。在前面的“正在制造、剩余为零”成立后，未见供电为假的结束制造判定。 |
| 非法端口前缀与异常回放拓扑 | `topology.rs:172` 未走进口数超限。正式测试已有出口超限。`topology.rs:262` 没遇到组内起点次序均有值却不相等。`topology.rs:120` 没遇到非分流末端有多个通往非运输单位的出口。这类超出口数布局可在合规回放中出现。 |
| 状态边界与坏输入 | `snapshot.rs:135` 未走实际缓存与有效制造配方原料不符的拒绝分支。`snapshot.rs:282` 未在输出时遇到有货运输格已停仍是零。`snapshot.rs:296` 未由“放行为空、累计为零、名额非空”单独触发准入口行输出。 |
| 正式端口数与内部防线 | `model.rs:86–89` 的仓库取货口和制造机各档端口数没有在正式端口校验中执行。回放可以运行这些单位而不调用正式的端口校验。`step.rs:81,103,127`、`movement.rs:118,142` 是组或货位与单位种类错配的内部防线，正常建表和选位应当使其不可达。 |
