# 规则模拟器规格书（第一阶段：Slice A 直白参考版）

## 1. 目标、边界与权威准绳
在仓库根目录 `规则模拟器/` 下建立独立单包 Rust 步进与对拍程序（仅依赖 `serde`、`serde_json`，不引入额外抽象框架，不引用已冻结的 `求解器/crates/`）：
- **权威准绳**：本规格书若与 `../规则模型/Endfield/`（Lean 4 源码）、`../规则模型/对拍/格式事实.md` 或 `../规则模型/对拍/黄金/*.json` 存在任何不一致，**一律以 Lean 源码与黄金标准答案为准，并须在回报中明确列出不一致处，严禁自行猜测或给默认值兜底**。
- **只跟规则与格式正文、不跟 Lean 实现脾气**：Rust 实现的是游戏规则与 `../规则模型/对拍/格式事实.md` 明文规定的协议，**不模仿 Lean 无界 `Nat` 或 `deriving FromJson` 的派生副产物**（数值采用原生机器整数如 `u64` / `usize`，超出范围直接报错，不写大整数；物品、种类等枚举只认格式说明写明的字符串，整数只认普通十进制非负整数，不兼容单键构造子对象或科学计数法写法；格式之外的写法「Lean 认、Rust 拒」属有意边界）。
- **输入／输出协议**：严格实现 `../规则模型/对拍/格式事实.md`（对拍格式 v1）。命令行接收单个 JSON 文件路径，按段依次执行；每完成 1 步 `走` 或 1 项段内操作向标准输出打印一行无多余空白的规范化 JSON；若段内给出 `期望`，逐行核对内容与总行数；任何 JSON 语法错误（含同一对象内重复键）、超域／乱序／重复表键、段首不合规矩或操作 `做得了 == false`，均向标准错误输出原因并以非零状态码退出。
- **阶段边界**：本阶段先以清晰直白的数据结构实现模型语义（例如 `整理` 直接按 `带内` 顺序反复前移至不动点），严禁把未验证的提速技巧混入初版；待全部黄金集、接口错误集与随机差分对拍零差异通过后，下一阶段再做定长零分配／单链逆序 `整理` 提速与 `70×70` 静态场地建表（Slice B）。

## 2. 正式求解入口与回放专用兼容项的类型隔离
以下两项机制在正式求解中永不使用，仅用于通过历史实测回放对拍，**须在模块与类型上与正式入口隔开（不靠运行时布尔开关混用）**：
1. **对拍回放入口 `OracleRunner`**：接受任意满足 `历史.合规` 的段首输入，支持：
   - **回放专用项 A（`待接箱的次序`，见 `拓扑与级别.lean` 92–105 行）**：当 `运输带从` 找不到任何有终点的运输带时，有入通道的 `分流器` 在「无出通道」或「唯一出通道通往无出通道的 `桥接器格`」时取次序 `1`；其他元件（`所在元件(1, e) == Some(e)` 且非分流器）仅当 `下游元件` 恰有 1 个 `[f]` 时取 `待接箱的次序(f) + 1`。
   - **回放专用项 B（`输入判定都没货时` 的四种已排除旧说法，见 `判定.lean` 127–141 行）**：对通往汇流器 `j` 且起点不是分流器的通道 `c`，记步初整理后状态为 `s1`、元件移动判定结束后状态为 `s3`：
     - `"每步判两次"`（现行唯一正式规则）：`s3.输入判定(j) == Some(c)`（元件移动阶段调用时传 `s3 = s1`，即认 `s1` 的判定；非运输单位移动阶段传真正的 `s3`）；
     - 其余四种仅回放对拍用：若 `s1.输入判定(j) == Some(c')` 则四者均返回 `c' == c`；若 `s1.输入判定(j) == None`，则 `"不收"` 返回 `false`、`"都收"` 返回 `true`、`"再判一次"` 返回 `s3.输入判定(j) == Some(c)`、`"轮到的那条"` 返回 `元件先后(p, 位置上的通道(p, s1.进货上次(j))).head() == Some(c)`（`p` 为 `j` 的进货表）。
2. **正式运行入口 `LegalBase`（封装新类型）**：构造函数强制校验 `历史.合法`（`合法基地.lean`：`历史.合规 && 历史.端口数合 && 布局.走得通`），不通过直接返回 `Err`；其参数类型不含 `输入判定都没货时` 字段，固定按 `"每步判两次"` 执行（且因满足 `走得通`，所有连着通道的运输单位均在正经运输带上，自然不触发 `待接箱的次序`）。

## 3. 严格 JSON 解析与规范化状态读写
- **禁止重复键**：反序列化时须拦截同一 JSON 对象内的重复键并报错退出（对齐 `对拍/编码.lean` 的 `StrictJson`）。
- **输出行格式**：紧凑单行 JSON（无多余空白），空数组字段整键省略，全默认时输出 `{}`；所有 JSON 对象内部键按 UTF-8 字符串字典序输出（与 Lean `Std.TreeMap String Json` 一致）。
- **状态十二项字段的有效域、默认值、排序规则及段首合法性检查**：不另抄第二份表，**完全以 `../规则模型/对拍/格式事实.md`「状态的完整写法与比较」与「段与历史」「段内操作」三节（及 `对拍/状态.lean`、`对拍/执行.lean`）为准**。注意其中两条细则：
  - `已停` 与 `来处` 的规范输出键域仅为**当前有货的运输物品格**（段首输入若在现有非运输格或空运输格上显式写出默认值 `0` / `null` 允许通过，给非默认值报错；给不存在的格位报错）；
  - `进货上次` 在段首输入时须已满足规范范围（表长 `0` 或 `1` 时只能为 `0`，表长 `L >= 2` 时须 `< L`），输出时按现布局 `进货表` 长度取 `if n == 0 || len <= 1 { 0 } else { n % len }`。

## 4. 核心常量、历史拓扑与单步流水线（对齐 `Endfield/*.lean`）
1. **常量与种类**：`tick = 8` 步；19 种物品枚举顺序、单位种类及端口/物品格数、18 条固定配方完全对齐 `配方.lean`、`单位.lean`、`合法基地.lean` 与 `格式事实.md`。
2. **历史与立表**（`通道与移动.lean`、`拓扑与级别.lean`、`判定.lean`）：
   - 按 `1..=H.len()` 依次应用 `建成 / 接通 / 重接 / 拆除` 得各时刻布局 `布局于(H, t)`；
   - `终点的时刻` 与 `组的时刻` 均用 `最近一次变成(p, now)`（满足 `t..=now` 恒真的最小 `t`）；
   - `是末端元件(L, e)`：`e` 是元件、至少有一条通往非运输单位的出通道，且（`e` 为 `分流器` 或所有出通道均通往非运输单位）；`终点(L, e)` 在 `!是末端元件(L, e)` 时返回 `None`，对末端元件中的分流器返回自身 `Some(e)`，其余末端元件在唯一出通道 `[c]` 时返回 `Some(c.止)`；
   - `级别(H, now, g)`：组内通道按当前 `通道表` 接通先后排；元件组要求各通道 `c.起` 的次序均存在且全相等，非运输组取各通道 `所在元件(c.止)` 次序均存在时的最大值；按 `(次序, 组的时刻)` 字典序升序排级别（无级别的组照 `历史.立表` 不入表）。
3. **轮询与移动**（`判定与轮询.lean`、`物品格.lean`）：
   - **强类型区分两种轮询状态**：`分流器上次: Option<Channel>` 与 `出货已移动: Vec<Channel>` 存通道本体 `(起, 止)`（离线重排后仍指向原通道）；`进货上次` 存 `usize` 表下标（离线重排后按同一数字在新 `进货表` 上取模）。
   - `元件轮询(n, last_idx)`：`[0..n]` 循环左移 `last_idx.map(|i| i + 1).unwrap_or(1)` 位。
   - `非运输单位轮询(n, is_machine, moved_indices)`：`未移动` 为不在 `moved_indices` 中的递增下标；若 `is_machine && 未移动.first() == Some(&0)`，把 `0` 移至 `未移动` 末尾；返回 `未移动 ++ moved_indices`。
   - `放进哪` 制造单位存货格规则：先找已有同种物品 `x` 的存货格（件数 `< 50` 放入，已满 `50` 直接拒收，**绝不放入另一空存货格**）；各存货格均无 `x` 时放入编号最小的空存货格。
   - `移一件` 准入口计数：仅当 `累计上限.is_some()` 时 `累计已收 += 1`；仅当 `每5tick上限.is_some()` 时向 `名额` 末尾追加 `37 + (6 - 拍 % 4) % 4`。
4. **单步 `一步于` 执行顺序**（`判定.lean` 395–403 行）：
   1. **步初 `整理`**：按顺序扫 `T.带内`，能移即 `移一件`，反复扫至整趟无移动；记此时状态为 `s1`。
   2. **`元件的移动判定`**：按 `T.元件的组` 顺序逐组按轮询判定各通道（进汇流器的非分流器通道须过 `汇流器收(s1, s1)`）；**每成功 `移一件` 后立即执行一次 `整理`**；全部元件组跑完后记状态为 `s3`。
   3. **`非运输单位的移动判定`**：按 `T.非运输单位`（建成先后）逐个单位 `u`：令 `k = 未定.传输排在几组之后[u]`，先跑前 `min(k, 组数)` 组移动判定（每成功 `移一件` 立即 `整理`，汇流器判据用 `(s1, s3)`），再对满足 `!仓储模式 && 有电(u) && 开关[u] && 冷却还剩 == 0` 的协议储存箱执行 `传输一次`（**箱内无货也触发并重置 `冷却还剩 = 40`**；按格 `0..6` 依次向仓库转入 `min(件数, 80000 - 仓库[物])`，不改 `出货已移动`），最后跑剩余各组移动判定。
   4. **`结束制造判定`**（按建成先后遍历制造单位 `u`，分两小步）：
      - 若 `制造中[u] == Some((r, 0))` **且 `有电(u) && 开关[u]`**，执行 `结束一次制造`（`缓存 := [产物]`，`制造中[u] := None`）；
      - 随后（**不看 `有电` 与 `开关`**！）：若 `制造中[u].is_none()`、`缓存` 为单堆产物且 `取货` 格为空或同种合计 `<= 50`，整批转入 `取货` 格并清空 `缓存`。
   5. **`开始制造判定`**：若 `有电(u) && 开关[u]`、`制造中[u].is_none()`、`缓存` 为空且存货格满足唯一配方 `r` 的原料用量，扣减原料入 `缓存` 并设 `制造中[u] = Some((r, r.时长 * 8))`。
   6. **`计时`**（`框架.lean` 266–289 行）：有货运输格 `已停 = min(8, 已停 + 1)`（其余归 `0`）；运行中的制造单位剩余步数减 1（停在 0 不下溢）；准入口各名额减 1 并滤除 `0`、`拍 = (拍 + 1) % 4`；运行中且处于无线传输模式的协议储存箱 `冷却还剩` 减 1（停在 0 不下溢）。
5. **段内操作**：`设准入口`、`重置计数`、`设储存箱模式`、`设取货指向`、`拨开关`、`放货`（照 `格子/供电与操作.lean` `放进单位` 逐件调用 `放进哪`）、`收货`、`入库`、`出库`、`离线`（核验 `做得了` 后替换历史重算 `立表`，供电、端口映射与未定策略沿用本段设定）。

## 5. 三道机器验收硬门槛（全部通过才算交付）
1. **黄金集全量逐字节对拍**：遍历 `../规则模型/对拍/黄金/*.json` 全部 43 份文件，Rust 程序标准输出与各段 `期望`（以及 `lake exe 对拍` 实时输出）逐行逐字节全等。
2. **错误与边界接口核验**：覆盖重复 JSON 键、未知字段、超域／乱序表键、非运输格或空运输格带非默认 `已停`/`来处`、各项 `做得了 == false` 操作及 `../规则模型/对拍/核接口.py` 全部用例，非法输入一律非零退出、零静默兜底。

# 第二阶段：Slice B（70×70 静态场地建表、蓝图判定与正式题面校验）

## 6. 阶段目标与模块边界
在现有 `endfield-sim` 单包内新增场地模块（如 `src/site.rs`），只做**纯静态几何与从空地逐件建成事件表**，不引入 `remove` 或带替换的 `place`，也不把场地类型塞进 `LegalBase` 内部：
- **权威准绳**：场地层几何、端口排序、重接事件、供电与取货口号规则严格对齐 `../规则模型/Endfield/格子/`（`几何与端口.lean`、`场地与建造.lean`、`供电与操作.lean`）、`../规则模型/对拍/场地.lean` 及 `../规则模型/对拍/格式事实.md`「场地模式」一节；照旧遵循第 1 节「只跟规则与格式正文、不跟 Lean 实现脾气」，先求语义清晰准确，不做未经剖测的提速技巧。
- **坐标系约定（严禁上下颠倒）**：场地层同 Lean `格子/` 采用**屏幕坐标**：左上角为 `(0, 0)`，`i` 向右递增（列 `0..=69`），`j` 向下递增（行 `0..=69`）；顺时针四边依次为 `上(0)、右(1)、下(2)、左(3)`。因此基地**左边界是 `i == 0`（仓库取货口朝 `右`，占 `1×3`），下边界是 `j == 69`（仓库取货口朝 `上`，占 `3×1`）**。与《求解约束.txt》左下角原点坐标 `(x, y)` 的换算关系为 `(x, y) = (i, 69 - j)`（方向 `上/右/下/左` 在两边指向同一屏幕方向）。

## 7. 公开类型与三个纯函数／方法接口
1. **几何与摆件类型**（对齐 `几何与端口.lean`）：
   - `Dir { 上, 右, 下, 左 }`、`Parallel { 上下, 左右 }`、`GridPos { i: u8, j: u8 }`（`i < 70 && j < 70`）；
   - `PlacementKind`（注意各变体携带的方向含义与源码严格一致）：
     - `传送带(in_edge: Dir, out_edge: Dir)`：**存货边**与**取货边**（不是货走的方向；两边相同时非法）；
     - `分流器(in_edge: Dir)`：**存货边**（其余三边取货）；
     - `汇流器(out_edge: Dir)`、`物品准入口(out_edge: Dir)`、`协议储存箱(out_edge: Dir)`、`仓库取货口(out_edge: Dir)`、`制造(MachineKind, out_edge: Dir)`：均为**取货边**（大制造单位 `6×4` 的 6 格长边在取货边与存货边上，即取货朝上下时宽 6 高 4，朝左右时宽 4 高 6；`仓库取货口` 无存货端口，唯一取货端口位于朝内的取货长边中间一格，即边上格号 `1`）；
     - `桥接器(first_edge: Dir)`：桥接器自己的**第 1 条边**当前朝屏幕哪边；占 `id..id+4` 四个单位号，其中 `id + k`（`上 0、右 1、下 2、左 3`）是**存货端口在屏幕第 `k` 条边**的那个 `桥接器格`，屏幕边 `e` 上的取货端口属于对边 `e.opposite()` 那个号；
     - `协议核心(out_parallel: Parallel)`：**取货**的那一对平行边（占 `9×9`）；
     - `供电桩`：占 `2×2`，占用自身摆件号 `id` 参与防重号，但生成 **0 个**里层状态机单位。
   - `Placement { id: Id, pos: GridPos, kind: PlacementKind }`；
   - `CorePortOrder`：协议核心 20 个端口（两条非取货边各列格号 `1..=7` 共 14 个存货口，两条取货边各列格号 `1, 4, 7` 共 6 个取货口；边上格号从 0 起，水平边自左向右、竖直边自上向下）的排序号表，并提供默认全 `0` 构造器（按固定 `上、右、下、左` 及格号递增破同）。
2. **场地构造与事件生成（不绑 `LegalBase`，场地层只出数据）**：
   - `Site::new(placements: Vec<Placement>) -> Res<Site>`：做一次与施工先后无关的集合合法性检查（完整矩形在 `70×70` 内不越界、占格互不重叠、所占编号 `占号` 互不重用、协议核心 `<= 1` 个、仓库取货口背向取货边的长边贴基地四条外边界之一、传送带进出异边；注意准入口落空格不在此处限制，而在蓝图判定中查），并一次性算出与施工先后无关的两张静态表：
     - `site.powered() -> &[Id]`：仅制造单位与协议储存箱，占格中任一格落在任一供电桩左上角 `(i, j)` 的 `[i-5..=i+6] × [j-5..=j+6]` 范围内即有电，按单位号升序；
     - `site.ports() -> &[(Channel, usize)]`：从协议核心或仓库取货口出去的每条紧贴通道对应的固定几何取货口号（核心上下型为上 `0..=2`、下 `3..=5`，左右型为右 `0..=2`、左 `3..=5`；仓库取货口唯一口为 `0`；与 `CorePortOrder` 无关），按通道 `(起, 止)` 升序。
   - `site.history(order: &[Id], core_order: &CorePortOrder) -> Res<Vec<Event>>`：校验 `order` 恰好是 `site` 全部摆件 `id` 的一个排列（无缺漏、无重复），按 `order` 从空地依次调用 `场地.建成` 拼接事件：
     1. 先发该摆件对应的 `Event::Build`（桥接器按上、右、下、左发 4 个，供电桩 0 个）；
     2. 再按新摆件的有序端口列表依次扫描已有摆件端口，对唯一正对紧贴且至少一方为运输摆件的配对发 `Event::Connect`：
        - 端口总序：先全部存货端口，后全部取货端口；
        - 非核心同边多口（箱、制造单位）：按 `同边先后(取货边 d, n)`——取货朝 `下` 或 `左` 时边上格号 `0..n` 递增，取货朝 `上` 或 `右` 时 `n-1..=0` 递减（存货边与取货边共用同一顺序，不绕周长）；
        - 分流器 3 个取货口 / 汇流器 3 个存货口：从唯一的那个存货/取货边 `d` 起顺时针依次为 `[d.顺时针, d.对边, d.对边.顺时针]`；
        - 桥接器（第 1 条边朝 `d`）：存货四口依次为 `[d, d.对边, d.对边.顺时针, d.顺时针]`（即第 1、3、4、2 条边），取货四口依次为 `[d.对边, d, d.顺时针, d.对边.顺时针]`（即第 3、1、2、4 条边）；
        - 协议核心：存货先于取货，同类内按 `CorePortOrder` 排序号升序，同号按 `上、右、下、左` 再按边上格号递增破同。
     3. 最后当新摆件是普通 `传送带` 时，按**先上游（`false`）后下游（`true`）**沿正对紧贴的相邻普通传送带链走到尽头（成环走不到头、缺口或尽头未接其它摆件均不产生），若带端格在相应端已有对外通道（且两端均不属于新摆件自身），发 `Event::Reconnect`。
3. **正式题面静态检查与蓝图分批判定（独立纯函数／方法，不影响对拍入口）**：
   - `site.check_problem() -> Res<()>`：检查 Lean 模型未查的两项场地级正式要求——① 协议核心**恰好 1 个**（规则第 73 行）；② 所有仓库取货口**只贴左边界（`i == 0` 且朝 `右`）或下边界（`j == 69` 且朝 `上`）**（题面「仓库取货口位置」）。
   - `LegalBase` 限速准入口总数检查（规则第 84 行）：在 `LegalBase::new` 与 `LegalBase::apply(Action::SetGate(..))` 中检查全场开启 `每5tick上限` 的物品准入口数量 **`<= 50`**（超限返回 `Err` 且原状态保持不变；`OracleRunner` 不查此项以保持与 Lean 对拍一致）。
   - `site.check_blueprints(batches: &[Vec<Id>]) -> Res<()>`：给定分批蓝图的摆件号列表，校验其展平后恰为 `site` 全部摆件的一个排列，且对每一张蓝图 `batch`：
     1. **非带先于带**：所有非普通传送带摆件均排在普通传送带之前（`蓝图先后`，物品准入口属非普通传送带）；
     2. **外接框 `<= 50×50`**：非空 `batch` 中全部摆件占格满足 `max_i - min_i + 1 <= 50 && max_j - min_j + 1 <= 50`；
     3. **准入口依靠条件**（规则第 84 行字面、实测-2026-11-25）：本张蓝图中的每个 `物品准入口`，在**本张或更早蓝图**已包含的其他摆件（含同一张图里稍后建成的普通传送带）中，至少存在一个端口 `(c, d)` 使得 `c.邻格(d) == Some(该准入口位置)`。
