**规则**: 给 GPT Pro / 推理模型的提示词 = 一句**开放的问题** + 必要交代(哪个包、sha、附件是什么),就完。两类废料别往里塞: 脚手架、自言自语。

**owner 教的对比 (2026-06-16)**:
- owner 的提示词: 「看看落地的改动是否符合我们的讨论、哪里偏离了」「看看这套工具有没有什么问题」—— 一句开放问题,材料给足就放手。
- 我的提示词(被否,连删多次重发): 在问题外裹了 ① 把 5 个工具挨个解释一遍(替它读、还可能带偏它)② 一张「要找哪几类问题」的清单(逻辑 bug/边界/漂移/gate 失效/设计隐患 —— 给它划了框,容易只在我列的几类里找、漏掉清单外的)③ 规定输出格式(按严重度、附定位、附触发条件、不确定标推测)。

**两类要删的废料**:
1. **脚手架** —— 替它预读代码/工具、给「请找以下几类」清单、规定输出格式。对会自己 CoT 的模型这不是帮它,是**框住它的搜索面 + 加噪声**。
2. **自言自语**(owner 2026-06-16:「你经常把自己脑子里的事、自言自语的东西写进提示词」)—— 把只在我脑子里有意义的**框架词 / 内部区分**漏进去。典例:「**独立**看看这套工具有没有问题」的「独立」,是我自己「#1 验证修复 / #2 独立找问题」分工里的词,对 GPT 毫无意义(它本来就只能自己看,不可能找人讨论)。

**Why**: 两者都是从**我的视角**写的、不是从读者视角。GPT 收到的是包 + md + 一句话,它接不住我脑子里的框架,也不需要我替它划范围。给足材料 + 开放问题,它发挥得更全、更不带偏。

**根因(我反复犯)**: owner 上一轮纠「别放无意义的元历史,每个内容都要有用」,我 overcorrect 成「那就把信息塞全」。其实「有用」= **别有废话**;不是「指令越全越好」。共同上游 = 没真正站在读者那头想就把自己脑子里的东西倒出去([[fact-understand-before-output]])。

**How to apply**: 每个词发出去前过一遍**读者视角** —— 这个词对收到的 GPT 有意义吗,还是只对我有意义?
- 删: 替它读代码/工具的段落、「请找以下几类」清单、输出格式规定(脚手架);只在我脑子里成立的框架词/区分词(自言自语,如「独立」)。
- 留: 开放问题 + 哪个包(名+sha 让它先校验)+ 附件是什么。
