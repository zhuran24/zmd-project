# 块三：CGRA、流式微流控及压缩子图布线的一手文献核对

研究问题：怎样把物理端口/开关状态与路径变量分开，以及怎样压缩逐格布线图。本文是文献证据记录，正文以论文摘要或指定全文节为依据；对应本题的模型改法是推论，未在 70×70 布局上实现或验证。

## 立题问题

1. 物理可达图与应用连接需求怎样分开？词：routing resource graph；device-model graph；spatial mapping；CGRA mapping。
2. 能否用连通子图替代逐边商品变量？词：graph minor embedding；vertex model；route sharing；generic connectivity-based mapping。
3. 流道布局怎样表达共享、交叉和不希望发生的接通？词：flow-based microfluidic channel routing；control channel routing；multilayer channel routing；exclusion zones。
4. 静态可布线和吞吐/时序的边界在哪里？词：modulo routing resource graph；streaming application mapping；synchronous dataflow；fluidic resistance。

5. 怎样压缩整个可布线解集合，而不是逐条生成路径？词：frontier-based search；zero-suppressed decision diagrams；graph sets；permanent non-overlapping pathfinding。

## 游戏规则锚点

依据只读文件 `/home/zhuran24/zmd-research-fresh/《明日方舟：终末地》游戏规则.txt`：

- 端口：“除供电单位外的所有单位的部分边，每个端口占一格宽”。
- 自动接通：“不同单位的取货端口与存货端口相对紧贴、且至少一方是运输单位时，自动形成通道”。
- 传送带：“大小1x1，任意一条边为存货端口、其他任意一条边为取货端口”。
- 桥接器：“大小1x1，四条边都为存货兼取货端口，四个物品格各只与一条边的存货端口和对边的取货端口相连”。桥接器不是可任选连通的四向交汇点。
- 时间：“物品在运输单位的物品格中必须停留至少 1 tick”；“基地每 1/8 tick 为一步”；“汇流器只通过出现输入判定的通道和与分流器形成的通道收货”。

## 证据行（边读边追加）

- [10.1109/FPL60245.2023.00052] Zhou、Stojilović、Anderson 2023，GRAMM: Fast CGRA Application Mapping Based on A Heuristic for Finding Graph Minors（FPL，305–310）。解的问题：将应用数据流图嵌入 CGRA 硬件图，找合法放置与路由。方法：有向、带类型的 graph minor；每个应用顶点对应一个含功能节点及路由节点的 vertex model，以加权最短路重建模型，迭代提高冲突资源的历史代价。规模：18 个基准，数据流图 6–43 节点；6×6、8×8 阵列，FFT 为 10×10；表 II 中 8×8 的大多数平均时间为 0.02–1.36 秒。对应本题：应用图≈机器/物流需求；设备图≈实际物品格及端口；vertex model≈带子路径连通子图。可借类型标签区分机器、单通道带、桥接器内部的四个独立通道。不对应的：本题运的是不可复制的物品，不能把电子信号扇出当作任意分流；论文硬件已给定，不处理单位朝向导致的自动接通，也没有本题轮询和反压语义。对本题有什么用：用在 L 的启发式布线候选生成，替掉逐格多商品 ILP 搜索中的寻路步骤；失败不能用于 U。静态/速率边界：这篇的图 minor 合法性和资源冲突消除不证明本题每个循环态吞吐。依据：全文 §II–III（PDF 页 2–4），§IV 表 II（PDF 页 5）；[作者机构全文](https://infoscience.epfl.ch/server/api/core/bitstreams/47ea37f2-41fb-4959-b81b-6879a5535dc6/content)；[作者项目出版清单](https://cgra-me.ece.utoronto.ca/pubs/)。

- [10.1109/ICCD.2009.5413185] Amin、Thies、Amarasinghe 2009，Computer-Aided Design for Microfluidic Chips Based on Multilayer Soft Lithography（ICCD，2–9）。解的问题：从期望流模式推导阀门控制，再把控制阀连接到外部控制端口。方法：先定义流 ISA，再推阀门和可共享控制线组；布线将网格点拆成容量 1 的 conduit 边，连接用最小费用最大流；扩展至多种流并为允许共享的流使用 max 容量约束。规模：3 张真实芯片，设置阶段≤5 秒、各自布线<1 秒；未见可用于本题规模比较的阀门/网格数量。对应本题：物理图与期望激活流分开；点拆分可表示每格一个资源，共享组须另定义。不对应的：这是压力控制线、可共用控制信号，不是每条线输送不同物料；目标端口可任意选，本题机器端口、配方和物流终点有限定；论文不自动规避本题紧贴端口产生的额外通道。对本题有什么用：L 的建模基线：把实体物品格容量写在内部边，把通道作为格间边；能简化一部分端口分配子题，不能直接证明多商品整数可行。静态/速率边界：控制线“flow”变量是求路由的数学流，既不是实际物料流量，也未证明逐 tick 吞吐；论文 §VI 明确不能表达所需可调高频阀门切换。依据：全文 §IV（PDF 页 5–7）、§VI（PDF 页 7）；[作者机构全文](https://www.microsoft.com/en-us/research/uploads/prod/2016/12/Computer-Aided-Design-for-Microfluidic-Chips-Based-on-Multilayer-Soft-Lithography.pdf)；[MIT 书目信息](https://dspace.mit.edu/entities/publication/521ee42d-0767-404c-a97d-fa6e369f916d)。

- [arXiv:1901.11129；10.1109/FCCM.2019.00019] Walker、Anderson 2019，Generic Connectivity-Based CGRA Mapping via Integer Linear Programming（FCCM）。解的问题：完整硬件图逐资源编码产生过大 ILP，怎样减小并继续找可布线映射。方法：从 MRRG 提取功能单元（FU）可达邻域、候选无环路径；使用放置、允许资源超用的放置、固定放置后路由三个 ILP。路径变量 p_uvq 与放置变量 f_ou 分开；完整路径共享/冲突表负责资源排他。规模：3 架构、4×4 ADRES/HyCUBE、2×2 clustered；表 III 的 MRRG 为 2320–5056 顶点，routing-only 仅 410–412 变量；结果的 90 分位平均运行时间 410 秒。对应本题：FU≈机器端口；候选路径≈两机器端口之间的带段，路径相交资源集合可含桥接器的方向内部通道；先抽可达关系，再只对选中的端口对做完整路由。不对应的：硬件开关可配置，游戏端口紧贴自动形成通道；同一信号源路径可共享不代表物品可复制；本文固定每对最多 20 条最短无环路径，有限路径集合会丢解，结果中 17 个（6.7%）实例基线有解而本文找不到。对本题有什么用：L 中用“端口关系+有限候选路”替代商品×格变量作为搜索压缩；详细资源检查仍保留，失败不作 U。静态/速率边界：MRRG 本身可带 (空间,时间上下文) 与延迟，硬件可每周期切换配置；本题单位与带朝向固定，不能搬用这种时间复用，只可借静态抽象和路径冲突。依据：全文 §II-C、§III、§IV、§V-B 表 III；[作者预印本全文](https://arxiv.org/html/1901.11129)；[作者项目清单](https://cgra-me.ece.utoronto.ca/pubs/)。

- [10.1145/2593069.2593084] Lin、Liu、Chen、Lee、Ho 2014，An Efficient Bi-criteria Flow Channel Routing Algorithm For Flow-based Microfluidic Biochips（DAC，1–6）。解的问题：一个多端 net 连接矩形障碍物间的端点，同时缩短总线长与树的直径。方法：障碍规避 Voronoi 图（OAVG）把平面压成 O(n) 顶点、O(n) 边，O(n log n) 建图；用 Kruskal 式贪心合并树，以 α×总长+β×直径评估候选路径，再几何细化。规模：表 2 合成实例 50–500 组件、n=200–2000；作者单 CPU 时间 0.004–0.075 秒。对应本题：矩形障碍≈机器占用区；pin≈机器物流端口；OAVG 稀疏图可作端口间候选通路生成器。不对应的：解一个可共享多端树，不解几十物料同时互斥布线；未含有向朝向、桥接器四独立通道和相邻端口自动接通；合成实例端点一律用组件左下角。对本题有什么用：L 的候选路压缩，把逐格网格换成端口/障碍角点/走廊相关稀疏图，再展开成格并做物理连接检查；它的 O(n) 不保证多商品路径打包可解。静态/速率边界：直径作为最长流道/运输延时的几何代理，不是本题吞吐，也没有容量、轮询、反压证明。依据：全文 §2、§3.2.1（PDF 页 2–3），§4 表 2（PDF 页 5–6）；[作者机构全文](https://homepage.iis.sinica.edu.tw/papers/dtlee/17045-F.pdf)；[作者所属机构 DOI 元数据](https://scholars.nthu.edu.tw/esploro/outputs/conferencePaper/An-efficient-bi-criteria-flow-channel-routing/9957777327506774)。

- [10.1109/TCAD.2021.3058313] Li、Wijerathne、Chen、Pathania、Mitra 2022（在线 2021），ChordMap: Automated Mapping of Streaming Applications Onto CGRA（TCAD 41(2)，306–319）。解的问题：多个通信 kernel 组成的 SDF 流式应用，怎样在资源受限 CGRA 上映射以提高整体吞吐。方法：时空映射与 modulo scheduling，安排多个 kernel 并行执行。规模：摘要给出 8 个流式应用，平均吞吐为对比方法的 1.74 倍；未获得全文，未核其操作节点数。对应本题：SDF kernel≈机器/模块，SDF 固定产消率可对应配方；它说明完整应用的速率约束须与映射一起考虑。不对应的：本题建好后连接固定，物品不可复制，有限物品格和轮询反压规则未在摘要出现；不能仅用 SDF 连通图替代这些规则。对本题有什么用：L 的建模分层参照，提醒端口路由压缩之外还须有流率/周期运行层；本摘要未提供可直接替换逐格路由的细节，也不给本题 U。静态/速率边界：该论文优化硬件调度下的吞吐，不能把其吞吐结论迁移成所有本题可达循环态的保证。依据：仅出版方摘要与作者出版清单；[IEEE 摘要和 DOI](https://ieeexplore.ieee.org/document/9351547)；[作者出版清单](https://staff.fnwi.uva.nl/a.pathania/publication/)。

- [10.1109/ICCAD66269.2025.11240924] Spoelstra、Kramer、Rietveld、Loessberg-Zahl、Segerink 2025，Invited paper – Connecting the D.O.T.S.: Design of fluidic circuit boards for multi-OoC platforms using CAD Tools for Standardization（ICCAD）。解的问题：多个标准化模块、流体回路与气动控制线在有限板面上布线，只允许指定 routing block 区域多层交叉。方法：模块逻辑 Symbol/Pins、物理 Footprint/Pads 分开，netlist 写连接需求，物理层写障碍及分层禁区，再调用 PCB 自动布线并人工修整。规模：3 个并行 fluidic units，每个含 3 个模块；最终 32 个 vias，制作 3 块无泄漏平台；论文不报告求解时间。对应本题：Pin/Pad 分离≈端口需求与实际格边位置分离，指定区域/器件允许交叉≈桥接器许可交叉，exclusion zones≈机器占地。不对应的：真正跨层可在 vias 转向，本题桥接器只直通对边，四个内部方向不可互转；它通过预设间距避免意外连通，不实现本题紧贴端口自动接通；人工移 via 和修角，非完整自动求解器。对本题有什么用：L 的实体端口层建模范例，可借 netlist 与 footprint 的边界写法，避免把“希望有的连接”误当全部物理连接；不能据此断言 70×70 可解。静态/速率边界：§V 明确 PCB router 未控制液压阻力和流动态，几何合法与运行流率分开；本题也须另验逐 tick 物流。依据：全文 §II–III（PDF 页 2–5），§IV–V（PDF 页 5–6）；[作者机构全文](https://ris.utwente.nl/ws/files/523335611/Invited_paper_-_Connecting_the_D.O.T.S._Design_of_fluidic_circuit_boards_for_multi-OoC_platforms_using_CAD_Tools_for_Standardization.pdf)；[机构书目页](https://research.utwente.nl/en/publications/connecting-the-dots-design-of-fluidic-circuit-boards-for-multi-oo/)。

## 可操作的对应关系（模型建议，尚未验证）

- 单位类型、位置和朝向先定义每个物品格与格边端口；桥接器拆成四个直通内部方向资源，不把整格当一个容量 1 节点，也不把它当自由转向交汇点。
- 相邻端口是否形成通道由物理条件决定：两单位不同、取货与存货边相对紧贴、至少一个运输单位。应编码该物理条件与通道存在的等价，而不是用路径变量选择是否接通；不被需求路径选中的物理通道仍然存在。
- 路径变量只允许用物理通道，可用 Walker 的端口对候选路径集及资源冲突表压缩。压缩图要附保实际占格/内部方向资源清单，否则不能检查桥接器或自动接通副作用。
- Lin 的 OAVG 可提供稀疏候选通路。格路径展开以后仍须核朝向、占格、桥接器内部资源和所有额外邻接通道。要做 U 时，必须有包含全部可能布局的放宽模型；截断候选路径或 heuristic minor 失败都不能证明无解。
- 静态可达、稳态平均流率、逐步确定性执行是三个条件。电子同源路由的共享和压力控制线共享不能直接成为物料复制、混料或吞吐保证。

## 引用链种子补核：CGRA2014

- [10.1145/2655242] Chen、Mitra 2014，Graph Minor Approach for Application Mapping on CGRAs（ACM TRETS 7(3)，Article 21，出版元数据为 25 页）。解的问题：把有 route sharing 的 kernel 数据流图映射到 CGRA，并整合寄存器分配、放置、路由和 modulo scheduling。方法：物理资源在 MRRG 中建成带时间的有向图；应用顶点映成互斥的有根树，内部 contraction edges 表示路由，minor edges 必须到达目标树根；另加时序约束；定制 graph minor 搜索和剪枝，另有启发式加速。规模：作者稿 §6 表 I 为 18 个 kernel、12–87 operations；表 II 从 4×4 扩到 16×16，G-Minor 平均编译时间 0.23–7.08 秒。对应本题：MRRG 的硬件资源与 SRG（被选的调度路由子图）分开，可以借来把实体端口/内部资源与需求连接模型分开；有根树可表达一源多终点的共享带段。不对应的：电子值可扇出，本题物品需由分流器逐件分配；MRRG 能每周期换配置，不能当作建好后固定的带朝向；没有本题自动接通、轮询、反压和所有可达循环态要求。对本题有什么用：L 中可把逐格多商品模型改写成有类型的受限嵌入，保留树根、内部方向和资源排他；对 U 只能采用包含全解空间的精确版本和本题有效约束，启发式失败不可证明无解。静态/速率边界：§3.3 图节点为资源与周期的 tuple，§4.3 除连通外还设 timing constraint，原文已经区分“图上有 minor”与“调度合法”；本题仍须用自己的滞留和判定规则验证。依据：[作者出版清单](https://www.comp.nus.edu.sg/~tulika/publications.htm) 将该链接标为 2014 TRETS；[22 页作者稿全文](https://www.comp.nus.edu.sg/~tulika/TRETS14.pdf) §3.3、§4.2–4.3（PDF 页 6–9）、§6 表 I/II（PDF 页 15、20）。作者稿页头有期刊卷期及 DOI 占位符，不能把其页码当作出版终稿页码。

## ZDD 引用链新增核对

- [W2975355122；10.1109/CIG.2019.8848043] Kiarostami、Daneshvaramoli、Monfared、Rahmati、Gorgin 2019，Multi-Agent non-Overlapping Pathfinding with Monte-Carlo Tree Search（IEEE CoG/CIG，1–4）。解的问题：m×m 网格内若干固定端点对的路径永久空间不重叠，明确不要求覆盖全部节点；路径不必最短。方法：MCTS 节点为整个格子着色配置，子节点只延伸当前路径到一个相邻空格，分支数≤4；优先扩展低分支位置，固定预算后返回最佳 child。规模：表 I 每实例执行 50 次取平均；40×40 /100 路径的 MP40100-2 为 1257.686 秒（约21分钟）、5648 MB；40×40 /10路径为143.789秒、7837MB。对应本题：一对端口对应一个“agent”的永久路径，比允许随时间共享格子的通常 MAPF 更接近带子布线；不填满条件也更贴近留空矩形目标。不对应的：所有格是单容量、没有桥接器四方向内部资源，未含分汇、朝向自动接通和物流速率；固定端点且物理连接已给，不同时摆机器。对本题有什么用：L 的静态不相交候选路搜索可借低分支优先和 MCTS，给一条接近尺寸的规模参照；失败不能用于 U。静态/速率边界：本文取消时间维度，仅处理空间路径；不能验证本题滞留、仲裁或循环态吞吐。依据：全文 §I（PDF页1–2）明确不覆盖全部节点；§II、Eq.(6)、Algorithm1（PDF页3）；§III、表I（PDF页3–4）；[会议一手全文](https://ieee-cog.org/2019/papers/paper_254.pdf)。复杂度核对：原文把手设 I 带入 O(m²)×O((m²+n)I)，再按 I 为常数简写 O(m⁴)，内存 O(Im²)；这是固定预算条件下的工作量估计。Algorithm1 返回 bestChild；原文没有给出保证找到任意实例完整解的预算上界、成功概率或完备不可行证明。因此不能把 O(m⁴) 当成对任意实例求解成功的多项式保证，也不能去掉预算 I。

- [W2750925158；10.1587/transfun.E100.A.1773] Kawahara、Inoue、Iwashita、Minato 2017，Frontier-Based Search for Enumerating All Constrained Subgraphs with Compressed Representation（IEICE E100-A(9)，1773–1784）。解的问题：给定 graph universe，隐式枚举满足度数、连通对、分离对、组件数、环与边数要求的全部子图。方法：依固定边序逐边选/不选，只记 frontier 中顶点的度数 deg 与连通分组 comp；补 vset（指定端点成员）、cc（封闭组件数）、cycle、noe 等状态，在相同层将相同状态合并，直接建共享决策图。规模：同作者技术报告 §4 表4，15×15 s–t paths：354,414,745 DD节点、106.72秒，代表约2.2745×10^47条路径；§4表3的10×10 spanning trees：99,101,715节点、435.35秒。上述是2014技术报告数据，未核它们在2017期刊终稿是否相同。对应本题：把“所有端口间布线候选”写成子图集合；组件标签保存端点归属，分离对防止不该合流的端口属于同一连通组件；窗口内可用共享状态压缩替代显式列举路径。不对应的：这里的通用状态针对无向子图，不包含单位类型/朝向诱发的自动通道、桥接器独立方向、物料标签和运行规则；这些要添状态或约束，不能直接用 deg/comp 判全部物理合法。对本题有什么用：L 中作小窗口或走廊布线集合的精确枚举器；若物理单位与朝向编码完备，空集合才可用于该限定子题的 U，未实现前不能称本题证明。静态/速率边界：“连通组件”只描述静态边集合，本题有向可达和吞吐需另核。依据：[2017出版方摘要](https://www.jstage.jst.go.jp/article/transfun/E100.A/9/E100.A_1773/_article/-char/ja)，该终稿标为受限访问，PDF请求未取得正文；[同题同作者2014技术报告全文](https://www-alg.ist.hokudai.ac.jp/~thomas/TCSTR/tcstr_14_76/tcstr_14_76.pdf) §2.2、§3、§4；[作者2017出版记录](https://www.lab2.kuis.kyoto-u.ac.jp/jkawahara/publications.html)。宽度核对：技术报告定义 w=max_i|F_i|，构造复杂度 O(w|D|)，|D|为构造的决策图节点数而非解数；明确 |D| 理论上仍可能指数增长，添状态还可能增加节点。论文未给70×70的规模结果，不能从压住10^47条15×15路径推出70×70/多物料也能压住。

- [W1990249463；10.1007/s10009-014-0352-z] Inoue、Iwashita、Kawahara、Minato 2016（在线2014），Graphillion: software library for very large sets of labeled graphs（STTT 18，57–66）。解的问题：对同一图 universe 上极多满足结构或复杂条件的子图，做集合筛选、查询和优化。方法：每张图作为边集合、图族作为边集合的集合，用ZDD共享相同后缀；frontier枚举树、森林、路径、环等结构，family algebra做交并差及子图/超图筛选。规模：§6.1在9×9网格约10^37个角点有根树上基本集合操作<10秒、约500MB；§6.3最大电网432顶点/468边，>10^58可行森林用约1.5GB、优化约1分钟。对应本题：固定物理端口图上的路径/森林候选族可共享决策图状态，无需给每条候选一个独立对象；把坏模式变成集合，再一次筛除包含它的布线。不对应的：共享的是数据结构后缀，不是允许物流路径共占一格；ZDD缩的是解族，不缩物理graph本身。论文的结构创建不是现成本题有向多商品路由器；方向、自动接通、桥接器通道及物料仲裁仍要自定义。对本题有什么用：L 的候选集合表示/筛选层；对 U 可探索“全可行静态子图族−包含坏模式的子图族”批量排除，但前提是图族完整且坏模式对本题有效。静态/速率边界：电网例先枚举 rooted spanning forests，另算违反容量/电压降的树，再按子图包含关系整族排除；非线性损耗优化用了专用搜索，不能说ZDD自动解决吞吐或所有全局条件。依据：出版方全文 §3–4、表2–4、§6.1/6.3、§8；[开放出版全文](https://link.springer.com/article/10.1007/s10009-014-0352-z)，[出版PDF](https://link.springer.com/content/pdf/10.1007/s10009-014-0352-z.pdf)。限制：论文§8把directed/hypergraph的通用创建扩展列为future work，脚注虽允许边集合抽象含有向边，不能混为现成有向约束枚举器；压缩比例未给普遍保证。
