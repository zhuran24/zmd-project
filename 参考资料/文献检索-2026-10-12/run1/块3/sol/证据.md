# 块3：传送带布线模型的文献证据

## 本块小结

**结论：找到可试的布线表示组件，未找到能直接、保真地替代本题70×70逐格多物料模型并保证解动的完整方法。** 建议优先把实体单位/端口状态与需求路径分开，再组合“禁止转接资源图、物理集合容量、路径列或局部ZDD解族”；自动接通、同格供需与运行达标仍须按游戏规则补齐。

- **检索领域：** VLSI/FPGA详细与全局布线、通信网络/运筹的多commodity与合流、图论的禁转接/不相交路径、多agent静态寻路与Numberlink、CGRA空间映射、流式微流控物理设计；另沿GRAMM原文引用追到量子退火minor嵌入。
- **一共留下82篇文献形成逐条证据**，包括论文、预印本、技术报告和少量学位论文。全文/摘要/版本范围逐条说明；pool还存着全部返回及背景书目，不能把pool总行数当作已确认有用篇数。
- **检索额度：** key恢复前OpenAlex search四次；恢复后补检九次，未超过追加十五次上限。arXiv、Crossref及网页查询见下表，失败请求标明；没有注册、填表或下载100MB以上文件。

### 最可能有用的五篇

1. **Walker/Anderson2019，Generic Connectivity-Based CGRA Mapping（10.1109/FCCM.2019.00019）。** 端口可达关系、放置和有限路径分层，直接针对逐资源变量过多；它也明确暴露有限路径丢解，适合L候选层。
2. **Albrecht等2005，Multicommodity Flow Algorithms for Buffered Global Routing（arXiv:cs/0508045）。** 状态扩图配集合容量，并先证实体路线与扩图路径一一对应，最适合借来防止桥接/方向副本复制资源预算。
3. **Kanté等WG2015/2016，Finding Paths in Grids with Forbidden Transitions（10.1007/978-3-662-53174-7_12）。** 明确以入边/出边对表达禁转接，能补普通格点流无法表达的桥接直通限制。
4. **Kawahara等2017，Frontier-Based Search（10.1587/transfun.E100.A.1773）。** 对窗口保留端点归属、连通及度数边界状态，压整个解族，适合完整局部模板枚举；规模/宽度条件已经逐条限制。
5. **Beidas/Anderson2022，CGRA Mapping Using ZDDs（10.1109/ASP-DAC52403.2022.9712571）。** 把放置与有向路由一起枚举再选择，补链才出现；目前核了官方摘要与作者讲稿，论文正文未取得，须在试前核全编码和hop上限。

### 仍未找到可直接搬用结果的方面

- **自动接通的保真压缩。** 搜了`routing port constraints automatic connections`、`pin access unintended connections routing`、`induced disjoint paths`、`non touching paths`及微流控/FPGA词；找到端口模板冲突和禁邻接概念，没有找到把“所有兼容紧贴端口必有边”与单位选型一起完备压缩的现成方法。完全禁并排过强，选边忽略额外通道又过松。
- **同一个运输格中同时注入、取出。** 搜了`zero length multicommodity routing source sink`、`local production consumption multicommodity node`、`multi commodity routing local production consumption grid`。数学供需净额/多源绑定存在，但未找到同时保存实体运输格、滞留和自动边的一一对应模型；净供需抵消不能代替实体端口。
- **单层加可连续串联的1×1四方向独立桥接器。** 搜了`single layer routing jumpers`及PCB/jumper minimization变体；结果多为产品说明或其他jumpers词义，没核到与游戏桥接器完全匹配的学术表示。禁转接/集合容量只提供构造部件，不能把普通via或二金属层当桥接器。
- **本题规模的完整证据。** 没找到70×70、容量1、几十物料、几百永久线路并含机器孔洞/自动接通的对等实验。MCTS40×40/100路约21分钟、ZDD20×15数十GB、GRIP几十万nets但多层容量tile且数小时，均不是本题70×70已可解的证明；静态连通也不保证所有可达循环态产量。

这些是本次有时限检索的局部空白，不是不存在论文的证明。

- R6（规则第 81 行）：分流器：大小1x1，任意一条边为存货端口、其余三条边为取货端口
- R7（规则第 82 行）：汇流器：大小1x1，三条边为存货端口、一条边为取货端口
- R8（规则第 73 行）：运输单位：除桥接器外只有一个物品格，每个物品格上限 1
- R9（规则第 58 行）：小制造单位：大小3x3，一条边全为存货端口，对边全为取货端口，1 个存货物品格、1 个取货物品格

## 论文证据（边读边追加）

- [W2275304190; DOI 10.1145/201310.201328] McMurchie、Ebeling 1995，PathFinder: A Negotiation-Based Performance-Driven Router for FPGAs（FPGA）。
  解的问题：在既定 FPGA 资源上把各信号源接至多个接收端，消除资源争用并压低关键路径延迟。
  方法：有向资源图的点表示导线/电气节点，边表示开关；逐网最短路构造有向树，当前拥塞和历史拥塞改变点代价，反复拆线重布。

  规模：官方摘要称小/中问题可把全部映射存几MB，大问题枚举成千上百万解，相对既有方案两个数量级加速；摘要没有阵列或节点数。
  对应本题：和Frontier/Graphillion一起支持“压完整局部放置-路由解族，再选方案”的思路，而不只压单条路径。
  不对应的：静态/时序硬件映射不是R1强制接通、R5四通道桥和不可复制物料；大问题只枚举很多解不等于枚举全部解。
  对本题有什么用：L的机器/端口/带联合窗口解族表示优先候选；U需要额外确认该实例的枚举是完整的，不能从摘要加速数据外推70×70。
  依据：[会议官方摘要](https://www.aspdac.com/aspdac2022/taoka/program/program_abst.html)，8D-1；`lit.py full`没有拿到论文PDF。[作者会议讲稿](https://aspdac2022.github.io/taoka/pdf/8D-1.pdf)可追读，讲稿不能替代论文正文；本条算法主张与规模依据摘要；源/汇/arc分域和hop限制依据讲稿第10–13页。

- [W4293024180; DOI 10.1145/3489517.3530453] Kou、Zeng、Han 等 2022，GEML: GNN-based efficient mapping method for large loop applications on CGRA（DAC）。
  解的问题：大循环应用的CGRA映射编译时间过长。
  方法：图神经网络（GNN）辅助loop mapping；摘要未详述资源编码和训练条件。
  规模：摘要给平均编译时间10.8倍改善，未核DFG节点/阵列数。
  对应本题：可探索学习路径/端口决策优先级，供L候选生成器使用。
  不对应的：不提供本题物理状态的完整表达或保真压缩证明，模型输出仍需实体/运行核对；数据分布泛化未核。
  对本题有什么用：保留低优先的搜索指导思路；不把学习预测作为U证据。
  依据：OpenAlex摘要（pool W4293024180），[ACM/SIGDA会议书目](https://www.sigda.org/publications/dac22-toc/)和[DOI](https://doi.org/10.1145/3489517.3530453)；未取得全文。

- [W2122171990; DOI 10.1145/1454115.1454140] Park、Fan、Mahlke 2008，Edge-centric modulo scheduling for coarse-grained reconfigurable architectures（PACT）。
  解的问题：CGRA上必须显式把生产者操作的数据路由到消费者，同时安排操作位置/时间。
  方法：以DFG边路由为主，操作放置从路线安排导出；路由成本给全局调度视角。
  规模：多媒体循环基准，摘要称比迭代modulo scheduling吞吐提高25%，接近模拟退火吞吐的98%；绝对规模未核。
  对应本题：可把机器端口连接需求先定成路由骨架，再根据路径布局放机器，改变“先摆完再逐格布线”的决策次序。
  不对应的：modulo时间调度与R2滞留、轮询运行不同；机器尺寸/端口朝向和R1自动边未建模。
  对本题有什么用：L的以路由带动放置的生成方式；并非本题吞吐或U证明。
  依据：OpenAlex摘要（pool W2122171990），[原出版记录](https://doi.org/10.1145/1454115.1454140)；未读全文。


## 可操作的模型组合（本席推论，尚未实现）

从已读论文能组合出一个布线表示，但没有一篇替本题证明它完整或能解动70×70。

1. **先定义实体，再定义需求路径。** 每格选择空格或一个带方向的单位状态；普通传送带的入边/出边、分汇流器朝向是实体状态，桥接器状态含四条独立直通内部资源（R4–R7）。机器端口以实体外边位置为准。
2. **通道存在取等价，不只取蕴含。** R1的“两个不同单位、兼容取货/存货端口紧贴、至少一方运输”成立时，通道必须存在。路径可以使用存在的通道，不能决定它是否存在。需求之外的额外通道也交给物料/运行检查；只有已经证明有害的接触才列为禁接。
3. **资源图可以扩状态，物理资源预算不能复制。** 禁止转接图描述允许的入→出；Albrecht式集合容量把状态副本绑回同一物品格/实体格。普通带不同物料若共用相同朝向，平均负载要相加，不能一律按不同commodity禁止共格。桥接四方向有不同内部资源，但占地仍只算一个格。平均容量约束只是必要条件，不证明轮询/反压下达到该速率。
4. **路径列和端口模板分工。** 宏路径列附每个实际格的方向/单位要求、资源清单与端口接触清单；端口周围少量格用FastPass式候选模板与冲突表。支持流量、端口绑定与实体状态一起选；拥塞协商、A*、有限路型为L找候选，列生成可持续加路。
5. **中部注入/取出不能被压没。** 把各物理端口的产出和消耗分别保留，而不因净供需为零就删资源。如果一个运输物品格同时连接上游制造输出和下游制造输入，“空间距离为零”的候选仍要占运输实体、耗用其容量并经历R2的滞留。Dr.CU的长边缩点只可用于确实没有端口、侧接、交叉和状态选择的度二段。任意更强缩点需要另证等价。
6. **窗口可以压整个解族。** Frontier/ZDD的边界状态至少增加方向、端口身份、局部单位状态、物料及资源兼容信息；枚举完整局部解族，再按坏模式一次筛除包含它的整族。Graphillion证明的是该数据结构可处理巨大解集合，不能保证本题新增状态后仍小。

**L验收边界：** 这些表示只生成候选。候选必须展开成实际单位，重建所有自动通道，再由本题逐步模拟内核确认目标产量；这里没有构造布局，也没有提高L。

**U验收边界：** 有限路径表、只取某些路型、固定窗口外部或过强的“不同物料不得共带”等限制均可能漏掉布局。要用于U，需证明每个合法布局都投影到放宽模型、所有学习的禁段/割对该类布局有效、定价或局部解族穷尽完成。超时、MCTS固定预算失败、heuristic minor失败、随机舍入超容都不构成不可行证。
