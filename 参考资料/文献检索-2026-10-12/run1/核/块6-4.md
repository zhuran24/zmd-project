#### 1. Dantam 等 2018：IDTMP

**题录核实：** Neil T. Dantam、Zachary K. Kingston、Swarat Chaudhuri、Lydia E. Kavraki，*An Incremental Constraint-Based Framework for Task and Motion Planning*，DOI `10.1177/0278364918761570`。作者全文首页印有该 DOI；Crossref精确 DOI 记录的题名一致。采用 Kavraki Lab 的20页作者稿，[原文 PDF](https://www.kavrakilab.org/publications/dantam2018incremental-tmp.pdf)，本地全文：[dantam2018.pdf](块6-4_依据/dantam2018.pdf)、[转写](块6-4_依据/dantam2018.txt)。

**完整原文句（§7.3，PDF p.13；12词）：**

> Using constraint (5), we generalize motion planning failures to all task steps.

**逐项核对：**

- 「§7.3–7.4 把失败推广到阻挡物」：**成立，但应细分。** §7.3式(5)在固定状态下排除同一失败动作的所有任务步；§7.4式(6)把固定整个状态替换为仅固定碰撞检测中涉及的物体位置，因此可排除多个状态。依据是PDF p.13；撤销这些约束的规则见p.14。
- 「§7 把超时和证出不可行分开」：**部分成立，原说法容易误导。** §2.3（PDF p.3）和§7.1、§7.3（pp.12–13）明确说明采样式运动规划一般不能证明运动不存在；有限时限内失败只是暂时避开，步数与采样时限增大后重试。§7.4（pp.13–14）同样撤销碰撞推广约束。论文没有低层求解器的 `UNKNOWN/INFEASIBLE` 二值证明接口，更没有从低层取假设文字不可满足核。作者所证明的是整个搜索的概率完备性。
- 「IDTMP 推广依赖后配置连通」：**成立。** §7.1定义8–10（PDF p.12）定义配置集、计划后配置、状态后配置；§7.3（p.13）明确要求状态后配置连通，才能将一个配置的失败推广；§7.4末尾（pp.13–14）沿用同一假设。不能据此把阻挡物集合称为已证明的最小不可满足核。

**剩下的依据：** 这篇支持“反馈粒度越小、能影响更多上层候选”的设计思路及“搜索失败不可永久排除”的边界；对块6-4的证明型不可满足核方法只属类比，未给出该方法本身。

**剩下的依据：** 这是三篇里对“已证明不可满足子问题回传上层、缩小核提高剪枝覆盖”最直接的支持；其可迁移的前提是候选确实包含同一个完整子问题及依赖条件。

### CP-SAT接口与“删到极小”的核查

这不是六篇论文中的另一篇文献，而是块6-4自称“现成接口”的实现依据。核查使用[OR-Tools官方源码](https://github.com/google/or-tools/blob/stable/ortools/sat/cp_model.proto)及[官方排错说明](https://github.com/google/or-tools/blob/stable/ortools/sat/docs/troubleshooting.md)，2026-10-12下载快照见[源码](块6-4_依据/OR-Tools-cp_model.proto)、[排错说明](块6-4_依据/OR-Tools-troubleshooting.md)、[来源与哈希](块6-4_依据/OR-Tools来源.json)。当前隔离小例使用 OR-Tools 9.15.6755。

- 源码快照第777–796行确认：该字段在 INFEASIBLE 时返回足以保持不可行的假设子集；**不保证包含极小**。单线程且纯可行性问题才进行内置缩减；优化问题会返回全部假设。块6-4提到单线程是对的，但其现成角区脚本第17行仍调用 `minimize=True`，局部模型第283–285行保留运输格数目标。提核试验应先关掉这个目标，不能预期原来的优化调用自动给出小核。
- 逐条删去假设并重解，在每次结论都确定时，可以得到**包含极小**的核：任何一个成员都不能再删。它不保证核的条数最少。删去后的重解返回 UNKNOWN，只能保留成员，最终称“已缩减的有效核”，不能称已经证明极小。原案“每次约0.5秒”没有依据：减少约束后，搜索可能更难；0.5秒只来自原来一次固定出口模型的日志。
- 删除测试须清空原 assumptions 并重新加入待测子集，保持同一硬约束、窗口、编码和边界条件。被删除决定不能仍藏在变量域、预枚举、其他硬等式里，否则没有真正测试去掉决定后的可行性。
- 求解器的 INFEASIBLE 是该编码下的证明型结果；核列表本身没有给出独立可重放的全套证明日志，更不校验游戏编码正确性。至少保存模型、假设含义、范围和结果，以便重解核查。

**成立的映射留下什么：** 模块归属、出口、桩位作为上层决定，逐格摆放布线作为下层检查，是可用的分层搜索接口。额外限制和窗口外条件必须随反馈保留，这一点也成立。

**不成立的映射删掉后留下什么：** “阻挡物就是核决定”“规则本身提供精确模型”“IDTMP采样失败就是证明型不可满足”都应删去。仍剩普通的有限约束求解：确认某个已明确编码的模型不可满足，抽取其中足够导致矛盾的上层假设，反馈给相同模型范围。它的有效性来自约束逻辑和编码核查，不来自游戏规则对TAMP术语的直接等同。

### 回传所需的条件，及转置推广

记 `B` 为该次模型的全部硬约束，包括窗口尺寸、固定外部占用、边界接口、运输类别限制、预枚举域、规则版本；`a_j` 为真正可撤销的计划假设。只有已确认

```
B ∧ (∧_{j∈C} a_j)  不可满足
```

才可以在**同一个 B 的搜索范围内**加入 `∨_{j∈C} ¬a_j`。若计划层也允许改变B，须写成“保留B时不能同时保留C”，或分开管理该范围内的约束；不能抹掉B，把它当作游戏全域的布局禁止式。空核说明硬模型自身已经矛盾，不说明所有计划都不行。以上是逻辑推论，不是本报告已经给整厂规划实现了回传。

所需方向是：准备排除的真实候选都必须有该模型内的表示。模型精确当然足够；包含全部真实候选的可靠放宽模型也足够。反过来，仅生成部分合法布局的受限模型，INFEASIBLE不足以排除规则下的整个计划。L侧可以选择只搜索一个受限类，但应明确是类内剪枝。

“按 x↔y 转置推广”也只能有条件成立。规则第9行的正方形基地，第11行的旋转，第90行的正方形供电范围，在同步变换机身朝向、端口和全部外部条件时支持静态几何映射；《求解任务.txt》第15行的左／下边界也在转置下互换。**这不能证明固定整厂背景中的两个任意区块同构。**

此外，规则第32行包含“面朝取货方向从右到左”及汇流器“右、后、左”的接通次序，第45行以接通先后轮询，第46行对精炼炉最先接通通道另有处理。坐标转置是反射，右左次序不会原样保持；若模型或充分条件使用这些运行机制，须重证，不能只转置坐标。这不否定纯静态模型在完整同构下的转置，而是否定“几何像对称就直接搬核”。Iannopollo的组件重命名定理没有补上这个缺口。

现成角区代码也不直接支持原案所列的三类假设：[角区联合快照](块6-4_依据/角区联合快照.py)第9–14行把角色数量、可供矿点和可出料点编进spec；局部模型第125–144行是在枚举时排掉不允许的点，不是已有的可加布尔守卫等式。该角区模型没有桩位变量。要撤销出口或所属角色，必须开放相应候选域并控制有关约束；给残留硬编码等式加一个守卫，不能自动得到所说的自由度。它仍是可试的模型改造，不能当成已实现／仅改几个等式即可。

## 3. 尝试反驳“对本题有用”：找到了现成模型会误排的具体布局

### 3.1 布局：两座相邻桥，横向一条线，纵向两条线

在70×70基地内取窗口 `W={(21,21),(22,21)}`。窗口外的运输接口已固定，窗口内只可改这两格：

- 蓝铁块从 `(20,21)` 的向东传送带进入，经两座桥，送到 `(23,21)` 的向东传送带。
- 源石粉末从 `(21,20)` 的向北传送带，经第一座桥，送到 `(21,22)` 的向北传送带。
- 砂叶粉末从 `(22,20)` 的向北传送带，经第二座桥，送到 `(22,22)` 的向北传送带。

窗口的固定边界是一个西进／东出接口和两个南进／北出接口，各自保持上述物料身份。这里假设外部候选提供这些接口，并固定只能在两格窗内修复；不是声称已造出达标全厂。

```
              源石粉末↑    砂叶粉末↑
蓝铁块 →      [桥1]  →     [桥2]      → 蓝铁块
              源石粉末↑    砂叶粉末↑
```

两个交叉格各要独立通过横向和纵向物料，不能用只有一个物品格／单入单出的传送带实现；用 `(21,21)`、`(22,21)` 两座桥接器可以实现。关键规则原句如下：

- 第9行：所有单位在70×70基地内；上述坐标在范围内。
- 第74行：传送带任意一边存货、另一边取货，允许这些单向外部接口。
- 第77行：桥接器四边都兼存取，四个物品格分别连相对边，允许每座桥同时承载由西到东与由南到北的独立流。
- 第17行：相邻的取／存端口自动形成通道。两桥之间有前向与反向的自动通道；反向使用的是另外的桥接器物品格，本例没有给它们来料。不能将它们虚构成不存在，但它们不堵断指定的前向路线。
- 第24行：运输物品滞留至少1 tick。本例仅声称有合法静态通路，没有用“过桥零时间”来规避滞留。

第77行没有“相邻桥禁止”“桥端口必须先由其他单位定向”的条款；相反，第17、77行给出了相邻桥间自动通道的定义。按这些原句，指定局部物流通路合法。它不构成完整厂达标、供电、调试或所有循环态吞吐的证明。

### 3.2 它在哪里使现成方案失效

[角区联合快照](块6-4_依据/角区联合快照.py)第8、17行调用的是[局部联合模型快照](块6-4_依据/局部联合模型快照.py)。后者第5–10行自列受限类，其中P5禁止相邻桥；第68–74行把它写成 `br[c]+br[n]≤1`。相关注释仍使用“桥端口类型由先接的单位决定”的旧前提，当前规则第77行已经没有这个前提。

对上面的两格固定接口，P5会禁止仅有的合法交叉摆法。若把模型返回的核翻成无范围条件的“这些出口／机器安排不可行”，就会排掉当前规则允许的局部修复。**核即使真的不可满足、删到极小，也不会修正模型的覆盖损失。**

原稿第208行已经承认额外限制必须保留，所以这个反例并未反驳“保留P5等条件的类内核回传”这一逻辑方法；它反驳的是第207行的现成模型精确性前提，以及无条件把模型失败升级成规则失败的用途。对需要相邻桥的候选，保留P5后的反馈最多会告诉计划层“当前受限模型做不了”，不能指出当前规则下应该改变哪条决定，类内修复会错过这个解。

### 3.3 隔离复现结果

使用现成局部模型的逐字快照，设机器列表为空，保留模型的运输编码；将上面的六个窗口接口按相同物料、方向和格点写入spec，求2×1的纯可行性问题，单线程、5秒上限。

| 检查 | 改动 | 结果 |
|---|---|---|
| 现成模型 | 不改P5 | **INFEASIBLE**，25变量、88约束 |
| 对照模型 | 仅在内存中删除P5的相邻桥不等式 | **OPTIMAL**（纯可行性成功），25变量、87约束，解为两座相邻桥 |

可复查：[相邻桥反例.py](块6-4_依据/相邻桥反例.py)、[结果JSON](块6-4_依据/相邻桥反例结果.json)、[执行参数与脚本哈希](块6-4_依据/反例执行元信息.json)。JSON的运输格为局部 `(0,0)`、`(1,0)`，加 `(21,21)` 即为上述基地坐标。全部输出在交付目录；没有在正式仓库内写入模型、日志或Python缓存。

这是**静态模型误排的隔离复现**，并非逐步模拟内核验收。对照求解器仍没有完整重建桥间所有反向通道，规则合法性由第17、74、77行另行核对；不能只拿对照的OPTIMAL当游戏内核证明。

### 3.4 另一种没有有效核的情形：只返回UNKNOWN

实际记录已经给出符合任务结构的场景：两套植物单元塞13×16或14×16窗口，各240秒UNKNOWN；18×18角区允许出口变化，239.7秒UNKNOWN（[搜索范围汇总快照](块6-4_依据/搜索范围汇总快照.json)第5–34行）。这些场景受规则第64行5×5种植机／采种机机身、第116–122行种植与采种配方，以及第17、24行物流连接／滞留约束，不能把尚未完成的搜索当不可行。

这里方案的提核步骤没有输入，缩核和回传都启动不了。它不证明模型有解或无解，也不证明提核方法永远没用；它说明当前最难窗口上的效率收益没有被已有记录证实。固定出口角区的一次0.5秒INFEASIBLE不足以替代这种规模验证。

## 4. 最终判定与可保留试点

**判定：部分成立。** 有原文支持，也有可调用的证明型假设核接口；规则映射中的分层职责类比成立。现成模型的精确性前提不成立，IDTMP与Patterson的部分归纳过强，转置推广缺完整同构条件；已找到并复现当前规则允许、现成模型拒绝的相邻桥局部布局。

可保留的试点是：先固定一个明确的受限模型范围，正确开放并守卫计划决定，关掉优化目标；只对INFEASIBLE提核；删除检查未决时不声称极小；把全部硬前提连同核送回同范围计划搜索。按已证完整同构推广，或直接在转置模型重解核查。只有实际核比现有手算／整计划排除更有信息时，才有本题上的效用证据。

这项结果用于构造侧选择下一次计划，不能证明已有达标布局，不能抬L，不能压U，也不能替代当前规则下的完整静态检查或运行验收。
