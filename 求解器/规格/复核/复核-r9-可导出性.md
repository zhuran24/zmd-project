## 3. 级一良定义与率保持的独立核查

### 3.1 准入不是从目标必要条件反推

任务L7只保证两矿足够消耗，没有保证仓库能接收回矿。令矿量分别为79999、80000，回1件在规则L41下一个可收、一个不可收；后一运行入矿账为0不能证明没有观察矿量。因此[转移§6.1 D.2](../受限转移定义.md)要求在任何physical/级排序/授权之前筛现存核心回矿候选，有资格的传输在全箱汇总后、容量规划前筛含矿。即使年龄或额度尚不满足仍停止，是明确保守的工程域；普通有限运行继续照真实容量，不把这种输入判为游戏非法。这一处置补齐了KQ-08指出的前件。

D.3也没有从约束·取货口配置推“任意输入的成品格都无出口”。它机械检查实际指派、O和命名冲突；坏运行仍可在finite_concrete出现。D.4保留其它物种库存，D.5只给代表化容量界。三个条件的损失均已登记，没有借必要条件假设成功布局存在。

### 3.2 对六步归纳逐项检查

1. **代表化**：两成品数量归0而不释放历史身份；两矿保留正代表值。O为空且规范名不被其它物种占用，保证成品格的存在/标签差异不会改变其它物种落格。D.2先读保留字段识别回矿候选，同键状态同步通过或同步停止；停止没有游戏后继。这一步不是把具体玩家每tick清仓当作规则。
2. **时间边界**：相同工作余量、功能状态和冷却余量同时减或保持；年龄与elapsed同时加1，窗口同时满5。完成由remaining归零而非旧绝对预计时刻触发。固定global模板序不随绝对t变化，sufficient没有有限补给历史尾部造成不对称停止。
3. **物理可动及调度**：非仓库选择器、植物等仓库存量、门、桥和额度相同。矿只见相同物种及非空；成品代表容量由D.5保证。因此physical集合相同，继而级排序、局部出支表、授权相同。未先借授权筛矿，避免循环论证。
4. **PC后效**：相同判前授权集合A决定成功或失败，成功两端各过1件，失败只推进A内的侧。库存、预算、entered_at、门计数/删边和图映射因此对应，入库/出库逐物种增量相同。
5. **制造及传输**：配方输入、同种单格、整批容量、进度与冷却守卫均相同。有资格含矿箱在容量前停止；其他箱对非成品读取相同真实容量，对成品读取安全代表余量。规则L72给每箱最多300件，约束L30端口速率给每个核心入库PC每tick最多1件，§5.2又限制每箱一刻最多尝试一次；故B界确实覆盖同刻多箱、多物种、再收货的情况。B<80000使本刻每次完整批都能进入成品代表格。
6. **闭包与后继**：同序非仓库后效及成品入量已逐访问对应。在一刻内部没有代表化扣量，成品数量只增，已有身份不释放。因此两扫描边界的具体闭包键相等必然意味着中间没有成品入库/新绑定，另一代表同样成立；首次重复轮次一致。非轮询变化次数有限，余下有限环指针必重现，得到相同的归一化后继。生产键没有被偷用于提前结束同刻扫描。

上述证明是D内G的有守卫商转移证明。它不证明删字段后的任意StateSeed良定义，也不证明所有已登记工程读法均获正式允许。转移§5.3、声明§4及四义务仍保留一般动态约束相容性审查，未以“未定”直接许可任意取值。

### 3.3 周期、合法行为和平均率

设(a,b]全部G转移真实完成且两个端点键相等，P=b−a>0。按上述逐步对应，下一周期的每个检查和事务与本周期对应，D的动态条件也随保留字段重复；不能只验证端点矿量。周期台账实际入库量为核心入库加无线入库，精确率D_i/P与3/5、11/20比较。代表调整和矿回补不算交付；两者分别记账，守恒没有借抽象丢件。计账区间(a,b]与after_closure首条t+1吻合，没有重复计a刻事件。

## 4. 级二：取空标签、接收读法与容量卡点

### 4.1 主席“待驳”读法的处理

任务L8允许外取，L9却以“基地的状态”定义循环，规则L14把仓库纳入核心。许可外取本身并不逻辑蕴含从状态删去仓库存量。转移§6.5 L211明确记下这个解释差别，同时依第五轮任务采用可观察读法、在证书声明；没有把字面全状态周期重新强加给级一，也没有把主席的待驳解释冒充条文必然结论。T12保留“只证明生产重复就报告该范围”，不以不规则拿取产生的空真发完整目标证书。未见执行走样。

### 4.2 取空后标签与空格序

retain_history下，成品格被取空时原item转为empty_identity的指定物种，item置null、quantity置0；该格仍有身份，不属于E，也不进入O。再入同种仍选这一个历史格，反向转换非空编码。因此不是每次取空就生成一个新W_new标签。D.3确保既有成品格无出口指派、匿名序为空、未来规范名不被别种或预指派占用，所以此变化不会经取货、其它物种目标或O次序泄漏到非仓库状态。

不能将这一步外推到release_on_empty、成品格被出口指派或可观察匿名格竞争。正文§6.5 L216恰把这些情形列在证明之外。规则L41/L73对固定指派格的访问是条件非干扰的根据，规则L13的一种单格是同种重新选回历史格的约束，retain_history是明示工程选值而非新玩家设定。

### 4.3 `warehouse.acceptance`不能代替实际整批守卫

|---|---|
| 容量可接1件 | 整数q<80000推出q+1≤80000，因此两成品各能接1件。不能推出下一整箱n件可收。 |
| 当前`capacity_and_path` | 还需逐观察边界核实际核心入库PC或有电开启的传输接口。固定图/开关使这项在投影对应时保持，但它不是F本身的结论。路径报告不承诺冷却就绪、剩余额度、来源全程可达或整箱能收。 |

转移§6.5 L218列出了上述范围；输出§5.2要求P项逐边界、两成品分别报告接收位；acceptance_quantifier仍与接收谓词分轴。本版读法没有被冒称覆盖所有目标读法。

### 4.4 原F在完整批容量处确实不足

取有电、开关开、冷却0的箱，装2件电池，仓库电池79999、胶囊0。两者均未满，但79999+2>80000。本版all_or_nothing使该次全箱拒收，仓库仍79999，因而拒收后的前缀继续符合F；G以0代表则成功入库2，箱内容与台账已分岔。不拿取造成这个前缀不需要精确操作，之后在宽时间段拿取也无法消除已经发生的差异。

这是规则L13/L41容量与L36全箱尝试、已登记all_or_nothing读法的局部守卫反例，足以说明“只要未满就与G逐刻相同”这一步不能从此前件推出。它不是从蓝图到目标布局的可达周期反例，也不能宣布正式任务无解；正文L222已作这个限定。

F_safe的逐事务q_i+n_i<80000确为足够容量条件，但比原F强，不能暗换。平均率0.6/0.55也不给任意前缀突发上界，更不直接给拿取的最大等待时间；还要核周期长度、前缀最大入量和操作策略族可实现性。§6.5保留这些缺口，periodic_lift只停止级二而不阻断D内级一，符合第五轮S1允许写精确卡点的要求。

## 6. 普遍审查场景与运行语义L149/L151的全部前件

### 6.1 轮询均分

[场景§1](../普遍审查场景.md)给的是实际分级精炼炉的三取货边，不是把未分级分流器直接称同级。逐项对应如下：

| 正式前件（运行语义L149、约束L82） | 场景落点及验收边界 |
|---|---|
| 同级k条取货通道 | L7：精炼炉三口各接非汇流器首格，按规则L31同属other级，k=3。 |
| 所有待出物品能由任意一条取出 | L7–9：每次同种蓝铁块，三首格均可收，源非运输额外停留选zero。 |
| 除首格占用外无其它移动障碍 | L9：身份无额外限制，源/目标端口本tick额度0，独立下游能收；L15补核双端授权，未只凭physical就算成功。 |
| 首格独占来源并接所有待出物品 | L9：每格唯一入边，只收U对应通道物品；不混入另一供货源或共享桥轴。 |
| 每次收件后恰1tick腾空 | L9–11：同一物品的出入事件时间差为1，且释放发生在下一组服务前；不能用平均排空或最终为空代替。 |
| 恰隔1tick成组待出 | L7：精炼配方1tick、每个整数边界实际完成转出；真实矿源及实际供料列为K线必须核的条件。 |
| 初始首格全空、相邻组件数和≤k | L9：全空起，逐组1件，相邻和2≤3。 |

局部递推可独立推出成功A/B/C循环：U的当前同级游标有可动候选，各首格目标侧只有该入边，所以访问游标边时双方授权成功；访问别边不会消费U的游标；源空以后U不再授权，不能被额外失败空扫推进。六种U出边模板序的已给递推均如此。其它模板序若破坏事先声明的真实供料/释放条件，必须标前件失败，不能作为正式均分反例或普遍通过。

这仅给一个满足条件的接口场景与有限前缀检验义务。有限长链和末端箱不能自动证明无限可收；L11要求周期均分另有下游闭合状态。L16、L19又明示此场景没有覆盖所有未分级出侧组合。因此原局部脚本每刻重置首格只是在给定接口条件下推递归，不能视为真实箱体每刻凭空消货的运行证据；其标注没有越界。

### 6.2 密集结点

运行语义L151与约束L16的两个关键前件分别为D→M真实直接PC，以及M其它存货边在被核循环中实际通过量>0。场景L23–29同时要求这两项；D总出量>0使分流比有定义。同一参数族只改变judgment.order，以周期账比较a件数/D总出件数，不能把“有另一条边”当“另一来源有流量”。

有限前缀内末端箱能装下源矿不等于循环正流量。场景L25明确无循环证据时inconclusive，L29明确较低优先级导致另一来源零量时前件失败。若要证明某个场景确实随判定先后变，需不同序下有前件成立的周期和不同比例；若要用恒比例提交机制冲突，需完整排序域及循环/可达性证据，两份相同比例轨迹不够。此处没有用静态构型代替L151的动态前件，也未把场景说明冒称普遍相容性证明。
