## 1. S2-r5-L1-01：正文未修订与指纹

从第4轮附录丙直接解析得 11 个唯一 id、11 个 false；这只证明上一席没有否掉发现，不证明每条机制意见都是真理。正文未更新这一主事实仍成立，目录变化不构成 A 线已修复的证据。不能从相同终态哈希反推历史上绝无编辑后回退，故这里判断的是交付终态。

## 2. S2-r5-L1-02：传送带端口形状生命周期

**判定：refuted=false，未能否证。**

规则 L60 原文确为“任意一条边为存货端口、其他任意一条边为取货端口”；L11 允许旋转，L22 的任意更改以“可自行设定的项目”为前件，L10 只明确重建使通道重新接通。令边编号为 0…3、形状为有序对 (s,t)，s≠t。旋转给两数同加 r，差 (t−s) mod 4 不变，取 1、2、3 三值；12 个配置恰为三个四元轨道。附录乙另做枚举核验。

当前目录确有传送带三个 layouts、桥接器四个，其余16类各一个；桥接器定向另受先接历史约束。内核输入 L51 已能表示三种形状，故“没有形状表示”可否掉，但这不是本发现的主张。

缺的是第一轮任务书 §3.A.2 所要求的生命周期：T11 L104–106、参数轴 L88–90 只登记旋转阶段及拆建库存；内核输入 L232 的 rotate 只带 rotation，rebuild 只指回 unit，未给 port_layout 重选与继承语义。一般“额外动作要升级”不是该自由度的候选域。

“已经选择不可改”应收窄：格式没写永远不可改，且会拒绝未支持动作；它实际没有定义可改与否，不能把缺定义当已证明不可变。这个收窄不补齐遗漏。

## 3. S2-r5-L1-03：受限模型三轴漏选

polling.level_tie 更明显：规则 L31/L32 给级的排序键，L28 给通道接通时刻。受限模型 L22 的通道初始并列仲裁、L50 的“未给平局仲裁报 unresolved”没有说明并列级是保留并列还是固定仲裁，以及从 connection.tie 到级排序的派生关系。停止护栏避免了猜值，不等于完成这一组选值交付。

## 4. S2-r5-L1-04：供电交叉核验及约束辖域

**判定：refuted=false，未能否证主缺口；不采纳“全部约束只以达标布局为论域”的附带断言。**

T15 L137 与参数轴 L103 确实把约束·供电下限、约束·侧旁供电列为尚须核验。受限模型 L52 的取据只有“一部分”的非零面积读法；覆盖表 L192/L203 指静态核验；第二轮任务自查 L19 仅验证格集合与区间交公式。第4轮否证中的计算没有被写入被审正文。因此“已登记而未完成交叉核验”仍成立。

独立算术得到：桩起点 (a,b)，覆盖连续方形为 [a−5,a+7]×[b−5,b+7]。小机起点横坐标在 positive_area 下为 a−7…a+6，在 closed_touch 下为 a−8…a+7。附录乙给实际24/32台构造；侧旁一维列数分别为 [3,3,3,4,4,4,5] 和 [3,3,4,4,4,5,5]。这些数字不能替代约束 L115 的完整二维、投影、端口和“循环态中有制造”前件。

对反排除意见单独回源：求解约束标题仅写“由规则推出的约束”，没有“下列所有陈述只适用于达标布局”的总前件。L92 同一句明确区分“至多为24台制造单位供电”和“至多为23台循环态中有制造的制造单位供电”。规则 L19/L20/L35 又区分供电状态与制造功能运行。L93 的据汇集整条的推导来源，不能把仅供其它子句使用的边带、进料条件默加到24台子句；例如该条“至少10桩”和末尾217有关式子确有达标台数依赖，不代表每个子句都有相同前件。

32台密排构造没有证明达标，也有机器没有进料通道，这点属实；但对源文独立写出的24台供电子句，仅“没有进料”不能使其脱离供电台数论域。若要主张该子句另有隐含达标前件，须给正式依据，本席未找到。对侧旁的有制造上界则不能使用同一构造直接反驳。此处不把约束全体一概扩成物理规则，也不一概缩成达标约束。

## 5. S2-r5-L1-05：仓库及核心逐行入口

**判定：refuted=false，未能否证索引缺陷；发现的“一个入口都没点到”过强。**

规则 L14 定义仓库，L41 给核心格容量和可设取货格指派，任务 L6 给初始库存。覆盖表 L24 确把仓库行标为“库存、容量、缓存闸门；T7”，但 T7 实际处理制造端口、混装与配方，仓库初始锚点及接收域在 T11/T12。该标签错误未被修改。

反证查到已有正确入口：两行均指向运行语义 §2.2，该节 L43 已有“仓库格数量不限，每格80000”和“每个取货口独立指派仓库格”；仓库行另指 §2.1，L28/L32 有设定及初始锚点，§4.1 又有拿取与补给。因此不能说容量、指派在去向里完全没有入口，更不能说全规格漏了仓库语义。L41 的 T1 也确与核心六口的 H 论证有关，并非全然无关。

但正确的宽章节引用没有把仓库行错误的 T7 改成 T11/T12，也没有把用途栏写成该行实际持有的语义。依第一轮任务书 §3.A.6 与第二轮 §3.A.7 的可核对、同步要求，仍保留这项次要索引问题，而不接受夸大的“零覆盖”描述。

## 6. S2-r5-L1-06：占格互斥的来源及 A 线落点

**判定：refuted=false，未能否证。**

内核输入 L58 确写“任意两实例的像不相交且在基地内”，据列规则 L8/L11/L41；样例检查器 L140 实际拒绝重叠。L8 只规定基地边界，L11 只给旋转，L41 只给核心唯一、尺寸和接口，三者没有明文给任意实例互斥。运行语义、选择点清单、参数轴中也未找到一般互斥条款；T11 的“占格合法性”未展开此条件。

最强的反证来源是第二轮任务书 §3.C.7 已明确要求样例合法，“占格不重叠、端口相遇成通道”。故不能指责 C 线检查器无任务授权，也不能仅据正式规则未明说就要求放行重叠样例。但该要求针对合成样例交付，不能替 A 线完成一般物理不变量的来源说明。内核输入的据列也没有引用这项任务要求。

发现所提约束·占地下界、面积预算、四通结点、边带排布可以支持其建模意图，却不能仅凭聚合下界就形式上推出所有合法坏布局也绝不重叠。需要写明这是何种论域的已采纳前提或补论证；不能换一组据名就声称一般互斥证明已经完成。当前缺口保留。

## 7. S2-r5-L1-07：仓库空格身份与首次落格

**判定：refuted=false，未能否证。**

规则 L13 规定一个格单种及同一单位一种物品至多放一格，核心不在例外中；它限制同时库存分布，没有规定格标识永远等于物种。L41/L73 的设定对象是“仓库的某一物品格”，这使格身份是否随清空/换种保留成为可观察问题。

T12 L119 的“按种类落格”和参数轴 G1 L150 没有定义新种第一次进入时选哪个未赋种格、清空是否解除身份、被端口指派的空格是否可以再赋别种。内核输入 L98 明确允许 item=null，L99 仅要求引用既有 slot，没有排除指向 null 格。

例：两个独立命名空格 w0/w1，一取货端口指 w0；新种甲第一次入库后若占 w0 与占 w1，该端口可取出的物品不同。单种单格、每格80000在两种局部赋值下都未被违反；没有任何交换对称性证明允许忽略这个差别。这是定位缺定义的局部状态比较，不是两条完整合法历史的认证。

须收窄两句：空格当前没有货可取，并非可以凭空取任何物品；未知的是后来赋种和指派延续。现行最小检查器 L282 要求 item 属已知物品集合，内核输入 L279 也已声明这个子集，所以 null 格不会被当前样例检查器悄悄执行。子集拒收不补完整格式及运行语义的遗漏。

## 9. S2-r5-L2-02：closed_touch 与供电台数

## 11. S2-r5-L2-04：内部通道分级、直接接与损失

规则 L18 把内部路径称为通道，L29 用“端口”限定轮询，L31/L32 用取货/存货通道规定分级。参数轴 L36 的“内部通道不入分级、不入端口轮询；是否入通道分级另审”在候选及待办间切换，未明确给出第二方向的辖域和含义；受限模型 L48 的“其它内部通道分级”损失因而无法逐值对应。C8 L131 也只是另审。

## 12. S2-r5-L2-05：准入口断边后的身份求值

**判定：refuted=false，未能否证缺失的解释边界；未证明观察读法本身违法。**

回源规则 L64、L16、L24：分别写阻断/断边、端口相遇自动形成通道、物品通过通道移动，没有定义断边时“当前候选来件”的存在条件。参数轴 L68 只区分当前候选与上游可能种类集合，L69 只区分条件恢复与锁存；T8 L79–83 未说明断边期间怎样取候选。受限模型 L39 却明确取物理邻源的候选来件并用于恢复。

最强的否证理由是：这已经作为受限解释明写在表中，且“身份不符”本就需要某种跨单位守卫，不一定意味着增加实体传感器或物流通路。规则没有局部可观察性限制，故不能仅因出现“检查邻源”就证明违法或断言它出于实现方便。可是现稿仍未说明这个细化取值与登记轴的关系，也未记录“候选仅在通道存在时定义”等替代边界及损失，无法证明已完成所需覆盖。

发现给的无观察替代也尚非已证合法机制：把“通道不存在”直接视为“无来件，所以身份不符为假”本身就是一个求值选择；若源持续持有错种，自动接通→发现身份不符→断开→又自动接通，可能需要额外同刻闭包/锁存规则才不无限振荡。须联核 T1/T3/T8、接通记录及判定位置，不能直接用该草案替换现有读法并宣布问题结清。

## 13. S2-r5-L3-01：供电复算的证据强度

**判定：refuted=false，未能否证。**

本条独立核规则 L12/L44/L76 与约束 L92，再核被指 r5_供电覆盖复算.py：它只枚举横纵各三个模3相位，共九种规则网格，未枚举一般交错排布。函数名 max_machines 与输出不能替代“所有最优排布必在这九种网格中”的证明。24/14/8 与正式数字吻合，也不能证明正式条目的历史推导过程必然如此。

但附录乙已直接验证 closed_touch 的内部32、左边16、右边16构造，排除一个24/14上界只需一个超界实例，不需全局最大值。24台与23台有制造的限定不同，见 §4。因而脚本的最优性证据不足不消除该冲突，正文尚未处置这一发现。

同时，角上两种读法都可构造8台，故角部数字本身不能区分两读法；本条有效证据来自内部/贴边超界，不来自“三重吻合即唯一”的推理。

## 14. S2-r5-L3-02：汇流器分级起轮的锚点

**判定：refuted=false，未能否证初始化缺口；“两取值互不相容”尚未证明。**

规则 L32 主语是“一个单位”，含运输单位；L68 的汇流器有三存货端口。若两三条存货通道中一条直连分流器，其自成一级，其余另级；L30 要先服从最高可移动级。L29 的“从第二条接通的通道起轮”确需在这个分级情形定义。约束·密集结点 L16 点名相同局部连接，但不是实际达标布局存在性的证书。

取全侧接通序 a<b<c、a 直连分流器，级为 {a}、{b,c}。全侧第二条是 b；二成员级内部第二条是 c；单成员级 {a} 没有第二条。这样已经显示数“第二”的集合选择与三种起轮含义不同。该例只是合法端口构型及条件次序分析，不宣称其完整运行可达或达标。

T3 L31 未明确按侧还是按级解释“全体”；L35 的级间记忆处理离开/返回，不能确定首次进入每级的指针；受限模型 L21 的单通道说明也未明确是否包括“全侧多通道但当前级单通道”。L25 的 per_level、保留续接位置没有补首次初始化。

不能据此证明 second_cursor 与 per_level 在数学上不兼容：可以另定义全侧第二位置到各级环的投影，以各级投影初始化后分别保存；这会兼容两个表示。但现稿没有给投影，且该例投影与级内第二会不同。所以保留的是缺定义/未登记的发现，不认定这两个取值永不可组合，也不把建议新增轴的两方向直接授为合法。

## 15. S2-r5-L3-03：相遇几何候选和唯一性

**判定：refuted=false，未能否证登记缺口；唯一性旁证不充分。**

参数轴 L46 实有一个具体方向“共边同位置相对存取端口”，并排除同类与两非运输端口；故“没有任何候选或限制”不准确。但“其它几何读法未定”未列具体几何替代和排除据；D11 L142 推给外部输入，T5 只处理接通历史、平局及桥方向，覆盖表规则16行没有该轴入口。第一轮任务书 §3.A.4 的候选/排除登记尚不完整。

内核输入 L68 已说明仅按共边做结构子集检查，并未宣称替 A 线裁定全规则。因此“C线硬编码已裁掉其它合法布局”不能直接成立，子集声明也没有补 A 线的候选域。

规则 L12 的长度一格不推出两个边段相遇必整段重合。例如运输格 [0,1]² 的北边 [0,1]×{1}，与斜邻格 [1,2]² 的南边 [1,2]×{1}，均长1且法向相反，只共享 (1,1)。要排除这种候选，需说明“相遇”不含端点接触，或给其它适用条文的矛盾，不能把边段长度当作交集长度。此例不证明角触已获规则允许。

约束·边带排布/核心邻格针对特定矿口，约束·四通结点在定义 x 时使用“四个邻格”，不单凭这一条件式定义就普遍禁止其它连接。故未采纳“已唯一确定”的建议改法，但无法否掉候选说明与入口确有缺口这一点。

## 16. S2-r5-L3-05：箱体 F1 的合法格

**判定：refuted=false，未能否证措辞歧义；未证明实现实际跳格。**

规则 L72 明确区分存货选最小编号“能放它的”格，取货选最小编号“非空”格；运行语义 L52 原样分开。参数轴 F1 L145 写“箱体逐次取编号最小合法格已定，空格不另降级”，未给“合法”的本地资格定义。其引用的独立清单-r3 F1 L391–399 同样明写两侧原词，并把空格不另降级用于存货可放格。

最强否证依据是 F1 已指到正确的运行语义 §2.2，“取”可以泛指选择，“合法”可以按各侧原词解释；在此读法下根本没有新增跳格算法。因此不能把 F1 唯一翻译为“后面的可出物品先出”，也没有当前内核执行来证明已发生错误行为。

但文中确未明确区分，无法证明歧义已消除。条件例：箱格1为甲、格2为乙，空的下游准入口只接乙。先选最小非空再核守卫会卡在甲；先按下游兼容性筛格可能跳到乙。两者行为不同，但这里不宣称两算法均合法或该局部状态已完成可达性认证。若下游格本来被占，任何物种都不能进入，跳格不能解决这个障碍，原复核的这一并列例子也不充分。

## 17. S2-r5-L3-04：轮询前件“都”及修正版排除

**判定：refuted=false，未能否证辖域未说明；修正版证据仍有缺口。**

规则 L29 的“多个……都建立了通道时”自然可读为对所说的多个已接通端口量化，而非该侧所有物理端口；这支持现稿，但 T3、polling 表和覆盖表规则29行没有写出此语法论证或说明另一读法如何处置。主缺口仍在。

新版改用取货侧，修复了上一版引用存货侧的错位，却出现更直接的量词跳跃：约束·研磨进料 L52 是“采种机恰16台时每台至少2条取货通道”，规则 L50 给5个取货端口。可推 2≤k≤5，不能推出 k=2 会在达标布局中出现；台数恰16这个前件自身也未证明必有实例。即使某侧恰两条有通过量通道，还须区分零流量但已建立的其余通道。

此外，恰16台时约束·满载配置令每台采种机每tick连续产2粒；若按每tick整批2件成组待出，则相邻两组件数和为4，k=2反而不满足约束·轮询均分 L82 的相邻组件数和≤k前件。发现没有给另一种可达待出安排并核全前件。因此该“k=2”例子远未形成唯一排除证明。

最后，“不由轮询规则推出结论”不等于“必与均分结论矛盾”：即使读法缩窄了轮询规则的前件，仍需给满足其它规则但违反正式均分的运行，或证明二者必不兼容，不能仅以失去机制来源代替反例。保留缺登记问题，不照抄其建议的排除论证。

## 附录乙：独立算术核验与复现代码

以下代码以 Python 标准库在仓库根、python -B 标准输入方式执行，未写文件。先逐台检查占格、基地边界及连续矩形交叠，再核给定构造数量；不是以九种网格的最大值冒充任意排布的最优值。输出是条件算术与工具核查，未运行游戏、未验证送料、起动或达标。

```python
from itertools import product

def cells(x, y, width, height):
    return {(i, j) for i in range(x, x + width)
            for j in range(y, y + height)}

def check(name, pole, starts_x, starts_y, touch, expected):
    # 只核给定构造，不声称穷举最大不重叠集合。
    a, b = pole
    pole_cells = cells(a, b, 2, 2)
    occupied = pole_cells | cells(50, 50, 9, 9)
    selected = []
    for x, y in product(starts_x, starts_y):
        footprint = cells(x, y, 3, 3)
        if footprint & pole_cells:
            continue
        assert not footprint & occupied
        assert all(0 <= i < 70 and 0 <= j < 70 for i, j in footprint)
        lengths = (min(x + 3, a + 7) - max(x, a - 5),
                   min(y + 3, b + 7) - max(y, b - 5))
        assert all(value >= 0 if touch else value > 0 for value in lengths)
        occupied |= footprint
        selected.append((x, y))
    assert len(selected) == expected
    print(name, "closed_touch" if touch else "positive_area", len(selected), "通过")

for touch, positions in [(False, [23, 26, 29, 32, 35]),
                         (True, [22, 25, 28, 31, 34, 37])]:
    check("内部", (30, 30), positions, positions, touch, 32 if touch else 24)
    check("左边", (0, 30), [0, 3, 6], positions, touch, 16 if touch else 14)
    check("右边", (68, 30), [61, 64, 67], positions, touch, 16 if touch else 14)
    check("左下角", (0, 0), [0, 3, 6], [0, 3, 6], touch, 8)
print("侧旁列数 positive_area", [(g + 9) // 3 for g in range(7)])
print("侧旁列数 closed_touch", [(g + 10) // 3 for g in range(7)])

shapes = {(source, target) for source in range(4)
          for target in range(4) if source != target}
orbits = []
while shapes:
    source, target = min(shapes)
    orbit = {((source + rotation) % 4, (target + rotation) % 4)
             for rotation in range(4)}
    assert len(orbit) == 4
    orbits.append(sorted(orbit))
    shapes -= orbit
print("端口配置旋转轨道", orbits)
```
