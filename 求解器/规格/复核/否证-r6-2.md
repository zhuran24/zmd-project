## 3. S3-r6-L2-01：制造出缓存的单位级库存守卫

**结论：未能否证，refuted=false。**

规则 L13 将“一个单位内一种物品也只能放在一个物品格内”的例外明确给协议储存箱和缓存格；制造存货格与取货格均不是该例外。规则 L17 允许存货格接收任意物种，L18 限制成品整批出缓存，L35 规定完成后产物先进缓存；L81 为粉碎机的 1 源矿→1 源石粉末、1 tick 配方。

《受限转移定义》L71 的完整条件是“若completed且取货格同种/空且剩余容量够整批，则成品整批由缓存转取货格”。L72 接着处理新批输入，未在 L71 与提交之间增加跨存取两侧的同种单格检查。《受限模型声明》L67 只概括“不兼容或容量不足则整批留在缓存”。

独立复算采用一台有电且开关开启的粉碎机 X、一条已滞留到时的传送带 B，模板序 `move(B→X)` 先于 `manufacture(X)`。X 仅此存货边，取货侧无外部边；不需要阻尼分叉或级平局补值。可取 X 左下角 (10,10)、南存北取，B=(11,9)、南存北取，桩左下角 (14,10)，核心另置 (40,40)，满足占格及正面积供电的局部前件。

| 时刻与动作 | X 存货格 | X 缓存／批次 | X 取货格 | 同种单格 |
|---|---|---|---|---|
| t=0 闭包后合成种子 | 空 | 在制 1 源矿，remaining=1 | 空 | 满足 |
| t=1 完成阶段，按 L19、L21 | 空 | 1 源石粉末，completed | 空 | 满足 |
| B→X，B 的 entered_at=0 | 1 源石粉末 | 1 源石粉末，completed | 空 | 满足，缓存例外 |
| 按 L71 输出 | 1 源石粉末 | 空，idle | 1 源石粉末 | 违反，两普通格同种 |

前三个状态均满足本版种子形状、普通格容量及物种约束。收货时输出格为空，缓存例外使该收货合法；规则没有“进入存货格的物品必须是该机型的原料”限制。最后一步三个明示条件全部满足，且源石粉末不是任何粉碎机配方原料，L72 不会紧接着把它消费掉。运输年龄达到 1，只有一次外部移动，端口速率也未越限。

重点审查了两个可能的否证入口：

1. **L11 的总则已有同种单格。** 确实有，且《运行语义》L58 也明确同一限制；所以发现不能表述为全文遗忘规则 L13。问题是总则与 L71 的具体充分条件冲突。总则能证明非法提交不可接受，却没有把“冲突时保持 completed、整批留在缓存”落实到当前步骤。临时补一个提交前守卫属于修正规范，不能用修正后的算法否证现文缺口。
2. **L37 的 physical 已含其它守卫。** 它的论域是现存 PC，L27 与 L69 明确本版缓存移动属于制造判定内部 BC 子动作，不是另一次 PC 模板调用。不能假定 L71 自动调用未写的 PC 检查。

本例是现规范支持的合成条件种子，不声称已证明由蓝图及非精确调试可达，也不反驳任何真实达标布局。即便实现者在提交后报 invalid，也没有产生应有的合法阻塞后效，仍不足以否证此项可实现规格缺陷。

## 4. S3-r6-L3-01：同刻窗口恢复次序

**结论：未能否证，refuted=false。**

规则 L64 给窗口从首件起算、5 tick 走完后下一件重起；第三轮任务书 §2.2 已排除窗口永久锁闭。规则 L29 给接通先后轮询，L31 使非运输源直连两个准入口的边同属“其余通道”一级。任务 L14 固定同刻判定先后，但不自动为当前实现的非判定维护阶段补一个排序。

《受限转移定义》L23 在判定闭包前做窗口维护，L55 在原因全清后恢复边，L57 要求“任何删边/加边后重算”并规定恢复边不抢存活续接位置；L45 又规定普通新级从当前接通环首条起轮。L27 的模板集合只有 move、manufacture、transfer，未包含窗口恢复；L21 为同时完成的制造另行指定了制造模板序，窗口维护没有相应句子。

设制造源 U 的同级出边 a、b 分别连两个只放源石粉末、窗口上限均为 1 的准入口。每支继续经一格传送带接独立且传输关闭的箱，故现存路径的阻尼有终点。两门 t=0 各收过一件，两条入边均因窗口用尽断开；旧货到 t=2 已分别入箱。t=5 边界前两门为空，U 输出格仅有一件源石粉末，存货格与缓存均空。两条入边全断导致 U 的该级已删除，没有存活指针。固定原接通序 a<b，移动模板序同样 a,b；其余完整输入保持相同。

| 维护次序 | 第一次恢复 | 第二次恢复 | 扫描前 next_channel |
|---|---|---|---|
| a 然后 b | 新级仅 a，起点 a | b 加入，保留 a | a |
| b 然后 a | 新级仅 b，起点 b | a 加入，保留 b | b |

第一行访问 a 即成功，窗口上限重新耗尽使 a 断开，U 留存的成员和指针为 b。第二行访问 a 时源授权 b、目标授权 a；按 L49 的 both＋advance_authorized，a 失败只推进目标单成员环，源保持 b。随后 b 成功、b 断开，U 留存成员和指针为 a。U 已无货，两个分支继续扫描都无法把新入门物品搬走，因为规则 L23 要求滞留 1 tick。

因此闭包投影分别为：

```text
先 a 后 b：门 a=1，门 b=0；U 出边={b}，next=b，current_level=null。
先 b 后 a：门 a=0，门 b=1；U 出边={a}，next=a，current_level=null。
```

投影的库存不同已足以证明完整后继不同；这不是单纯失败日志或循环截断位置的差别。两次恢复间没有移动判定，两分支采用同一输入模板序和实例排序规则；实际获资格的判定集合可以因恢复后状态不同而不同。采用“全部恢复后仅重算一次”可以定义一种确定处理，但正文没有规定该批处理，而且改变了逐次保留指针的组合后效。固定接通序也不能把尚未恢复的 a 当成第一次恢复 b 时的环成员。

L103 的唯一性归纳依赖“成员变更均单值”；单次变更单值不蕴含多个未排序变更的合成单值。本例也不属于已明确停止的离线、重建或无终点路径，不能以一般未决声明替代其排序或明确停止条件。

## 5. S3-r6-L3-02：多物种整箱落格与停止识别

**结论：未能否证，refuted=false；限于发现现有的较窄表述。**

规则 L36 的传输对象是全箱所有格的所有物品；L13 要求仓库单格单种、同种单格；L41 让指定仓库格具有后续取货可观察性。规则 L72 的编号条件分别修饰箱体的存货端口和取货端口，不能直接移植为无线传输的物种序。第三轮任务书 §2.3 只要求空格指派同时给 empty_identity，不要求仓库所有未来落格关系已解。

《受限转移定义》L65 对一个已给物种定义“已有同种格→历史身份格→无身份空格序首个→规范新格”。L79 则先汇总全箱按物种数量，再原子传输。输入接口《内核输入》L284 的 arbitration 只有 `level_order` 和 `warehouse_empty_slot_order`；《参数轴-对内核输入请求的答复》L24 的对接声明也是这两个字段。《受限模型声明》L102 及配置 JSON 对应项没有批内物种序或批量分配函数。

本例给定两无身份空格 W0<W1，两者 empty_identity 均为已指定的 null；电池、胶囊均无现存或历史身份格。箱内两物种各一件，冷却 0、有电、开关开；固定一个核心取货口指向 W0。对同样的输入，两个局部落格计划是：

| 未指定的内部物种顺序 | W0 | W1 | 固定端口以后可取物种 |
|---|---|---|---|
| 电池先 | 电池 1 | 胶囊 1 | 电池 |
| 胶囊先 | 胶囊 1 | 电池 1 | 胶囊 |

两计划都可先形成整箱计划再原子提交，不要求把传输拆成两个判定；数量远小于 80000，也没有同种跨格。固定端口未跟着交换，所以不能按无物理差异的标签规范化消去区别。《受限转移定义》L13 还明禁将数组、单位 id 或目录顺序暗作优先序。该局部差异说明“空格序已给”不足以推出“整批落格已解”，不证明任意补全均通过全规则认证。

**支持否证的最强原文已核到：** L79 明确写“若仓库落格关系尚未解，返回unsupported，不能把未定义当拒收”；L105 明列 T12 空格分配仍未覆盖／未决，L103 的唯一性也限制在支持域。覆盖报告 §6、可导出性报告 L160 因此没有把该情形报作新增发现。这些条款确实足以反对“必须任选一个正常后继”“全文没有停止机制”或“本版承诺覆盖全部落格情况”。本报告不作这三种指控。

但本次发现已经承认上述兜底，所问的是**现有字段全部齐备时，识别哪类批量落格尚未解的可执行条件**。目前 L65 给的是单物种选择器；L79 没有定义多物种同时调用时的分配关系，也没有明确将“至少两个无现存／历史身份格的新物种竞争已声明无身份空格”识别为停止触发。L13 的必需数据列表及 L65 的空格序完整性检查在本例均通过，不能据此触发缺字段的 invalid。

把本例保守判为 unsupported 是合理且安全的执行选择；但要证明当前规范已提供了精确识别，仍需说明如何从整批输入检测此触发，或明确给出整批计划及其唯一性检查。直接在本报告新增该检测而称“正文已覆盖”，会把补法当既有定义。泛化停止条款与本例的关系已有披露，但未能取得足以否证“具体识别缺口”的文本证据，故依否证判据保留 false。

这项结论比 §4 弱：这里不能把两个局部计划宣称为现规格允许返回的两个 `ok` 后继，也不把安全停止本身当错误。缺口是接口齐备与落格已解之间的识别条件；无需新增物理规则或重审主席的空格身份要求。

## 6. S3-r6-L3-03：配方符合的数量与物种关系

**结论：未能否证，refuted=false。**

规则 L18 分别规定开闸前“物品符合某个配方”和开闸后“通过一次制造的用量即关闭”；后句定通过量，不能独自证明前句一定允许库存超量。L17 的容量 50 允许存货格出现多于一批的库存；L81 的一次配方只需 1 源矿。

回读《选择点清单》L85、L87、L91，《选择点参数轴》L59–60，《受限模型声明》L59–60 及配置对应字段：

- `recipe_match_scope` 区分逐格与并集求值。
- `recipe_completeness` 区分完整批用量、全部物种但数量不足、部分物种开闸。
- `recipe_selection` 决定多候选配方先后，不决定单个配方的匹配谓词。
- 本版转移 L72 已实际采用“存货格并集足够完整用量”。

取存货格含 2 源矿、缓存空、上一批已进取货格、制造启用的状态。两种谓词为：

```text
足量：input[源矿] >= 1。
恰等：input == {源矿: 1}。
```

两种都可要求“全部物种与一批数量备齐”；都可按并集、单种、整批归集求值。前者取一件入缓存，后者此刻不开闸。改变它们无需改变现有的求值论域或最低完备度，因此不能用 `full_batch` 这个名称自动覆盖“是否容许更多”的决定。另在乙混装方向，`{源矿:1, 蓝铁块:1}` 是否同时符合两配方，也取决于是否允许配方之外的物种；《运行语义》L93 的多候选例子事实上使用了允许额外物种的解释，但没有给出排除相反读法的论证。

核查了可能的否证理由：“一批用量即关闭”天然表示允许过量；“符合”已笼统列未决；“满载配置”可排除恰等。第一项混淆通过量与开闸谓词，第二项未提供具体方向、覆盖损失或排除据，第三项还需证明在正式约束完整前件下必然违例，不能从一个库存为 2 的堵塞状态推整套读法非法。现文没有完成这样的排除证明。

第一轮任务书 §3.A.4 要求每处未定登记取值及排除据，§4 要求受限选择登记覆盖损失；第二轮 §2 又要求各工程选值可替换。现表的损失仅列 per_slot、all_kinds/partial_kinds，没有指出超量／额外物种关系。该遗漏未被已有“符合谓词仍未决”一句消除。

严格相等及额外物种禁配在此只是待审方向，不因缺排除证明自动成为合法机制，也不据此推全题无解。发现要求登记或有据排除，未越过“未定不是取值来源”的边界。

def gate_successor(recovery_order):
    ring, cursor = [], None
    for edge in recovery_order:
        ring = sorted(ring + [edge])  # 固定原接通序 a<b。
        if cursor not in ring:
            cursor = ring[0]
    source, gates, used = 1, {'a': 0, 'b': 0}, set()

    def state_key():
        return source, tuple(gates.items()), tuple(ring), cursor, tuple(sorted(used))

    seen = {state_key()}
    while True:
        for edge in ('a', 'b'):  # 两分支使用完全相同的模板序。
            if edge not in ring:
                continue
            physical = {member for member in ring
                        if source and not gates[member] and member not in used}
            cycle = ring[ring.index(cursor):] + ring[:ring.index(cursor)]
            source_auth = next((member for member in cycle if member in physical), None)
            target_auth = edge in physical  # 门存货侧只有该边，按分级侧筛选。
            if source_auth == edge and target_auth:
                source -= 1
                gates[edge] += 1
                used.add(edge)
                cursor = ring[(ring.index(edge) + 1) % len(ring)]
                ring.remove(edge)  # 收下第一件即再次耗尽窗口。
                if cursor not in ring:
                    cursor = ring[0] if ring else None
            # 只有目标获权时，失败推进单成员环，对此投影无改变。
        key = state_key()
        if key in seen:
            return gates, tuple(ring), cursor
        seen.add(key)
