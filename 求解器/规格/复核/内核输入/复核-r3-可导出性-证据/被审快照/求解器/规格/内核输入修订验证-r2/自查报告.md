## 规格与代码的读者自审

已按独立读者视角重读正文、修改过的共享轴/清单/覆盖表和修订记录，核对以下辖域：

- 几何有事件锚点；完整设计/最终快照的核心要求与建造中快照的表示区分；首次placement不借最终几何倒算。未解桥轴不当无边，无相邻口的pending轴可保留。PC可能边与当前实际活动边分开。
- 所有事件引用共用命名空间；建成顺序、关系、动作先后和原因后效须求交集；重建保留同一设计实例但产生新的接通实例。历史中的精确时刻不成为玩家可指定时刻。
- settings只有明文设定；仓库实际物种、空格身份及当前件数归运行状态；成品策略有动作/数量/重复/谓词/不精确时刻族编码，拿走件数不冒充入库量。正拿取必要性以确实存在完整达标周期和无其它已审去货机制为前提。
- semantic_context的未决事件、当前判定与tick内端口额度有字段；准入口离线累计数、窗口数、窗口起点各有轴。未知后效不默认保持或清零。
- 第7节来源绑定给总性、identity相等、域、互异、52口覆盖和两张端口表的一致性；非空绑定仍未实现，程序明确unsupported。
- 第8节子集与实际诊断对应；主样例通过只指提交的蓝图完成快照。invalid与unsupported均不表示游戏无解；未认证供电、调试可达、吞吐和全部可达循环。
- 日期/状态、交叉文件链接、16条逐项记录及13条前轮映射已核对；旧句扫描无已定位残留。修订历史在记录文件，正文采用当前定义。

## 复现

在仓库根执行：

```bash
python -B 求解器/规格/内核输入修订验证-r2/run_checks.py
```

[执行脚本](run_checks.py)把依赖缓存、构建目录、临时目录和报告都定位在求解器内；保留原A失败，另外运行当前覆盖核验，并逐项保存命令与退出码。原A失败只有在诊断为旧指纹、当前覆盖证明差异先于本轮且其它检查通过时才归为历史不兼容，不能吞掉其它失败。脚本不会替换任何旧指纹。

单独重建三个合成输入：

```bash
python -B 求解器/数据/样例/generate_examples.py
python -B 求解器/数据/样例/check_examples.py --self-test --report 求解器/数据/样例/检查结果.json
```
