# 源矿进料的粉碎机双下游黄金轨迹

日期：2026-09-19。状态：指定 `kernel_profile_v1` 赋值和合成初态下的手工期望轨迹；区间为时刻 0 到 3，含两个完整 1 tick 制造周期。数值属于候选前提下的算术推论，不是游戏实测或达标证书。机器可读期望见[黄金轨迹.json](混做粉碎机两下游-黄金轨迹.json)，独立有界重算见[check_golden_trace.py](check_golden_trace.py)，实际检查记录见[运行记录.json](混做粉碎机两下游-运行记录.json)。

## 1. 固定输入与规格依赖

输入为[混做粉碎机两下游.json](混做粉碎机两下游.json)。14 个实例占 153 格，11 条 PC、8 条 BC；这些数是从当前目录和明确坐标导出。核心位于 (50,50)，仓库取货口 ore_source 位于 (29,0)，向北取货口连接 (30,1) 的 feed_belt，再连接 (30,2) 粉碎机南侧第一个端口。其取货北侧两口分别接 a、b 两条带路，两台研磨机位于 (26,8)、(33,8)。所有制造机在 (34,3) 供电桩的正面积覆盖内；只用于供电判定的覆盖列/行为 29…40／−2…9，与各制造机占格交集非空。依据：内核输入 §2.1–2.3；规则 L44、L54、L60、L73、L76；约束端口对接。

仓库六类初始各 80000；核心六口和 ore_source 都指向源矿实物格，核心没有出库通道。源矿从仓库扣减，没有非仓库凭空投料；区间内显式补矿事件为空（到时刻 3 仍有 79996，足够每一次取货）；区间外持续充分的补给史不在本次回放内，不能由这段前缀证明补给日程唯一。依据：任务 L6–7；内核输入 §4、§6；参数 warehouse.external_supply。

本例按完整赋值运行：整数时刻、同刻先完成再判定、反复模板扫描、无成功完整调度状态重复才闭合、两端成功合取、单侧授权失败只推进授权侧、单格单种、并集齐批原子入缓存、制造判定内输出、输入同刻级联、非运输无额外停留。参数不是玩家设定。模板次序明确存于 judgment.order：先源口→进料带、进料带→粉碎机、粉碎机→a0、粉碎机→b0，再 a、b 带路各 PC，后粉碎机、两研磨机制造模板。每轮 14 个机会，身份 `J|t|轮|模板索引`，新启用事件依此续接；完成事件 `C|t|unit` 在本刻扫描前发生，不算规则 L25 判定。依据：内核输入 §5.2、§5.4；受限模型声明时间/轮询/制造各行；规则 L18、L23–25、L29–35。

## 2. t=0 前历史与种子

蓝图见证次序从 core 开始，其余非带先建，输出带随后，feed_belt 最后在时刻 0 建成；相邻建成见证相隔 1 tick。core 建成时取六类满格初始锚点，各非仓库单位按本次输入的 empty_on_build 解释为空，制造开关显式开启。不是规则默认全空/全开。先前没有连通仓库的运输路，空的输出网络和制造机持续尝试也不能产生物品；故 t=0 进料带建成前非仓库仍全空、无在制、无端口额度消耗。依据：蓝图、接通、移动、缓存格、配方；内核输入 §3.1、§6；受限模型声明 initialization.* 的输入条件。

蓝图完成、空调试程序结束与最后一次建成在本历史同刻先于运行扫描；StateSeed 是这条实际历史的扫描前状态。玩家没有需要精确到 tick 执行的操作；整数见证只是一条历史，不能证明所有允许结束时刻给同一 StateSeed。可达性标 conditional_history，尚不覆盖其它建造时距、初值解释与调试结束时刻。依据：任务 L10–12；内核输入 §3.1、§6。

每单位每侧的全部级、成员、下一通道及当前最高可动级都保存在 poll-memory-v1。本布局没有分流/汇流，所有非空侧只有一个级。粉碎机输出按先接 a 再接 b；初始 next=a。当前全部非仓库为空，因此仅源口输出、进料带输入为可动分级侧；运输单位非空拓扑的输出侧保留唯一非分级位置，即使没有货。空侧也显式列出 levels=[]。依据：内核输入 §6.3；规则 L29–32；受限模型声明初始游标、per_level、判前筛级。

失败/无请求机会没有隐去物理后效。t=1、2、3 首次扫描源口先遇到尚满的 feed_belt；后续扫描才补入。每次真实失败仅推进已经授权的侧，单成员环推进仍指自身。粉碎机无货时分级侧没有可动级，不借扫描强行轮转它的 a/b 游标；t=3 a 有货可收但没有当前输出许可时也不能抢过 b。未获任一侧许可的扫描机会记录 no_request，不宣称它是规则 L25 已发生判定。依据：受限模型声明 polling.both_failure、eligibility_stage；规则 L29–32。

时刻 0 共扫描两轮；时刻 1、2、3 各三轮。最后一轮没有成功、完整库存/进度/两侧级内记忆/当前级/端口额度在扫描边界重复，因此闭合；判定日志里的绝对轮号和事件 id 是诊断序号，不参与物理后继相等。把它们也纳入闭包判等会永不重复，故须区分编码计数与调度状态。该归约只在本有限模板、无隐藏失败后效的 profile 中使用，不作为其它日程的定理。依据：受限模型声明 time.instant_end；内核输入 §5.2。

手算守恒核：出库总量 4＝两件已制粉末＋一件在制源矿＋进料带一件源矿。粉碎原矿配方件数 1→1，故这里可以直接以件数核；其它配方不可照抄。每口每个所列 tick 最多 1 件；运输格容量为 1，所有出运输格的事件都满足真实年龄至少 1。依据：配方粉碎-源矿、规则 L23、L59；约束端口速率。

## 4. 本次可推范围与未决

本轨迹没有用砂叶粉末，研磨机也尚未收到原料；没有源矿/蓝铁块交替配方，文件名中的“混做”是保留的拓扑测试意图。0–3 tick 已覆盖首次制造及再开工，但不覆盖混做清空、两台下游制造、产物正确分拣、箱体相位、分叉选择变化或离线接续。

全部轴都有值不等于全域证据：stop 的机制仍未定义，触及时应停；其它取值未跑。合法启动的全历史族、闭包的全状态正确性、仓库环境量词与完整周期提升仍未结清。若共享受限模型改变事件插入、完成位置、物理可动谓词或失败后效，必须重算本表，不能只刷新哈希。具体共享依赖对齐状态见[本轮自查](../../规格/内核输入修订验证-r3/自查报告.md)。
