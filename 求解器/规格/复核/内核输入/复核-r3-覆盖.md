## 2. 发现

### K3-r3-L1-01：逐时刻排序缺少周期或函数编码

**where**：`/home/zhuran24/zmd-research-fresh/求解器/规格/内核输入.md:246`、`:248`、`:250`（§5.2）；同文 `:140`、`:141`（参数域）。

**claim**：`event-order-v1` 对 `per_instant` 只允许有限 `instant_overrides`，不能输入“偶数次共同到期先 A 后 B、奇数次反过来”这样的完整合法周期排序，因而没有覆盖 `judgment.order` 的全部逐时刻取值。

**severity**：重要。

**evidence（正式原文）**：

- 规则 L25：“同一时刻的多个判定逐个进行，先后无法确定”。
- 任务 L14：“同一时刻多个判定的先后固定”。
- 约束 L3：“不得依赖的量（目标须对其每种取值都达成）”；L10：“判定先后：同一时刻多个判定的先后”。
- 规则 L36：“即使那个物品格中没有物品也一样，5 tick 冷却”。

**具体取值及全规则检查**：

取两个彼此没有物流通道的协议储存箱 A、B，各格为空，供电且传输开关开。可将 A、B 分别放在 `(10,10)`、`(16,10)`，供电桩放 `(13,10)`，核心放 `(50,50)`，全部 r0；占格不重叠、在基地内，桩的正面积供电覆盖两箱。仓库按任务六类各满、其他为空，两个箱无输入路径。四单位一次蓝图逐个建成，例如核心、桩、A、B 的时刻分别为 −20、−15、−10、−5；没有传送带。箱的首次尝试后按 5 tick 冷却，故在时刻 0、5、10……共同到期。调试期可以无操作地结束；这里不需要玩家精确开关或拿取。

预先固定以下规则：在共同到期的时刻 `t=5k`，偶数 k 先 A 后 B，奇数 k 先 B 后 A。其它时刻无这两个到期判定。每个时刻的顺序从头到尾固定，两个动作仍逐个原子执行。每箱仍恰按 5 tick 冷却，空箱仍尝试；无物品增减、无端口通过量、无轮询或优先级竞争，容量和滞留全部保持。交换两个独立空箱的执行次序没有改变任何物理后效，亦未借“未定”加入投料、跳过尝试或清零。它是合法的合成运行，未声称满足任务产率。不能用达标布局的机型下限等必要条件排除这种合法但不达标的运行。

该例的前八次共同到期顺序保存于[覆盖反例证据](r3-覆盖证据/覆盖反例证据.json)的 `event_order_periodic_witness`。这里的反例是一个有明确定义的二周期函数，并不要求在 JSON 中穷举任意不可计算函数。

**编码穷举**：

1. `scope=global` 要求 `instant_overrides=[]`，只能保留一份模板序，不能交替。
2. `scope=per_instant` 的每一项只能是一个具体 `instant` 加完整模板序；文中明确“进入未列时刻即 unsupported，不回落默认序”。任意有限数组都有下一次共同到期未列。
3. `repeat_embedding=scan_round_then_template` 只组织同刻重试，不提供时刻间二周期或函数。
4. `Time.kind=symbol` 只给一个带关系的时刻符号；格式没有把一个 override 声明为“所有偶数次共同到期”的量词或模式语法。把该公式塞进 `Decision.basis` 也不会变成可识别的排序编码。

因此，有限历史可以回放，完整合法取值不能作为一个固定指纹的输入给出。输入正文自己承认“无限或符号函数需另增函数编码”，所以本发现并不把缺口解释为隐蔽默认。问题是这项待补接口正位于通用参数覆盖路径上；它不能被“有限例已经跑通”结清。

**所需修订边界**：增加明确的周期/函数式排序接口，或给通用格式的可扩展机制引用和已定义调用约定；至少让上述二周期取值可表示。参考执行器可以继续对超出自身 profile 的取值返回 `unsupported`。输入合法域与执行器首版支持域应分别验收。

### K3-r3-L1-02：StateSeed 缺闭包中途阶段

**where**：`/home/zhuran24/zmd-research-fresh/求解器/规格/内核输入.md:252`（§5.2 `judgment_context`）、`:284`、`:286`、`:310`（§6 完整状态与恢复）；`/home/zhuran24/zmd-research-fresh/求解器/规格/内核输出.md` §2。

**claim**：v3 的 `judgment_context.phase` 只有 `before_boundary/after_closure`，没有边界已处理但本刻判定尚未结束的状态编码，导致调试结束落在两个同刻判定之间的合法初态无法作为完整 StateSeed 保存和恢复。

**severity**：重要。

**evidence（正式原文）**：

- 规则 L25：“同一时刻的多个判定逐个进行”。
- 规则 L22：“可自行设定的项目都可以随时任意更改”。
- 任务 L11：“布局的全部工作可以不用完全依赖蓝图，同样可以由玩家来做部分操作”。
- 任务 L12：“玩家的操作无法精确到某个 tick，也无法精确计时”。
- 任务 L8：“建造完成且调试期结束后，玩家对基地内的任何单位不再有任何动作，从仓库中拿取成品除外”。
- 约束 L30：“每个端口每 tick 至多通过 1 个物品”；规则 L20：“不运行时进行中的进度保留，恢复后继续”。

**已有轨迹中的具体断点**：

本席以 Python 行跟踪只读观察原 `check_golden_trace.run`，捕获实际执行完 `J|2|0|1`、进入下一模板之前的物理投影；代码和数据分别为[取证脚本](r3-覆盖证据/coverage_probes.py)、[覆盖反例证据](r3-覆盖证据/覆盖反例证据.json)的 `mid_closure`。没有修改参考实现。

此时：

- `C|2|crusher` 已完成：粉碎机缓存中是源石粉末 1，批次 `completed`、剩余 0。
- `J|2|0|1` 已成功：进料带已空，粉碎机存货格有源矿 1，该 PC 两端本 tick 的端口预算已各用 1。
- 粉碎机制造模板 `J|2|0|11` 尚未执行，故缓存产物还没进取货格，下一批也还没开工。
- 当前轮为 0，下一个模板位置为 2；这是边界处理后的判定闭包内部。

在另一条具体历史中，保持同样建造、库存、开关和所有物理事件，让空调试期的结束标签位于这两个原子判定之间。标签改变运行阶段，不改变库存或制造规则；此前、此后玩家都没有动作，符合零干预条件。它只是允许历史中的一个实际结束位置，不是玩家保证命中 `J|2|0|1` 的定时策略。操作精度不授权把其他可能结束位置删除，也没有把调试结束钉在扫描边界的条文。

若要把这种状态作为零干预起点，必须同时保存“本刻边界已办完”和“闭包未办完”，以及既有轮号、下一模板、已用端口预算等。后几类字段已经存在；缺的是合法的执行阶段及其恢复解释。

**现有编码为何不足**：

1. 标成 `before_boundary` 会把已完成的边界阶段记为未办，可能重复完成、补给或窗口维护。
2. 标成 `after_closure` 则把尚未进行的制造及后续移动记为已办完，可能直接推进时间。
3. `round/next_template/ordered_events` 不能自行创造第三种 `phase`；文中明确更一般中途恢复需要额外的阶段去重状态并返回 `unsupported`。
4. `tick_context` 能保存本 tick 的端口账，但不能单独说明下一步处于哪个阶段；清空它又违反端口速率核验要求。
5. v2 的旧上下文已在 §6 明确不作为运行恢复输入，因此也没有旧版本的无损回退。

原种子在 t=0 扫描前，故当前样例通过是正确的。本发现落在通用初态接口：仅能停下报告不支持，还不能保存并读回这类完整状态。输出 schema 对 `Decision.value` 留空结构校验，不会自动补上正文未定义的阶段语义。

**所需修订边界**：补充边界处理中、边界已完成/扫描中等适用阶段和必要去重信息，给出轮号、游标、已实例化事件、待事件、端口账之间的一致性规则；至少使上述实际断点能够无损编码。是否在第一版执行器实现恢复可另列为支持范围。

## 3. 三种新接口的逐项判读

| 接口 | 已能表达的内容 | 全域覆盖判读 |
|---|---|---|
| `EventOrder` | 有限模板全序；以轮号和模板位置为新判定命名；固定整场序；逐具体时刻列不同顺序 | 有具体的整场周期取值缺口，见 K3-r3-L1-01；单一 `scan_round_then_template` 也没有声称穷尽其他重试嵌入 |
| `DampingBranch` | `(查询 PC, 分流器)` 到当前出支；整段固定表；有限的逐求值表；缺项停下；不把分支相加 | 固定表与有限实际调用记录可表示；无限时变序列/相关关系无函数编码，且跨次固定性的一般合法域仍待审。本席不把任意时变序列仅因列为 open 就定为合法反例，故不另列独立 finding |
| `PollMemory` | 每个非供电单位两侧；每侧各级成员、级内下一通道及当前可动级；无边空表；运输取货侧一个非分级环；桥按单位两侧 | 满足本版 `per_level` 的明确结构要求。`per_side` 投影等方向没有完整独立编码/后继证明，属于已登记未覆盖域；尚未给出通过全规则审查且不能无损改编的具体机制，故不把候选状态表示本身当新游戏合法值 |

`DampingBranch` 的新回归确实使用非空分支表，并分别读取固定/逐次记录；该回归不等于求值器已支持所有分流布局。当前参考运行没有分流器，运行检查会明确拒收分叉子集。`PollMemory` 当前样例有 26 条侧记录，且该布局所有非空侧只有一个级；它验证字段齐备，未验证多级抢占或所有级间续接读法。

## 7. 未计为发现的边界

1. 当前样例没有真正混做，也没有研磨出货，正文和黄金文件已明确说明；本轮“至少一个完整制造周期”的有限实例要求已达到，不能凭文件名另要求它证明完整工厂。
2. 三种新接口的某些候选方向尚未通过全规则审查。参数表列 open 不等于允许该任意赋值；本报告未用它作新增非法/合法机制的替代证据。
3. 合成初始全空、具体建造时距、无离线与无玩家动作只是一条条件历史；这不是全称认证，但本轮样例允许条件见证。
4. `stop` 是共享 profile 的工程处置，原 91 轴“都有值”不等于这些机制已解决；当前轨迹未触发相关处置，不将其算缺值或规则取值。
5. per_level 之外的轮询状态、无限时变阻尼关系、仓库拿取的所有可能策略、完整周期提升、Rust 内核与一般状态恢复仍须后续工作；未拿这些尚未完成的普遍证明冒充本轮新增阻断。
