### K-r1-L1-1

**结论：`refuted=false`，未能否证。** 保留“重建接通史的具体表示及其派生依赖缺口”。

独立回源规则 L63 与 L16：桥每对角色需要先接端依据，条文没有要求每座桥必须四侧都有邻接端口，更没有要求闲置轴必须先接到谁。运行语义 L27 明确保留逐对方向待定。目录桥接器记录（L2241 起）确有四个 layout，各为两条轴的二元方向组合，`port_assignment=first_connected_peer`（L2483）也不把方向变成玩家设置。

### K-r1-L3-03

**结论：`refuted=false`，未能否证。**

回源规则 L13/L14/L41：仓库是核心格集合，格内内容受单种单格与容量约束；唯一相应可设定关系是取货端口连接某仓库格。L22 使明文可设定项可改，不能反向把任意 JSON settings 子项变为游戏授权。任务 L6/L8 分别约束初态和玩家动作，没有另授权格的物种设置。

### K-r1-L3-04

**结论：`refuted=false`，未能否证。** 保留 source_map 的覆盖及双表关联没有足够明确机械条件的问题。

第二轮任务书 §3.C.6 要求与送料契约对接。回源规则 L41/L73、约束“取货口配置”：核心/边界实际输出端口必须逐口区分，不能只用核心单位身份替代。送料契约 L80–82 明确 LF 端点含机器、来源变量、核心，逻辑端口序号是标签。来源表 L114–125 把 ORE 变量定义为单个取货端口身份而不是一整台核心。

实际 contract.json 全量读取后为 219 台机器、315 条 LF、52 个来源；LF018 的源为 `ORE000`、逻辑口 `ORE000:out:1`（L8071），LF112 的目标口为 `CORE:in:1`（L10048）。输入 L247 要 source→实际 output 口，L249 要 logical_port→physical_port，L250 用 port_map 约束路径端点；的确有两个表示指向同一矿源端口身份。

可用于否证的文字是 L249 的“等逻辑端口”“角色、端点须匹配”：其中“等”不能读成只准 M 前缀，CORE 口也能由 core_map 约束到核心。故不是 ORE/CORE 在语法上绝对禁止。可是文中没有把端点匹配展开为 `port_map[ORE:out:1]=source_map[ORE]`，对单口来源与多口核心如何取相等/仅归属仍缺显式规则；L246 对机器有完整覆盖要求，L247 对来源只有互异，L250 也未要求完整覆盖所有 LF。不能从“逐个互异”推出“恰有全部 52 项”。

即使把双表相等视为“端点须匹配”的自然推论，完整性这一分项仍不足以否掉。最小检查器 L338 拒收非空 binding，所以本条不影响当前三个样例的已报静态结果，也没有实测发现一个矛盾绑定被通过。

### K-r1-L3-05

**结论：`refuted=false`，未能否证。** 三个拒收信息已在不改样例的内存副本上独立复现。

回源规则 L9/L28 要求蓝图先后和按建成时刻接通，没有要求只存相邻链而不存其真传递关系。第二轮任务书 §3.C.7 的样例检查是最小合法性检查；输入 L80 明确允许 selected_order=null，L82 定义关系记录但未要求恰为相邻链，L98 明确允许仓库 item=null；L279 承诺超出程序子集时报 unsupported。

|---|---|---|

### K-r1-L3-06

**结论：`refuted=false`，未能否证。** 保留非语义依赖文件变化导致静态复现命令硬失败的事实，不将其说成已经把候选推论当正式规则。

第一轮任务书 §1/§4、第二轮 §4 都区分候选与正式约束，同时要求本轮不得改候选文件。检查器 L55–60 把候选指纹与三份正式文件一起存入 SOURCE_HASHES，L430–431 无条件逐字节比对，L461–463 将该 CheckError 转为退出 1。输入 §1 的语义来源及具体静态检查均未使用候选条文。

以下代码复现第 2、3 项，不产生输出文件或字节码缓存：

```bash
python -B - <<'PY'
import copy
import importlib.util
from pathlib import Path

base = Path('求解器/数据/样例').resolve()
spec = importlib.util.spec_from_file_location('checker', base / 'check_examples.py')
checker = importlib.util.module_from_spec(spec)
spec.loader.exec_module(checker)
path = base / '桥接器双通路.json'
original = checker.load_json(path)
catalog = checker.load_json(base.parent / '正式静态目录.json')

def probe(mutate):
    data = copy.deepcopy(original)
    mutate(data)
    try:
        print(checker.check(data, path)['status'])
    except checker.CheckError as error:
        print(str(error))

probe(lambda d: d['construction'].update(selected_order=None))
probe(lambda d: d['construction']['time_relations'].append({
    'before': 'build_0', 'after': 'build_2', 'relation': 'strict',
    'basis': ['已有严格先后关系的传递推论']}))
probe(lambda d: d['settings']['warehouse_slots'][0].update(item=None))

data = copy.deepcopy(original)
old = checker.geometry(data, catalog)
bridge = next(u for u in data['layout']['units'] if u['id'] == 'bridge')
bridge.update(rotation='r180', port_layout=3)
new = checker.geometry(data, catalog)

def face(port):
    return port['unit'], port['cell'], port['normal'], port['role']

new_names = {face(port): pid for pid, port in new[2].items()}
assert {face(port) for port in old[2].values()} == set(new_names)
port_map = {pid: new_names[face(port)] for pid, port in old[2].items()}
channel_map = {
    edge['id']: 'PC|' + port_map[edge['source_port']] + '|' + port_map[edge['target_port']]
    for edge in old[3]
}
data['layout']['physical_channels'] = new[3]
for route in data['scenario']['expected_paths']:
    route['physical_channels'] = [channel_map[cid] for cid in route['physical_channels']]
print(checker.check(data, path)['status'])
PY
```
