# 判等独立推演 r8

日期：2026-09-19。状态：阅读《受限转移定义》§6 前封存的独立推演。依据为三份正式文件、受限转移§1–§5、内核输入§5.2/§6及现行 State/closure_key 字段；未采用第五轮证明、参考判等脚本或自查结论。

## 1. 时间平移的逐字段义务

令观察时刻为 t，比较锚点必须同为 after_closure；整数 profile 中下一次处理 t+1。只比较同布局、同设定、同接通关系、同全局模板序、同参数和同未来环境机制。若以后还有按绝对日期发生的离线、补矿、拿取或非周期判定序，删 t 会丢失其相位，不能直接认证。

| 字段 | 独立判定及理由 |
|---|---|
| environment.time | 可以去掉平移原点，前提是所有未来守卫均完成下述处理；stage/online 仍保留，拿取策略有记忆时不能随 t 一起删除。 |
| inventory.contents.entered_at | 非空运输格用 age=t-entered_at；规则L23只读年龄≥1，边界令年龄加1，新收件年龄为0，因而精确年龄相等可保持。非运输该字段在本版无停留守卫时为审计，保留精确相对年龄仍安全，但会漏掉物理周期；不得据此宣布状态有限。null 与有值须有明确区别。 |
| progress.remaining / cooldowns.remaining | 已经是工作量或时长，不再减 t。规则L20要求停用时保留，§2.1只在功能运行时减。recipe、锁定、候选、phase及冷却归属保留。 |
| gate_counters.window_started_at | 改为 null 或 elapsed=t-start；规则L64以收首件为起点、经过5 tick到期。计数、原因集合保留，不能仅保存是否阻断；窗口到期只去窗口原因。total_received 未获删除证明，精确保留可能漏检。 |
| pending_events.trigger.at_time | 普通定时语义可用 due-t，连同 operation/target/status 和依赖关系。制造完成例外：§2.1规定 remaining 归零决定完成，预计截止只是审计，停用后不能让旧截止控制完成；保留相对预计截止是较细但可能不完备的键。 |
| pending_events 的 after_event / condition / predecessors | 不能仅把 event 字符串删掉。需要给依赖图一致改名并证明其守卫可平移，或明确排除不支持的触发/前驱。事件注册表碰撞是编码校验，不能混作物理不周期。 |
| tick_context.window_start / window_end | 变为 start-t、end-t；本版闭包后窗口为[0,1)。本刻 port_usage 到下一边界清零，闭包内部不能清零；movements/internal_passages 的事件、批次标签只有证明不再被未来依赖读取才可在闭包锚点删掉。 |
| judgment_context.instant / round / next_template / ordered_events / next_event | instant 去原点；phase 必须保留。仅在 after_closure 且下一步重开扫描时，当前轮号、游标、已执行前缀可以不进跨 tick 键；中途锚点还需 continuation.seen_boundaries 等，不得套用。 |
| connection_order 及建造/接通时间 | 规则L28–32读的是接通先后与同刻平局。固定历史不是要随运行时钟增长的年龄；同一运行可保留历史引用及已解序，不应强行变为 t-built_at 造成持续增长。要跨输入比较须连同依据的历史比较，不能只比较字符串名。 |
| settings_anchor、layout_snapshot、parameter_values 的事件/时间引用 | 固定上下文保留或以涵盖实际内容的指纹锁定。全局判定序无绝对时钟依赖；per_instant 的表/周期/表达式可能读绝对时刻，不能未经相位证明归一。传输相位须反映到种子实际冷却。 |
| 日志中 J/C/W/I 身份的时刻部分 | 正式规则不读取日志标签。只可作为审计另存；若恢复验证或前驱仍读取，先一致改名或停止，不能留下悬空依赖。 |

现行 closure_key 的11项是 warehouse、inventory、progress、memory、active_channels、blocked_channels、gate_counters、connection_order、arbitration、pending、usage。同刻键包含的量不能原封不动当跨刻键：它在固定 t 下使用，且缺环境/固定参数上下文。State 的 layout/settings/environment/parameter_values/judgment_context/tick_context 必须另逐项处置。反过来，闭包内部仍须保留仓库完整容量和端口预算，跨刻抽象不替代 §5 的原闭包键。

## 2. 两矿及两成品的读取路径

两矿出库：§4.1按指派格读当前 item 与非空，§3.1据此构造 physical，§3.2据 physical选级授权，§3.3移动后写非仓库库存、预算和指针。sufficient 以一次事务扣1补1，使任意正数矿量在这条路径等价。矿物种、格身份和端口指派不能随数量一起删除。

回矿入库：§4.1单件入库读 q+1≤80000；§4.3整箱先汇总再读每物种 q+b≤80000。q=79999、b=2拒收，q=79998则成功，两者都非空且未满，后继箱内容、冷却后的物流和指针可不同。故删除矿量必须禁止回矿入库，或将容量余量作为可观察量保留；任务L7只保证供矿，不能推出无限接收。约束“矿系不入库”是达标循环态必要条件，不能用于证明任意坏运行不出现回矿。

成品：不被取货端口引用时，成品物种/数量经核心入库和无线传输容量被读；“存量<80000”只保证单件可收，不保证整箱 b 件可收。两条入库途径应分记，外取不能扣除已经交付的分子。只有明确定义的生产抽象接收器及每次事务足额余量前提，才能让去库存的后继确定；把一个具体有限库存段循环重放，最终会遭容量变化。

## 3. 取空成品格对非仓库的泄漏

§4.1 retain_history 下，成品格清空仍保留该物种身份，不回入匿名集合 E，原空格序 O 不增加它；同种再入回该格。若所有这些格均未指派端口、标签不被其它机制读取，则清空本身不改变非仓库。这里尚须单独核容量和规范新标签的冲突；“标签只是编码”不等于可以忽略一个会触发 invalid 的标签冲突。

若释放身份而加入 E，已有指派端口可观察它后来装入何物：先取空成品格 w，再由新物种占用 w，指向 w 的端口读到新物种，遂改变候选货、准入口身份维护、physical、轮询及运输格。这是一条完整的非仓库后效链。因此一般释放身份模型不能照搬 retain_history 的删除证明。即使没有成品端口指派，非空匿名 O 与新物种落格也须保持顺序或证明置换对所有可观察引用不变。

较强但可核的受限域可要求：E/O为空；成品格不被端口引用；两矿唯一正格且 sufficient；禁止两矿回库；仅 after_closure；无未来玩家/离线/结构事件；全局固定模板与已解参数。该域内生产抽象可在每次入库事务之前选同一足额容量代表，把成功入库计入外部台账；这定义的是生产部分转移。它与真实拿取族逐刻同轨仍需另证，不是定义即得。

## 4. 独立结论

时间平移需要各读取点同时协变，不能只换字段名。精确年龄、无上限累计及失效预计截止可让键无限增长：这通常造成漏检，不会凭空制造假周期。仓库抽象的主要危险是容量守卫、端口可见身份和分配后效；只有上述限制或更强不干扰证明成立时才能归纳后继等价。对“任意始终未满的拿取日程”不能从未满直接推出整箱可收，故级二必须保留卡点。
