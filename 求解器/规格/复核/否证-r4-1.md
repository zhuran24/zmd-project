## 1. S2-r4-L1-01：传送带端口形状及生命周期

**结论：refuted=false，未能否证。**

回源：规则 L60 确为“任意一条边为存货端口、其他任意一条边为取货端口”；L11 只明文给旋转；L22 的任意更改以“可自行设定的项目”为前件；L10 只明文规定重建后通道重新接通。第一轮任务书 §3.A.2 要求逐量记录生命周期，第二轮任务书 §3.C.1 要求输入能表示实例端口。

令四边编号为 0、1、2、3，端口配置为有序对 (s,t)，s≠t。旋转加同一个 r，不改变 (t−s) mod 4；这个差有 1、2、3 三值。因此 12 个配置恰分为三个四元旋转轨道。差 1 与差 3 不能靠平面旋转换位。此为规则 L60、L11 的条件算术，不把镜像添加为动作。

目录的传送带确有 south→north、south→east、south→west 三个 layouts；制造单位、核心、准入口、分流器、汇流器、箱体各只有一个规范 layout。内核输入 L51 正确表示了三形状乘四朝向。因而不能把发现扩大成“静态布局连弯带也表示不了”。

真正未覆盖的是变更语义：运行语义 L47 仅复述两边；选择点清单 T11 的 L104–106 处理旋转和拆建；参数轴 L88–90 处理调试动作、rotation_stage、rebuild_inventory，没有形状选择时点及形状继承字段。内核输入 L232 的 rotate payload 只有 rotation，rebuild payload 指回 unit，未说明是否重新选 port_layout；额外动作要升级编码，不是现有可执行动作。

尝试否证的最强依据是“layout 已含端口”及 T11 的一般调试未决声明。前者只解决表示，后者没有指出这个旋转不变量，不能补齐逐量登记。另一方面，layout 分组本身并不逻辑蕴含不可变，L51 也没有明说“永不改变”：发现中“已写成不可变”的措辞应收窄为“当前格式未给变更路径及后效”。这个收窄不消除主缺口。

## 3. S2-r4-L1-03：T15 与正式几何约束的交叉核验

**结论：refuted=false，未能否证。**

回源：选择点清单 L137、参数轴 L103 都明写还须核约束·供电下限、约束·侧旁供电；受限模型 L52 直接选择 positive_area，其取据是非零面积读法。覆盖表 L192、L203 只将两条约束登记为静态核验，没有完成两读法的相容性比较。第二轮自查确实核了格集合与区间相交算式，但这不同于核两条正式约束的台数结论。

规则 L44 的 3×3、L76 的中心 12×12 与 T15 算式给出：positive_area 时小机左列在 a−7…a+6，closed_touch 时在 a−8…a+7。原发现将 6×6 减至少一台写成 35，这只是松上界，不是可实现见证；“上界是 35”不能推出存在超过 24 台。附录甲另给了可核实的 32 台见证，消除了这一证明弱点。

侧旁计算独立复算如下。设矩形左界 X=a+2+g，讨论整体在其左侧的 3×3 机器，x+2≤X−1，故 x≤a+g−1。g=0…6 时，两个读法的合法起点数分别是 g+7、g+8；一维不相交区间最多取 ceil((g+7)/3)、ceil((g+8)/3)，得到：

| g | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|---:|
| positive_area 的一维列数 | 3 | 3 | 3 | 4 | 4 | 4 | 5 |
| closed_touch 的一维列数 | 3 | 3 | 4 | 4 | 4 | 5 | 5 |
| 正式 c_g | 13 | 14 | 14 | 17 | 18 | 19 | 22 |

positive_area 的列数跃变位置与 c_g 的两次 +3 跃变相同，但这没有推导 c_g 的七个精确上界。该约束还要求循环态中有制造、覆盖投影在矩形跨度内、矩形短边至少 6；完整二维排布及端口条件不能由一维计数代替。

因此主发现“已登记而未完成核验”成立；“数字吻合”只作定位线索。至于“不能演绎排除 closed_touch”，若只凭其松上界及侧旁投影，确实不能；结合约束 L92 没有“有制造”限定的 24 台子句与附录甲的具体见证，则已有直接冲突，见 §5。这项加强不构成对核验缺口的否证。

## 4. S2-r4-L1-04：仓库与核心的覆盖入口

## 5. S2-r4-L2-01：closed_touch 与 24／14 上界

**结论：refuted=false，未能否证。**

回源：约束 L92 原句区分“至多为 24 台制造单位供电”和“至多为 23 台循环态中有制造的制造单位供电”，随后给特定边列/边行桩的 14／8。24 台子句自身没有“循环态中有制造”前件，不能把相邻 23 台的限定回填进去。规则 L19 将供电定义为由桩赋予的状态，L20/L35 将是否运行与供电、功能另行区分。因此不需要证明这些机器都有流量，才能检验 24 台几何子句。

具体内部见证：桩起点 (30,30)，连续覆盖正方形为 [25,37]×[25,37]。取 3×3 机器左下角横纵坐标均来自 {22,25,28,31,34,37}。共 36 个网格位置，删去横纵坐标各在 {28,31} 的四个位置，剩 32 台。各机占格互不相交且不压桩，全部在 70×70 内；最外机器与供电方形至少闭边接触。远处可放唯一 9×9 核心。附录甲逐台直接检查连续矩形交集，不借原复算脚本的格集合函数。

贴边见证：桩 (0,30)，横坐标 {0,3,6}，纵坐标沿用上述六值；删去 (0,28)、(0,31)，余 16 台。桩含第 1 列，满足 14 台子句的几何前件。机器不要求循环制造，见证只用来检验供电台数，不冒充达标布局。

对原脚本的证据收窄：供电覆盖计数核验-r4.py 枚举全部候选落位后，只比较九个共同模 3 相位网格；注释断言最优集合必由其中一个达到，但没有证明。另一个脚本只取一个网格。两者都不能仅凭该代码宣布穷举了全部不重叠集合或取得全局最优。然而排除只需一个超过 24／14 的具体见证，32／16 已足够，最大值是否更高不影响矛盾。

第二轮任务书 §2 与 §4 不允许将已与正式约束冲突的读法保留为应覆盖的机制。因此现稿继续为该 closed_touch 读法记录“边界触电”的覆盖损失，未被证明合理。在 T15 当前列出的两个精确定义之间，冲突落在 closed_touch 一支；这不额外宣称已穷尽所有可能的几何解释。若否认 24 台子句的无条件几何含义，须回到正式来源澄清，不能默删该子句或默加达标前件。

## 7. S2-r4-L2-03：内部通道分级与“直接接”

**结论：refuted=false，未能否证。**

回源：规则 L18 两条缓存路径称为通道；L29 的轮询前件是多个存取端口；L31/L32 的分级表述改用取货/存货通道。两者不能仅因同名“通道”就自动共用辖域。

参数轴 L36 原文先列“内部通道不入分级、不入端口轮询”，后写“是否入通道分级另审”；L131 的 C8 处置也只说分级另审。受限模型 L48 则选择两者均不入，并登记“其它内部通道分级”损失。可以善意读作一个候选外加尚未展开的另一方向，而非形式逻辑上的 P 与非 P 同时断言；但该表确实没有把分级的纳入/排除及各自候选语义写成可逐项核对的集合。第一轮任务书 §3.A.4 与第二轮 §3.A.2 要求的交接仍不完整。

发现关于“内核 enum 只会有一个变体”的说法并非已发生的实现事实。参数轴 L7 明说方向包括而非穷尽，内核输入 L213 对新增或未解机制要求停止，不能反过来证明实现者必然封死为一变体。不过停止护栏不补足候选登记。

对顺带的 direct_peer 论证另核：规则 L16 的一条实体通道连接相遇的两个单位；L27 若需沿链走到非运输单位，会明确写沿途终点。非运输单位→传送带→汇流器涉及至少两条实体通道，起始通道的另一端是带，不是汇流器。这支持受限模型 L48 的“物理通道另一端”解释，而参数轴 L37 仅把隔带方向列为“须另证，不先授权”，尚未给准许依据。不能把这类未经核验的方向直接当已成立的覆盖损失。

本条的主缺口足以保留 false；不据“另审”三个字宣称分级域已完整，也不据候选登记直接承认隔带读法合法。

## 8. S2-r4-L3-01：供电轴的独立复核

**结论：refuted=false，未能否证。**

本条独立回源规则 L8/L44/L76、约束 L92、选择点清单 L134–139、参数轴 L103、受限模型 L52；判据不依赖另一复核席的结论。

发现给出的坐标在 (a,b)=(30,30) 时成为 {22,25,28,31,34,37} 的笛卡尔网格。删除与桩重叠的四台后，各 3×3 方块没有相互重叠；它们到中心 12×12 方形的连续矩形交集在两轴均非负，故依 closed_touch 全部获电。32>24 是具体违反约束几何子句的见证，不是从较大的松上界倒推存在性。附录甲使用独立代码检查这一点。

发现列出的几何证明链以及第一轮任务书 §3.B.3 的静态核验范围，不需要全部复证才能判定当前 T15 的冲突。当前草稿没有处理这项冲突，仍保留边界触电损失。因此未能否证；不把这份局部算术报告升级为全部几何约束证明。

## 9. S2-r4-L3-02：相遇判据的登记与唯一性

**结论：refuted=false，未能否证；发现的唯一性旁证尚不充分。**

回源：参数轴 L46 实际给出了一个具体方向“共边同位置相对存取端口”，所以“没有任何候选”按字面过强。但“其它几何读法未定”未列具体另一方向或相应排除论证。L142 仅说几何判据为外部输入；T5 L48–55 处理建造序、平局与桥方向，没有展开相遇几何。覆盖表 L26 也未指向 connection.port_meeting。现有的角色限制——存取互补、至少一端运输——不是几何歧义的消解。

内核输入 L68 已明确说明共边检查是本版结构子集，不裁定其它解释。故不能把 C 线描述成已经把 A 线未定永久裁成全规则；但子集声明也不提供第一轮任务书 §3.A.4 所需的候选/排除依据。

尝试核实发现提出的“规则唯一确定”：L12 的一格宽保证长度，不独自说明“相遇”必须是长度一的重合而不能是端点接触。例如两条各长一格的边段可以只共享一个格点；要排掉这种读法，还需说明“相遇”的交集谓词或从其它普遍条款导出矛盾。约束·边带排布（L94）与约束·核心邻格（L100）约束特定达标矿口；约束·四通结点（L123）以“四个邻格都是……端口格”定义所计的 x。这些能支持共边模型，但不能仅靠该条件式定义反推任何单位、任何工况都不存在其它接触。此处没有宣布端点接触已通过全部规则审查。

因此本条保留的是登记不完整、入口缺失和依据未展开。即使唯一性旁证不能直接成立，也没有证明草稿已完整覆盖相遇轴，不能标 true。

## 10. S2-r4-L3-03：F1 的“最小合法格”

**结论：refuted=false，未能否证；不能据此断言实现已经跳格。**

回源：规则 L72 分别规定存货选“编号最小的能放它的物品格”，取货选“编号最小的非空物品格”。运行语义 L52 正确分开两者。参数轴 L145 的 F1 则用“箱体逐次取编号最小合法格已定，空格不另降级”概括。独立清单-r3 的 F1（L391–399）也明确保留存货与取货的两条原文，空格不另降级主要在说明存货选格。

最强否证理由是 F1 已链接运行语义 §2.2，“取”可以指一般选择而非取货，“合法格”也可以按存取各自规则解释。若明确如此解释，就不会授权跳过最小非空格。因此发现把该句直接翻译为“下游不兼容就跳到下一格”并非唯一读法，尚无实际执行代码证明这种行为。

不过“合法格”的资格在 F1 未定义，局部语句也没有指明按哪一侧展开。规则原词“非空”换成同时容易承载容量、种类、下游守卫的“合法”，确实形成歧义。给出反差即可定位风险：箱格 1 有甲、格 2 有乙；目标运输格已空且只允许乙时，按 L72 先选格 1，再因甲不符而失败；若先按下游可出筛格，则可能从格 2 成功。这是两算法的条件差异，不宣称该状态已作完整可达性认证。目标格被占导致任何种类都不能进入时，则不能用换格规避，发现将此一并列为跳格收益的例子应收窄。

在没有明确定义“合法＝取货时仅非空”的情况下，不能证明歧义已消除；故依拿不准不否证的口径保留 false。必要修复应保持两侧资格原文，不新增绕过箱头物品的机制。

## 11. S2-r4-L3-04：轮询前件“都”的辖域

**结论：refuted=false，未能否证；发现给出的排除推理不能直接照抄。**

回源：规则 L29 为“一个单位的多个存货端口或多个取货端口都建立了通道时”。选择点 T3 L26–35、参数轴 L28–38、运行语义 L109/L145 都围绕已接通通道集合展开，没有把“全部物理端口接满才适用”与“多个已接通端口即适用”分别登记或说明前者为何排除。覆盖表 L39 的用途也不含此辖域问题。第一轮任务书 §3.A.4 的候选与排除说明要求尚未在这里落实。

普通语法中，“多个……都”可以对所说的多个对象量化，不必等于“该侧全部端口”；这支持草稿的取法。不过支持一种自然读法与已证明排除另一读法不同，草稿没有写出这一层解释。

对发现的正式约束论证，须区分三个命题：

1. 约束·轮询均分（L82）没有要求全部物理端口接满；其适用域是给定 k 条同级取货通道及其余全部前件。
2. 约束·封装进料（L54）允许讨论恰五条存货通道，而规则 L54 给大机六个存货口；这说明“有空口”不是自动无效的结构条件。
3. 但“L29 在该侧不启动轮询”本身不逻辑蕴含“一定存在违反轮询均分的运行”；仍须构造符合其它条款却不均分的具体日程，或证明不轮询与其成功序结论不能共存。且封装例子是存货侧，轮询均分是取货侧，不能省去侧别转换。

因此现成证据不足以完成发现声称的唯一排除，但实际未登记、未解释的辖域缺口仍在。既不能以发现的旁证欠缺证明草稿完整，也不能把本条改判成已经存在错误实现。

## 附录甲：独立供电见证核查

以下代码在仓库根以 Python 标准库、-B 方式实际运行；无文件写入。它逐台核查给定见证，不求最大独立集。数量为候选排布的条件算术，断言通过为工具核验，均不是达标运行实测。

几何取机器闭方块 [x,x+3]×[y,y+3]，桩中心方形 [a−5,a+7]×[b−5,b+7]；占格不重叠用整数格集合检查。positive_area 用两轴交叠长度均严格正，closed_touch 用两轴均非负，因此没有复用待核脚本的覆盖格公式。

```python
from itertools import product

def cells(x, y, width, height):
    return {(i, j) for i in range(x, x + width) for j in range(y, y + height)}

def check_case(name, pole, starts_x, starts_y, rule, expected):
    a, b = pole
    occupied = cells(a, b, 2, 2)
    core = cells(50, 50, 9, 9)
    assert not occupied & core
    occupied |= core
    selected = []
    for x, y in product(starts_x, starts_y):
        footprint = cells(x, y, 3, 3)
        if footprint & cells(a, b, 2, 2):
            continue
        assert all(0 <= i < 70 and 0 <= j < 70 for i, j in footprint)
        assert not footprint & occupied
        dx = min(x + 3, a + 7) - max(x, a - 5)
        dy = min(y + 3, b + 7) - max(y, b - 5)
        assert (dx > 0 and dy > 0) if rule == "positive_area" else (dx >= 0 and dy >= 0)
        occupied |= footprint
        selected.append((x, y))
    assert len(selected) == expected
    print(name, rule, len(selected), "边界/不重叠/连续矩形覆盖/唯一核心：通过")

for rule, start, count in [("positive_area", 23, 5), ("closed_touch", 22, 6)]:
    positions = list(range(start, start + 3 * count, 3))
    check_case("内部", (30, 30), positions, positions, rule, 24 if count == 5 else 32)
    check_case("贴一边", (0, 30), [0, 3, 6], positions, rule, 14 if count == 5 else 16)
    check_case("贴两边", (0, 0), [0, 3, 6], [0, 3, 6], rule, 8)

print("侧旁投影列数 positive_area:", [(g + 9) // 3 for g in range(7)])
print("侧旁投影列数 closed_touch:", [(g + 10) // 3 for g in range(7)])
```

实际输出：

- 内部：positive_area 24、closed_touch 32。
- 贴一边：positive_area 14、closed_touch 16。
- 贴两边：两者均为 8。
- 六项均通过基地边界、占格不重叠、连续矩形覆盖和远处唯一核心检查。
- 侧旁一维列数分别为 [3,3,3,4,4,4,5] 与 [3,3,4,4,4,5,5]。

这里不从六个见证反推所有桩位置的全局最大台数，不证明 32 台有持续制造，也不对侧旁 c_g 的完整端口几何作认证。24／14 子句和“有制造”的 23 台子句不能混用。
