# 循环判等的独立推演（第9轮）

日期：2026-09-19。状态：独立推演存档；本文件形成时尚未阅读《受限转移定义》§6及第五轮规格修订的证明、自查报告。它给出之后逐项比对的基线，不表示对所有参数、初态或读法的认证。

## 1. 依据与所问命题

规则依据为仓库根目录的《明日方舟：终末地》游戏规则.txt、求解任务.txt、求解约束.txt。工程转移依据为《受限转移定义》§1–§5；状态字段依据为《内核输入》§3–§6。第五轮任务书§2.1已决定两级认证与仓库抽象；本推演核查该决定能在什么前件下执行，不重新裁定已定读法。未用候选约束或面积分档推论。

须证明的是带输出的后继一致性：同一布局、设定、参数点和接通环境中，若两个合法闭包状态的键相等，则下一时刻同为停止，或后继键相等，且同一段内逐物种入库量相等。只证明末状态相等而未证明事件物流相同，不足以保存目标平均率。

## 2. 绝对时刻逐字段处理

规则L23只读运输停留时差；L35及配方只读已完成的有效工作量；L36只读传输冷却；L64读从首件起经过的5 tick。任务L14的同刻固定性本身不推出跨时刻固定序，因而以下处理限于§2.2的global模板序。

| 字段或引用 | 独立判定 | 必要前件与后继 |
|---|---|---|
| `environment.time=t` | 不直接入键，作为其余时钟的基准 | 只比较同一整数边界相位；若有日历驱动事件，不能只删t |
| `inventory[].contents[].entered_at=e`，运输格含桥两轴 | 用年龄`t-e`；空格无年龄 | 移动守卫为年龄≥1；未移动时加1，新入格为0。精确年龄足以保真，但不自动给有限键域；阈值饱和另需证明 |
| 非运输库存的`entered_at` | 本版无额外停留守卫，可删或保守保留相对年龄 | 若另一读法启用非运输停留则须保留必要年龄，不可沿用删除规则 |
| `progress.remaining`、`cooldowns[].remaining` | 已是剩余时长，原样保留 | 暂停时保持、运行时递减；不能用预计完成日历时刻代替remaining，因为规则L20要求进度保留 |
| `gate_counters.window_started_at=w` | null保持null，非空变`t-w` | 在5 tick阈值触发维护，关闭窗口置null，下一件重新置年龄0；计数及各阻断原因必须保留 |
| `judgment_context.instant` | 归零 | 比较点固定为after_closure；中途状态还需保存真实扫描游标与seen记忆，不能挪用边界键 |
| `judgment_context.round/next_template/ordered_events/next_event` | 只有在已闭包、下一刻重新扫描且不再被任何活动引用读取时可省略已消费部分 | 它们不都是时刻字段；若恢复in_closure，直接删除会改变首次重复位置和失败轮询后效 |
| `tick_context.window_start/window_end` | 相对`t`的两个偏移 | 闭包后的本刻额度下一边界重置；若省略必须明确只对已闭包比较，且没有跨边界依赖 |
| `tick_context.movements/internal_passages`里的event和batch | 已消费纯审计可不入键；活动引用必须保留关联 | 字符串中含t不是删除整条记录的理由；不能漏掉未消费依赖 |
| `pending_events[].trigger=at_time(d)` | 活动截止用`d-t` | 时间推进后余量减1；制造预计时刻若仅审计，则守卫仍以remaining为准。外部有限历史截止另见下项 |
| `pending_events[].event/predecessors/after_event` | 对活动事件图作一致重命名 | 保留operation、target、trigger、status、先后关系及同一事件的共享身份；不可只把字符串中的数字抹掉造成不同事件合并 |
| 显式矿石历史`events[].time`及`through` | 不能在固定输入历史下任意移除或反复循环使用 | 余下整个事件日程和有限终止边界是可观察环境；用sufficient并排除外部后继事件才可免除此状态 |
| per_instant排序的`origin/instant`及函数中的时刻常量 | 一般不能删除 | 周期函数至少要保留相位；任意非周期函数无可靠周期归一保证。本版global排除它们 |
| 建成/接通/重建/恢复历史中的时刻 | 本段只保留能导出排序的全预序、并列及固定仲裁；不必保留距当前时刻的年龄 | 规则L28–L32只比较接通先后；§3.4恢复沿用原建造记录。若改为按恢复时刻重排或有离线则须重审 |
| `settings_anchor/layout_snapshot`和构造/调试事件id | 固定上下文保留引用及其解释，不对每个已过去事件计年龄 | 当前设定、几何、桥方向不可删除；同键比较限相同上下文 |
| `withdrawal_memory`中的已执行及待响应事件 | 无拿取运行段为空；在真实拿取环境下不能擅自清除策略记忆 | 级二投影一致性可对每个已给外部日程作条件归纳，不能据此把策略改成即时补空机制 |
| 输出日志时间、完成审计身份、历史累计统计 | 不参与物理守卫者可排除，证据记录仍保存 | 不能将累计交付差直接用作忽略拿取后的仓库库存差 |

非时刻状态仍须保留：全部非仓库物种与数量、制造阶段及锁配方、箱体冷却、门累计与窗口计数/原因、实际边、轮询各级成员/续接位置/当前级、分级与阻尼表、输入仲裁及各参数。它们均可进入下一次物理判断或调度。

## 3. 两矿存量被抽象后尚存的读点

1. §4.1核心及仓库取货口先按指派格找物种与数量；§3.1据此判物理可动。sufficient使每矿唯一正库存格在出矿事务中扣1补1，因此这里数量仅经“至少1”被读，身份及指派仍须保存。规则L13/L41限定单格及容量，任务L7只授权供应充足。
2. §4.1对任何PC回矿入库检查`q+1≤80000`；§4.3对整箱矿物汇总检查`q+b≤80000`。这两处直接读取q，即使实际拒收、从未成功回矿，也会改变运输源是否清空、箱冷却/库存及后续轮询。因此“实际矿入库账为0”不足以证明独立。
3. 反例算术：同一运输源有一件蓝铁矿，目标核心格分别有79999和80000；源已滞留、额度未用。忽略矿量后的生产键相同，前者可收、后者不可收。若箱含两件矿，79998与79999同样给出成功/失败。必须在容量读发生之前统一停止，或在进入抽象前静态排除所有回矿路径；不得先以矿容量算授权再检查。
4. 正式约束“矿系不入库”说明达标循环的必要后果，不能直接把尚未证明达标的候选轨迹中所有回矿尝试删除。停止是本版覆盖界限，不能作为轨迹合法性的反证。

## 4. 两成品存量、标签与空格序

### 4.1 数量与容量

核心PC每次入库一件，但整箱传输按物种总量b原子检查，规则L41容量固定80000。因此“q<80000”只保证下一件可收，不保证整箱b可收。若q=79999、b=2，批量拒收且q仍<80000；玩家拿取0件也不改变这一事实。故对满足“库存始终未满”的所有日程直接归纳生产轨迹一致，必须另给可观察接收域或逐批容量余量条件。平均0.6不限制单个时刻的入库突发量，也不能保证某个拿取间隔不会碰边界。

### 4.2 取空后的标签传播

retain_history读法中，清空将item转到empty_identity，不重新进入匿名空格序O；同种下一次入库仍落原格。因此不会因取空本身改变O。其他读法若释放身份，将该格重新并入O，其顺序会影响以后新物种落在哪个格。

有端口指派的格不能任意改名或删除：规则L41/L73的取货读取指定格，标签重分配可以改变输出物种，继而改变准入口身份阻断、通道图、阻尼、轮询和制造。即使当前该格为空，只要之后能被新物种占用就可能可观察。无指派的匿名格则可通过一致置换解释；其空格序、引用与新格标签都须同时对应，不能只排序仓库数组。

足够的隔离条件是全部取货指派只指向两矿的永久格，成品和匿名格均无指派；保留其它物种的真实库存与容量，并按物种表示其无指派格身份。在该域中，成品标签及消耗匿名格导致的序变化不能被物流取货读到。但仍须逐次保证其它物种的单格和容量守卫相同，并处理规范新标签碰撞等编码拒收；不能让重命名把非法编码变成合法编码而宣称相同后继。

### 4.3 接收域与级二范围

任务L2“仓库同时可以接受两成品”与L8拿取例外不直接给出每批必收。对F中任一日程的证明须明确“可接受”是逐件余量还是整批可收，并保证该条件在整段真实运行中成立。加强为每次尝试前每个物种q+b≤80000可支持条件归纳，但这是更小日程族，不能冒称已覆盖原F。原F证明失败时，级一只能自称生产部分周期。

## 5. 后继与平均率的独立证明骨架

比较同参数闭包锚点，先核上述环境和仓库隔离前件。边界中的remaining、冷却、门年龄按相同相对量更新；完成只转换同一批原料；窗口批事务删除相同原因并产生同一图。按同一模板序归纳：源货、目标容量、年龄及门守卫相同，授权相同，成功/失败相同，轮询后效相同，制造与传输的整批数量相同。若任何尝试触及被删除的矿量或未经保证的成品容量，应在读取前同停，不继续归纳。

于是每轮物理状态及轮询投影保持对应，同刻首次重复位置一致，后继键相等。保留每次核心PC入库及箱无线入库的物种/件数，得到周期内入库向量D相同；周期长度P未变，平均率D/P相同。日志时刻和格标签可重命名，真实入库量不能以代表仓库存量差替代。

这一骨架只证明固定支持域的转移和奖励保持；没有证明每条轨迹可从蓝图及不精确定时调试到达，没有证明非周期轨迹不存在，没有证明所有种子、参数和相遇读法都达标，也没有给出仓库字面完整状态周期。
