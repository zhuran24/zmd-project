# 第8轮规格修订论证

日期：2026-09-19。范围：第五轮任务书的S线第8轮修订。三条存活发现均已修复，KQ-07、KQ-08已有规格答复；本文不证明K线实现完成或正式目标达成。当前配置为`round5-specification-r8`，99轴的字段集合、处置类别和实际值保持，新增的是准入说明与接口澄清。

## 1. 整箱新物种停止前件

S5-r8-L1-01和S5-r8-L2-01指向同一缺陷：接口答复省掉了取货端口指派前件。正式规则L13要求每种单格，L41/L73规定取货访问指派格；任务L8及受限转移§1的无改指派/拿取/离线运行段，使未指派标签不能被取货观察。第四轮任务书§1和§3.3据此明确收窄停止条件。现行[受限转移定义](../受限转移定义.md)§4.3的两分支已给出这一范围，不需要重定规则。

令U为本批无非空同种格、也无该种历史身份空格的物种集合，E为已声明的无身份空格集合，O为E的当前严格全序，A为当前`warehouse_assignments[].slot`集合。竞争停止的充要触发是`|U|≥2`且`E∩A≠∅`，与E自身是否非空不能混淆。停止保留判前库存、身份、O、交付账与冷却，不作为容量拒收或游戏后继。

反例取两成品各1件，E=O=[W_empty]，A只含两个矿格。虽有两个新物种及一个空格，交集为空，不能停止。物种UTF-8升序中胶囊先配W_empty，电池使用`W_new_`加物种UTF-8小写十六进制标签。两目标互异，每种1件满足80000容量，成功后O=[]。此前件还要求箱有电、开关开、冷却0、标签无冲突及输入身份/O合法。它是局部事务反例，不是已证可达的完整布局或周期。

给W_empty加取货指派后，交集非空，同批必须停止；仅一个新物种时即使E有指派也不触发这条竞争停止，仍按其它守卫继续规划。E为空时各新物种创建规范标签。脚本从转移与答复提取现行谓词，枚举新物种数0–3、空格数0–3及空格指派子集，共60组，与独立的可观察性判据逐项比较；结果见[停止条件复算](停止条件复算.json)。该有限枚举不证明一般标签对称性，后者仍使用转移§4.3的条件归纳。

同步落点包括[接口答复](../参数轴-对内核输入请求的答复.md)当前接口、[规则覆盖表](../规则覆盖表.md)规则L36、[四件义务](../四件前置义务对照.md)§2和[选择点清单](../选择点清单.md)T12。[修订记录](../修订记录.md)旧第6轮宽条件及第五轮全文核对结论已标明此次纠正。级一生产抽象仍要求D.3的O为空；它不能缩小上述普通有限运行范围。

## 2. 验证范围字段

S5-r8-L2-02涉及接口拼写。[内核输出](../内核输出.md)§1、§3及封闭schema的RunRecord均使用`validation_scope`。接口答复已使用该名，未为旧拼写增加兼容别名，也没有放宽必填或未知键拒收。

AJV2020试样使用最小invalid_input记录，只核结构，不冒称真实运行或来源迁移。保留现行字段的试样通过；仅改为旧拼写的副本失败，错误同时指出缺少现行必填字段及出现未知字段。详见[字段名复算](字段名复算.json)。原第五轮183项检查另保留完整/增量结构、循环结果和15输入轴的正负例。

## 3. KQ-07：种子不是运行史反演

规则L29–32允许轮询位置由成功/失败及级切换历史改变；独立级仲裁只在正式排序键相等时起作用，不能由接通并列序或标签排序唯一推定。库存和图相同不足以重建这两个量。

[内核输入](../内核输入.md)§6.4沿用`arbitration.level_order`作为显式全序入口，调用方可以选择或枚举具体序；缺失、重复及额外标签拒收，不新增状态字段或物理轴。新调度起点的before_boundary可派生起轮和冗余上下文，但合成起点仍须标可达性未证；有历史的边界恢复必须保留或重放真实记忆。after_closure检查点保留游标、参数、账和事件，冲突拒收，不重起轮；下一刻为t+1。

这确认KQ-07的不可唯一反演判断，同时限定“派生before_boundary”的适用范围。K线仍须按[修改请求](../对内核的修改请求.md)验证种子往返、两个显式仲裁序、缺/重复仲裁及检查点记忆不重置；本席没有把字段定位自查当这些运行测试。

## 4. KQ-08：回矿失败也是容量观察

两代表矿量分别为79999和80000，均满足取矿充分。若核心PC或有资格箱请求回仓1件矿，前者容量通过，后者失败且成功入库账为0。因此“本代表无成功回矿”不能推出矿量只经非空被读取；容量比较已经可能改变physical集合、最高可动级、授权和后继。

[受限转移定义](../受限转移定义.md)§6.1 D.2使用矿容量读取前的候选检查：对现存PC先按源选择器识别矿候选指向核心，在容量、其它physical筛选、级排序和授权前停止；对有资格箱，在汇总全箱后、容量规划前识别含矿并停止。候选检查依赖键保留的图、物种、箱内容、资格，独立于被抽象矿量，故相等键对这项检查同步通过或同步停止。停止不是抽象后继，不能纳入循环。

通过检查后，不会读取被删除的矿容量；非矿容量保留，成品容量由D.5与代表化保证，所以§6.3物理、权限与传输的归纳前提成立。对周期内每个访问和独立重跑都核该动态前件，才能将一个周期的结果延续；端点检查不够。规范选择较保守：即使矿PC此刻年龄、预算或权限不足，也不先借这些条件跳过候选。

约束·矿系不入库只限制成功入库，不能单独证明这个更强准入。普通finite_concrete仍按真实容量处理候选，不新增游戏规则。声明/配置、轴表、输入投影、运行语义、输出§5.3和K线请求已同步；[回矿容量复算](回矿容量复算.json)只核上述局部算术，代码是否在正确调用位置执行须由K线重验。
