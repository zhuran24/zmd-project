# 运行语义

日期：2026-09-30。状态：r30 整数步内核的现行规格；固定输入的有限执行与诊断周期已实现，完整基地周期和全称覆盖仍须证明。

时间为整数步：1 步 = 1/8 tick。每步先结束到时制造，再按先后逐个判定，最后开始制造。任务行号为拿取9、循环10、建造11、调试12、精度13、离线14、仓库取货口位置15。

## 2. 完整状态与静态目录

### 2.1 步边界状态

状态直接按 [内核输入](内核输入.md) §6 编码，无独立状态 schema 字段。`environment.time=s` 表示已完成第 s−1 步，下一次执行第 s 步。玩家操作只发生在两步之间；本版遇到要回放的操作即停。

| 字段 | 当前内容及边界 |
|---|---|
| `layout_snapshot`、`settings_anchor` | 布局快照与设定锚点；几何、设定由输入承接 |
| `warehouse` | `slots`、`unlisted`；每格物种、数量和空格历史身份；同种唯一仓格，每格上限 80000 |
| `inventory[]` | `slot` 与 `contents[]`；每项含物种、件数、`entered_at`、可选 `last_unit`；运输格有步时刻，非运输格时刻必须为 null，同物种合并 |
| `progress[]` | `unit/phase/recipe/remaining/cooldown`；制造为 idle、working、completed；仅 working 有 1…8d 剩余步；箱为 idle 且冷却 0…40 |
| `logistics.poll_state` | poll-state-v1，循环侧 `cursors[{side,last_success}]`、非运输送货侧 `recency[{unit,order}]` |
| `logistics.gate_counters[]` | 单位、累计件数、窗口件数、窗口起点；未开窗口起点 null、计数 0 |
| `environment` | `time` 是下一步；stage、online、withdrawal_memory 记录环境边界 |
| `semantic_context` | `warehouse_empty_slot_order`：当前尚未占用且身份未定的仓格顺序 |

运输件要求 entered_at≤time；只在桥轴格允许 last_unit。working 缓存恰为一批原料、completed 恰为一批产物、idle 缓存空。轮询侧集合恰等于几何元件导出的多通道侧，不能缺侧或多侧。窗口若起点为 w，边界需 w≤time<w+40。非运输普通格单种、同单位同种单格，箱体、缓存和桥接器按规则例外。

## 3. 参数与接通历史

机器可读注册表仅为 [内核配置-v2.json](内核配置-v2.json)：66 轴，已定21、本版选值14、输入全称量化15、超出覆盖即停16。说明表见[选择点参数轴](选择点参数轴.md)。F 放 fixed，O 放 offline_mutable，U 放 fixedness_unproven；本次运行固定所有具体参数不证明其在全部运行中的生命周期。

### 3.1 派生图与先后

元件身份须唯一；若纯带环与桥轴的身份格式碰撞，装载拒绝该命名并要求换用不冲突的单位 id，不能将两个元件合并。

接通时刻取两端较晚建成时刻，同时刻用 connection.tie 的通道全序；同一步内不同建成引起的通道必须与 construction.selected_order 的建成次序一致，违反则 invalid_input(connection.tie)；只有同一次建成引起的通道可由 connection.tie 自由排序。元件、层数、收货组、完整判定次序在装载时由整图及 step.order 派生。准入口只改变收货资格，图及接通序不变。离线可能改接通先后，继而改变判定先后、轮询及层数选支；本版不实现其接续，遇事件即停。显式输入取值域详见[内核输入](内核输入.md) §5。


### 3.2 元件

- 元件是一个分流器、汇流器、物品准入口，桥接器的一对平行边（竖轴、横轴各一个），或一段连续的传送带（L29）。
- 一段连续的传送带 = 沿「传送带→传送带」通道首尾相接的最长一串。每条传送带只有一个存货边和一个取货边，所以一串要么是链（有入口带和头带），要么是纯带环（没有头带）。链的外部来货只进入口带，外部送货只从头带出，结构上自动成立，装载时断言。
- 元件身份（字符串，用于输入、状态、记录）：
  - 分流器、汇流器、物品准入口：`C|<单位id>`；
  - 桥接器一轴：`C|<单位id>|vertical` 或 `C|<单位id>|horizontal`；
  - 传送带链：`C|<头带单位id>`；纯带环：`C|ring|<环中字典序最小的单位id>`。
  单位 id 只含字母数字下划线（`Geometry::build` 已核），不会与 `|` 冲突。
- 非运输单位 = 协议核心、制造单位、协议储存箱、仓库取货口。供电桩没有端口、不做任何事，不进先后。

### 3.3 层数

- 元件 C 的候选 D(C) = 经 C 的送货通道送往的元件中，自身至少有一条送货通道的那些（L28「还往下送货的元件」按结构读：有送货通道就算，不看此刻能否送出；与 sim2 相同）。非运输单位不算。
- |D(C)| = 0：层数 1。|D(C)| = 1：层数 = 该元件层数 + 1。|D(C)| ≥ 2：按哪一个数「随接通先后而定，无法确定」，由输入 `step.order.layer_choices` 给出（每个这样的元件恰一条）。不只分流器会有多个候选：桥接器一轴两边都能送时也会有，按同一条处理。
- 选定后每个元件至多一条「数层边」C→choice(C)，构成函数图。图上有环时「成环数不出来，无法确定」，由输入 `step.order.cycle_layers` 给环上元件指定层数（正整数）：每个环至少给一个，只能给在环上的元件（包括因选支而在环上的）；被给定的元件用给定值，不再沿边数。缺选支或环缺给定值 → `unresolved`（轴 `step.order`）；给多了、给错位置、候选不在 D(C) → `invalid_input`。
- 相邻两个桥接器同一轴互为送货（两条相反的通道），它们常互为候选；布局工具按显式代表规则填选支，填出环时再给环上层数。
- 层数和先后都在装载时从整张几何图算一次。运行中通道不变（准入口只拒收，§4.10；离线、调试触及时停止），所以整段运行固定。

### 3.4 先后

- 每步先判定全部元件，再判定非运输单位（L27）。
- 元件按（层数，送货通道中最早接通者的接通序位）从小到大。接通序位：先按接通时刻（步），同时刻按 `connection.tie` 给的通道全序；于是任意两条通道序位不同，不同元件不会并列。传送带链的送货通道只算头带的外部送货通道，带与带之间的通道不算（它们不是把物品送出元件）。
- 没有送货通道的元件层数为 1，判定什么也不做，也不属于任何收货组（它不往任何单位送货），它的位置不可观察；统一排在层 1 的末尾，按元件身份字典序。
- 非运输单位的次序由输入 `step.order.nontransport_order` 给全排列（全部非运输单位，不含供电桩），内核核：其中有送货通道的那些单位，相对次序必须等于按「最早送货通道序位」的次序（L27）；没有送货通道的单位，条文不给位置，按输入放在任何位置都合法。它们的判定只可能有协议储存箱的传输是可观察的。

## 4. 一步内的运行语义

### 4.1 步与状态时刻

- 1 步 = 1/8 tick（L25）。内核时间一律用整数步。配方时长 d tick = 8d 步；滞留 1 tick = 8 步（L23）；传输冷却 5 tick = 40 步（L37）；物品准入口窗口 5 tick = 40 步（L65）。这些数从目录读（§2.2），不写死。
- 状态只在两步之间存在。`environment.time = s` 表示「第 s−1 步已算完、下一步是第 s 步」。玩家操作、外部补给、建成都记在步与步之间（L25「玩家的操作都在两步之间」）。每个状态都是步边界，只支持在步边界恢复。
- 第 s 步依次做（L25、L36）：
  1. 边界：外部停止检查；生产抽象时成品归零代表；显式补矿事件（时刻为 s 的）入库；有电且开传输的协议储存箱冷却减 1（下限 0）。
  2. 结束到时的制造：有电且开制造、在制的机器剩余减 1，减到 0 的结束，产物进缓存格；之后对所有「完成待出」的机器试一次整批入取货物品格。
  3. 所有传送带段按 §4.7 前挪。
  4. 按先后逐个判定（§3.4、§4.4—§4.6）。
  5. 开始能开始的制造（§4.8）。
  6. 收尾：准入口窗口到期的清零（§4.10）；`time = s+1`。
- 由此：开工在第 s 步末、剩余 8d，第 s+8d 步开头结束。协议储存箱在第 s 步传输后冷却 40，第 s+40 步再次可传。

### 4.2 轮询

- 「一侧」按存货侧／取货侧分，桥接器每轴各有两侧。只有一条通道的侧没有轮询状态。
- 循环侧（全部元件的两侧、非运输单位的存货侧）：通道按接通序位排成环，从「上次成功」那条的下一条开始依次尝试；从未成功时，分流器送货侧、汇流器收货侧从第二条接通的开始（L32），其余从第一条开始（`polling.initial_cursor=first_connected`，本版选值：条文「从上次成功的下一条开始」在没有上次时的最简读法）。状态只存 `last_success`（通道 id 或 null）。
- 非运输单位的送货侧：先按取货优先级分级（§4.6），同一级里先试「上次成功最早的」，从未成功的按接通序位排在最前（L32）。状态存「按上次成功时刻从早到晚排列的已成功通道表」`recency`，成功一次就把该通道移到表尾；不在表里的是从未成功的。这张表不含绝对时刻，便于周期判等。
- 何时更新：只在一次移动成功时更新，失败不动。一次成功同时更新送出方的送货侧（循环侧改 `last_success`，非运输送货侧改 `recency`）和收货方的收货侧（改 `last_success`）。分流器自己送进某单位的那一件，也算该单位收货侧的一次成功（「上次成功」按侧计，不分由谁发起；与 sim2 相同）。
- 旧语义「尝试后立刻传给下一条」「失败也前移」「双端授权」「按级记忆与回级续接」全部删除。

正式轮询均分须同时核同级k条、每件可走任一条、首格独占且收后恰1 tick腾空、恰隔1 tick成组、全空首格及相邻组件数和≤k等全部前件；不得以平均间隔替代实际组间隔。分流器直连汇流器且另一支有量时，约束·密集结点要求核先后影响，不能无条件按端口数均分。

### 4.3 运输速率与条件必要性

内核没有独立的每 tick 每端口次数守卫。约束「端口速率」由滞留8步和运输格上限1推出，运行中不另加计数预算；以下假设H按每tick计，与现行每步至多外送一件不同。

设 H 为“每个单位的每一存货侧或取货侧每 tick 合计至多成功移动一件”。H 与存在达标布局不相容，且不需要任何制造台数前件。协议核心六个取货端口虽在两条物理边上，按规则 32 的端口类型同属该单位取货侧；汇流器跨三条物理边仍从第二通道起轮，也排除了按几何边拆“侧”的理解。任一达标循环由取货口配置要求核心六口全部满速，即该侧每 tick 成功 6 次，与 H 的上限 1 矛盾。等价的总量核验为仓库每 tick 至多 46+1=47 件，低于矿石需求 52 件。数字为条文直引及算术推论。（据：轮询、汇流器、协议核心、约束·取货口配置、约束·出库上限、约束·矿石需求、约束·端口速率）

因此 **H 成立则全题无达标解；在达标布局论域内 H 已排除**。这是按H对正式必要条件作出的条件论证，不使用“题目必有解”的公理。H不是现行参数轴，当前规则每步只判定一次不会推出每tick同侧至多一件；每tick有8步。不新增“所有执行必进入循环”的命题。（据：目标、循环态、约束·取货口配置；条件推论）

独立的制造占地核验：在 H 下，以物料流量和配方计算各机型每 tick 必需输入件数，下表取上整得到台数下界，再乘单位占地；未用机型恰等于原下限的前件。（据：约束·物料流量、配方、小制造单位、中制造单位、大制造单位；算术推论）

| 机型 | 输入件/tick | H 下台数至少 | 占地至少 |
|---|---:|---:|---:|
| 粉碎机 | 18+34+5.5+10.5=68 | 68 | 612 |
| 精炼炉 | 34+17=51 | 51 | 459 |
| 研磨机 | 3×(17+9+5.5)=94.5 | 95 | 2280 |
| 塑形机 | 2×5.5=11 | 11 | 99 |
| 配件机 | 6 | 6 | 54 |
| 种植机 | 11+21=32 | 32 | 800 |
| 采种机 | 5.5+10.5=16 | 16 | 400 |

输入合计 304.5 件/tick，加成品 1.15 为 305.65，与正式总流量核对一致。占地合计 5328>70×70=4900，尚未计核心、取货口与供电，也已矛盾。这仍是 H 下的无达标解证明，不是实际机型下界的新无条件替代。（据：基地、约束·物料流量；算术推论）

更窄的条件计算同样成立：达标且恰 3 台封装机时，每台平均输入 25/5=5 件/tick；达标且恰 16 台采种机时，每台每 tick 产 2 件，输出侧仅出 1 件不能周期配平，有限初存及取货格容量 50 不能消除长期差额。这些台数前件可为空，但不影响上述不带台数前件的核心与占地证明。（据：约束·满载配置、约束·封装进料、配方、存货/取货物品格、循环态；条件算术推论）

回路存量的观察取每步判定完成后的边界；每tick条件量按8步换算。

### 4.4 判定

每个元件、每个非运输单位每步只判定一次（L26），一次判定至多送出一件。判定前先看是否已被收货组带动判定过，判定过的跳过。

- 分流器：若自身物品已停满 8 步，按自己送货侧的轮询依次试各条送货通道，第一条送成功即止；都不成就不送。分流器不参加任何收货组（L31「非分流器」），即使只接一个出口也一样。
- 非分流器元件（传送带链、汇流器、物品准入口、桥接器一轴）：它的判定就是触发收货组（§4.5）。
- 非运输单位：见 §4.6。
- 被送物品要「放得下、种类合规」：运输格空（上限 1）；制造单位、协议储存箱、协议核心按选格与容量守卫（`Engine::target`、仓库计划）；物品准入口另按 §4.10；桥接器一轴不收刚从该单位来的物品（L24「不会移回刚离开的单位」）。

### 4.5 收货组

- 收货方 R：一个非运输单位，或一个元件。桥接器按轴分收货方（L64「两对平行边互不相干」，而元件已按轴拆分；把两轴并成一个收货方会让互不相干的两条线相互带动）。
- 组 G(R) = 以送货通道接入 R 的全部非分流器元件。
- 某非分流器元件 C 轮到判定且未判定时：以 C 为起点求「一起判定的闭包」：C 所在的每个组都触发；新拉进来的成员若还属于别的组，那些组也触发（它此刻被判定，就是那些组里最先判定的一个，L31 字面）。闭包只在一个元件有两条以上送货通道时才会扩展，现有元件里只有桥接器一轴可能如此。闭包内全部成员立即标记为本步已判定。
- 执行：按收货方被发现的次序（从 C 起，按成员自己送货侧轮询次序逐条看其送往的收货方，广度优先）逐个办理。每个收货方按自己收货侧的轮询次序，逐条看来自闭包成员的存货通道：该成员有停满 8 步的头件、该物品可去往 R、R 放得下，就移过去。一直试到这个收货方的成员通道都试过为止（「收满为止」对上限 1 的运输收货方就是只进一件）。一个成员成功送出后本步不可再次送出；带链随后跟上的头件也受本步已判定限制。
- 没送出的成员本步也不再判定（L31）。

### 4.6 非运输单位的判定与取货优先级

- 候选物品：制造单位取取货物品格的物品；协议储存箱取编号最小的非空物品格的头一件，这件去不了就不送，不跳到后面的格（L73）；协议核心与仓库取货口每条送货通道的物品是其端口所连仓库格的物品。
- 送货次序：取货优先级把送货通道分级——直接接汇流器的通道各自一级，其余合为一级；一级的层数取其中各通道所通元件的最大层数，接通序位取其中最早的；（层数，序位）小的级先试（L33）。级内按 §4.2 的 `recency` 次序。依次试，第一条成功即止。
- 协议储存箱：有电且开传输、冷却为 0 时，在它的判定里传输；在送货之前还是之后由输入 `transfer.timing` 按箱给出（L37「与它的送货先后无法确定」）。传输按「能送多少送多少」（`transfer.partial_acceptance=max_receivable`），每次尝试后冷却 40（空箱、全拒收也一样，`transfer.failure_cooldown=every_attempt`）。
- 顺带的结构事实：非运输单位只从元件收货（通道至少一端是运输单位），全部收货都发生在元件判定阶段，都早于非运输单位的判定，所以协议储存箱同一步先收后送、制造单位同一步收下的原料可在本步末开工，都是条文推出。

### 4.7 传送带段内前挪

- 条文：物品一直在尝试移动；只有「送出一个元件」要等判定（L24、L26）。所以一段链里，某格物品已停满 8 步、前一格空，就挪进前一格，入格时刻记为当步，不等判定，也不算判定。
- 实现：`settle(段)` 从头带前一格往入口方向逐格检查（头在前），能挪就挪；刚挪过的物品当步入格，不会再挪。这样头件送走后，后面停满的物品在同一步里依次跟上。纯带环取最小不动点：从每个空格往回走，前一格已停满就挪进来，直到遇到未停满的物品或另一个空格；满环不动。
- 调用时机：每步第 3 阶段对所有段各一次；此后每当一段的头件被送走或入口格收进物品，立即对该段再 `settle` 一次；链式共同构型的差分范围见[差分记录](../内核维护/2026-09-30-步进规则同步/差分.md)。

### 4.8 制造

- 三阶段（L25、L36）：
  - 结束：第 2 阶段。剩余减到 0 的，缓存格里的在制原料换成配方产物，阶段记 `completed`。
  - 进取货物品格：缓存格里做好的一批，取货物品格放得下（同种或空、合计不超过 50、且单位内其他普通格没有这种物品，L13）就整批进入，随时发生（L18）；阶段回 `idle`。触发点：结束之后、每步第 2 阶段末对所有 `completed` 的机器、以及每次从该机器取货物品格取走一件之后。
  - 开工：第 5 阶段。条件为有电且开制造、阶段 `idle`（即上一批已全部进入取货物品格）、存货物品格里的物品符合某个配方（按 manufacturing 的 recipe_match_scope、recipe_completeness、recipe_quantity_match、recipe_extra_items、recipe_selection、input_slot_selection 各轴取值）。开工时一次用量从存货物品格进缓存格，阶段 `working`、剩余 8d。机器之间互不影响，按单位 id 顺序办理。
- 存货物品格通往缓存格的闸只在开工时打开（L18），制造需电（L36），所以停电或关开关的机器既不收料进缓存、也不开工；不设置停用时预收缓存原料的阶段。进行中的制造在不运行时剩余不减、恢复后继续（L20）。
- 阶段只有 `idle`、`working`、`completed`；`completed` 时剩余为 null。

### 4.9 协议储存箱的格与传输

收货放进编号最小的能放它的格，送货从编号最小的非空格取（L73）；传输按仓库可收余量逐物种尽量送（部分接收时跨编号格残留的分配仍 `unsupported`）；冷却在有电且开传输时每步减 1（`transfer.pause=pause_with_function`）。

### 4.10 物品准入口

- 阻断 ⇔ 设了放行物品而来件不是它，或累计收下已达上限，或当前窗口已达上限（L65）。阻断时不收货，仅此而已：通道不断开，层数、先后、收货组、轮询都不变。计数和窗口起点已经足够判断当前准入资格。
- 计数：收下一件时累计加 1；若窗口未开，窗口从本步起算、窗口计数 1，否则窗口计数加 1。窗口起点 w 覆盖第 w 到 w+39 步；每步收尾时，若 `w + 40 ≤ s+1` 就清空窗口（起点 null、计数 0），使边界状态唯一。累计从建成起计（`gate.counter_start=since_build`）不变。
- 「身份不符」就是对当前来件判定放不下。

### 4.11 仓库、补给、玩家操作

- 仓库身份、空格序、容量 80000、`sufficient` 模式出矿即原子回补并记账、`explicit_ore_history` 的最后一件矿检查均按当前状态核验。显式补矿事件时刻用步，在第 1 阶段入库。
- 离线、玩家拿取、调试动作、拆建：在触及时 `unsupported` 停止（对应停止轴不变）。具体为：时间线上时刻为 e 的这些事件，以及时刻 e 大于种子时刻的建成事件，在第 e 步开始前停止；时刻不大于种子时刻的建成与接通是已发生的历史，由种子承接。

### 4.12 不移回刚离开的单位

两个单位之间的一对相对端口只能形成一个方向的通道，除非两端都是双向端口，也就是两边都是桥接器；所以只有物品从一个桥接器进入另一个桥接器后才可能有回头的通道。仍只给桥接器轴格里的物品记 `last_unit`，其他运输格不记。桥接器一轴送货时跳过通往 `last_unit` 的通道。

## 5. 起动、环境与循环验收

任务初始仓库的六种矿石/植物/种子为满，其余为空；任务初始锚点与执行种子是不同对象。建造须有完整历史，非带先于带，种子承接不晚于自身时刻的已发生事件；本版不回放未来建成或玩家操作。调试允许清理、手工放料、拆建与改设定，但不得把“只能在步间操作”解释为玩家能精确选步。

默认起法的关闭机器、填满带和存货格、上游逐批准备及末级最后开启，是需要物品收支和后置状态证明的程序。关闭时不进缓存、不制造；每个条件种子须另证如何到达。本版只核输入引用与合法状态，不给起动可达性证明。

普通模式保留真实仓库；显式补矿使用步时刻及 through 覆盖界，取走最后一件矿被拒。sufficient 模式出矿即原子回补并记台账。周期模式另用生产抽象：目标前提为仓库收得下成品，成品代表清零另记调整量；它不是实际玩家拿取。每物种满足 ΔW=外部补给+核心入库+无线入库−端口出库−玩家拿取+代表调整。

生产周期接口及 D.1—D.5 见[受限转移定义](受限转移定义.md) §6，结果为 diagnostic_cycle。完整基地周期须复原真实仓库和外部过程；全称认证还须覆盖全部调试后起点、合法参数与离线恢复。离线切换发生在过渡段时的状态不能被只枚举固定次序终态循环替代。

## 6. 正式约束的使用边界

对荞花、砂叶分别记一个周期的采种、粉碎植株、种植批次为 `seed_batches`、`crush_batches`、`grow_batches`，植株/种子入库数为 `plant_in`、`seed_in`。条文周期等式为 `seed_batches = crush_batches + plant_in + seed_in`、`grow_batches = 2 * seed_batches - seed_in`；植物零入库由约束·非成品零入库对任意台数给出。种植机恰 32 台时，荞花采种/种植率为 5.5/11、砂叶为 10.5/21。（据：约束·非成品零入库、约束·回路守恒；条文直引）

正式逐 tick 式的计数域为“仓库外（含缓存格）”：种子加植株存量变化＝采种完成批次−粉碎植株完成批次−两类入库件数。仓库属于基地但不属于此计数域，入库减少域内库存；域内搬运不改变总数。制造原料进入在制阶段时须按同一物料核算口径跟踪，不能让暂时退出普通格的在制用量被漏计；完成批次按正式式记录净变化。该式在正式条款适用的运行论域使用，不覆盖调试外取/外注入而不另列其收支。实际观察边界为 §4 定义的步边界。（据：约束·回路守恒、仓库、缓存格、制造、配方；域内移动收支为算术推论）

传输箱周期收支为进箱件数等于无线入库件数加取货端口外送件数；它和箱内至多 18 件的条件式界分别核验，不能将无线入库与普通取货混记为同一个端口事件。（据：约束·传输箱不满、传输、协议储存箱）


## 7. 条件设计律、连续制造与共同状态

非运输输出按所有实际通道分级，单级时无需层数的级间比较，直接对端全非汇流器是充分结构条件；它不消去元件的全局先后。没有分流器直连汇流器只排除约束·密集结点指定的构型，仍须核共享收货、轮询与服务。每项应列单位、全部通道、对端、级分组与实际几何；缺几何实例不能报通过。

末端箱同时满足只收成品、无取货外送、有电、开传输、仓库全收时，才应用约束·传输箱不满的循环容量结论；到达该域的过渡另证。

continuous_required_types 按约束·满载配置及实际台数产生，仅含恰下限的粉碎、精炼、配件、种植、采种、封装。真实周期逐台核工作步数和批次；研磨、塑形、灌装按实际交付及供排服务核。

以连续制造代替目标比较的 D 域须含：完整合法周期、全矿取货、仓库收得下成品、非成品零入库、普通库存和正常批次复原，六类台数为 68/51/6/32/16/3，且仅用规则 L82—115 配方。域内电池率 b=3/5，植物平衡 16=25b/3+20c 给胶囊率 c=11/20，均以件/tick 计；其他台数组合另证反向充分性。A=1113 的台数及无箱条件按正式约束核，尚未认证候选的 r=0 要由实际路由或完整收支给出。

共同状态路线须实例化安全集合 S，证明起态包含与正常、离线、恢复保持；每成品给有限 V_i，使 d_i−ρ_i·Δs/8≥V_i(s′)−V_i(s)，其中 Δs 为步数、ρ_i 为件/tick。沿周期相加得到目标。周期键路线还须证明后继、耗时、覆盖与有限表示；两条路线的未完成义务分别登记。
