## 2. 发现

### KR-r1-L2-01：空补矿史在矿石耗尽后仍被当作有效有限运行

- **严重程度：阻断。**
- **位置：**`/home/zhuran24/zmd-research-fresh/求解器/crates/kernel/src/transition.rs:267–278`（`check_external_stops`）；`src/interfaces.rs` 的 `check_input_axes` 外部历史检查；`src/engine.rs:737–752`（仓库源选择）；`src/tests.rs` 的 `ore_history_horizon_stop`、`warehouse_80000_and_recipe_conservation`。
- **一句话论断：**内核只检查显式补矿史的时间上界，未拒绝运行段内不再持续充分的矿石供应，因而把矿石耗尽造成的停料轨迹输出为 `completed`。

**规范依据。**《求解任务》L7：“仓库中的源矿与蓝铁矿持续可得且足够覆盖任意数量的消耗。”《受限转移定义》§2.1 明确规定：“空历史只有在当前库存足够覆盖整个被测段消耗且未违持续可得时才可作该段见证。”《内核输入》§6 区分任务初始锚点仓库和当前 StateSeed 仓库；《受限转移定义》§1 允许有限合成条件种子，但没有解除回放段外部过程的前件。

**公开入口复现。**[负例输入](r1-测试与证据/空补矿史耗尽-input.json)以粉碎机样例为基础：任务初始锚点仍为六类各 80000，当前合成 StateSeed 的源矿改为 1，非仓库格仍空；显式补矿 `events=[]`、`through=3`，出处改为本复核的负例说明，并同步当前参数副本。没有把它宣称为已经证明可达的真实历史；它专门检查明显不足的外部历史是否被拒绝。

[CLI 进程结果](r1-测试与证据/空补矿史耗尽-process.json)为退出码 0，[实际输出](r1-测试与证据/空补矿史耗尽-record.json)为 `status=completed`，四项 `summary.warehouse_ore` 都是 `"0"`。t=0 唯一一件源矿出库；t=1 进入粉碎机；t=2 完成唯一一批；t=3 仍无补给、无新批。原同段样例则实际出库 4 件、完成 2 批。在 t=1 第一件已离开进料传送带以后，上游矿口因仓库空而不能补上第二件，已具体影响后继，不能解释为仅在段末余额恰好用尽。

代码中 `check_external_stops` 对该轴只检查 `t > through`；`ore_supply` 只执行已经列出的事件；仓库源的 `item=null` 被普通地映为无候选货。没有前件检查把该错误历史排除。本次 [Rust 验收对照](r1-测试与证据/Rust记录验收对照.json)还调用 `output::verify_record`：它会重新产生同一错误轨迹并接受该记录。

**为何既有测试漏掉。**`ore_history_horizon_stop` 只跨过 `through=3` 测停止；守恒测试从足量 80000 出发跑四刻，检查账目相等，不检查供给充分性。缺货也可以守恒，故这两个测试同时通过不能排除此问题。

**修订验收要点。**对回放段的补给充分性作可机械检查的验证；无法建立此前件时应停止并给出轴名及发生位置，不能自动补满或输出一条由缺矿引起的正常低产轨迹。本负例应被拒绝；同时保留原足量空历史及合法显式补矿正例。

### KR-r1-L2-02：落盘验收脚本漏查来源闭合和验证范围

- **严重程度：重要。**
- **位置：**`/home/zhuran24/zmd-research-fresh/求解器/crates/kernel/tests/verify_outputs.py:18–46`，尤其 27–28、42–45；`crates/kernel/evidence/实现验证.md`“测试与证据自审”。
- **一句话论断：**交付的落盘验收函数允许删除三份正式源指纹或伪造验证范围、完成批数及黄金匹配标记，仍报告记录通过。

**规范依据。**《内核输出》§1 要求依赖清单由校验器重建并严格比较，明确“禁止删掉某个依赖以绕过核验”；§3 要求包括 `validation_scope` 在内的逐字段、逐 JSON 类型严格比较。

**复现及对照。**`audit.py::record_checks`逐份读取两个全状态记录，构造以下两类各两份负例：

1. 从 `fingerprints` 删除全部 `role=formal_source` 的三项，其余内容不变。
2. 把 `validation_scope.through` 与 `manufacturing_cycles_completed` 改为 999，并翻转 `golden_match`，轨迹不变。

原 `verify_outputs.verify` 接受全部四份。分别保存为 [粉碎机删指纹](r1-测试与证据/混做粉碎机两下游-删除三份正式源指纹.json)、[粉碎机假范围](r1-测试与证据/混做粉碎机两下游-伪造验证范围与批数.json)、[分流器删指纹](r1-测试与证据/分流器三路轮询-删除三份正式源指纹.json)、[分流器假范围](r1-测试与证据/分流器三路轮询-伪造验证范围与批数.json)。对照负例只改末刻 `summary.warehouse_ore`，两份均被拒绝，说明调用确实运行了轨迹比较，失败不是由于完全没有执行校验。

根因是 27–28 行只核“尚存的每个指纹是否正确”，没有重建必需集合；42 行只数轴标签；43–45 行只检查三个认证布尔为假，没有核范围起止、批数、起点说明或黄金匹配值。schema 不能替代这些跨字段语义关联。

**结论边界。**Rust `output::verify_record` 的完整对象重算比较可以拒绝上述四份元数据负例，本席用独立 [record-probe](r1-测试与证据/record-probe/src/main.rs)验证了这一点，并核四份原交付记录均通过。故本发现针对实际文档推荐、用于生成 `record-validation.json` 的 Python 落盘验收入口，不能扩大为“所有验收入口都漏检”或“原四份轨迹已经错误”。强入口存在，不能替代弱入口尚未执行的检查。

**修订验收要点。**让落盘入口重建必需依赖并严格核 `validation_scope`，或可靠调用完整 Rust 记录验收后再做独立 Python 轨迹和身份检查；把这四份负例加入验收回归。

### KR-r1-L2-03：按制造事件前缀批量标记轴已执行

- **严重程度：重要。**
- **位置：**`/home/zhuran24/zmd-research-fresh/求解器/crates/kernel/src/output.rs:234`（`coverage`）；`src/tests.rs` 的 `coverage_five_states`。
- **一句话论断：**一次制造启动成功便使全部 `manufacturing.*` 轴标为 `exercised`，包括本次从未进入的整批输出受阻分支。

**规范依据。**《内核输出》§1 将 `exercised` 定义为实际执行，并要求逐轴证据，强调“填了本版值不等于已验证该机制”；《受限转移定义》§4.2 第 1 步只在 `completed` 时处理整批输出及受阻保留。

**复现。**不改粉碎机的运行语义数据，只将请求截到两个时刻。复制输入为 [仅开工未完成-input.json](r1-测试与证据/仅开工未完成-input.json)，[输出](r1-测试与证据/仅开工未完成-record.json)的 t=0、t=1 粉碎机阶段分别是 `idle`、`working`；制造完成事件为 0；唯一制造成功是 `J|1|0|11`，只完成归集和开工。其 `uncovered_axes` 却给出：

```json
{"axis":"manufacturing.output_blocked","coverage_status":"exercised","evidence":["J|1|0|11"]}
```

该输入初始所有制造机 idle、缓存全空，在两刻内没有任何批次成为 completed，故 `transition.rs::manufacture` 第 1 个 `if phase == "completed"` 的输出处理主体从未执行。这不是要求必须有区分不同读法的实验，而是连被标注的本版分支都没有到达。

`coverage_five_states` 只验证五类标签都存在，以及箱体冷却未触发、窗口批到期已触发两条；没有对制造各轴的未触发情形作负例。真实的输出冲突单元测试已存在，但另一场测试的证据不能补进本次有限记录。

**修订验收要点。**按实际机制触发点生成轴证据，区分开工、整批输出、受阻保留、停用搬运等；该两刻记录的 `manufacturing.output_blocked` 应保持 `not_exercised`。前缀匹配只能用于枚举候选轴，不能单独证明它们被执行。

## 3. 黄金、差分、确定性与不变量的有效范围

### 3.1 比较不是摘要替代完整轨迹

`tests/reference.rs:12–31` 的递归比较检查对象键全集、数组长度和次序、全部叶值及 JSON 类型。`differential`先逐刻比较 Rust 输出与原 Python 运行记录的完整 tick，再把粉碎机的全部 summary 对原黄金的 `ticks` 比较。手填黄金本身是摘要，不是完整 StateSeed；完整状态、events（含 basis/detail）、closure 的比较对象是独立 Python 记录。`live_python_differential`现场调用 Python 后又比较“现场 Python = 原落盘 tick = Rust tick”，没有在差分前删字段或合并事件。

Python `check_golden_trace.run`从输入、目录、模板序和状态计算后继；黄金文件只在其生成入口或 Rust 比较阶段读取。Rust 核心转移没有用黄金内容决定状态。两样例的 JSON 指纹及参考源都在 1250 项基线中，当前没有发现为通过比较而改黄金或放宽比较的证据。

分流器比较的是 12 刻参考记录，没有冒充它另有一份与粉碎机等价的手填完整黄金。粉碎机四刻只跑源矿配方，不能推出实际混做、研磨下游生产或所有初态通过。

### 3.2 输入顺序确实发生改变

`src/tests.rs:125–150` 对 `layout.units`、`physical_channels`、`buffer_channels` 原位 `reverse()` 后重新经过 `Input::parse` 和 `Engine::new`，不是打乱了未使用的副本。它保持 `judgment.order`、`connection.tie` 等真正有语义的显式排序不变，这与转移 §1 不得拿容器次序充当优先序相符。

本席通过公开 CLI 再跑粉碎机 4 刻和分流器完整 12 刻，覆盖原确定性单元测试未跑到的 t=6 双门恢复。实际数组长度及是否变化如下：

## 5. 独立手推：同种源矿不能同时占桥的两轴

### 5.1 输入和先验预期

以实现席 [bridge-manual-input.json](../evidence/bridge-manual-input.json)的几何及日程为基础，只把 `initialization.other_inventory` 所引用的具体 StateSeed 中西箱编号 1 格的物种由蓝铁矿改为源矿。南箱、西箱各 1 源矿，桥及两个目标箱空，四箱传输关闭。仓库六种各 80000 不变，t=0 为 before_boundary。这个合成初态仅用于条件测试，不证明调试可达。

四条 PC 简记为 S（南箱→桥纵轴）、N（桥纵轴→北箱）、E（桥横轴→东箱）、W（西箱→桥横轴）。每轮显式访问顺序为 S、N、E、W，随后四个关闭的传输模板。桥存货侧是分级的 `[S,W]` 环，初始 next=S；取货侧是不分级的 `[N,E]` 环，初始 next=N。各箱对应侧只有单成员级。

依据为规则 L13 同单位同种单格及缓存/箱体例外、L23 至少滞留一刻、L29 尝试后前移、L63 桥双轴独立；细化使用《受限转移定义》§3.1–§3.3、§4.1。桥的格独立不解除同单位同种单格，不按轴另造四套轮询状态。

手算期望由 `audit.py::manual_bridge` 的字面常量先写出，再启动内核，没有从实际输出提取期望。对照范围为完整非空库存投影、实际成功 PC 顺序、入格时刻及闭包轮数；附加从完整 StateSeed 重新核仓库、逐物种总账和端口账，没有声称手算覆盖每条失败事件的所有说明文字。

### 5.2 每刻推导

| t | 成功 PC，按实际顺序 | 闭包后的全部非空非仓库格 | 扫描轮数 |
|---:|---|---|---:|
| 0 | S | 桥纵轴：源矿 1、entered_at=0；西箱格 1：源矿 1、entered_at=0 | 2 |
| 1 | N、W | 北箱格 1：源矿 1、entered_at=1；桥横轴：源矿 1、entered_at=1 | 2 |
| 2 | E | 北箱格 1：源矿 1、entered_at=1；东箱格 1：源矿 1、entered_at=2 | 2 |
| 3 | 无 | 同 t=2 | 1 |

**t=0。**S 获两端许可，源矿进入纵轴，桥存货指针前移 W。N 的运输年龄不足一刻，E 无货；两次访问分别消费桥取货侧的授权，指针按 N→E→N 回到 N。随后 W 虽有源矿，但桥另一轴已有同种货，目标选择器拒收；两个分级侧都无物理可动成员，所以该访问没有实际移动判定。首轮改变库存，次轮只重复失败/无请求访问且全部闭包投影回到上一轮边界，于第 2 轮首次重复。

**t=1。**S 已无货。N 满一刻且两端有权限，送入北箱，释放桥内该物种的占位；桥取货指针到 E，E 空尝试后回 N。现在 W 物理可动且存货续接位置为 W，成功进入横轴，存货指针回 S。横轴是 t=1 新入货，后续同刻不能离开。两轮后闭包。

**t=2。**N 空尝试，取货指针转 E；E 的源矿已滞留一刻，送入东箱，指针回 N。其它源已空。首轮改变库存，第二轮重复，闭包为 2 轮。

**t=3。**N、E 的失败访问使指针转一整圈，库存、图、批次、预算及轮询边界都不变；初始边界已在 seen，因此第一轮即闭包。

四刻中仓库完全不变，全基地源矿恒为 80002，蓝铁矿、荞花、砂叶及两种种子各 80000；没有制造、补给或无线入库。每次 PC 成功记两个不同端口各 1，端口账项数依次为 2、4、2、0。实际记录全部吻合，详见独立检查结果的 `manual_bridge`；完整库存与移动账的对照布尔值均为 true。
