## 1. KR-r5-L2-01：D.2 之前的容量与当前级计算

**结论：`refuted=false`。未能否证；本次实跑确认所指构造顺序仍存在。**

### 契约与实现

[受限转移定义](../../../规格/受限转移定义.md) §6.1 D.2（第135行）要求：现存 PC 源候选为两矿且目标为核心存货端口时，在目标容量及其它 physical/权限筛选之前返回 `unsupported(cycle.domain.D2)`；年龄、预算或权限不满足也不得先绕过该守卫。[内核输出](../../../规格/内核输出.md) §5.1.1、§5.3 第3项再次要求在矿容量、physical、级排序和授权读取前检查。[修改请求](../../../规格/对内核的修改请求.md) KQ-08 同时保留普通 `finite_concrete` 的真实容量语义。

当前调用链没有在构造前启用生产守卫：

1. [main.rs](../src/main.rs) 第205–209行先装载输入，再 `Engine::new(input)`，返回后才 `domain_report("static")`。循环搜索的 [cycle.rs](../src/cycle.rs) 第594–602行同样先 new，第596行才设置 `production_abstraction=true`，随后检查域。
2. [engine.rs](../src/engine.rs) 第311行将标志初始化为 false；第350行在构造器返回前调用 `rebuild_memory`，并比较计算结果与输入记忆。
3. [polling.rs](../src/polling.rs) 第349–360行重建后调用 `refresh`。第168–170行的 D.2 保护依赖该标志；false 时跳过，第217行仍调用 `physical`。
4. [engine.rs](../src/engine.rs) 第1048–1059行的局部回矿守卫也依赖该标志；第1060行进入目标选择，核心目标调用 `plan_deposit`。[warehouse.rs](../src/warehouse.rs) 第158–166行读取原矿量并计算原量加1是否超过 80000。

因此输入库存合法性核验与回矿接收容量判定在这里不能混为一谈：被指出的是后者已经被执行，并影响当前可动级。

### 独立试验

从现有 `tests/fixtures/core_inbound.json` 读取几何，在 `belt:transport:0` 放1件源矿，`entered_at=-1`、种子时刻0，显式选择 sufficient。分别把矿库存设为79999和80000，使用当前 `seed` 接口各自产生完整合法记忆。两份材料都通过普通 check、公开 `Engine::new` 和1刻普通有限运行。

API 探针在调用 `domain_report` **之前**读取公开构造器返回的 `memory` 和模式标志，结果如下：

| 源矿库存 | 构造器成功返回 | 模式标志 | core/input 当前级 | 随后的 D.2 |
|---|---|---|---|---|
| 79999 | 是 | false | `L\|core\|input\|other` | fail，回矿候选 PC |
| 80000 | 是 | false | null | fail，同一 PC |

两份派生种子恰有两处差异：矿数量和上述当前级；图、候选物种、年龄、参数及其余状态相同。对应 `cycle --no-record` 都最终在 D.2 停止、无周期。这证明本次观察的是前置顺序违反，**没有发现错误发证或域外轨迹被运行**。

证据：[domain-observations.json](否证-r5-2-证据/domain-observations.json)、[79999 API 日志](否证-r5-2-证据/ore-79999-api.log)、[80000 API 日志](否证-r5-2-证据/ore-80000-api.log)、[79999 域检查](否证-r5-2-证据/ore-79999-domain.log)、[80000 域检查](否证-r5-2-证据/ore-80000-domain.log)。合法输入为同证据目录 `ore-79999-seed.json`、`ore-80000-seed.json`。

### 否证尝试与边界

- **“普通构造必须核 current_level，所以可先读容量。”** 输入 §6.3 确实要求当前级与实际容量等一致；这支持普通有限模式的上述差异，不豁免生产入口在第一次 physical 前执行明确的 D.2 守卫。可以先核结构、物种和数量合法性，再在生产路径上拒绝回矿候选；无需放过伪造记忆。
- **“最终 D.2 已 fail，发现不成立。”** 该控制结果限制了影响范围，但发现说的是读取前的先后要求；事后 fail 不能证明此前没有读取。
- 另将79999合法种子只改矿量为80000而不更新记忆，域检查先报 `invalid_input @ poll_memory`，D.1–D.5均 not_checked。该材料确实不是合法种子，仅作校验先后佐证，不承担合法输入反例。见[交叉试样日志](否证-r5-2-证据/ore-crossed-domain.log)。

现有运行期 `refresh` 守卫和物理检查的局部守卫没有覆盖构造阶段，故不足以否证此发现。

## 2. KR-r5-L2-02：相对路径记录的入口不一致

**结论：`refuted=false`。未能否证；契约允许的路径表示变化足以复现三个记录入口拒收。**

### 契约与实现

[内核输出](../../../规格/内核输出.md) §1 的 fingerprints 明确允许绝对路径或相对记录文件的路径；§5.1规定目标 JSON 自身的相对路径仍相对目标文件目录，§5.3要求嵌套路径按所属文件目录解析。修改记录路径文本会改变记录原始字节，故证书对该记录的 sha256 必须重新计算；来源文件不变时不能改写它们的摘要。本试验遵守这个区别。

[main.rs](../src/main.rs) 第138–149行 `verify-record` 把 input 指纹中的路径直接传入 `Input::load`，没有拼接记录目录。第181行的记录 checkpoint 分支虽拼接了该目录，随后仍调用相同 `verify_record`。[output.rs](../src/output.rs) 第566–568行将原始对象与生成器的绝对路径对象直接比较，没有在比较前规范路径。[verify_all.py](../tests/verify_all.py) 第43–54行会对 completed 记录调用该入口，证书已通过也不会跳过这份记录。

相反，[cycle_io.rs](../src/cycle_io.rs) 第173–191行按记录目录规范 producer.path 和全部 fingerprints，核原始字节摘要后，再与重算记录比较。因此它能够接受同一相对路径记录。

### 独立试验与对照

本席从现有 `数据/样例/生产循环环带.json` **重新运行** cycle，得到21刻前缀和 P=20 的周期结果，并通过独立 verify-cycle。以新生成记录分别构造 `absolute-package` 和 `relative-package`：后者仅相对化 `fingerprints[].path` 与 `producer.path`；其证书相应指向本地 `record.json` 并更新记录自身摘要及 producer 路径。输入、轨迹、状态、台账、参数及来源摘要不变。

脚本逐一验证相对路径解析后所指文件的原始 sha256；将路径在内存中规范为绝对值后，整个相对记录与原记录严格相等。两包及初始材料通过当前 schema，排除了语法非法、陈旧来源或不同轨迹的解释。

| 同一新生成运行的验收入口 | 绝对路径包退出码 | 相对路径包退出码 |
|---|---:|---:|
| verify-cycle（含引用记录） | 0 | 0 |
| verify-record，cwd=求解器 | 0 | 2，错误目录下找不到输入 |
| verify-record，cwd=记录目录 | 0 | 2，完整重算逐字段不同 |
| checkpoint，输入为记录 | 0 | 2，完整重算逐字段不同 |
| verify-batch，目录含记录及证书 | 0 | 2，失败于记录独立验收 |

绝对路径批验还通过了12项既有保护基线。相对包的周期核验实际重建21刻前缀并重跑20刻周期，`cycle_replayed=true`；它不是只通过 schema。

证据：[path-observations.json](否证-r5-2-证据/path-observations.json)、[相对证书核验](否证-r5-2-证据/relative-cycle-verify.log)、[根目录记录核验](否证-r5-2-证据/relative-record-root.log)、[本地目录记录核验](否证-r5-2-证据/relative-record-local.log)、[记录 checkpoint](否证-r5-2-证据/relative-record-checkpoint.log)、[相对批验](否证-r5-2-证据/relative-batch.log)、[绝对批验](否证-r5-2-证据/absolute-batch.log)。材料包在同证据目录 `absolute-package/`、`relative-package/`。

### 否证尝试与边界

- **“只需切换 cwd。”** 已实际切到记录目录，此时来源装载通过，但原对象中的相对文本仍与重算绝对文本不同，退出2。
- **“严格逐字段比较就是契约要求。”** 契约同时明确允许路径两种表示。先按所属文件解析并核字节摘要，再比较规范路径和完整语义字段可以满足两项要求；已有 verify-cycle 就采用此做法。
- **“证书已核记录，批验应能通过。”** 绝对包验证批量脚本及保护基线可用；相对包仍在 completed 记录的再次验收处失败，故该覆盖实际不存在。

此发现不要求省略来源、刷新来源哈希或放宽轨迹比较；问题仅是合法材料不能被一致消费。

## 3. KR-r5-L2-03：诊断外壳的 checkpoint panic

**结论：`refuted=false`。未能否证；原有合法材料原样输入即触发 null 解引用。**

### 契约与实现

[内核输出](../../../规格/内核输出.md) §5.1.2允许尚未形成可回放输入的装载外壳有 `replay_input_ref=null`、`last_state=null`、`cycle=null`、`completed_ticks=0`；资源失败保持 inconclusive/resource。§5.3第1项将“相同装载停止的诊断复现”与周期重跑区分。[受限转移定义](../../../规格/受限转移定义.md) §1的错误返回也不构成游戏后继。

[cycle_io.rs](../src/cycle_io.rs) 第89–142行专门复现外壳来源的装载错误，核对相同诊断后返回 `status=input_checked, diagnostic_replayed=true, cycle_replayed=false`。这是合法且有意义的核验成功，但没有恢复状态。

[main.rs](../src/main.rs) 第164行只要求此函数返回 Ok，忽略返回对象的分支；第168行立即对 `artifact["replay_input_ref"]["path"].as_str()` 调用 unwrap。合法的 null 必然产生 None，于取得 last_state 之前即 panic。现有分支没有提前拒收外壳。

### 独立试验与对照

直接读取被审交付 `crates/kernel/evidence/round6/cli/overflow.json`，没有编辑或搬改其内容。原始 SHA-256 为 `5dafe7e264eef6ad796ec580d5e15162dddf244edffe665301d97adb74f55179`。

1. 当前输出 schema 验证通过。
2. verify-cycle 退出0，明确返回 `diagnostic_replayed=true`、`cycle_replayed=false`，说明来源仍可访问且同一资源装载停止得到实际复现。
3. checkpoint 在 `main.rs:168:77` panic，错误为 `called Option::unwrap() on a None value`，退出101；stdout没有 JSON，指定输出文件未生成。
4. 同次试验中新生成、已核的循环证书和绝对路径记录均成功导出 checkpoint，排除了命令普遍不可用或目标目录不可写。

证据：[load-shell-observations.json](否证-r5-2-证据/load-shell-observations.json)、[诊断复现日志](否证-r5-2-证据/load-shell-verify.log)、[panic 日志](否证-r5-2-证据/load-shell-checkpoint.log)、[有效周期 checkpoint 对照](否证-r5-2-证据/fresh-cycle-checkpoint.log)、[有效记录 checkpoint 对照](否证-r5-2-证据/absolute-record-checkpoint.log)。

### 否证尝试与边界

- **“没有状态的外壳本就不应恢复。”** 成立，但只能支持带位置的明确拒收，不能把未检查 null 的 panic 解释为正确恢复接口。本发现也没有要求从外壳生成状态。
- **“外壳已过期、verify-cycle 应先失败。”** 本次原材料的结构与独立诊断均成功；panic发生在核验返回之后，与来源失效无关。
- 没有证据表明该 panic 生成了错误检查点或破坏了来源文件；本次影响限进程异常退出和缺少结构化拒收。
