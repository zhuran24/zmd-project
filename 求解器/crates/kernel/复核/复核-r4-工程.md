## 2. 缓存读取依赖与失效条件

### 2.1 缓存到底保存什么

`cache.rs:67–79`保存的是每个PC的物理结果，包括选中的源格、目标格、物种和失败原因；它不保存轮询授权。`engine.rs:997–1067`实际读取现存图、源选择器、目标选择器、门原因、运输年龄、端口预算及生产抽象模式。制造普通格的同种占位会跨本单位输入/输出格影响目标；桥接器另一轴的同种占位同样影响目标。因此仅按发生变化的单格或当前PC失效不足，当前实现采用整单位依赖。

另有两个不同的派生量：

- `level_keys`缓存某级的静态排序键 `(最大阻尼, 最早接通时刻)`；存货侧及单级不求阻尼。它依赖完整现存图、级成员、桥轴、带串规则、固定分支表、接通历史。
- `current_level`选择含可动成员的最高级，依赖上述键、独立 `arbitration.level_order` 和各成员的 physical；用 `dirty_sides`标记重新计算。`grant`仍在每次访问读取真实 `next_channel`，没有把游标结果当成可长期复用的缓存。

依据：规则L13、L23、L27–32、L63–64、L72；约束“端口速率”；现行受限转移§3.1–3.4、§4.1。

### 2.2 状态变化逐项核对

下表以当前实现的全部物理读取项及其写入入口分类；对本版停止的外部变化另列，不能借本表声称更广游戏机制已覆盖。

| 状态变化 | 会改变的结果 | 实际失效或不缓存路径 | 复核结论 |
|---|---|---|---|
| 普通源格数量减少、取空、物种更换 | 有货与否、源物种；箱最小非空格也可能改变 | `engine.rs:1070–1101 remove`先调用`invalidate_slot`，按整单位清相关PC及两端dirty侧 | 覆盖 |
| 普通目标格收件、数量增加或由空变非空 | 容量、物种许可、后续源选择 | `engine.rs:1104–1116 put`同样按整单位失效 | 覆盖 |
| 制造输入/输出任一普通格改变同种占位 | 该单位其它口的合法目标可能改变，不能只失效当前格 | `cache.rs:15–35`清本单位全部入/出PC；`target`在`engine.rs:958–970`跨普通格检查 | 覆盖 |
| 桥接器一轴收发影响另一轴同种占位 | 另一轴物理可收性 | 依赖按单位而非桥轴建立；仍由PC端口axis选择独立格 | 覆盖，不把两格混为一格 |
| 箱体任一编号格收发或清空 | 最小非空源格、最小可放目标格可能切换 | 普通收发走put/remove；全箱传输在`warehouse.rs:279–282`显式失效整箱后清空 | 覆盖六格选择器 |
| 仓库扣量、取空、保留历史身份 | 各指派出口源选择；同种再入的落格 | `remove`通过仓库索引识别`@warehouse`并失效；`cache.rs:43–60`登记全部指派端和核心端PC | 覆盖 |
| 核心入库、无线入库、外部补矿 | 容量、物种身份、目标选择及相关出口 | 全部走`warehouse.rs:179–229 commit_deposit`，先失效`@warehouse` | 覆盖三条提交入口 |
| 仓库匿名格赋种、O稳定删项、规范新格创建 | 其它物种下一目标格或标签冲突可能改变 | 与库存同笔commit；`@warehouse`失效，仓库格索引同步登记新格 | 覆盖，不能只监听数量 |
| sufficient出矿后原子等量回补 | 矿量、身份、O保持；本次端口预算变为已用 | 目标put/入库事务至少清掉本PC并标记其两端dirty；其它仓库口库存观察不变 | 覆盖，详见下文端口论证 |
| 一次PC成功使两端端口预算增加 | 相关PC变为本刻不可再成功 | 普通移动在写预算前已由put/remove/commit使本PC失效，事务中间不调用physical；预算随后在`transition.rs:244–245`提交 | 覆盖 |
| 时钟推进、运输年龄增加、端口预算清零 | 滞留条件及每刻额度改变 | `transition.rs:668–670`在边界前全失效并清level_keys；boundary随后推进时间、清usage | 覆盖，包括初次after_closure推进 |
| 门收件增加累计/窗口计数、首次开窗、耗尽原因出现 | 门物理许可、现存PC、远处阻尼及级排序 | 每次门成功收件均在`transition.rs:261–311`调用rebuild_graph，再rebuild_memory全清物理和级键 | 覆盖，即使尚未耗尽也保守重建 |
| 多门窗口同时到期 | 原因删除、断边恢复、环成员/续接及远处阻尼 | `transition.rs:480–518`收集同快照到期集，改全部原因后一次rebuild_graph | 覆盖，没有逐门重起轮 |
| 现存边身份不符批量维护 | 一批入边删除及全部相关级/路径 | `polling.rs:422–465`先收集、统一修改，再一次重建图 | 覆盖，断边不继续观察上游 |
| 分叉可用集合改变或恢复 | 固定v2表查询结果、远处路径最大阻尼 | `polling.rs:354–365`图事务清空所有level_keys，重新分组；`damping:138–168`按现存出边集合重新查表 | 覆盖，不仅更新门邻接级 |
| 制造完成、旧批出缓存、新批归集 | 后续源/目标库存及同种占位改变 | 完成写buffer经过put；出buffer先put(output)再清buffer；归集逐物种remove(input)/put(buffer) | 覆盖；直接清buffer不遗漏普通格依赖 |
| 制造phase、remaining、锁配方；箱冷却递减或重置 | 制造/传输资格改变，间接改变后续库存 | 这些模板守卫逐次实读，未缓存；真正改变普通库存时走上述失效入口 | 无需额外physical失效 |
| 生产模式成品代表归零 | 仓库代表数量、身份改变 | 只在`step_inner`已全失效之后调用`represent_products`，随后才刷新物理 | 覆盖；代表调整单独记账 |
| 成败后的next_channel改变、回到某级 | 授权边改变，physical及静态级键不变 | `polling.rs:316–350`grant实读游标，advance只前移；dirty刷新选择最高可动级 | 不需要使physical失效 |
| 固定仲裁序、接通序、分支表、指派、门设定、布局/方向/供电、轴值改变 | 可改变物理、环、静态级键及仲裁 | 本版没有这些运行中修改后效；新输入重新构造全部索引和仲裁rank；运行期未支持动作按`check_external_stops`停止 | 仅在固定输入域成立，不能直接推广 |
| 诊断日志、交付总计、证据文案、扫描轮号 | 不被physical或级排序读取 | 不以这些值触发物理缓存失效；错误仍使本次执行停止 | 不影响缓存结果 |

**端口预算没有漏失效。** 本版几何由互不重叠单位的唯一格边端口推出，`catalog.rs:495–523`先核格边端口唯一，再查唯一对面端口，故一个端口至多连接一条PC。普通成功移动修改源/目标时会清其PC；sufficient没有实际扣矿，但目标put也清同一PC，并把其源侧和目标侧同时加入dirty。目标是仓库时commit清仓库相关PC；不存在“预算已用、本PC仍保留ready”的后续读取间隙。库存未变的其它仓库口不共享这个端口预算，保持缓存是正确的。

**级键与可动级不是同一缓存。** 库存改变只需重算受影响侧的可动成员及current_level，静态级键可复用；任何图事务必须清所有级键，因为下游门切边可改变远处源级的阻尼。当前实现满足这一区分。代码还在每个tick清级键，比“只在图变化时清”更保守，不造成漏失效。多级取货会遍历所有有成员级求阻尼，包括其中暂时全不可动的级；没有把KQ-04错误改成“只数含可动成员的级”。

**实测。** 原`round5_cache_differential`已随83项库测试重跑，包含九个机制样例以及三档压力布局。另由本席[cache_cli.py](r4-工程-证据/cache_cli.py)对九个样例各造三组显式全序/表示变体，重新派生后分别运行缓存和`--no-cache`八刻，27组全部装载成功，完整输出JSON逐字段相同。见[差分结果](r4-工程-证据/cache-cli/results.json)。这是依赖论证的运行补充，不是全部布局/参数族的穷尽证明。

引擎的公开字段可被Rust调用方直接改写；本结论没有为任意绕开解析器的直接改写提供合法性或缓存一致性承诺。正式的跨参数点运行及检查点恢复须重新经过Input/Engine构造。当前固定段没有可合法改变仲裁全序、布局或指派而遗漏失效的内部转移入口。

## 3. 确定性、数值及错误处理

源码检索未发现Rust内核使用`HashMap`、`HashSet`、`f32`、`f64`或unsafe块，crate在`lib.rs:2`启用`#![forbid(unsafe_code)]`。见[静态检索](r4-工程-证据/static-tokens.log)。这里指内核自己的实现，不声称审计了Rust标准库/serde的内部实现。性能计时报告中的浮点ms是测量表示，不参与游戏数量、时间、排序或率比较。

状态与依赖索引用BTreeMap/BTreeSet；语义有序数据仍来自显式模板全序、接通并列序、级仲裁序、输入格序和配方序。箱格按编号；库存数组按slot规范化。`byte_determinism_and_layout_permutation`重跑通过，同输入输出逐字节相等，布局单位/PC/BC排列反转不改变轨迹；库存反转另有回归。没有对轮询环members或模板全序做语义丢失的排序。

数量、时刻用整数/有理字符串；运行域转为i64，关键累加与年龄/相对时差用检查算术，周期率按i128交叉相乘比较3/5、11/20。`read_json`拒绝重复键及JSON浮点，内存入口的`validate_tree`同样拒浮点。资源不足保留inconclusive，不能从溢出或预算限制生成游戏后继。

本轮检查的`.ok()`/`is_ok_and`并非一律错误：历史固定参数先经过完整验证；事件及周期验收中的筛选处有前置结构/时序校验和完整重算；CLI错误分支对原输入的尽力读取只用于附加读法，不把原失败改为成功。reachability文档路径的可选规范化也不参与物理守卫。没有据此发现可由本版合法输入实际触发的吞错转移。

既有第3轮畸形输入回归59次调用已用当前release重跑；本席另用[cli_edges.py](r4-工程-证据/cli_edges.py)对布局、初态、设定、时间线、建造中的124个复合字段做单点布尔替换，所有响应均可解析，退出码仅0/2，没有panic。这个变异探针只检查异常退出与响应边界，不把可接受的纯元数据变动自动判成规则错误。见[边界结果](r4-工程-证据/cli-edges/results.json)。

执行途中失败由`transition.rs:646–665`封存Engine；之后再次step返回同一停止，不把半刻状态继续当完整种子。输出只保存已闭包前缀，周期partial_events仅为审计；资源分类与低产反例分开。
