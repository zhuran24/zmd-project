# 全厂静态检查器 B

日期：2026-09-22。状态：检查器 v1.1 实现完成，56 项自测通过。支持 `full-factory-static-v1` 的已核读 71 条、72 条规则版本；当前正式文件为 72 条。尚无完整全厂正例接受本检查器验收。局部结构、纯速率层和执行覆盖测试均不构成全厂布局证书，不更新 L。

## 输入、命令和结论

输入契约是上一级的 [格式.md](../格式.md)。唯一规则口径是仓库根目录的《明日方舟：终末地》游戏规则.txt、求解任务.txt、求解约束.txt。程序核对三份文件的实际 SHA-256，拒绝未支持的版本。格式文件的指纹表是 71 条快照；当前《求解约束》为 72 条，含新增“1113 位置”。本实现未改动格式文件或正式文件。

| 约束版本 | SHA-256 | 兼容性 |
|---|---|---|
| 原任务/格式快照，71 条 | `cf44821f07779490b9b1d913bfb87d7757ae8abfe784c912bb7891868780f7f3` | 保留规则目录和实现；当前正式文件已不是此版本，旧指纹候选在 CLI 中拒绝 |
| 当前正式文件，72 条 | `a67c18dec5f6ae59c41e8620d270007f20c2d3e5b202521d0cca12f616bca3df` | 候选须填写此指纹；额外核面积 1113 的八种位置 |

两份检查器联核必须使用同一份候选和正式文件指纹。对其他未经核读的 SHA，程序仍拒绝，不动态加载新规则。[版本差异证据](test-results/source-version-transition.json)列出新增条目与原有条目的表述、依据调整。

从仓库根目录运行，`候选.json` 替换为实际文件名：

```bash
python -B 求解器/构造/第一张全厂候选/检查器B/check.py \
  求解器/构造/第一张全厂候选/候选.json \
  --output 求解器/构造/第一张全厂候选/检查器B/结果.json \
  --witness-output 求解器/构造/第一张全厂候选/检查器B/平均流见证.json

python -B 求解器/构造/第一张全厂候选/检查器B/selftest.py
```

省略 `--output` 时 JSON 写到标准输出。`--witness-output` 仅在取得精确正流见证时写出见证，不改候选。全部文件输出限于 `第一张全厂候选/`。连续 LP 使用 SciPy/HiGHS，显式限制为 1 线程；相关 BLAS 线程也限制为 1。需要 Python 3、SciPy 和 NetworkX；自测还会间接使用 SciPy 的 NumPy 依赖。不调用内核、git、cargo 或浏览器。

`--time-limit` 默认为 120 秒，分别约束基础 LP、共同 δ 优化和需要时的不可行证书搜索；不是整个命令的合计时限。

| 状态 | 退出码 | 含义 |
|---|---:|---|
| `STATIC_PASS` | 0 | 指定受限类、结构、正式静态投影和一份严格正支持的精确平均流见证通过；运行义务仍未认证 |
| `REJECTED` | 1 | 至少一个已执行条件违反，包括附带见证错误；不排除换见证、换支持或换布局的分支 |
| `UNRESOLVED` | 2 | 存在未解释的额外限制、未执行的必需静态检查或数值未决，不能报通过 |
| `INVALID_INPUT` | 2 | JSON、类型、字段、枚举、版本或正式文件指纹不符合契约 |

报告含候选文件字节 SHA、检查器版本与各实现文件 SHA、每条检查的依据和证据、重建通道、供电清单、最大空矩形、对应版本的 71/72 条正式约束台账、固定项、开放自由度、所查量词和失败范围。Python API `check_document()` 默认绑定其 `indent=2`、末尾换行的 UTF-8 JSON 序列化字节；CLI 始终替换为实际输入文件字节 SHA。

台账区分 `PASS_STATIC_PROJECTION`、`VIOLATION`、`STATIC_ANTECEDENT_FALSE`、`RUNTIME_PENDING`、`BLOCKED`。涉及通过量的前件只按本次精确见证判断。某前件在这份见证中不成立，不代表在所有可达循环态中不成立。若结构或流失败，依赖流量的台账显示 `BLOCKED`，不伪装全部检查完成。

供电依据规则“供电桩”：锚点 `(x0,y0)` 的覆盖格列、行均为 `x0−5…x0+6`，与需电单位至少一个占格相交即覆盖；只在边界相碰不计。制造开关、箱体传输开关由 LP 独立处理。未供电、关闭、零流量实体仍计占地。

仓库取货口按真实 1×3 / 3×1 实体和长边中间端口重建；左、下各 23 个，包含核心六口后源矿 18、蓝铁矿 34。核心存货口为两边偏移 1…7，取货口为另两边偏移 1、4、7。六个出库口分别传播其设置物品，不把核心当成自由换料节点。核心、仓库取货口和协议储存箱均纳入相应 N1/N2 判断。

非运输单位相贴不形成通道。过滤准入口的物品设定不删除结构边。桥只依据邻格端口推方向：单端已接入仍保留那一条自动通道并拒绝 N4a；两端同型或相邻桥使方向不能唯一确定时，拒绝 N4，报告 `channel_graph_complete=false`，N5a 为 `BLOCKED`，不把已知子图称为完整重建。

协议储存箱在无电或关闭传输时仍有真实物理端口。`p2p` 拒绝箱体，`n_restricted` 支持箱体平均守恒与有供电且开关开启的无线弧。六个编号格、每格 50 件、最小编号存取、无线相位及仓库余量条件保留在运行义务中，不将箱体解释为任意选货的 300 件池。

`n_restricted` 的 P 项报告不适用。纯运输槽必须既能从非运输单位取货口到达，又能到达非运输单位存货口，孤立运输环和断头不能靠自循环 LP 流充数。植物图按种子/植株、桥两轴分开，仅在采种/种植配方处转化，检查每台实际粉碎植株机器的再生回路来路。

物品传播不使用 `allowed_items` 作为过滤器。它以真实来源各端口物品、设计配方产物为种子，并继续加入完整机型配方表中来料种类已到达的配方产物，直到最小不动点。分别报告本机型误料、设计外配方原料/可启动配方和设计通道集合外物品。保守风险未被排除时拒绝受限类，不将其推广为所有布局不可能。

### 平均流和证书

每条物理通道按物品建连续变量；每个普通运输槽共享总容量 1，桥 H/V 分别守恒且分别容量 1。逐台机器的输入、输出分开守恒，配方用量与耗时固定，`Σ耗时×批率≤1`；无电或关机时批率为 0。每个真实矿口供其指定矿恰 1 件/tick，非成品入库为 0；两种成品仅从核心存货通道和实际箱体无线传输汇总，分别达到 3/5、11/20。准入口过滤、k5/5 与有限累计长期 0 均加入模型。

未附见证时，先求基础可行性，再最大化所有结构通道共享的 δ。浮点求解只负责寻找候选数值；用多个有理数近似上限重建向量后，以 `Fraction` 逐行核所有等式、不等式、非负性和 δ>0。这些近似上限是取证策略，不限制问题内部流量分母。返回的精确 δ 是已核正流下界，不宣称其精确最优。

附见证时，先检查通道/机器配方/箱体覆盖恰一次，再用同一份从真实布局重建的约束精确复算；不是信任候选的自报结果。错误见证会被拒绝，不据此宣称同布局无其他平均流。

`INFEASIBLE_EXACT` 须有零系数矛盾行或经精确逐列核验的 Farkas 证书；`ZERO_SUPPORT_EXACT` 须有证明 δ≤0 的精确对偶界。浮点 infeasible、微小正数、超时或有理化失败均不能直接作证，返回数值未决。不自行改变输入的 `allowed_items`、配方集合或固定路径速率来获取通过。

### 额外限制登记与候选 B

N/P 必选限制 ID 及非空的来源、覆盖损失、撤去义务、失败范围必须齐全。对其他多配方机型选用严格子集时需登记 `recipe-subsets`；附 `logical_feeds` 时需登记 `fixed-logical-feeds`。为避免把自由文本当作已执行约束，目前只解释下列额外 ID，并要求 `statement` 与表中对应文本完全一致。未知 ID 显示 `UNIMPLEMENTED`，阻止 `STATIC_PASS`；不会静默放行。

| ID | 支持的 statement |
|---|---|
| `recipe-subsets` | recipe_ids 限定本候选的配方集合；不把它当成游戏开关。 |
| `fixed-layout` | 本候选文件固定全部单位的位置、朝向与设定。 |
| `fixed-channel-items` | physical_channels.allowed_items 固定设计物品支持。 |
| `fixed-logical-feeds` | logical_feeds 固定端点、路径、物品与精确速率。 |
| `candidate-b-preserved` | 逐项保持候选 B 的机器、52 个来源与 315 条逻辑送料。 |

其他登记字段仍按格式填写真实内容。该白名单是检查器可执行解释的边界，不是原问题的新增数学约束。

有 `logical_feeds` 时，逐条核起终 PortRef、每段真实通道、相邻段同运输槽、桥不换轴、单物品及速率等式；每条实体通道恰归一条路径。旧逻辑端口名不直接解释为物理 offset。

声明 `candidate-b-preserved` 时，核候选 B 来源文件 SHA、219 台的 ID/机型/配方、52 个来源到全部真实矿口的双射及物品、315 条 LF 的 ID/源汇/物品/精确速率，以及不同旧逻辑端口到不同实际端口的映射。仅在 provenance 中记录 B，不等于宣称逐项保持；报告明确区分这两种情况。

### rt_k16 / rt_k17

## 验收边界

当前没有一份真实完整全厂正例用于端到端 `STATIC_PASS` 验收。已有证据覆盖解析、几何/通道正反例、全部台账执行、纯速率层精确可行性和全厂反例拒绝；不能把这些测试相加当成已获得全厂候选。

完整候选还须由另一独立实现核对。静态通过也不交付调试办法、运行初态、时序与库存不变量、全部合法先后及全部相关可达循环态证明，不把任何结果报为已认证 L。失败范围遵守冻结共识稿第四节：只限已记录的候选、支持、限制与所核见证；不排除未覆盖分支。
