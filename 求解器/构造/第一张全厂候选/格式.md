# 全厂静态候选文件格式

日期：2026-09-22。状态：v1 格式定义完成；生成器和两份独立检查器的待实现输入契约。本文不包含全厂可行布局或运行证书。

格式标识为 `full-factory-static-v1`。一个 UTF-8 JSON 文件完整描述一张 70×70 布局、建成后保持的全部可设定项、设计物料限制和声明的最大空矩形。生成器写入，两个检查器分别从单位占格和端口重建结构通道，联合连续 LP 检查平均流量。静态通过不更新已认证运行布局的 L。

## 1. 依据与适用范围

唯一规则来源是仓库根目录的以下三个文件。本版核读时，《求解约束》有 71 条，按每条的“据”行计数。

| `source_fingerprints` 键 | 仓库根相对路径 | 本版核读的 SHA-256 |
|---|---|---|
| `rules` | `《明日方舟：终末地》游戏规则.txt` | `52df4c12ce90975b861a6a663bd37873e03c9549658d200dc7e95fabc4bc29f3` |
| `task` | `求解任务.txt` | `1630ca1febec79b324aa3afb110be2d3330298e266c68b06415c3d1516108bac` |
| `constraints` | `求解约束.txt` | `cf44821f07779490b9b1d913bfb87d7757ae8abfe784c912bb7891868780f7f3` |

表示与证据边界依据 [会议 3 纪要](../../会议成果/会议3/纪要.md)及[冻结共识稿](../../会议成果/会议3/共识稿-v4-7aae9e20.md) §1.1、§1.3、第三节第 3 条和第四节。字段核对了 `seat-opus-3/p2p.py`、`router.py`、`check.py`、`seat-opus-4/check_full.py`，并读取 `seat-opus-2/flowcheck.py`、`seat-opus-1/fulllp.py` 的流量接口。

可用的会议布局样本是 `seat-opus-3/rt_k16.json`；`r_k16_tile.json` 为 UNKNOWN 记录，没有 `layout`。不能把未找到布局的记录转成空布局。候选 B 的来源是 [contract.json](../../数据/候选B/contract.json)：219 台、315 条逻辑送料记录、52 个尚未指派物理身份的矿石来源；它没有完成几何布线。其旧报告及《思路.txt》的 56 条约束口径不能代替上述现行文件。

引用说明：现存 [seat-codex-3.md](../../会议成果/会议3/seat-codex-3.md) 为最终立场，没有第六节。本文 §8 的限制登记依据冻结共识稿 §1.3 明列的“来源、覆盖损失、撤去后的义务、失败范围”，不声称复现一份现存的第六节。

v1 支持 `p2p`、`n_restricted` 两种受限候选类，定义见 §8。它可以表示五类运输单位和协议储存箱，但受限类检查会进一步拒绝不满足该类要求的实例。局部窗口、虚拟来源和运行初态不是本格式的完整全厂输入。

## 2. 基础类型、坐标和端口

### 2.1 编码与严格读取

- JSON 对象不得有重复键；拒绝未知字段、未知枚举、遗漏必填字段和错误类型。下文仅标明“可选”的字段可以省略；`null` 只在明确允许的位置有意义。
- 整数必须是 JSON 整数，布尔值仅用 `true`、`false`；不得把布尔值、浮点数或数字字符串当坐标。所有列表无隐含时序，数组顺序不表示建造、接通、判定或轮询次序。
- `Id` 是匹配 `[A-Za-z][A-Za-z0-9_.-]{0,63}` 的字符串。单位 `id` 在整个 `layout` 内唯一；通道 ID、逻辑送料 ID、限制 ID 各在自己的列表内唯一。引用按 ID 解析，禁止按数组下标猜身份。
- `Text` 是非空字符串。`Sha256` 是恰 64 位小写十六进制字符串。
- `Rate` 是非负、约分后的有理数字符串：`"0"`、正整数如 `"1"`，或 `"n/d"`（正整数 n、d，d≥2，互素，无前导零）。不接受 `0.6`、`"0.6"`、`"2/2"` 或指数记法。流量单位是件/tick，配方批率单位是批/tick。例：`"3/5"`、`"11/20"`。此编码不规定统一分母或实际运行周期。
- `Item` 只取 §3 的正式物品名。物品集合以无重复字符串数组编码。`Rates` 是键为 `Item`、值为 `Rate` 的对象；未出现的物品值为 0，已列的值须大于 0，空对象表示全零。
- 无单位占据的格自动为空；不另存 ASCII 图、4900 格矩阵或占格总数作为第二份权威数据。日志、求解状态和检查结果放另一个文件，不混入候选根对象。

### 2.2 坐标和方向

左下角格为 `(0,0)`，x 向右、y 向上，格坐标均为 0…69；与正式“矩形离带”相同。这里的 `(x,y)` 指格，不是图像左上角或格中心的实数坐标。

| `Side` | 方向 | 从本格到邻格的位移 |
|---:|---|---|
| 0 | E，右 | `(1,0)` |
| 1 | N，上 | `(0,1)` |
| 2 | W，左 | `(-1,0)` |
| 3 | S，下 | `(0,-1)` |

方向始终表示本单位边的外法向。对边 `opp(d)=(d+2)%4`。例如向右行进的直带为 `in_side=2, out_side=0`；`in_side` 不是物品行进方向。

`Bounds` 为四个必填整数 `x0,y0,x1,y1`，占格闭区间 `[x0,x1]×[y0,y1]`，满足 `0≤x0≤x1≤69`、`0≤y0≤y1≤69`；宽 `x1-x0+1`、高 `y1-y0+1`。锚点是旋转完成后的占格左下角，不绕锚点再旋转。所有实体单位不得重叠。各类型再按 §5 核对固定尺寸；冗余上界不得被读者静默修正。

例：`x0=10,y0=20,x1=15,y1=23,Din=3` 是宽 6 高 4、下边存货、上边取货的大制造单位。

### 2.3 唯一端口引用

`PortRef` 恰有三个字段：

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `unit` | 已存在的单位 `Id`；不能是供电桩 | `"M000"` |
| `side` | `Side` | 端口所在的世界坐标边，如 2 |
| `offset` | 非负整数，须小于该边格数，且该位置确有端口 | 沿整条边从 0 编号；不是只给已有端口编号 |

E/W 边的 offset 自下向上递增；N/S 边自左向右递增，四边均不随旋转反转编号。给定 `Bounds`，端口内侧格依次为 E:`(x1,y0+offset)`，N:`(x0+offset,y1)`，W:`(x0,y0+offset)`，S:`(x0+offset,y0)`。外侧格再加该边位移。

运输单位的四条边长度均为 1，故 offset 必为 0。桥的 side∈{0,2} 指水平物品格、side∈{1,3} 指竖直物品格，不能用一个笼统桥节点让物品换轴。

例：`{"unit":"M000","side":2,"offset":1}` 是 M000 左边从下数第二格的端口。存取类别由单位定义推导，不在 `PortRef` 再写一遍。

## 4. 根对象和 layout

| 根字段 | 类型与取值 | 含义／例 |
|---|---|---|
| `schema` | 固定字符串 `"full-factory-static-v1"` | 必须显式版本匹配，不自动当作旧格式 |
| `candidate_id` | `Id` | 候选身份，例如 `"factory-0001"` |
| `source_fingerprints` | 恰含 `rules,task,constraints` 三个 `Sha256` | 对应 §1 的正式文件字节；检查器同时核验自己支持的规则版本 |
| `provenance` | 可选数组；元素恰为 `{path,sha256}` | `path` 是仓库根相对文件路径 Text，不含 `..` 或绝对路径；`sha256` 为 Sha256。例：候选 B 的 `contract.json`。仅记录来源，不动态导入其语义 |
| `targets` | 恰含两个 Rate | `高容谷地电池:"3/5"`、`精选荞愈胶囊:"11/20"`；均固定，不准降低目标 |
| `layout` | 下表对象 | 全部实体单位与占格 |
| `empty_rectangle` | `Bounds` | 声明的全布局最大合格空矩形，见 §7 |
| `design` | §8 对象 | 受限类、全部声明通道、设计物品范围及可选逻辑路径 |
| `flow_witness` | `null` 或 §9 对象 | `null` 表示未附平均流见证，检查器仍须求解 LP，不能当作流量为零或已通过 |

| `layout` 字段 | 类型与取值 | 含义 |
|---|---|---|
| `W`,`H` | 整数，均固定为 70 | 基地尺寸 |
| `machines` | 制造单位对象数组，详见 §5.1 | 台数由实际数组重算，不在格式中钉死为 219 |
| `warehouse_outlets` | 仓库取货口对象数组，§5.2 | 每个实体分别占格、设置物品；达标静态条件要求左、下各 23 个 |
| `core` | 单个协议核心对象，§5.3；不允许 null | 基地内唯一协议核心 |
| `power_poles` | 供电桩对象数组，§5.4 | 全部桩；覆盖状态重算 |
| `storage_boxes` | 协议储存箱对象数组，§5.5 | 无箱时必须显式为 `[]` |
| `transport` | 运输单位对象数组，§6 | 每一实体运输格恰一条记录 |
| `vin`,`vout` | 均固定为 `[]` | 保留会议字段以显式禁止虚拟边界供料、接收；非空即拒绝 |

除核心外的单位数组长度在语法层为 0…4900；占格、正式台数下限与受限类再决定是否合法。空数组只说明没有该类单位，不代表检查已通过。

## 5. 非运输单位及全部可设定项

各对象的字段集合恰为本节所列字段；`Bounds` 展开为 `x0,y0,x1,y1` 四键。物品库存、制造进度、传输冷却、轮询指针、初始累计已收量和调试操作不是静态设定，不得混入这里。

### 5.1 制造单位

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | `Id` | 如 `"M000"`，可保留候选 B 机器 ID |
| `model` | §3 的九个机型全名之一 | 如 `"精炼炉"`；这是机型权威字段 |
| `kind` | `"小"`、`"中"`、`"大"` | 必须与 model 对应，不独立改变机型 |
| `x0,y0,x1,y1` | `Bounds` | 旋转后的占格 |
| `Din` | `Side` | 整条存货边的外法向；取货边为 opp(Din) |
| `recipe_ids` | 非空、不重复的本机型 RecipeId 数组 | 设计中允许采用的配方集合，例如 `["精炼-蓝铁矿"]` |
| `settings` | 恰含 `manufacture_on` 布尔值 | 建成、调试后保持的制造开关；`false` 时设计批率须为 0 |
| `role` | 可选 Text | 旧代码的显示角色名，如 `"精炼-蓝铁矿"`；不解析它来确定机型、配方或端口 |

小型占 3×3，中型占 5×5。大型 Din∈{1,3} 时占宽 6 高 4，Din∈{0,2} 时占宽 4 高 6；6 格长边全为端口。各机型所有存、取货边格都是端口，不能因为设计只用了一个就删掉其他端口。

正式规则没有“玩家锁定机器配方”的设定。`recipe_ids` 是设计声明，用于限定本候选 LP 的配方批率及核查实际可达来料，不能阻止机器在收到其他合法原料后启动其他配方，也不能使存货口自动拒收误料。两份检查器须分别报告本机型误料和设计外配方原料；在本受限候选类中，未消除的设计外来料风险不能以该字段覆盖。单配方选择是候选限制，须登记在 §8。

例：`{"id":"M000","model":"精炼炉","kind":"小","x0":2,"y0":1,"x1":4,"y1":3,"Din":2,"recipe_ids":["精炼-蓝铁矿"],"settings":{"manufacture_on":true}}`。

### 5.2 仓库取货口

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | `Id` | 如 `"OUT_L00"` |
| `x0,y0,x1,y1` | `Bounds` | 完整实体占格 |
| `Dout` | 0 或 1 | 唯一取货端口向基地内的方向：左带为 0，下带为 1 |
| `item` | Item；本任务合格候选仅 `"源矿"` 或 `"蓝铁矿"` | 该口连接的仓库物品格，属真实设定项 |

左带：Dout=0，`x0=x1=0`，`y1=y0+2`。端口为 side=0、offset=1，内侧格 `(0,y0+1)`，外侧格 `(1,y0+1)`。

下带：Dout=1，`y0=y1=0`，`x1=x0+2`。端口为 side=1、offset=1，内侧格 `(x0+1,0)`，外侧格 `(x0+1,1)`。

沿边锚点范围是 0…67；没有钉死角格为空。两边各 23 个及全部实体不重叠会限制剩余空格，检查器按正式“边带排布”重算。全体 46 个口加核心六口的物品设置，须共 18 个源矿口、34 个蓝铁矿口；LP 中每口总出货率为 1。

例：`{"id":"OUT_L00","x0":0,"y0":1,"x1":0,"y1":3,"Dout":0,"item":"蓝铁矿"}`。取货口不需电，无开关，也没有可设的输出速率。

### 5.3 协议核心

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | 固定 `"CORE"` | 唯一核心身份，兼容候选 B |
| `x0,y0,x1,y1` | `Bounds`；宽高均 9 | 语法锚点范围 0…61；核心离带等正式约束另查 |
| `Din` | Side | 标识其中一条存货边；Din 与 opp(Din) 为存货边，另两边为取货边 |
| `output_items` | 恰 6 个 `{side,offset,item}` 对象，无重复端口 | 六个取货端口各自设置的物品，不按数组顺序编号 |

`output_items[].side` 必须是 `(Din+1)%4` 或 `(Din+3)%4`；每边 offset 恰为 1、4、7，六种组合必须齐全。`item` 是 Item，合格候选仅源矿或蓝铁矿。每条存货边 offset=1…7 各有一个存货端口，共 14 个；存货端口没有过滤设定。核心不需电，也没有制造或传输开关。

Din=0 和 2 在端口几何上等价，Din=1 和 3 同理；保留四向写法以与机器 Din 统一。`output_items` 使用世界坐标边和 offset，不通过旋转旧列表推断物品身份。

例：核心占 `[20,28]×[20,28]`、Din=0 时存货边为 E/W；取货配置的一项 `{"side":1,"offset":4,"item":"源矿"}` 指 `(24,28)` 上边端口，其外侧格为 `(24,29)`。完整六项例见 §11。

### 5.4 供电桩

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | Id | 如 `"P000"` |
| `x0,y0,x1,y1` | Bounds；宽高均 2 | 锚点 0…68 |
| `orientation` | 整数，固定 0 | 2×2 方形且覆盖旋转不变，采用唯一规范值，不增加无意义朝向分支 |

把格 `(x,y)` 视为平面方格 `[x,x+1)×[y,y+1)`，桩中心为 `(x0+1,y0+1)`，供电范围为 `[x0-5,x0+7)×[y0-5,y0+7)`，与基地相交；对应覆盖格列 `x0-5…x0+6`、行 `y0-5…y0+6`。需电单位与该范围有至少一格重叠即得到供电状态，仅边界相碰不计。任一桩覆盖即可，不要求整个单位在范围内。

例：`{"id":"P000","x0":6,"y0":6,"x1":7,"y1":7,"orientation":0}` 覆盖基地内列 1…12、行 1…12。桩无端口、无开关；不存 `powered` 或被供电单位列表。检查器从全部桩重算制造单位、储存箱的供电，关闭开关的单位仍占地。

### 5.5 协议储存箱

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | Id | 如 `"BOX000"` |
| `x0,y0,x1,y1` | Bounds；宽高均 3 | 锚点 0…67 |
| `Din` | Side | 该边三格均存货，对边三格均取货 |
| `settings` | 恰含 `transfer_on` 布尔值 | 无线传输开关；不控制物理端口 |

例：`{"id":"BOX000","x0":30,"y0":10,"x1":32,"y1":12,"Din":2,"settings":{"transfer_on":true}}`。

六个编号物品格各可放 50 件，编号为 1…6，规则固定，无玩家指定槽位物品或取货优先序字段。无线传输必须同时有供电且 transfer_on=true；无电或关闭传输仍可物理中转。LP 的按物品守恒是平均流必要条件，不把箱子认成可任意挑货的 300 件池。p2p 类必须 `storage_boxes=[]`。

## 6. 运输格状态与设定

每条记录的公共字段恰为 `id:Id`、`x:0…69 整数`、`y:0…69 整数`、`type`，再加下表中该 type 的字段。全部运输单位均为 1×1，无需电功能或开关，不另填 Din、Bounds 或旋转角。

| `type` | 附加必填字段及范围 | 确切含义 |
|---|---|---|
| `belt` | `in_side:Side`，`out_side:Side`，二者不同 | 一存一取，共 12 种；另两边无端口 |
| `splitter` | `in_side:Side` | 指定边存货，其余三边取货；三支共用一个容量 1 的物品格 |
| `merger` | `out_side:Side` | 指定边取货，其余三边存货；三支共用一个容量 1 的物品格 |
| `gate` | `in_side:Side`，`filter:Item或null`，`k5:1…5整数或null`，`cum:1…5000整数或null` | 存货边和对边取货；filter=null 表示不设物品限制，两个上限必须也为 null；设物品后可分别设两个上限 |
| `bridge` | `H_in:0或2或null`，`V_in:1或3或null` | 两轴存货方向的设计声明，只用于与邻格推导结果比对，不能用于先造端口再验证自己 |

准入口 `k5=null`、`cum=null` 分别表示不设该上限；不能用 0、-1、false、空字符串代替。两个上限均是收件限制；每 5 tick 窗口从首件收件起算，不是全局固定 tick 分组。结构通道重算不得因过滤、累计额度或暂时关闭而删边。

桥分 H/V 两个独立物品格，两轴可以承载同一种物品。某轴两端邻格确有一取一存的相向端口时，由邻格取货端所在的边确定本轴存货方向。两端都没有端口朝它时，该轴方向声明必须为 null；这不删除桥的实体占格。单端接入、两端同类、声明方向不符均不能通过本受限类检查。两桥正交相邻在 v1 两个受限类中均拒绝，不用声明 null 绕过；这是 N4b 的保守限制，须登记覆盖损失。

下列是五类各一条字段例，彼此独立，不代表它们摆在一起已接通；桥例假定邻格能推出向右、向上的两轴：

```json
[
  {"id":"T10_10","x":10,"y":10,"type":"belt","in_side":2,"out_side":1},
  {"id":"T12_10","x":12,"y":10,"type":"splitter","in_side":2},
  {"id":"T14_10","x":14,"y":10,"type":"merger","out_side":0},
  {"id":"T16_10","x":16,"y":10,"type":"gate","in_side":2,"filter":"蓝铁矿","k5":5,"cum":null},
  {"id":"T18_10","x":18,"y":10,"type":"bridge","H_in":2,"V_in":3}
]
```

## 7. 声明的最大空矩形

`empty_rectangle` 恰为 Bounds。其宽 `w=x1-x0+1`、高 `h=y1-y0+1`，均为 6…70；派生面积 `A=w*h`，短边 `s=min(w,h)`。对应正式“矩形离带”的 `a=x0,b=y0,W=w,H=h`，这里大写 W/H 是该条文的矩形宽高，不能与 `layout.W/H` 混用。

矩形须不含任何实体占格，包括无流量的运输格、关闭的机器／箱、未用桥轴所在格和供电桩。供电覆盖区不是实体，可以覆盖矩形。检查器独立搜索整张占格图中短边至少 6 的所有空矩形，按 `(面积,短边)` 字典序取最大，与声明比对。多处并列时允许声明任意一处；没有合格空矩形即失败。不能仅确认一块保留区为空，就把它称为全布局最大空矩形。

例：`{"x0":40,"y0":40,"x1":45,"y1":47}` 表示 6×8、48 格、短边 6。候选里不另存可被误信的面积或 L 字段；该声明不等于已认证运行的 L。

## 8. 设计声明、结构通道和限制登记

### 8.1 design 对象

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `class` | `"p2p"` 或 `"n_restricted"` | 明确本候选受限域，不设关闭检查的开关 |
| `physical_channels` | 通道对象数组，长度 0…9800 | 全部声明的实体端口相遇通道，须与独立重算集合完全一致 |
| `restrictions` | 限制对象数组 | 已使用的受限类限制及额外固定项，格式见 §8.3 |
| `source_bindings` | 可选绑定对象数组 | 逻辑矿石来源到真实端口的映射；沿用候选 B 时必填 52 项 |
| `logical_feeds` | 可选逻辑送料对象数组 | 已完成物理展开的逻辑路径；沿用候选 B 时必填 315 项；v1 仅 p2p 类使用此字段 |

每个 `physical_channels` 元素恰有：

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | Id | 如 `"PC000000"` |
| `from` | PortRef | 取货端口 |
| `to` | PortRef | 相邻的存货端口 |
| `allowed_items` | 非空 Item 集合 | 本通道设计流允许采用的物品；p2p 恰一种，n_restricted 可多种 |

不同 id 不得复用同一对物理端点。这个列表是供核对的声明，不是事实来源。先由格状态重建完整集合，再逐个端点比对；不能只比条数，也不能先沿列表找通道。至少一端须为运输单位，两端的端口内侧格正交相邻、方向相对、恰一取一存，才形成结构通道；反过来满足条件就必须列出。非运输单位之间贴靠不形成通道。无线入库不属于这个列表，缓存内部通道也不属于它。

例：`{"id":"PC000000","from":{"unit":"OUT_L00","side":0,"offset":1},"to":{"unit":"T1_2","side":2,"offset":0},"allowed_items":["蓝铁矿"]}`。

`allowed_items` 是搜索／设计限制，不是额外的游戏过滤器；不能在物品可达检查里凭它挡货。静态种类传播以真实结构通道为边，仓库取货口和核心的**每个取货端口**分别以其 item 为来源，不能把核心六口物品合并后分给每个口。制造单位以 recipe_ids 的产物为种子，再将完整机型配方表中原料种类均已到达的配方产物加入；这只是可能性传播，不作启动能力证明。普通运输物品格原样传播，桥两轴分开，gate 仅向下游传播 filter 允许的种类，储存箱将所收种类传播到物理取货口；核心存货不产生新的自由出库物品。求最小不动点后检查误料、设计外配方原料及通道 allowed_items 之外的可能物品。

单纯存在有向路径不证明物品一定到达；保守传播未能排除风险时，应记受限类未通过或未决，不据此证明所有几何布局不可能。种子传播同样不代表仓库能持续供应种子，植物起动仍在运行阶段处理。

### 8.2 两种受限类

两类均要求 N1–N5b：

| 限制 ID | 本版要求 |
|---|---|
| `N1` | 非运输单位有至少两条结构取货通道时，不得有一条直连汇流器。核心、取货口、储存箱同样纳入非运输单位判断 |
| `N2` | 一个单位有至少两条结构存货通道时，不得有一条来自分流器，含密集结点。桥先按同一个物理单位汇总此项；流量容量才分两轴 |
| `N3a` | 承载正设计流的准入口 cum 必为 null；因为 N5b，所有有结构通道的承载准入口均受此要求 |
| `N3b` | 对 filter 非 null 的准入口，从每个直接上游出口的可能物品中取出被拒种类；每种都须在该上游同一物品格／共用取货侧有另一条结构出口，其首格不按身份拒绝它。桥另一轴不算替代出口，核心另一个定物品取货端口也不算。筛查通过只确认未发现该类永久堵死图样，不证明及时通过或运行活性 |
| `N4a` | 桥每条接通轴的邻端口一取一存，未接通轴两端均无朝它的端口；声明方向与重算一致 |
| `N4b` | 不允许两桥正交相邻（v1 的保守加强）；无依赖接通先后的桥定向 |
| `N5a` | 按“当且仅当”重算全部结构通道，与 physical_channels 一一比对 |
| `N5b` | 每条结构通道物品流合计严格为正；由 §9 联合连续 LP 的共同 δ 或精确正流见证核验，不能以拓扑可达代替 |

`p2p` 在以上要求之外还要求 P1–P6：

| 限制 ID | 要求 |
|---|---|
| `P1` | 只用 belt、bridge，不放 splitter、merger、gate 或协议储存箱 |
| `P2` | 每条端口到端口路径只走一种物品，路径从一个非运输单位取货端口到一个非运输单位存货端口，中间只有运输单位；沿途同一物品、同一总速率 |
| `P3` | 每条形成的结构通道都在用，无零流量暗接 |
| `P4` | 桥的使用轴两端都为在用通道，未用轴没有邻端口朝它 |
| `P5` | 两桥不相邻 |
| `P6` | 粉碎机与采种机每台仅一个 recipe_id；其他机器单配方若也固定，须另登记，不能说成 P2 的自动推论 |

运输物品格不得成为没有非运输来源／去处的纯运输循环，不能靠 LP 自循环流伪装有效送料。植物回路可以存在，但必须经过真实的采种、种植转化，并按物品区分和正式“植物再生来路”等条目检查。

两种类名不限制台数等于某个历史候选；固定 219 台、固定边带排布、单机单配方、固定路线、固定数值速率及固定最小正流量等另登记。n_restricted 允许本格式全部单位种类，仍须履行 N 项及箱体的静态义务。解除上述任一 v1 必选限制需要新契约版本，不能静默忽略检查。

### 8.3 限制对象

每项恰有以下字段。必选类限制也必须登记，可引用本节编号，但其覆盖损失等四项不能留空。

| 字段 | 类型与范围 | 含义 |
|---|---|---|
| `id` | Id | 如 `"P6"`、`"fixed-b-layout"` |
| `source` | 非空、无重复数组；枚举 `"dynamic"`、`"shape"`、`"numeric"` | 分别为动态便于证明、形状便于求解、数值限制；可多选 |
| `statement` | Text | 限制或固定项的精确定义和参数 |
| `coverage_loss` | Text | 哪类原问题允许的布局／配方／流量可能被丢掉 |
| `release_obligations` | Text | 撤去限制后须补什么表示、检查或证明 |
| `failure_scope` | Text | 固定项、仍开放的自由度，以及失败最多能排除什么；初态／调试／全部合法先后未覆盖须明确写出 |

例：

```json
{
  "id":"P6",
  "source":["dynamic"],
  "statement":"每台粉碎机、采种机的 recipe_ids 恰有一项。",
  "coverage_loss":"不覆盖这两类机型混做配方的布局，包括可能的 217 台分支。",
  "release_obligations":"补多配方流、物品可达及混做清空等相应义务。",
  "failure_scope":"仅约束本候选的配方选择；位置与路径是否固定以候选完整字节为准。调试、初态和全部合法先后的运行不在静态检查内；本候选失败不排除混做或其他布局。"
}
```

执行失败报告须另外记录候选 SHA、检查器／模型版本、固定项、开放自由度、所查量词、失败类型和精确证据。UNKNOWN、启发式未找到、充分条件未通过、固定支持 δ=0 不等于全域几何不可行，均不降低 U。限制文本不是检查器可执行代码，也不能替代已实现的检查；遇到无法解释的额外限制须报告未覆盖。

### 8.4 候选 B 来源与路径的物理落实

`source_bindings` 每项恰为 `{logical_source_id:Id, port:PortRef}`，最多 52 项，两类身份分别无重复。前者如 `ORE018`；port 须是一个仓库取货口的唯一端口或核心的一个取货端口。沿用 B 时 52 个逻辑来源 ID 和 52 个物理端口全部覆盖，来源 item 与实体设定一致。例：`{"logical_source_id":"ORE018","port":{"unit":"OUT_L00","side":0,"offset":1}}`，B 中 ORE018 与 §5.2 的 OUT_L00 均为蓝铁矿。

`logical_feeds` 最多 9800 项，每项恰有：

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `id` | Id | 保留 B 的 LF ID，如 LF000 |
| `from`,`to` | PortRef | 真实非运输源取货口与真实非运输汇存货口 |
| `item` | Item | 路径唯一物品 |
| `rate` | Rate，0<rate≤1 | 设计固定的每 tick 件数；不是实测值 |
| `path` | 非空、无重复的 physical_channels ID 数组 | 唯一具有顺序语义的列表：从 from 到 to 的完整实体通道序列 |

路径相继端在同一运输物品格衔接：普通运输格为同一格，桥须同一轴且直穿。不得跳格、转轴、跨过制造单位或储存箱。每条实体通道恰属于一条 p2p 逻辑路径，全部实体通道均覆盖；共享一座桥的不同轴可以属于两条不同路径。路径速率进入本候选 LP 的等式，故“沿用 B 的固定速率／端点指派”须作为限制登记。

沿用 B 时逐个核对 219 台机器的配方、315 条 LF 的源汇物品和精确速率；机器侧旧 `Mxxx:in:1` 等是逻辑端口名，不能直接解读成 offset=1。转换须给每条 LF 分配具体 PortRef，并保持不同逻辑端口映射到不同物理端口。CORE 的六条成品入库路径也须逐条落实为其真实存货端口。若修改 B 的任一固定内容，应登记修改后的设计域，不声称原 B 逐项保持。

没有附 logical_feeds 时，由两个检查器对 p2p 实体图独立做路径分解，LP 自行选连续速率；此时不宣称已经兑现 B 的固定指派。无论是否附映射，`vin/vout=[]`，模块内的虚拟矿、植物粉和出料接收条件必须替换为真实完整通路。输入时序及实际下游接收能力仍属后续运行义务。

## 9. 可选平均流见证与联合连续 LP

### 9.1 flow_witness 对象

非 null 时恰有以下四个字段。它是可独立复算的设计见证，不含“已通过”布尔值，不代替检查器建模。

| 字段 | 类型与范围 | 含义／例 |
|---|---|---|
| `channel_flows` | `{channel_id:Id,rates:Rates}` 数组 | 每条 physical_channels 恰一项；rates 的正值键须在该通道 allowed_items 中 |
| `batch_rates` | `{machine_id:Id,recipe_id:RecipeId,rate:Rate}` 数组 | 每台机器每个 recipe_ids 配方恰一项，允许 rate=0；其余配方设计批率为 0 |
| `box_transfers` | `{box_id:Id,rates:Rates}` 数组 | 每个储存箱恰一项；无线入库各物品流量，无箱时为 [] |
| `delta` | Rate，0<delta≤1 | 一份经精确核验的所有结构通道总流下界，不宣称为最大 δ；无通道时不得附正 δ 见证 |

例：channel_flows 的一项为 `{"channel_id":"PC000000","rates":{"蓝铁矿":"1"}}`；batch_rates 的一项为 `{"machine_id":"M000","recipe_id":"精炼-蓝铁矿","rate":"1"}`；box_transfers 的一项为 `{"box_id":"BOX000","rates":{"高容谷地电池":"1/5"}}`。这些只是字段片段，不能独立构成全厂见证。

### 9.2 必须重建的流量条件

LP 使用分物品连续变量，不把候选 B 的 20 tick 速率窗口当作所有可能流量的分母或实际周期。至少包含：

1. 物理通道端口容量：每条通道各物品总流≤1。每个非桥运输物品格逐物品入=出、总出≤1；分流／汇流三支共享这一容量。桥 H/V 分别守恒、分别≤1，不跨轴抵消。
2. 机器逐物品进料等于各配方用量×批率之和，出料等于各配方产量×批率之和；同机 `Σ(耗时×批率)≤1`。机器没有供电或 manufacture_on=false 时全部批率=0。输入、输出分开，不能将运输格改成生产节点。
3. 仓库的 52 个物理取货端口只按各自 item 供矿，各为 1 件/tick；不增加植物、种子或模块虚拟来源。源矿合计 18、蓝铁矿合计 34。每种非成品入库量为 0；成品按 CORE 存货通道加箱体无线量汇总，电池≥3/5、胶囊≥11/20。仓库不能当成无限外源给植物回路凭空补料。
4. 准入口按 filter 限物品；k5 非 null 时总收量≤k5/5；cum 非 null 时长期循环平均通过量为 0，不以 cum/某个窗口估算持续供料能力。
5. 箱体逐物品入=物理外送+无线入库；无电或 transfer_on=false 时无线量=0。有限编号格和相位不能从这条平均等式推为已满足，须保留运行义务。无线弧不能绕过真实箱体、供电或成品入库限制。
6. allowed_items、recipe_ids、附带逻辑路径速率等设计固定项生效；求解基础可行性后，在全部非空结构通道集合上加 `Σ_i f[e,i]≥δ` 并最大化共同 δ。只要求每条通道合计正流，不要求每种物品或每个物品子集都在全部通道上为正。

检查器必须补查全部现行正式约束可在静态层核查的几何、计数、物品及平均流投影，并逐条列出前件和未覆盖义务。开关关闭的机器、无流量实体和桥的未用轴不得从占地计数消失；通道／箱体条件中“有通过量”“无线量为正”等前件按本份流见证判，不把全部结构边不加区分地代入运行支撑计数。

若附 flow_witness，以精确有理数核对全部等式、容量、目标和 delta。检查器仍需从真实布局建约束，不能接受仅“两个 LP 都返回 feasible”。未附见证时自行求 LP 并输出见证；浮点残差或很小正数不能直接充当严格正性的证书，无法确认应报告数值未决。δ=0 要有经核最优性／不可行证据才可否掉这组固定支持；超时或 UNKNOWN 仅为未决。非空全厂必须有正流结构；空支持需另查基础可行性，不能作真空 N5b 成功。

`flowcheck.py` 的不分物品、桥两轴合并且倍率 20 的网络只是放松筛子；`fulllp.py` 提供联合流思想，但其现有实例／配方表不是本全厂格式的自动实现。旧程序通过不等于以上全厂检查完成。

## 10. 两份独立检查器的输入与结论边界

两份实现分别完成：严格解析及版本／正式文件指纹核对 → 占格、端口和供电重建 → 桥方向推导 → 完整结构通道比对 → 空矩形重算 → N/P 限制与正式静态条件 → 联合分物品流核验。可以共用本文和规范数据，不能共用同一份通道重建函数再称独立互核。检查输出绑定候选文件 SHA-256 和所用检查器版本。

每条正式约束至少记录条名、前件依据、检查结果及剩余义务：已核、违反、静态可证前件不成立、运行阶段待证、未实现／数值未决须分开。71 条中涉及初态、时序、每个可达循环态和四个不得依赖量的部分，不能凭静态格式标成全部通过。没有箱子也不能免掉箱体接口中在 B=0 时仍成立的计数条件。

全静态闸门通过仅表示这份固定布局在记录的受限域内通过已实现的结构和平均流检查；两份检查器有差异、必需静态条目未实现或数值未决时不得给出全静态通过。运行条件、调试办法、内核执行及所有相关可达循环态达标不在本文数据范围，另行交付。不得用一个输入字段自行宣告运行成功或抬高 L。

## 12. 与会议字段的对应及迁移要求

| 会议／候选 B 字段 | v1 对应 | 设计理由 |
|---|---|---|
| 根 `layout`，内部 W/H、machines、transport | 原名保留；新增 schema 和固定全厂尺寸 | 降低布局导出改动，显式区分局部测点与全厂 |
| machines 的 Bounds、Din、kind | 原名及坐标语义保留；尺寸再由 model 核对 | 与两份旧检查器的端口计算一致 |
| `role` 隐含机型和配方 | model＋recipe_ids；role 仅可选显示 | 免除前缀猜测歧义，区分设计配方与真实可设项 |
| belt、bridge、splitter、merger、gate 字段 | 保留 in_side/out_side、H_in/V_in、filter/k5/cum | 桥方向仍为待核声明；gate 的三个可空字段必须显式给出 |
| vin/vout 虚拟接口 | 固定空数组；新增 warehouse_outlets、core | 防止模块免费来源和去处混进全厂 |
| 未有供电／箱体描述 | 新增 power_poles、storage_boxes 及单位 settings | 完整占地、供电和真实开关可以独立重算 |
| B 的 ORE 身份待求、逻辑端口名 | source_bindings＋PortRef＋logical_feeds.path | 给 52 个矿口和 315 条 LF 实际物理身份；保留平行送料记录 |
| 逻辑送料 315 条 | 逐格 physical_channels，加可选 LF 路径 | 315 是端到端逻辑记录数，不能冒充逐格实体通道数 |
| status、wall、grid、T、bridges 等求解摘要 | 留在旁路日志，不作为候选输入 | 检查器从布局重算，不信缓存统计 |
| 20 tick 标签、整数替代流 | 精确 Rate 见证＋连续 LP | 不将历史数值刻度施加为一般覆盖条件 |

旧检查器不能未经扩展直接接受此文件：它们会忽略核心等新实体，或继续解析 role。读取者必须先检查 schema 并支持所有字段和语义后才能认证；不得为让旧脚本通过而删除新实体、把真实矿口改回 vin，或仅提取 machines/transport 子图报全厂通过。
