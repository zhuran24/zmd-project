## 1. 非成品零入库

**verdict：未否证。revised_text：空字符串。**

核对条文：除两种成品外，物品经核心存货端口或箱子传输入库的周期件数均为零；植物回路每周期采种批次等于粉碎植株批次，种植批次为采种批次的两倍，适用于全部台数配置。

仓库是协议核心物品格的集合，协议核心在基地内，所以循环态的“基地状态重复”包含仓库存量重复。对既非两种原矿、也非两种成品的物品 x，所有仓库取货口和核心取货端口都只取原矿；制造使用制造单位自身的存货格和缓存格；箱子传输方向是箱到仓库；调试后玩家只拿成品。因此 x 没有仓库出口，也没有题设的外部补充。记一个周期两条入库途径分别送入 `I核,x` 和 `I箱,x`，则

`0 = W_x(t+P) − W_x(t) = I核,x + I箱,x`。

两个入量均非负，所以各自为零。植株、种子和全部植物粉末都在此范围内，论证没有使用种植机或采种机台数。

两种原矿不能直接套用这个仓库等式，因为有持续补矿和取矿；它们由正式“矿系不入库”覆盖。另按矿石收支核了一遍：全部18条配方都保持所含蓝铁矿和源矿的数量，电池含20份蓝铁矿、30份源矿，胶囊含40份蓝铁矿；每 tick 成品交付带走 `0.6×50+0.55×40=52` 份矿，全部仓库出口恰送出52份矿。仓库外状态按周期复原，因此额外返库的含矿量为零；任一原矿返库都会产生正的额外返库量，故两种原矿各自也零入库。

对一种植物，设采种、粉碎植株、种植的周期批次为 a、f、z，植株和种子入库件数为 w、s。逐种守恒给出 `z=a+f+w`、`2a=z+s`，消去 z 得 `a=f+w+s`。代入已经证明的 `w=s=0`，得到 `a=f`、`z=2a`。缓存格内尚未完成的批次在周期两端相同，计完成批次不会留下跨周期差额。

尝试的反例是调试时腾空植物仓库、调试后让多余植物持续入库。腾空只改变初值：每种物品在核心至多占一格、上限80000，成功入库会让仓库存量严格增加，该段运行尚未成为循环态。程序从79998件开始逐次尝试入库，实际增加量为 `1、1、0、0`；达到满格后持续入库消失。增加种植机台数也没有增加植物的仓库出口，故这两种尝试均未否证条文。

## 2. 传输按仓库余量判定（修）

**verdict：未否证。revised_text：空字符串。**

核对条文：有电且传输开启的箱子，每次冷却结束后的传输判定前，某非成品在箱内的件数 n 与仓库对它的余量 f 必须满足 `n=0` 或 `f=0`；仓库已满且不会再出库时，开启传输这一机制本身不阻止该物品经物理端口中转。

传输的一次判定发送箱内全部物品中仓库能收下的部分；不同物品有各自的仓库物品格，同一物品在箱内分占多个格也共用该物品的仓库余量。因此对一种物品，本次发送量恰为 `min(n,f)`。这里的 n、f 都取本次判定紧邻之前的值：同刻其他箱子或核心先入库造成的变化已经算在 f 内，尚未执行的判定则尚未改变它。由第1条，循环态每次非成品发送量都为零，所以 `min(n,f)=0`，恰好等价于条文的两个分支。

满仓钢块例子成立于这一步的机制层面：调试后仓库钢块已有80000件，仓库出口只取原矿，玩家只拿成品，钢块库存便一直满格；箱子即使物理收发钢块，每次无线发送仍为零。开启传输并没有关闭箱子的物理端口。脚本对进箱、出箱、传输的6种固定先后和每5 tick内以1/4 tick为步长的20种相位，共120种组合，运行20 tick，均得到物理出箱20件、无线入库0件、箱内首尾各1件。

尝试把钢块改成仍有一个空位，且安排传输在进箱后、出箱前执行：发送量立即为1，违反零入库。尝试只让钢块同刻进出、希望避开传输，则必须检查传输夹在进出之间的固定次序；有余量时仍会发送，满仓时仍为零。尝试让同一种物品分占六格，发送总数仍为 `min(n,f)`；程序核了36864种箱格与余量组合，均一致。两种原矿仍有仓库出口，钢块“满后恒满”的理由不适用于它们；它们也仍须逐次满足 n、f 的条件。

与现行文字的关系需要区分清楚。《求解约束.txt》第66行“只输送成品或植物系物品”若指无线入库，与本条相容；若用来禁止开传输箱子的物理中转，则其旧推导缺少仓库有余量这一前提。《候选约束.txt》第171—173行确实从“有相位撞上传输”直接推出“该物品入库”，而满仓时这一步的发送量为零。本条补上的是这一步，含矿物品零入库的收支结论仍成立。满仓钢块例子提供的是局部机制证据；一张含此接法的达标全厂布局还需要几何、供料和调试可达性证据。

## 3. 准入满额窗口

**verdict：未否证。revised_text：空字符串。**

核对条文：未设累计上限且每5 tick限收 k 件的准入口，循环平均通过量恰为 `k/5` 时，每个自起窗口恰收 k 件，相邻窗口起点相隔恰5 tick；k=1时相邻收件时刻相隔恰5 tick。

规则第64行把窗口起点定为收下第一件的时刻；5 tick到期后的下一件启动下一窗。取一个窗口起点作周期起点，设周期内有 m 个窗口，第 j 窗收 `n_j` 件，相邻起点相隔 `d_j`。由于窗口至少持续5 tick且每窗上限为 k，有 `d_j≥5`、`1≤n_j≤k`。窗口状态也按周期重复，所以这些间隔连同最后一个跨周期边界的间隔合计为 P，收件数合计为 N。于是

`kP−5N = k∑(d_j−5) + 5∑(k−n_j)`。

右边每项都非负。若 `N/P=k/5`，每项必须为零，即逐窗收满、下一窗准时启动。若某窗少收或下一窗晚开，右边便为正；同一缺口在循环态逐周期重复，平均速率严格低于上限。准入口自身的单件库存也周期复原，因此收件与出件的周期总数相等，使用“通过量”没有多算暂存的一件。

尝试用后续窗口补回此前少收的件数，需要后续某窗超过 k，违反规则。尝试把窗口固定在外部时钟的5倍数，或者限制任意滑动5 tick，均改变了规则的窗口。k=2、收件时刻 `0、4、5、6` 时，自起窗 `[0,5)` 和 `[5,10)` 各收2件，但滑动区间 `[4,9)` 收3件。所有相邻收件至少隔1 tick，满足运输滞留；这个序列说明滑动窗限制会更强。

独立脚本对 k=1…5、时间步长1、1/2、1/3、1/4 tick分别建立窗口与运输间隔状态图，共20张图。每条边记录经过时间和收件数；若一条环超过 `k/5`，对应累计代价为负；若环恰好取等，对应累计代价为零。计算结果无负代价环，全部零代价环的到期窗都收满，并在到期时立即启动新窗。有限时间格的复算支持上述推导；上面的等式允许 `d_j` 为实数，覆盖任意相位及任意周期。

## 4. 箱内滞货封住后格

**verdict：未否证。revised_text：空字符串。**

核对条文：箱子在所考察循环态中没有无线外送，第 j 格的物品又被全部取货通道在箱口按身份拒绝时，第 j 至第6格没有出货和周期进货，正流量至多使用前 j−1 格的 `50(j−1)` 件库存空间；j=1时没有循环通过量。

“在箱口拒绝”是物品不能进入紧接箱子的首个运输物品格，例如首元件就是只放行别种物品的准入口。零干预运行使身份设置保持不变。第 j 格的物品不能物理离箱，也没有无线离箱量，所以该格永不变空。每次取货又必须选编号最小的非空格，任何出口都无法跳过它去取更大的格。于是 j…6 各格在整个周期中都没有出件事件，件数只能增加；循环态要求这些编号格各自恢复原状态，因此它们也没有入件事件。所有正流量只发生在前 j−1 格，每格上限50，得到所述容量。

尝试让其他出口绕过第 j 格，失败于“每次从编号最小的非空格取货”；这不是各个出口分别挑格。尝试让后来同种物品补进第 j 格，只会增加它的存量，无法构成复原周期。尝试把“下游较远处拒绝”作为反例，则箱口第一段带子仍可能取走这件物品，已经不满足候选前提。

第2格堵住也不强迫整个箱子停流：`[B×1,A×1,空,空,空,空]` 中全部出口只放B，可以反复取空第1格再补B，箱内状态每次复原。独立脚本运行了100次。把A移至第1格，B即使占有后格也不能取出。另以六格各取空、A×1、A×50、B×1、B×50，枚举37500个“箱状态、被拒绝格”组合及225000个存取动作；全部保持被拒绝格非空，尾部无物理出货。周期内零进货由前述单调性与复原要求推出。j=1…6的周转容量上限复算为 `0、50、100、150、200、250` 件，静态尾部仍占着真实箱格。

## 5. 满速箱头限存

**verdict：未否证。revised_text：空字符串。**

核对条文：箱子没有无线外送，c条取货通道合计平均外送 c 件/tick；其中首运输格不按身份拒绝 x 的有 c_x 条。当 `c_x<c` 时，全部同刻判定结束后，1号格的 x 至多 c_x 件。

端口对接使每次出箱都先进入运输物品格，后者容量为1且必须滞留至少1 tick。因此一条通道两次成功出箱至少相隔1 tick，循环平均至多1件/tick。c条合计恰为 c，迫使每条平均都为1。对其中任一条，若周期内成功N次，相邻成功事件连同跨周期边界共有N个间隔，总长P；每段至少1，而 `N/P=1` 给出 `P=N`，故每段都恰为1。于是每个长1 tick的半开区间内，每条通道恰成功一次，各通道的相位可以不同。

取同刻全部判定完成后的 t。若1号格至少有 `c_x+1` 件 x，则在 `(t,t+1]` 中只有接受 x 的 c_x 条通道能减少它，每条至多减少1件，合计至多 c_x 件；入箱只能保持或增加该格的 x，其他物品不能占据尚未清空的格。该格便在整个区间内非空。其余 `c−c_x` 条拒绝 x 的通道无法越过1号格取货，在该区间成功次数为零，与逐口满速矛盾。

尝试错开出口相位，仍逃不过任意长1 tick半开区间的逐口计数。尝试在同刻先出后进、以不同轮询次序清头，最多仍只能让接受 x 的 c_x 条口各取一件；`c_x+1` 件无法清空。尝试让 x 分占后格也没有帮助，因为1号格尚未空。若传输能送走 x，会多出一种减量途径，但这已违反“没有无线外送”的前提；若某出口允许等待、总外送率低于 c，也已离开候选的满速前提。

脚本枚举 `c=1…3`、`c_x=0…c−1`，箱头取 `c_x+1` 和50件，加入三条存货通道各进一件的全部X/Y/Z组合及全部进出先后，共130896种；接受 x 的出口同时允许其他两种物品，给出口更宽的选择。所有情况中拒绝 x 的出口均未成功，总出件最多 c_x。另对无进货情形遍历每一个超界箱头件数及全部出口排列，共1130种，结果相同。特别是三口中两口接受 x、箱头有3件 x 时，最多出2件。

优先级和轮询只会进一步限制哪些出口能动，不能让身份拒绝的出口取走 x，也不能突破运输格的1 tick间隔，故证明无需预设它们的有利取值。
