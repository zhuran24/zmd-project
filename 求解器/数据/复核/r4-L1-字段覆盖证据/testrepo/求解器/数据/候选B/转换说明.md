## 疑点与处理

- **匿名矿口**：原通道表的所有矿石源都写「仓库出矿口」，无法恢复物理身份。按原 C 行顺序建立 ORE000…ORE051 独立变量，分别保留物品和下游。没有随意把前一批变量指给左边界；域为左／下／核心的端口集合并要求互异。身份未决保留在每个变量内。
- **平均值与时序**：原 `P=20` 注释写周期，原 `批间隔tick` 用窗口除批数得到。输入明确改为速率窗口和计划平均批间隔；从整数批数重算精确有理数；源 fanout 的十进制文本用 Fraction 核对，不读成二进制浮点，若原值已舍入而不相等则报错；不当逐批时刻。M068 平均间隔为 2（候选），M218 平均间隔为 20/3（候选），都不证明恒定排程。
- **扇出状态**：原「A 满速／B 原文前提内／C 需推广版」映射为三种计划形状，独立认证栏全部待验。原 A/B 文字不能作为运行前提已满足的证据。满速扇出定则、轮询均分（松）均是候选，未审，后者不进入验证器。
- **图与活性**：`scc.py` 关于以强连通分量界定死锁分析范围的注释不能成立为运行认证。转换不沿用该缩域。按机器／仓库合并的简单图计数也不能替代端口计数；原 C109/C110、C174/C175 映射为 LF109/LF110、LF174/LF175，两组平行边分别保留。细分矿口后，节点身份也不同于原匿名图，不能混报原图节点数。
- **原脚本的设计律**：不等比分配缺少当前实现不等于所有不等比分配都不合法；无混做、无分流／汇流／箱／准入口及均分都是候选设计限制，不是正式必要条件。覆盖损失见送料契约。没有把原脚本注释中的强说法搬进规则库。
- **规则目录缺项**：原脚本只列所用配方，未列正式的精炼「蓝铁粉末→蓝铁块」。内置正式目录包含该配方，转换器回源比较完整配方表；候选本身没有新增机器或流量。
- **局部运输字段全空（仅四类运输单位）**：全空表示未布线，与原方案排除分流／汇流／箱／准入口的全局计划并存。桥接器用量未知。不能用空字段推导 T、b、E 为零，也不能因为 B=0 就免验箱体接口等约束的可知投影。
- **供料与同步**：43 台到达义务机器（含 38 台多物品配方机）的平均物料平衡通过不证明两种原料同步到达，不证明按配方用量归一化后的供给偏差有界，也不允许将运行义务缩至这些机器。
- **资料自身证据状态**：会议附带候选文件仍含与共识终态不同的强措辞，例如由限流上界推出必恢复。它们不是规则来源，未被实现；起动接线、准入口恢复等未决不在本交付中补机制。

## 格式与目录对接

contract.json 使用 `feeding-v2`；逻辑送料数组为 `logical_feeds`，所有 id 使用 LF 前缀。原 C 行编号数字部分不变，原始来源文件不改。端口相遇实体通道的交接字段为 `physical_channels`、前缀 PC；缓存内部通道为 `buffer_channels`、前缀 BC；后二者不在本静态输入中。
