# 1113 流量层：覆盖证明与约束

日期：2026-09-22。状态：已实现；求解状态及复核结果见《报告.md》。

本模型检查 70×70 基地中含固定空矩形 `[49,70)×[y0,y0+53)` 的达标布局的必要条件，`y0∈{6,7,9,17}`。坐标均为 0 起算；矩形以左下角和宽高表示。模型可行只提供必要条件骨架，不能认证游戏运行。

## 1. 输入和几何约束

正式依据是仓库根目录《明日方舟：终末地》游戏规则.txt、求解任务.txt、求解约束.txt。本目录 `inputs/*.txt.md` 保存逐字节副本，扩展名不改变内容；`manifest.json` 记录原文件散列。会议 3 冻结共识稿第二节第 4 条提供独立子集网络的整数替代方法，不作为额外游戏规则。

开工《求解约束.txt》快照为 71 条。运行期间观察到该正式文件变为 72 条：新增“1113 位置”，并整理矿系不入库、非成品零入库及植物守恒的文字/引用；后续72条版本又删除了一句储存箱中转说明。本模型限定无箱，所用数值界未变，所用零入库与循环守恒命题保留；新增位置条文恰为本次四位置及其转置。因此同一模型适用于这些已核对版本。各版本散列、完整差异及逐条核对见 [输入变化.md](输入变化.md)、[input_change_audit.json](input_change_audit.json)。

`geometry.py` 来自已冻结的 `inputs/solve_relaxation.py` 的构建部分；几何辅助函数来自本目录 `filter_positions.py`。显式标签主轮、紧凑矿石轮和全体层长测不使用区间 DP 限制，四位置均保留全部 47 种仓库边带及 `P=10,11,12`。恢复原 P 域的辅助目标复跑另述如下，仍保留全部边带。

计数和坐标的精确定义如下。

- P 是所选 2×2 桩位数；T 是运输布尔之和；b 是桥布尔之和。J 统计占格触及第 1 或 69 列/行的桩，每个桩只计一次；因桩原点从 1 开始，这等价于原点横坐标或纵坐标属于 `{1,68}`。
- X 统计 `(69,y), y=1…68` 及 `(x,69), x=1…68` 中，不属于制造机身、核心、桩或 R 的格。若 `(69,69)` 不在 R 且不被桩覆盖，再加 2。
- Y 统计 R 外沿四边正交相邻一圈格中，不属于制造机身、核心或桩的格；不含四个对角，R 贴基地边界的一侧没有这圈格。X 与 Y 可以计到同一格，对应不同方向，分别计费。
- 桩原点为 `(p,q)` 时覆盖半开区域 `[p−5,p+7)×[q−5,q+7)`。机器原点 `(x,y)`、尺寸 `w×h` 得电，等价于某个所选桩满足 `x−6≤p≤x+w+4` 且 `y−6≤q≤y+h+4`，并按桩合法原点 1…68 裁剪。前缀和只是这项存在性条件的编码。
- 边带缺格分别为左边第 `3g_L` 格、下边第 `3g_B` 格，`g_L,g_B∈0…23` 且至少一个为 0，共 47 种。每边仓库口的起点为 `s_j=3j+1[j≥g]`，`j=0…22`；出矿邻格为左侧 `(1,s_j+1)` 或下侧 `(s_j+1,1)`。
- 九机型总占地 3291，核心 81，仓库口 138。记 F 为 R 外其余空格数，则 `T+F=277−4P`，给出 P=10/11/12 时 T≤237/233/229。这不是把 T 固定在某个下限。

每个合法机身/桩占位有布尔变量；每格结构布尔等于覆盖它的已选机身/桩布尔之和，再与仓库口占用、运输布尔合计限为 ≤1。小机、中机枚举两个端口轴，大机枚举 6×4/4×6 且只在长边设端口；显式流量版本再选择进出边和机型。核心只需两个取货端口轴状态，六个取货端口在两边偏移 1、4、7，存货端口在另外两边偏移 1…7。

R 在真正达标布局的映像中确为最大空矩形，因为正式上界为 1113，而 R 已有面积 1113。模型本身只禁止单位进入 R，不枚举其他全部空矩形。

机身不能占第 0 行/列：边带只有一个未被仓库口占用的格，放不下宽至少 2 的机身。该孤格至多与一格内部单位成通道，不能承载循环正流，因此机器有效端口邻格从坐标 1 开始；该格仍可选为闲置运输格。此项沿用原模型及异源核查的论证。

`--cut-mode none` 撤去核心走廊割、供电亏额割、两条面积缺口割，并继续放开全部 P 与边带。保留物理覆盖、数量、互斥、端口、运输下限、核心基本离带条件；用于排除结果的较弱模型复核。它不是删除全部正式几何条件。

`flow_model_min_edges_domain.py` 的正式约束模式恢复原位置筛选的 P 域：前三位置附加 `P≤11`，`(49,17)` 仍为 10…12。出处为开工前已有的 `1113放松/filter_positions.py` 及其报告、异源核查；本轮用冻结副本做了**同源精确整数 DP 重算**，见 [original_domain_recheck.json](original_domain_recheck.json)，没有把同源重算称为新的独立核验。P=12 时 `J≤6`，面积式要求 `X+Y≤7`；三个位置的 DP 下界依次是 `10+3=13`、`10+3=13`、`9+3=12`，均大于 7。因此这些 P=12 分支无需重新做流量搜索。DP 是对实际机身在外边与矩形邻圈上的必要投影；其可行域包含实际投影，故下界是必要界。该版本没有额外加入 P=10、11 的 X/Y 数值割；`--cut-mode none` 同时撤销 P≤11，复核时恢复所有 P。

## 2. 格级运输网络

每格 c 有运输布尔 `t[c]` 和桥布尔 `b[c]`，`b[c]≤t[c]`；总数为 `T=Σt[c]`、`b=Σb[c]`。相邻运输格之间每方向一条容量 ≤1 的候选弧；所有实体端口弧也单独限容 ≤1，并受所选机器/核心/仓库口和运输格支撑。模型不强制相邻合法端口自动接通，也不枚举传送带、分流器、汇流器的具体方向。

普通运输格：全部进入量等于全部离开量，进入合计 ≤1。允许任意转弯、分支、汇合，是对真实单物品格运输单位的放松。

桥：水平方向进入量等于水平方向离开量且 ≤1；竖直方向同理。两轴不能换路。模型放松同一轴端口的方向与接通先后，可有无用反向循环；固定状态后仍是一条有容量的水平节点和一条竖直节点，不是容量 2 的任意转弯格。

流量按层分开；层间只共用机器类型、朝向及运输/桥布尔。不加逐弧子集流 ≤全体流、不相加限容，不共享批率。出处为「端口速率」「滞留」、运输单位规则和会议共识第二节第 4 条。

## 3. 矿石子集层

物品子集是 `{源矿,蓝铁矿}`，不区分这两种矿的弧上身份。每个所选仓库取货口出矿为 1，每个核心取货端口出矿也为 1，总源为 52；均为等式，依据「取货口配置」。核心不能收矿，制造机不能产出原矿，依据配方及「非成品零入库」。

小机细分为 68 台粉碎机、51 台精炼炉以及 12 台其他小机；粉碎/精炼均显式选择哪条边是存货边。矿只进入这两类机器的存货边，每台矿石总收量 ≤1。粉碎合计收源矿 18、精炼合计收蓝铁矿 34；合并矿流只保留这两个收量数值，不能保证弧上原矿身份正确。

这些合计等式的依据：52 个出矿端口全部满速，目标至少耗源矿 18、蓝铁矿 34；两下限之和已用尽 52。原矿在循环态既不由制造产出、也不回仓，粉碎与精炼分别是唯一消费其对应原矿的机型。单机上限 1 来自一 tick 配方和制造能力。模型不要求某台只处理一种配方，也不给单台矿收量正下限。

原矿不能在循环态中以正流量进入其他机型：这些机型没有消耗该原矿的配方，误料不能离开存货格，周期库存守恒使其周期进量为零。出处为正式「存货误料停机与可用台数」及制造、存货格规则。粉碎机收蓝铁矿、精炼炉收源矿在真实循环中也同样为零；本层合并两种原矿后省略弧上的矿种身份，只保留已证机型收量总数。

本层取 K=1。它允许的整数替代流不等于真实矿流：真实矿流可以分流、跨机器分摊，也可以有任意周期分母。

矿石单层另有紧凑编码 `flow_model_compact.py`：暂时擦去小机的类型和进出方向，让原矿流入每台已选小机的两条端口边，合计容量仍为 1。真实布局擦除标签后显然映入这个连续网络；固定几何后也是整数容量网络。其任一整数解的 52 件源流必由恰 52 台小机接收，每台只有一个非零接收端口，因此可把该端口所在边恢复为存货边；其中任取 18 台标为粉碎、34 台标为精炼，其余 79 台里再标 50 台粉碎、17 台精炼、12 台其他小机。两个机型合计和各自 18/34 收量全部恢复。原矿身份没有逐弧绑定，故这个恢复合法；它只描述替代流。矿石单层在几何/运输/合并流上的整数投影与显式标签版相同。

紧凑编码导出时实际执行上述恢复，随后由同一份直接检查器按显式粉碎/精炼标签复核。此消元不能直接用于与全体层共同固定机型/方向的模型：全体层仍使用显式标签版本。矿石层中不参与原矿收货的其他小机，以及中机、大机，可以按相同几何签名补齐剩余规定数量；它们的全体物品流在矿石单层中没有检查。

## 4. 全体物品层

本层把全部物品相加，但机器两侧分别作为网络终点和起点，不要求机器守恒，更不把收、出量用配方比例连接。选中机器逐台上下界如下，单位均为件/tick。

`flow_model_global.py` 显式补写四条冗余全局界：制造收量 ≥304.5、制造出量 ≥253.65、核心收量 ≥1.15，以及 `运输到运输弧流量之和 + 305.65 ≤ T+b`。前三条由表中逐机型合计相加或单个核心条件得到；末条把全部运输物品格入流求和，并用各节点容量以及 52 个满速矿源得到。每个实际使用的机器端口只属于一台已选机器，因此固定布尔后这些行已由原网络蕴含，不改变网络可行集和整数替代证明。显式写出它们是为了加强求解器对未取整布局的线性松弛。结果 JSON 的 `variant=explicit_global_totals` 标识此版本。

`flow_model_min_edges.py` 保留加强版的全部约束，仅把全体层“运输格到运输格”弧流量之和设为最小化目标，并设置 `stop_after_first_solution=true`。它只改变搜索方式，没有运输长度阈值，可行集合保持不变；任何找到的解仍仅是必要条件骨架。此辅助目标的 OPTIMAL 不代表游戏布局达标或游戏目标已最优。是否执行、时限与状态以运行表为准。

## 5. 从达标布局到模型解

1. 取任意含指定空矩形的真正达标布局。正式面积预算给出恰 217 台、无箱、P∈10…12。按实际机身、端口轴、机型和进出方向选中相应占位布尔，按实际仓库边带选模式，按实际运输/桥状态设置 t[c]、b[c]；固定矩形不变。几何各行由第 1 节所列正式条件成立。
2. 取调试后任一可到达达标循环态，将周期内每条通道的各类物品件数除以周期。矿石层只相加两种原矿，全体层相加全部物品。真实桥的两轴分开；每个运输物品格在循环态守恒，容量 ≤1。机器收、出量分别满足第 3、4 节的必要界，得到连续可行流。
3. 固定上述布尔，每层都有网络扩展：运输节点拆成入/出两节点和一条容量弧；桥拆 H、V 两组。各机器收侧连接机型收汇聚点，出侧连接机型出汇聚点，逐台界放在机器侧弧，机型合计放在汇聚弧；核心、仓库源汇连接公共记账源/汇，再闭合循环。收、出两侧相互独立，所有汇总集合为机器分属机型的层状集合。
4. 矿石乘 1、全体乘 20 后，网络所有下界、上界、需求均为整数。有连续可行点的整数上下界网络存在整数可行点。每层各取一份整数替代流；它们只共享已固定布尔，因此可同时拼回 CP-SAT。求解刻度不是对实际周期分母的限制，也没有正流量 ε 假设。

因此本模型的 INFEASIBLE 能排除其覆盖位置；FEASIBLE/OPTIMAL 仅表示找到了上述必要条件骨架。整数替代流的正支持、饱和集合和桥双轴活跃数不能直接冒充真实运行事实。UNKNOWN 表示时限内既未找到可行见证又未证不可行。

## 6. 检查边界

`check_solution.py` 不导入模型构建器，直接按占格集合、端口坐标、非零弧重算互斥、数量、供电、面积缺口、来源等式、机器界和逐格/桥轴守恒；保存饱和格和机型合计。局部正反例检查涵盖普通格转弯、桥双轴交叉、桥跨轴转弯拒绝、普通格及桥轴过载、守恒破坏。

没有编码物品联合共享容量、实际配方批次比例、缓存/库存时序、自动接通、轮询、阻尼、调试和全部可达循环态的运行保证。普通格的多进多出比任一真实非桥单位更宽松；桥轴方向也更宽松。这些遗漏均扩大可行域，不可把骨架作为达标布局。
