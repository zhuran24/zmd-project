## 3. 最大流割的集合方向：独立推导

约定每个原节点满足入流减出流等于 d(v)，且全网需求和为0；弧界为 l≤f≤u。令 g=f−l、残余容量 c=u−l、平移后需求

    r(v)=d(v)−l(入v)+l(出v)。

超级源向 r(v)<0 的节点连容量 −r(v) 的弧，r(v)>0 的节点向超级汇连容量 r(v) 的弧。记需要饱和的总量 D=Σ max(r(v),0)。

任取包含超级源而不包含超级汇的割。令 R 是源侧的原节点集，X=V\R；去掉超级源、超级汇，保留机器侧和机型汇总等原扩展网络辅助节点。该割容量为

    C(R)=Σ[v∈X,r(v)<0](−r(v))
         +Σ[v∈R,r(v)>0]r(v)+(u−l)(出R)。

直接消元得到

    D−C(R)
      = r(X)−(u−l)(入X)
      = d(X)+l(出X)−u(入X)
      = −d(R)+l(入R)−u(出R)。

因此最大流不饱和时，最小割 C(R)<D，严格违反的是下列等价两式：

    补集 X：d(X)+l(出X) ≤ u(入X)；
    源侧 R：−d(R)+l(入R) ≤ u(出R)。

原节点 d 的总和为0是最后一个等式的条件；总和不为0时已经能直接否定流平衡，无需这次转换。`flowcheck.py` 把供需写成带下界的弧，使用的是 d≡0 的闭合循环流。其 `excess` 是上式 −r，构造方向相符，返回的是超级源侧，所以复核入边式需要取补集。

**v4 正文写的是 −d(R)，正确。** 用户消息末尾转述中的 −d(X) 不能代入源侧式；它不是冻结稿的写法。在 d≡0 的特例里这个符号误写会被掩盖，通用表述应保持 R。

### 两节点反例与精确小检查

a→b 的上下界均为1，b→a的上下界均为0，d(a)=d(b)=0。此时 r(a)=1、r(b)=−1；超级源只能到 b，a连超级汇，残余原弧均为0。最小割源侧原节点 R={b}，补集 X={a}，D=1，割容量0。

- 在正确的 X 入边式上，残差为1，严格违反。
- 在正确的 R 出边式上，残差同样为1。
- 把 R 错放进入边式，残差为−1，没有违反。

因此 codex-3 的反例成立，v3 保存源侧却用同侧入边式解释缺口的说法有实质错误。独立脚本 `check_cut_side_round8.py` 对此例的全部4个原节点子集检查上式恒等式；另加 d(a)=−1、d(b)=1、a→b容量0 的需求例，检查全部4个子集及 R/X 的非零需求符号。两例均通过，报告为 `cut-side-round8-result.json`。这只是抽象小网络的精确代数核查，不是工厂测点。

## 4. 对已有割与证书的影响

Hoffman 入边式对任意原节点子集都是必要条件，包含 R 本身。因此选错侧并不自动把该不等式变成无效割；错误是它未必违反当前点，却被误当作最小割缺口对应的分离证书。若据错误的集合或符号抄乘子、参数化容量系数，仍须从头核全列残差与当前违反量。

一般 Farkas 推导由乘子符号和全列不等式保证，与“源侧”这个标签无关。本席第6.7节已经独立复核的 `cert_D1_iter0.json` 使用所供母矩阵全部22730列和有理乘子，不依赖这次最小割集合选择；此次修订不推翻该已核证书。也不因此把其他未核生成割自动签为有效。

修正集合方向后，跨主变量反馈仍须恢复母网络所有相关容量及下界的参数形式；不能只反馈当前图的数值矛盾，也不能把任意扩展网络割径直简化成地图区域边界计数。
