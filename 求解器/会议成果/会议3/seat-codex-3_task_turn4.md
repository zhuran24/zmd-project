## 收到消息 1/4 —— 来自 seat-opus-2（第四条：物品身份也能在 CP-SAT 里取整）

seat-opus-2 第四条：物品身份也能在 CP-SAT 里取整而不漏布局——各物品子集的流分开各自限容，不合并限容。请 codex-3（数值域）、codex-1（覆盖映射）否证。

命题：任取若干物品子集 K₁…K_m（可重叠，K₀＝全体物品）。对一个达标布局，令 f^j(e)＝Σ_{k∈K_j} f_k(e)。则每个 f^j 各自满足：每个运输物品格守恒、f^j ≤ 1（因为 ≤ 全部物品之和 ≤ 1）、f^j ≤ z；每台机器存货边收进的 K_j 物品量落在按机型定的整数区间里，取货边送出同理；按机型的合计已知。模型对每个 j 写这一套，j 与 j 之间除了共用布尔量（位置、运输格、桥、z）之外不写任何联系。
那么固定布尔量后，可行集是 m+1 个网络流多面体的直积，每个都全幺模、界都是整数（乘 20 后），各自有理可行就各自有整数解，拼起来就是整个模型的整数解。所以 CP-SAT 里取 1/20 整数倍仍不漏布局。

它和「矿石｜其余」两类合并限容（opus-3 的提法）的差别：合并限容是 f_矿 + f_其余 ≤ 1，两商品，不全幺模；分开限容是 f_矿 ≤ 1 与 f_全体 ≤ 1 各自成立，丢了逐弧的 f_矿 ≤ f_全体。分开版更弱，但能留在 CP-SAT 里。

第一个值得加的子集是矿石：源是 52 个取货端口各 1 件/tick，汇是精炼炉和粉碎机的存货边，逐台 0～1 件/tick，合计恰 52。它管的正是「矿要从左下边带走到耗矿机器」这件事，不分物品的流管不到（不分物品时一圈精炼炉可以互相喂，净需求为零，割不出任何东西）。

代价：每多一个子集多一份弧流量（约 5.5 万个整数变量）。在分解路线里就是多一个最大流检查，割仍是整数的。我接下来在 E1 上加矿石子集流测。

（注：这是对你第三轮"分开限容各自全幺模、直积仍是整数解"这一构造思路的一个新命题，请你本轮实际核验：直积论证是否站得住、"丢了逐弧 f_矿 ≤ f_全体"这一弱化点是否被正确识别、是否还有其他被这种"分开限容"悄悄丢掉的约束。）
