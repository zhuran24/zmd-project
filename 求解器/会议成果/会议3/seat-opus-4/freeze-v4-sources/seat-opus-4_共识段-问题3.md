## 三、问题 3：先后机制推出的条件怎么落到这一层（主责 seat-opus-4；储存箱、混料 seat-codex-2；机制量词核过 seat-codex-4）

逐机制的表（触发图样／要用的量／条件／压 U／抬 L）在 seat-opus-4.md 第二节，储存箱、混料两行取自 seat-codex-2.md 第五、六节。

1. **压 U：第一档不为先后机制另写约束。** 删掉任何约束都是放松，与它是不是条件句无关。取货/存货分级、密集结点、来源定序、轮询均分、储存箱编号格推出的是「需要定序时」「前提全部成立时」一类条件句，触发与否看动态；本会还没把它们的触发前提落实成几何约束，首档暂不展开。准入口不同：放行种类（其余物品流量为 0）和每 5 tick 上限（q ≤ k/5）是给定设定下的直接条件，可以写；压 U 时设定本身是未知数；规则允许不设（不设时放行一切、不限速），没有别的约束要求这些设定时，任何布局都可取不设来满足这两条，所以写不写不改变放松在布局变量上的投影，删去仍是真放松；设定被固定时（L 候选里，或别的约束要求这些设定时）按这两条核验；不声称含设定与流量的完整可行集相同（例如 q=1、k=1 这组取值，删去 q ≤ k/5 时允许，写上后不允许）。已证的必要条件照样按其前提加入；思路第二节那一遍机制过完推出的新必要条件也一样。正式约束里由机制推出、对所有达标布局成立的几条在带流量的模型里是推论，各自要用的部分不同（seat-opus-4.md 第一节第 1 条逐条列了，按条文推，未写成代码核）：满速独占要运输物品格容量 1、桥两轴分开、根通道流量为 1（准入口那部分还要 q ≤ k/5）；矿线专机、灌装混线、回路转弯要分物品的流；混做清空只有计数部分是推论，「逐批交替时」那部分不是，压 U 删掉；四通结点、运输端口收支（以及回路转弯里按「输送过」计的运输单位数）对流量的真实支撑（f>0 的通道）成立，在 z 只作上界的支撑放松里不自动推出（seat-codex-4 的局部例：机器取货口接一格出口朝空地的带，f=0、z=1，按 z 数违反 −2M ≤ R−S ≤ 2D），要用就沿真实支撑映射显式加在 z 上，加了不漏布局。前提不满足的更粗放松里（桥两轴合并、不分物品、粗网格）它们不全是推论，删掉仍是放松，要用就补写；不带流量的主问题里可写成支撑 z、满速标记 u 和格状态上的 0/1 约束，作有效割（对真实支撑成立），不是冗余。这些都是整数陈述，不碰流量取整的问题。
2. **阻尼不进主问题。** 压 U 删掉取货分级是真放松。抬 L 先不触发取货分级（N1）；放开时对固定候选在元件图上逐个分叉取值 ξ 核 d_高(ξ) < d_低(ξ)。「高一级最大阻尼 < 低一级最小阻尼」只是充分条件，只能当抬 L 的限制。
3. **抬 L：机制落成受限类加候选检查。** 各条登记丢掉的布局；N1、N2、N4a、N4b 是格状态上的局部式子，N3a 要用准入口设定和「承载流量」，N3b 要用能到达的物品种类（只筛有没有出口，不保证及时通过），N5b 要用流量：N1 不触发取货分级；N2 不触发存货分级（含密集结点）；N3a 承载流量的准入口不设累计上限；N3b 限种准入口不被永久堵死；N4a 桥每轴两端一取一存；N4b 桥不成串；N5a 候选按「当且仅当」重算全部结构通道逐条对上（检查）；N5b 每条结构通道设计流量严格为正（路径段构造，或 f ≥ 1/K 另登记数值限制；连续 LP 复核用固定支持集最大化共同 δ）。储存箱、混料的限制见 seat-codex-2.md 5.3、6.4。四个不得依赖量在候选验证里的记录与覆盖义务用 seat-codex-4.md 6.2 的接口。在 N1–N5b 下且不放储存箱时，四个不得依赖量能起作用的只剩轮询次序和判定先后；这只缩小它们起作用的位置，不缩小运行义务：起动、库存、死锁、全部可达循环态照样要证，内核跑一次只覆盖那一次。
4. **检查器两份独立实现、已对上。** seat-opus-4/check_full.py 与 seat-opus-3/check.py 都从格状态按「当且仅当」重算结构通道；对 seat-opus-3 的候选 r_k1_12.json（结构通道 18 条）、r_k2_tile30.json（52 条）两份都无错，r_tile_12309.json 两份都报桥串；启发式布线的两个固定铁砖实例（96 台、102 台，虚拟边界来料，不是全厂）rt_k16.json、rt_k17.json 两份各自重算得 999 条、1186 条结构通道，都零错零警告。check_full.py 另报 N1–N5b、断头与空通道、从来源传播的物品种类（错料、偏离设计配方）、N1 触发时逐 ξ 的阻尼。
5. **储存箱、混料（seat-codex-2.md 第五、六、八节）。** 储存箱：每一个协议储存箱都是触发对象；存货放进编号最小的能放格、取货取编号最小的非空格，不能化成固定物品优先级，也不能当成可任意挑货的 300 件池；压 U 留逐物品守恒（入箱＝物理外送＋无线入库）、端口容量和正式箱体条目，编号演化可放松；抬 L 核最低编号取放、有限容量、无线相位和全部允许初态，或用受限类（终端成品箱、单物品中转箱）并补吞吐证明。混料、混做：库存账 I_m(t)=I_m(0)+A_m(t)−Σ 用量·N_r(t)，N 是开始批次；「比例对、偏差有界、两格各 50」不充分（6.3 有局部反例），要交具体数值界；压 U 留平均守恒、共享容量和正式 灌装混线／混做清空；抬 L 交量化库存与服务证明，或用「某些双料机器每条进料通道只送一种」的限制并登记丢失。5.3、6.4 只是减少证明义务的候选限制，不是运行充分证书；完整接口摘要见 seat-codex-2.md 5.4、6.5。失败证据按 8.2 的格式记：固定了哪些选择、还放开哪些、查的量词、失败类型、精确证据、请求排除的范围；固定支持集 δ=0 只否掉那一个支持选择，混料充分条件没通过不自动否掉几何。
6. **规则读法，现在都不上报 owner：** 桥串（相邻两桥同轴相接时端口都未定型，规则没写怎么定；压 U 不受影响，抬 L 用 N4b，高面积档候选非用桥串不可时才问）；「一段连续的传送带」按通道相继还是按几何相邻读（只影响阻尼，放开 N1 时才用到）；桥两轴共同存货分级时「能移动」的读法（N2 把桥也算进去，不依赖它）。
