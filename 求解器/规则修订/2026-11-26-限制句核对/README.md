## 一、 建账目的与核对规矩（必读）

此前口头确认只留在对话历史里，换上下文或派子代理复核规则时只查 `实测-*.md`，导致 owner 答过的常识被反复重问。自本台账建立起：

1. **核对先查本账**：任何会话或派出的复核席位在核查规则条文依据、排查“假禁令”或盘点未测项时，**任务书必须指明先查阅本文件**。
2. **禁止重复盘问**：凡本表已标为 `有实测`、`owner 试过反面` 或 `owner 已确认（未分试过反面与否）` 的条目，**一律视为已有记录在案的依据，禁止再向 owner 重复发问**。
3. **严格区分「试过反面」与「未细分」两档**：
   - `owner 试过反面`：owner 明确表示亲手在游戏里试过违反该限制的操作且确实不行；
   - `owner 已确认（未分试过反面与否）`：owner 在扫表时确认该条符合游戏实际、无已知例外，但当时未逐条拆开区分“亲手试过反面”与“一直这么以为”。若日后某条核心上界证明死死压在其中某一条上、且一旦游戏允许反面就能直接省出面积突破上界，可直接开游戏做一次 2 分钟反面实测升级为 `有实测`，不必让 owner 凭记忆回想。
4. **新发现待补的一条规则外限制（2026-11-27 摸底新见）**：
   - 物品准入口面板左上角显示「已限速数量 X/50」（「当前地区准入口限速管理」列表），现行《游戏规则.txt》未写全地区限速准入口 50 个上限；待开游戏实测第 51 个的行为后一并补入本账与规则文件。
