# 1113 放松模型：异源核查（Claude 源）

核查对象：本目录 [报告.md](报告.md) 及其脚本、结果。正式口径为仓库根目录的《明日方舟：终末地》游戏规则.txt、求解任务.txt、求解约束.txt（与本目录 `input_snapshot/` 逐字相同，已 diff 确认）。本核查的脚本与结果全部在 [异源核查/](异源核查/)，没有改动报告目录下的任何文件，没有 git 操作。

## 1. 结论

**成立。** 两个 INFEASIBLE 位置——21×53 的 (49,13) 与 53×21 的 (13,49)——用我独立写的、更弱的边界带放松模型复算，P=10、11、12 全部放开且不用区间 DP，仍然不可行：面积缺口式左端 S=16P−2J+X+Y 的最小值分别为 200、204、213（P=10/11/12），而达标要求 S≤187。CP-SAT 与 HiGHS 两个求解器给出同一最优值。

完整模型的每条约束都能追到正式条文，报告所引行号与原文对得上；没有发现偷偷固定的未证量。编码（尺寸、朝向、端口、供电覆盖、X/Y 计数、边带模式）逐项核对无误。位置清单独立重枚举，报告排除的 1238 个位置全部复核为不可行，没有一个被我的模型放回来。

报告没有说到、需要主会话知道的三点：

1. **(13,49) 的完整模型 INFEASIBLE 只在 P=10 上求得**，P=11、12 靠区间 DP 剪掉；报告「不依赖 DP」的复跑只做了 (49,13)。本核查全 P 复算补上了这一环；两者本来也是转置对称的同一问题。
2. **报告偏保守：22 个候选中另有 12 个也不可行。** 在与报告相同的前提（端口对接格不在第 0 行/列）下，我的模型给出 21×53 的 b=5、8、10、11、12、14 与 53×21 的 a=5、8、10、11、12、14 的 S 最小为 188 或 189，都超过 187；两个求解器逐个一致。用报告自己的边界子模型、去掉 DP 切割、放开全部 P，把这 6 个 21×53 位置和 (14,49) 逐个复跑，全部返回 INFEASIBLE（70…301 秒）；其余 53×21 位置是它们的转置，模型对 x↔y 对称。报告记为 UNKNOWN 只是限时不足（30 秒、2 worker）。若三审通过，候选位置由 22 个降到 8 个：21×53 的 b=6、7、9、17 及其转置。
3. 剩下 8 个位置在我的模型里可行：b=6、9 的 S 最小为 187（余量 0），b=7 为 186，b=17 为 179。单靠边界带与供电亏额排不掉它们，要再降需要新的条件；这 8 个位置在报告的完整模型里仍是 UNKNOWN。

## 3. 编码核对

- **尺寸与朝向**：小机 3×3、中机 5×5 各两种端口轴；大机 6×4 只配南北端口、4×6 只配东西端口，端口都在长边上（规则 54）。核心端口在一对边的偏移 1、4、7（取货）与另一对边的偏移 1…7（存货），即原文「第 2、5、8 格」「第 2–8 格」。
- **供电覆盖**：桩左下 (p,q) 的 12×12 范围是格 p−5…p+6，机器 [x,x+w) 得电当且仅当 p∈[x−6,x+w+4]（q 同理）；前缀和取 `pref[ux+1]−pref[lx]` 与之吻合，桩只在 1…68，越界裁剪无害。
- **亏额函数**：我独立写的 `pole_loss` 与报告的在 6 个矩形、20778 个桩位上逐一比对，零差异。侧旁供电的「投影落在跨度内」写成 `y−5≥b 且 y+7≤b+h`，g 为桩与矩形之间相隔的列（行）数，与条文一致。
- **X、Y**：X 取第 69 列第 1…68 行与第 69 行第 1…68 列、去掉 R，右上角不属桩与 R 时加 2；Y 取 R 四边外一圈、不含对角、贴界一侧没有。与条文一致。
- **模型与结果对应**：用当前脚本重建 (49,13)、(13,49) 的完整模型，指纹 `0x8454a61bb7913c4b`、`0xbb88d1104d2c50da` 与出 INFEASIBLE 的原运行日志一致，说明结果确由现行代码产生。

## 4. 独立复算

### 4.1 我的模型

[异源核查/strip_model.py](异源核查/strip_model.py) 从零写成，不导入报告目录的任何脚本。只显式放置「碰到 X 格、Y 格或右上角格」的单位，其余单位一律放任。它比报告的完整模型和边界子模型都弱：

| 保留 | 丢弃（向可行方向放宽） |
|---|---|
| 所有碰目标格的机器（4 种尺寸、全部朝向）、核心、桩，二维不重叠 | 边带模式、取货口机身 |
| 机器每条端口边至少一格在界内、不在 R、不被显式单位占 | 运输格变量、运输下限、供电覆盖 |
| 核心 6 个取货对接格、至少 2 个存货对接格同上 | 核心离带、核心 x0≥2 与角区排除 |
| P∈{10,11,12}；不碰目标格的边界桩只能在第 1 列或第 1 行，每个至少亏 9 并计入 J | 区间 DP 给出的 P 剪枝与 X、Y 下界 |
| 逐桩亏额取最大，总和 ≤23P−217 | 机器数只设上限 |
| X、Y 按正式定义计数 | — |

「端口对接格不在第 0 行/列」做成开关：关掉时（弱版）第 0 行/列的格也算可用对接格，比报告的所有模型都弱；打开时（edge0 版）与报告的前提相同，依据见第 2 节第二行。

真实达标布局里成立的，这里都成立：碰目标格的单位就是显式单位；端口对接的运输格不被任何单位占；第 1/69 列、行上的桩若不碰目标格只能贴第 1 列或第 1 行（第 68 列、第 68 行起的桩必然占到第 69 列/行的目标格或压进 R），照样计入 J 与亏额。因此模型不可行即可排除该位置。

求最小的 S=16P−2J+X+Y，最优值 >187 即不可行。每个可行解另用直接格集合复核（不重叠、端口边、核心对接格）。[异源核查/mip_check.py](异源核查/mip_check.py) 把同一组条件写成 0-1 整数规划交给 HiGHS，作为与 CP-SAT 无关的第二个求解器。

自检：报告边界子模型在 (49,17)、(17,49) 找到的两个可行解，原样代入我的模型均可行，且 P、J、X、Y 与报告记录一致（10、1、14、15 与 10、1、16、13）；转置位置的最优值两两相等；8 个位置可行，说明模型没有因编码错误而处处不可行。

(49,13) 分 P 求：弱版 P=10、11、12 的 S 最小依次为 200、204、213。原始数据见 `异源核查/results/scan_weak.json`、`scan_edge0.json`、`mip_*.json`。

**为什么 b=13 特别。** R 占第 49…69 列、第 13…65 行，上方只剩第 66…69 行共 4 行。第 49…68 列上，盖住 Y 格 (j,66) 的单位下沿必在第 66 行，盖住 X 格 (j,69) 的单位上沿必在第 69 行；两者叠在同一列里合计高度 ≤4，只能是两根桩，而上面那根占第 69 行、是边界桩。能单独盖一行的机身只有 3×3（6×4 的端口边一条出界），盖不住两行。第 69 列的 (69,66)…(69,68)、右上角，以及 R 下方的 (69,12)，任何机器都盖不上（端口边出界或整条落进 R），只有第 68 列的边界桩能盖。

以 P=10 为例（允许 X+Y≤27+2J，J≤1）：J=0 时上方 20 列至少付 20，(69,66) 双计 2、(69,67)、(69,68) 各 1、右上角 2、(69,12) 双计 2，合计 ≥28>27。J=1 时唯一的边界桩（亏 9）至多把这部分降到 25，X+Y 余量与亏额余量都只剩 4；而 R 左侧 53 格、下方 20 格一圈中段的贴边桩都要亏 10，用不起，相邻两台在产机器又必须隔开，远不够。求解器给出 P=10 时 X+Y 最小 42，允许量 29。b=12 时上方 5 行可放 5×5、b=14 时 3 行可放 3×3，一台机身就能同时盖住两行，所以压力小得多；其余 12 个新排除位置都只超 1 或 2，没有手推，依据是两个求解器的最优值。

- (49,13)：报告的边界子模型去掉 DP、全 P 也是 INFEASIBLE（报告 `results/W21H53_x49y13_proofcheck.json`）。与本核查一致。
- (13,49)：报告的完整模型只在 P=10 上求解（`allowed_P=[10]`），P=11、12 由区间 DP 排除（X/Y 下界 14+7>19、12+4>7）。本核查全 P 复算不可行；用报告的边界子模型去 DP、全 P 复跑，0.74 秒 INFEASIBLE。
