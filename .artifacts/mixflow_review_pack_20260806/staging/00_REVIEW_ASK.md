# 外审任务书：routing 模型混流表达手术（soundness 审查）

**日期**：2026-08-06。**审查对象**：对 certified-exact 求解器 routing 子问题模型的一次
**可行域放宽手术**（原型阶段，未合入 main、未接入认证路径）。

## 背景一句话

游戏语义终审（owner 08-06 公理审阅）确认：多商品共乘一条带合法（速率约束内）、
机器**输出口**门口混流过境安全（输出口只推不吞）；但机器**输入口**门口纯流是铁律
（错货趁缓存空窗被吞 → 污染/中毒）。旧模型无法表达合流/分流点的混流（use 变量
key 继承整个物理件图样，商品被迫声明不存在的入边 → 结构性 INFEASIBLE），比游戏
语义过严。本手术让模型表达力对齐游戏语义，同时**必须不引入任何伪解**。

## 审查的中心问题（按重要性排序）

1. **不纳伪**：手术后模型接受的每一个解，在游戏语义下是否全部合法？特别是：
   sink front（输入口门口格）的地面纯流防线从「结构涌现」改为「显式排除」
   （BRIEF §4.1）——排除规则是否有洞（多 owner 门口格、对向双口、L1/L0 组合）？
2. **不拒真回归**：手术是否意外收窄了原有可行域（单商品场景语义必须逐字不变）？
3. **「静态连通 ⇒ 正确送达」的丢失**（BRIEF 中心自攻）：模型声明「A 走东 B 走南」
   但真实分流器内容盲——de-mix 解的物理兑现依赖准入口（canonical 刻意不建模）。
   我方处置=诚实披露+随 W-PENDING-01 加 scope 声明（不改连通性谓词）。该处置
   是否可接受？有无更好方案？
4. **性能固有代价**：可行域放大后不可行证明变难（对抗 proxy 27.7s→600s 无结论，
   「慢可行+弱割」——source-side 割机器是前混流时代写的，全部回退弱 nogood）。
   接入批已列门控开关/割适配/benders 生产实测三件套。风险评估是否完备？
