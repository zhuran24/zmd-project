### step_8 翻译候选形态 + soundness 依据
- 形态候选：新 master API（镜像 `add_region_capacity_cut` 形状）`add_pose_pair_conflict_cut(group_a, pose_a, group_b, pose_b) -> bool`，翻译为 `presence(A,pA) + presence(B,pB) <= 1`，presence 用 `_pose_present_literal`（exact_coordinate_master.py:6983-7015，content-addressed 缓存 key=(sorted slot keys, normalized 3-int pose tuple)）；pose_id(str) → pose_idx → `_template_pose_tuple_by_idx[tpl][idx]` 解析同 F1（:7182-7187）。
- **soundness 依据不足（本族最大坑）**：master 的 certified 路径里 "所有 port front 必空" **不是**有效不等式——PROJECT_LOCK 明确禁掉了 coordinate 路径的 `_add_port_clearance_constraints`（over-approximation；pose_bool_exact_master.py:739-746 注释复述），binding 语义是"在 cleared 子集里选 active port"（demand ≤ port 数，pose_bool :630-634）。一个 pose 有多个 port 时，堵一个 port 不必然 INFEASIBLE。F3 v1.0 cert 不携带"该 port 必激活"的 witness（active_port_witness=None 且不验），所以 **presence 对偶约束按 v1.0 cert 直接进 master 是不 sound 的（会过切）**。可选出路：(a) 仅当可证该 port 必需（如 pose 可用 port 数 == demand，master 侧可算但 cert 不携带）才翻译；(b) F3 维持 NotImplementedError 等 Phase 1.5+ active_port_witness；(c) owner 拍板。这是 F3 的"F9 式实质停用"类似物：**没有 lock 条款写死，但 spec §9 OQ#1 + witness 缺位使 sound 的 master 翻译在 v1.0 语义下不存在**。

### 数学断言 + cert payload

Stencil 语义（owner 2026-07-08 M2 裁定）：2×2 pole anchored (px,py) 覆盖 `X∈[px-R, px+1+R], Y∈[py-R, py+1+R]`，R=5 ⇒ 12×12 方形、相交谓词——与 `rules/canonical_rules.json:semantics.power_coverage_stencil`、`placement_generator.gen_power_pole`（:398-414，覆盖域 `[x-5,x+6]×[y-5,y+6]` 截边）、live master 逐字节同一矩形；Euclidean 旧模型 retired（power_cover.py :14-25）。

### step_8 翻译候选形态 + soundness 依据
- 形态候选：新 master API `add_power_pose_exclusion_cut(*, group_id: str, pose_id: str) -> bool`（Protocol `MasterModelLike` lifecycle.py:1115-1130 加一个方法 + master_model.py 转发 + coordinate delegate 实现），翻译为 `model.Add(presence_lit == 0)`，presence 复用 `_pose_present_literal`；all-or-nothing：group/tpl/pose 解析失败或 literal 建不出 → False → step_8 raise（照抄 F1 :7137-7213 的 fail-closed 形状 + `_last_solution/_solver/_status = None` witness 失效三连 :7210-7212）。
- soundness 依据（与 F1 的"物理恒真"不同层）：master 本身已把供电覆盖当硬约束（谓词 6），F7 cut 是**冗余强化**；其有效性依赖 helper 的 CoverSet 语义与 master 覆盖语义**等价**——若 helper 少算一个可行 anchor（helper 说 ∅ 而 master 有 witness），attach 即过切真解（M2 前 Euclidean 模型正是这种 false-INFEASIBLE 地雷）。所以族 docstring :28-29 和 PROJECT_LOCK:486 都把 **helper-vs-master 等价回归**列为前置。
- **ghost 条件化 caveat（与 F1 的关键差异）**：F1 不等式对任意 ghost 物理为真；F7 的真值**依赖 ghost cells**。生产 master 可能带多 anchor 选择（`_selected_ghost_context` 返回 u_var）。翻译要么限定单 anchor master，要么像 `add_benders_cut` 的 `condition_lits` 一样 `OnlyEnforceIf(u_var)` 条件化——直接无条件 `presence==0` 在多 anchor master 上不 sound。

### BState 材料对照
生产 BState（:7600-7612）对 F7 的适配度**远好于 F3**：`candidate_placements={"facility_pools": facility_pools}`、`instance_to_facility_type`、`facility_templates=master.templates`、`canonical_rules=master.rules`、ghost_rect/ghost_cells 全有。`cell_owner={}` 对 F7 是**保守方向**（full-mask 更大 → CoverSet 更难为空 → 更少 cut；ghost-only 检查本就不看 cell_owner）；`exterior_blocks=frozenset()` 同理保守。剩余缺口只有：target_poses 无来源（Phase 1.5+ 计划从 master_solution 推）、oracle 版本集不含 `power_cover_v2_stencil`、`_maybe_attach_framework_cuts` 不调 F7 generator。
**ghost_rect 轴序坑**：BState.ghost_rect 注释 "(x, y, x_span, y_span)"（lifecycle.py:408），benders_loop :7566-7571+:7603 打包 `(anchor_x, anchor_y, ghost_h, ghost_w)`（ghost_w=master.ghost_rect[0], ghost_h=[1]）；F7 的 `ghost_rect_repr` 是对 state.ghost_rect 的逐字节比对（producer/consumer 同源所以内洽），但**任何从 ghost_rect 重导 ghost_cells 的新代码**在非正方形 ghost 下会踩轴序（F7 测试 fixture 用 16×16 正方形掩盖了这点）。

## B. helper-vs-master 等价回归（F7 升格前置）

### master 侧供电谓词实现清单（全部实测定位）
1. **certified coordinate master**（唯一 certified 默认 master）：`CoordinateExactMasterDelegate._add_geometric_power_coverage_constraints`（exact_coordinate_master.py:5846-5928）。分两条路：
   - **几何相交路**（前提 `_supports_rectangular_power_coverage()` :5160-5194 为真：power_pole 模板有 radius、每个 powered pose footprint 是实心矩形、且每个 pole pose 的 `power_coverage_cells` 等于重算的 `[x0-R, x0+1+R]×[y0-R, y0+1+R]` 截边矩形）：per powered slot 建 cover-choice witness，双轴区间相交约束 bounds 形式 :5349-5367（`powered_x_start <= cover_x + 2 + R - 1` ∧ `cover_x - R <= powered_x_start + width - 1`，2=pole 宽硬编码）或 delta 形式 :5373-5394，witness 绑真实 pole slot（block/wide element 编码，选择由 `EXACT_POWER_COVERAGE_WITNESS_ENCODING*` env）。无 pole slots 时 powered active==0（:5864-5869）。
   - **table 回退路** `_add_table_power_coverage_constraints`（:5196-5247）：用 owner 预算表 `_power_coverers_by_template_pose` + `AddAllowedAssignments` 的 (pole tuple, powered tuple) 白名单 + `sum(witnesses) >= active`。
2. **coverers 表的构建**（master_model.py）：`cell_to_poles`：pole pose 的冻结 `power_coverage_cells` 逐格倒排（:3483-3526）→ powered 模板每 (anchor,shape) 组代表 pose：coverers = ∪cell_to_poles[pose 占格]，再过 **footprint 不相交过滤** `representative_pose_cells.isdisjoint(power_pole_cells)`（:3738-3758）→ `power_index[pose_idx]=filtered_coverers`（:3792-3794）。即 master 谓词 = **stencil 相交 ∧ pole 体与设施体不重叠**。
3. **pose-bool 备选 master**：`pose_bool_exact_master.py:595-628`，`x_var <= sum(coverer pole vars)`（查同一张表）。
4. **legacy/exploratory master**：`master_model.py._add_power_coverage_constraints` :4881-4916（z_var 版，同表）。
5. **terminal 独立复验**（最强、TCB 内）：`pr2_l0_artifact_core.py:1023-1030` `any(cell in coverage_cells for cell in cells)`（冻结 pose 字节独立重算、相交谓词）+ 无冗余塔检查 :1035-1045。PROJECT_LOCK:65-74 把谓词 6 钉为 "master 硬约束 + terminal 独立复验"，owner 2026-07-07 裁定=相交。
6. binding/routing 子问题**无**供电约束（binding_subproblem.py 仅把 power_pole 当合成 pose-optional 实例映射 :56-59；routing_subproblem.py 零 power 命中）——供电只在 master + terminal 两层。
