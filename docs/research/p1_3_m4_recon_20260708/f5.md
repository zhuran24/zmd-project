### A3. 数学断言 + cert payload 字段表

**数学断言**：cert 携带一个 deletion-minimized 禁止模式 π = `forbidden_pose_pattern`（带匿名 slot 的三元组列表）。语义 = 子问题 oracle 证明"任何扩展 π 的完整解不可行"（liftable-reject 前提下），cut 禁止任何"逐组被选 pose 多重集包含 π 的 (group,pose) 多重集像"的赋值——评估语义见 `evaluate_literal_multiset`（`lifecycle.py:1015-1071`，Counter ≥ Counter 多重集包含）。**soundness 信任边界 = validator 重新查询 oracle 必须复得 INFEASIBLE**，witness 字节刻意不进 cert（跨 worker 非确定，Gemini F5 round-1 BLOCKER 修复；`pattern_nogood.py:20-24`、`pattern_nogood_oracle.py:210-212`）。

**cert payload 闭集字段**（`cert_schema.py:68-74`，allowed==required，多一个少一个都 `CertPayloadSchemaError`）：

| 字段 | 约束（validator 阶段） |
|---|---|
| `cert_kind` | == `"bounded_deletion_core"`（`pattern_nogood.py:81-89`） |
| `sub_problem_oracle_name` | 非空 str 且 ∈ 注册表，否则 schema_err fail-closed（`:92-120`） |
| `sub_problem_oracle_version` | 与注册 adapter.version 严格相等，否则 unsound（`:121-129`） |
| `forbidden_pose_pattern` | 非空 list of `[group_id, slot_index, pose_id]`；exact-triple 去重；slot 完整性三条（见 A6 锁）；pose ∈ pose_domain；长度 == `size_after`（`:183-288, 426-432`） |

### A4. step_8 翻译候选形态 + soundness 依据（与 F1 的本质区别）

- **现状**：未接线。`MasterModelLike` Protocol 只声明 `add_region_capacity_cut(*, group_cell_weights: Mapping[str,int], capacity: int) -> bool`（`lifecycle.py:1115-1130`），master 侧没有 F5 API。
- **自然候选形态** = presence nogood，与既有 whole-layout nogood `add_benders_cut` 同形（`src/models/exact_coordinate_master.py:7084-7135`）：`model.Add(sum(present_lits) <= len(present_lits) - 1)`（`:7115`）。presence literal 走三层 content-addressed 缓存：`_eq_literal`（:6921，key=(var.Index(), value)）→ `_slot_pose_match_literal`（:6937，key=(slot.key, normalized pose_tuple)）→ `_pose_present_literal`（:6983，key=(sorted slot keys, normalized pose_tuple)）。F5 设计稿 v1 §4.5 / v2 §4.5 都判定"presence nogood 机械直接承载 F5，无需新增 master 表达形式"。
- **soundness 类型 = 依赖 cert 门禁，不是恒真**。F1 的不等式对任何可行布局物理恒真（`lifecycle.py:1141-1151` 注释、`exact_coordinate_master.py:7143-7151`），attach 永远 sound、与 cert 新鲜度无关；F5 的 presence nogood **只有当 cert 的 INFEASIBLE 判决有效且轨道提升前提成立时才为真**——soundness 完全悬挂在 steps 5-7（validator 重查 oracle + scope 门）+ v2 设计稿三前提（P-HOM / 无重复 (group,pose) 及 presence-key alias / liftable-reject）上。这是审视 F5 接线时与 F1 最重要的范式差异。
- **两个已知翻译陷阱**（v2 稿已定裁）：① **multiplicity 坍缩**（BLOCK-2）：boolean presence 会把"同 pose ≥2 份才不可行"坍缩成"≥1 份即禁" = FP；方案 A = validator 禁 cert 内重复 `(group_id, pose_id)`——**当前 validator 还没有这条检查**（现只禁 slot 复用；v2 §4 现状/MUST 分离表明文确认）。master 现有 alias fail-close（`_conflict_pose_entries` 对重复 `(scope,pose_idx)` key 整体返回 `[]`，`exact_coordinate_master.py:7053-7055, 7074-7076`；all-or-nothing 注释 :7020-7028）恰好挡住这类 cut 的表达，v3 终审把它升为必须保持的不变量。② **pose 身份阻抗失配**：F5 literal 的 pose_id 是**字符串**，master presence 机械按 `(facility_type 模板, pose_idx int)` → `pose_tuple=(x,y,mode_id)` 寻址（`_template_pose_tuple_by_idx`/`_template_pose_idx_by_tuple` 由 `enumerate(pool)` 建，`exact_coordinate_master.py:1698-1713`）；step_8 F5 翻译需要 pose_id(str) → pool 下标的解析层（pose_id 在 `facility_pools[tpl][idx]["pose_id"]`）。

### A8. Phase 1.2「实质停用」条款检查

**没有 F9 tight-K 式的显式"实质停用"锁条款**。PROJECT_LOCK.md 里 F5 相关条款反而是：

1. **正向强制**（PROJECT_LOCK.md:408-411，F9 paradigm 降级 lock）：binding/routing/PCR-CUT INFEASIBLE **必须** fallback F5 pattern_nogood，不许 silent generalize 成 density cut——F5 是钦定的兜底族。
2. **slot 完整性锁**（PROJECT_LOCK.md:422-428）：`forbidden_pose_pattern` 每 literal 必须绑真实、唯一、界内匿名 slot（`slot_index < demand` + `(group,slot)` 唯一 + per-group ≤ demand），防 slot-collision 核被 multiset 提升成过强 cut（FP）。已实施于 `pattern_nogood.py:239-276`，红测 `:665, :680`。
3. **升级路径交叉引用**（PROJECT_LOCK.md:461）：恢复 tight F9 须"与 F5 v1.0 信任 INFEASIBLE 同类升级"。

**但 F5 事实上处于五层结构性停用**（A2 四层 + A5 selected_poses 空的第五层），且 P1.3 落地被 v2 设计稿的 MUST 表卡住：现源码是 pre-P1.3 形态——validator 无 `(group,pose)` 重复检查、oracle 协议仍是读 mutable state 的 `query(core,state)`、canonical 层只 sort+dedup 无重标、cert schema 无 `orbit_homogeneity_digest` 字段（v2 稿 §4 现状/MUST 分离表逐项列明）。M4 阶梯本身"待 owner 发话开工"（`00_master_roadmap.md:31`）。
