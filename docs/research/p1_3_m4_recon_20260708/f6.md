## 2. 数学断言 + cert payload 字段表

**一句话断言**：把某条 70 格 baseline（左列 y=0 或底行 x=0）被 `ghost_cells ∪ exterior_blocks` 切成的最大连续空段记为长度 ℓ_i（offsets 严格递增不重叠），则 1×L 刚性 pose（L=pose_length≥2）在该侧最多能放 `total_packable = Σ⌊ℓ_i/L⌋` 个；若被 pigeonhole 证明必须落在该侧的数量 `region_demand`（≤ `max(0, group_demand − 对侧 baseline 容量)`）**严格大于** total_packable（`total_packable < region_demand`，等号不切），则当前 ghost 状态不可行 —— Hall/区间见证。

**cert payload 完整字段表**（`src/cuts/cert_schema.py:75-90`，14 字段；`CERT_PAYLOAD_REQUIRED_FIELDS = CERT_PAYLOAD_ALLOWED_FIELDS`（:113-116）→ 全部必填、无多余字段）：

| 字段 | 语义/约束（family docstring :19-41 + validator 各 phase） |
|---|---|
| `cert_kind` | 必 == `"hall_interval_witness"` |
| `region_kind` | 闭集 `{"left_baseline","bottom_baseline"}`（family :76） |
| `region_total_length` | 必 == 70（audit anchor，family :146-152） |
| `partition_lens` | list[int]，每项 ≥1；validator 用 helper 重算严格相等 |
| `partition_offsets` | list[int]，≥0、严格递增、不重叠、offset+len≤70；**同样重算严格相等**（非 debug-only，spec §10 q3） |
| `pose_length` | int ≥ 2（==1 退化成 F1，schema_err 拒收，family :15-17） |

| `max_packable` | list[int]，len==len(partition_lens)，每项 == lens[i]//pose_length |

## 3. step_8 master 翻译（现状 + 候选形态）

**现状**：`step_8_apply_to_master(cut, master_model)`（`src/cuts/lifecycle.py:1133`）只接了 `region_capacity` 分支（:1153-1185）；其余族包括 F6 命中 :1186-1189 的 `raise NotImplementedError("step_8: family=... 的 master 翻译尚未接线 — P1.3 M4 阶梯逐族实施, 未接线族 fail-closed.")`。M4（F2-F7+F9 逐族阶梯）**待 owner 发话开工**（`docs/项目说明/00_master_roadmap.md:31`）。

**候选形态（我的分析，非既定设计）**：F6 的自然翻译是 **F1 式"计数容量"不等式（权重=1，不是 F1 的 cells_per_pose 面积权）**，且成对下发才干净：

- 对 region_kind ∈ {left, bottom} 各一条：`sum_{p ∈ domain(g), body(p) ⊆ 该侧未被挡 baseline 格} presence(g,p) ≤ total_packable(该侧)`。
- **soundness 依据**：total_packable 是"若干区间里最多塞几个不相交 1×L"的组合恒真上界 —— *条件是* 分区所用 blocked 集（ghost∪exterior）确实被 master 强制为空。生产里 exterior=∅、ghost 空置由 master ghost 约束强制 → 相对该 master（选定 anchor 前提下）是恒真/被蕴含的 valid inequality，与 F1 的 doctrine 相同（attach 不依赖 cert 新鲜度，staleness 留给 steps 5-7）。cert 的 `region_demand`/`group_demand` 在这种形态下**根本不需要进 master**（只用重算过的 partition → total_packable），符合"不信任无法重算的 cert 标量"锁。
- **presence-nogood 形态不适合**：Hall 见证不携带 incumbent pose 列表，nogood 形态弱于计数式且与 `_add_exact_whole_layout_nogood` 重复。
- **需要的 master API（现在不存在）**：`add_region_capacity_cut`（`src/models/exact_coordinate_master.py:7137`，`master_model.py:12095` 委托、非 exact 后端 fail-closed False）是对 group 的**全 pose 域**加权求和，无法按"pose 落在哪条 baseline"过滤。F6 需要新 API（例如 `add_baseline_packing_cut(group_id, region_kind, capacity)`），内部要把 pose tuple `(x,y,mode)`（`_template_pose_tuple_by_idx`，exact_coordinate_master.py:767）映射回 occupied cells（模板 dims+朝向，或经 owner.facility_pools 的 pose dict `occupied_cells`）来筛"整体落在该侧 baseline"的 pose，再走既有三层 content-addressed presence 缓存 `_eq_literal`(:6921)/`_slot_pose_match_literal`(:6937)/`_pose_present_literal`(:6983) 求和 ≤ cap，沿用 all-or-nothing fail-closed + witness 失效（`_last_solution/_solver/_status = None`，:7210-7212）。
- **⚠ anchor 条件性（最大坑，见 risks）**：master 的 ghost anchor 是决策变量（`u_vars` + AddExactlyOne；`_selected_ghost_context` benders_loop.py:5397-5478 从解里恢复唯一选中 anchor）。F6 的 partition 依赖**具体 anchor 的 ghost cells**，把按 incumbent anchor 算出的 capacity 无条件 `model.Add` 进 master，会约束住换 anchor 后的解 → 潜在 FP。已有机制参照：whole-layout nogood 走 `add_benders_cut(..., condition_lits=...)`（benders_loop.py:7506-7509）按选中 ghost literal 条件化。F6 翻译要么条件化（condition_lits 挂 u_var），要么用对所有 anchor 都成立的弱化容量（对 anchor 取 max 的 packable）。F1 的 `compute_static_capacity`（families/region_capacity.py:150-159，`|R|−|(ghost∪exterior)∩R|`）同样带 ghost 项，其"物理恒真"论证是以当前 BState 的 blocked 集为前提写的 —— F6 的区间结构对 anchor 更敏感，不能照抄 F1 的无条件 attach 而不过这一关。
