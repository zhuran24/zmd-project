# R3 方法论移植轮——实验设计（2026-07-20，owner 提出）

## 目的（与 R1/R2 的区别）

- R1（已完成，判读见 `05` 号）：全盲重推——测"独立大脑会不会收敛到我们的架构"，是**验证**型实验；
- R2（已备好待发）：判据探针——强制分解设定下问归属/反馈/上收的**判据**，测它会不会公式化出我们的元理论；
- **R3（本轮）：方法论移植——把我们的元方法论交给它、但不给任何对象层方法与历史，看它在干净路径上生成什么攻击方案**。是**生成**型实验，目标是绕开路径依赖盲区：我们的方法序列被"先撞哪堵墙"塑造，它没有我们的伤疤，可能长出我们从未考虑的刀法。

## 污染边界（成败关键）

**进包**（元层）：分层与规则归属三腿判据（尺寸/传播力/机器兼容）+薄腰原则；反馈语言原则与踏车警报；上收循环与必要条件证书（含"投影不得更严"）；六级漏斗；证明信任边界（solver 状态非证据/UNKNOWN 无结论/异构复验/全称判词纪律）；诚实边界汇报纪律。全部**抽象表述**，不带本项目实例。

**不进包**（对象层，一条都不给）：任何具体规则的归属结论（供电/走线口……）；任何编码（布尔化/紧凑表/查表……）；4 小实例规约；全部实验结果与数字（含 (1326,34)、47 模式）；失败史与判决；我们的架构（LBBD 三层这个词也不出现——分层作为**原则**在判据里自然出现，但不点名我们的切法）。

**攻击面自查**：简报写完后过一遍禁词扫描（对象层名词表）+"读者能否从简报反推出我们做过什么"的红队自问。

## 发送形态

新开对话（不接 R1/R2 线程）。附件四件：strict 外发三件（不动）+ `R3_methodology_brief.md`。提示词：按简报自行取舍地应用/批判该方法论，产出**它真的会去执行的具体攻击方案**（先上收什么、追什么证书、什么编码、什么探针序、什么放弃判据），方法论本身显得次优/不完整处直说并给更好的。

## 判读面

- 主判据：方案里出现**我们已试清单之外**的方法（对照 roadmap 换攻法清单+两个月全部已试项）→ 逐条评估可行性；
- 次判据：它对方法论本身的批判（哪条判据它认为不完备）→ 元层增量；
- 与 R1 对照：同一大脑，无方法论 vs 有方法论，方案差在哪 → 测方法论本身的"引导力"；
- 收编走既有纪律：外部方案先异构核实、再入 roadmap 候选，不直接当结论。
