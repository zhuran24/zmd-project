主推方案是“**交替极性条带 + 单一有向环 + live-pose 精确覆盖**”：先固定一套能承接全部 628 个激活终端的物流骨架，再只允许自带真实端口证书的机身、核心、孔洞和电杆候选进入精确模型。我对首轮 32 个宏模板变体内产出完整见证的粗估为 **约 60%**；主要不确定性集中在核心、6×7 孔洞和约数十根电杆对有限余量的精确咬合。【猜测】

下文的“可行”“判死”均只指这套构造族，不外推整个 benchmark。

## 一、材料核对与死亡名单结论

【已证明】`04_rules/` 与 strict instance 的关键数字闭合：266 个 mandatory 设施，219 台制造机，mandatory body area 3,544；制造端口 310 入、264 出，共 574；再加 52 个 generic 原料输出和 2 个 final 输入，总计 628 个激活终端。九个 port class 的数量也与 17 个 operation group 逐项相容。

【强论据】发现一处不影响合法性语义的资源口径差异：`05_strict_contract/problem.md` 写 48 GB，`00_ASK.md` 与规格书要求按 47 GB 折算。以下统一按 **47 GB** 做预算。

【已证明】规格书所称 82,829 个“完整候选 pose”不是纯 body-in-grid 池。例如 3×3 的纯机身池应为 `68×68×4=18,496`；17,952 已经排除了至少一侧激活 front 出界的姿态。数值正确，措辞最好改成“完整的端口可存活 pose 池”。

【强论据】三条死亡判定本身没有明显漏洞，但其范围都不覆盖本方案：

* 本方案不是 pinned body-only。每个 machine pose 在被选中前，已经带有真实 class、合法朝向和足够的可激活 front。
* 本方案虽然也使用交替南北极性，但 H20 判死只覆盖固定核心、固定保护矩形、固定 20 杆 token 语法及其行序空间。这里电杆自由摆放，并在几何主门内精确验证供电。因此这是“判死范围没有外推到这里”，不是推翻 H20 的证明。
* 本方案不是旧 monolithic 模型。路由不进搜索，核心和孔洞不是旧固定家具，候选变量约为旧全池的十五分之一量级。

## 二、主推构造的骨架

### 1. 先把 46 个边界源完全固定

采用如下显式布局：

* 23 个 bottom port：锚点 `(3k,0)`，`k=0,…,22`；
* 23 个 left port：锚点 `(0,1+3k)`，`k=0,…,22`。

其输出 front 分别是 `(3k+1,1)` 与 `(1,3k+2)`。

【已证明】两组机身均在图内，各自不重叠，且不在 `(0,0)` 相撞；46 个 front 全在图内。这样既消除了边界端口搜索，也自然留下 `x=1` 作为左侧物流干线。

### 2. 14 条制造带恰好填满高度

首选 band 顺序为：

`(5,3,4,3,5,3,4,3,5,3,4,3,4,5)`。

其中 3、4、5 分别表示 3×3、横放 6×4、5×5 制造带的高度。走廊 y 坐标为：

`c=(1,7,11,16,20,26,30,35,39,45,49,54,58,63,69)`。

制造带 `i` 位于 `c[i-1]+1 … c[i]-1`。

【已证明】

`6×3 + 4×4 + 4×5 = 54`，

14 条带需要 15 条单格走廊，因此：

`54+15=69`，

正好占用 `y=1…69`；`y=0` 留给 bottom ports。

奇数带统一用 `north_to_south`，偶数带统一用 `south_to_north`。于是：

* 偶数编号走廊 `c0,c2,…,c14` 只接输出，是 source corridor；
* 奇数编号走廊 `c1,c3,…,c13` 只接输入，是 sink corridor。

【强论据】这一步正面解决了 front 冲突：同一走廊格最多面对上下两个同极性终端。source 格可以用一个 merger 接受“环的前驱 + 上方输出 + 下方输出”；sink 格可以用一个 splitter 输出到“环的后继 + 上方输入 + 下方输入”。两者都落在 strict 合同允许的 2 至 3 个支路范围内。

### 3. 横向容量与名义余量

固定 `x=1` 为返回干线；每条制造带另留一个 1 格宽的竖向 riser。机身横向工作区为 `x=2…69`，共 68 列；扣除该带的一个 riser 后，仍有 67 列。

【已证明】

* 3×3：`floor(67/3)=22`，6 带容量 `6×22=132`，恰好；
* 5×5：`floor(67/5)=13`，4 带容量 52，需求 49；
* 6×4：`floor(67/6)=11`，4 带容量 44，需求 38。

对应的 body-zone 名义余量为：

`6×67×3 − 132×9 = 18`

`4×67×5 − 49×25 = 115`

`4×67×4 − 38×24 = 160`

合计 **293 格**。【已证明】

这 293 格不是任意形状的大空地，而是分散在各带里的碎片，因此不能只按面积乐观判断。它只是第一道门的账面上限。

### 4. 物流采用“14 行环 + 顶层馈线”

前 14 条走廊 `c0…c13` 组成一条有向蛇形环：

* `c0` 从西向东；
* `c1` 从东向西；
* 依次交替；
* 相邻走廊通过制造带中的单格 riser 相连；
* `c13` 的西端接入 `x=1`，沿 `x=1` 向南返回 `c0`。

顶层 `c14` 是 source-only 馈线，不进入环本体。它从东向西收集第 14 带的输出，再沿一个竖向 slit 汇入 `c13` 的环入口。左边界端口在 `x=1` 上直接以 merger 汇入返回干线。

基线物流格数为：

`15×68 + 54 + 68 = 1,142`。

其中三项分别是 15 条横向走廊、14 条带内 riser 的总高度、左侧返回兼源收集干线。【已证明】

核心宏会截短部分走廊并增加局部 feeder，因此每个宏变体都必须记录自己的精确 `|R_s|`，不能把 1,142 当最终常数。

### 5. 单一有向环为什么消灭了 commodity 路由搜索

对环上每个格 `v`，记环的进入方向为 `pred(v)`，离开方向为 `succ(v)`。

* 若 `v` 邻接一个或两个制造输出，则放 merger，输入集合为 `{pred(v)} ∪ 输出终端方向`，输出为 `succ(v)`；
* 若 `v` 邻接一个或两个制造输入，则放 splitter，输入为 `pred(v)`，输出集合为 `{succ(v)} ∪ 输入终端方向`；
* 无终端时放 straight 或 turn；
* 所有特殊转角及 feeder 接口由预编译宏给出，live-pose 生成器禁止把端口绑到方向冲突的角格。

【强论据】环本身在每个 merger 和 splitter 处都保留“前驱到后继”的有向通路，因此仍是完整有向环。每个输出都能进入环，每个输入都能从环分支取得物料。strict 数据中 19 种商品各自至少有一个源和一个汇，所以每个商品的任意源都能绕环到达该商品的任意汇，反向量词也同时满足。

这不是把 class 错当成一般意义上的 routing 等价类。它是本构造中特有的结论：所有终端都接同一有向环后，同一 port class 内的 recipe 身份不再影响几何可达性。商品标签仍在端口绑定门中逐个写入，并由最终 checker 复核。

### 6. 核心与 6×7 孔洞采用局部精确宏

一个首选核心宏为：

* core 锚点 `(60,60)`，机身 `x=60…68,y=60…68`；
* mode 为 `inputs_north_south`；
* 六个输出 front 位于 `x=59` 或 `x=69`，`y=61,64,67`，由两条竖向 source collector 向北汇入 `c14`；
* 两个 final 输入选择南侧 front，经 `c13` 的局部 sink branch 接入；
* `c13` 在核心西侧截短，避免被 9×9 机身切断。

【强论据】上述接口可以只用 straight、turn、merger、splitter 实现；它仍需由局部宏验证器逐格确认，不能靠文字描述直接晋级。

孔洞首选放在第 9 条 5×5 带：

`H=[a,a+5]×[39,45]`。

其中 `y=40…44` 是 5×5 机身带，`y=39,45` 本来就是 source/sink 走廊。只需在该带留一个 6 列宽机身缺口，便得到完整 6×7 body-free 矩形；两条横向带和一条 riser 可以穿过孔洞。

【已证明】该孔洞只额外消耗 30 个 body-zone 格，而非 42 个，因为 12 个走廊格本来就不得放设施。

对上述核心和孔洞宏，body-zone 剩余为：

`293 − 72 − 30 − 4P = 191 − 4P`，

其中核心有 72 格落在制造带 body-zone，另 9 格替代原走廊；`P` 为电杆数。【已证明】

例如 `P=36` 时余 47 格，`P=41` 时余 27 格。这说明最大的风险不是总面积，而是这些余格能否形成足够多的 2×2 杆位并覆盖全部机器。

每个宏变体还必须满足更严格的全图必要条件：

`4P ≤ 4,900 − 3,544 − |R_s ∪ H|`。

孔洞与传送带允许重叠，所以这里必须减去并集，不能把二者重复扣除。【已证明】

## 五、第一道构造门的可执行模型

材料核验不计入构造漏斗。第一道构造门是 **固定 skeleton 变体上的分数 live-pose LP**；第一个构件则是上面的交替极性条带与有向环，二者不是同一个东西。

对一个固定 skeleton/core/hole 宏变体 `s`：

* `Q_c`：port class `c` 的全部 live machine poses；
* `P_s`：所有不碰边界设施、核心、孔洞和预留路由格的 2×2 pole poses；
* `B(q)`：pose 的 body cell 集；
* `Cov(p,q)=1`：杆 `p` 的覆盖域与机器 pose `q` 至少有一个 body cell 相交；
* `N_c`：九个 class 的冻结数量。

变量：

`0≤y_q≤1`，表示分数选择 machine pose；

`0≤z_p≤1`，表示分数选择 pole pose。

约束族：

1. class 精确计数
   `Σ_{q∈Q_c} y_q = N_c`，对九个 class 分别成立。

2. 分数 cell exclusivity
   `Σ_{q:b∈B(q)} y_q + Σ_{p:b∈B(p)} z_p ≤ 1`，对每个未被固定设施占据的格 `b`。

3. 供电影子
   `y_q ≤ Σ_{p:Cov(p,q)=1} z_p`，对每个 machine pose。

4. 杆数面积上限
   `Σ_p z_p ≤ floor((4,900−3,544−|R_s∪H_s|)/4)`。

5. live-pose 生成条件
   pose 只有在其 input side 至少有 `r_in` 个可绑 port、output side 至少有 `r_out` 个可绑 port，且所有这些 front 落在正确极性的 lane 上时才进入 `Q_c`。转角、核心接口和 feeder 汇入口的方向冲突格预先从候选 port 集中删除。

【已证明】在固定 14 带 skeleton 下，未展开 port 子集时：

`|Q_m| ≤ 68×(6×4 + 4×2 + 4×3) = 2,992`。

括号中分别是 6 个 H3 带乘 4 个 3×3 class、4 个 H5 带乘 2 个 5×5 class、4 个 H4 带乘 3 个 6×4 class。

2×2 pole 的带内纵向锚点数上界为：

`6×(3−1)+4×(5−1)+4×(4−1)=40`，

每个纵向锚层至多 67 个横向锚点，因此：

`|P_s|≤40×67=2,680`。【已证明】

第一门总变量上界约 **5,672**。若 LP 不可行，Farkas 对偶向量就是机器可复核拒绝证书；若可行，分数解只作为 G2 的 hint 和 pole-count lower bound，绝不视为布局证书。

## 六、第一个构件的确定性路由编译器

对每个预留网络格 `v`，宏目录给出网络前驱方向 `a`、后继方向 `b`。端口绑定后计算：

* `I_v`：在该格进入网络的设施输出方向集合；
* `O_v`：从该格离开网络进入设施输入的方向集合。

编译规则为：

```text
若 I_v=O_v=∅：
    a、b 相对则 straight；垂直则 turn
若 I_v≠∅：
    要求 O_v=∅、|I_v|≤2、所有方向互异
    生成 merger(inputs={a}∪I_v, output=b)
若 O_v≠∅：
    要求 I_v=∅、|O_v|≤2、所有方向互异
    生成 splitter(input=a, outputs={b}∪O_v)
```

feeder 起点、末端、核心接口和环闭合点使用同样的有限方向签名表；每个签名在宏编译阶段逐格验过。

【强论据】这使 G4 不需要任何 commodity path solver。商品只作为图上的标签传播；一旦所有 source 接入环、所有 sink 从环分出，19 次 reachability 只是复核，不是搜索。

## 七、最大单点风险与最便宜的试探实验

最大单点风险是：**精确 power-pole packing，而不是路由。**

【已证明】首选 skeleton 只有 293 个 body-zone 名义余格。放入首选 core 宏和 H5 孔洞后只剩 `191−4P`。当电杆数接近 40 时，余量只剩约 30 格，而且还被切成细条和小块。面积闭合并不能保证能形成分布合理的 2×2 杆位，这正是密度与连通性张力在本方案中的最终形态。

最先应跑的实验是：

1. 固定上述 band 顺序、边界端口和有向环；
2. 生成 8 个 core 宏位置/朝向与 4 个 hole 横向位置，共 32 个变体；
3. 先跑 G1 LP；
4. 对 LP 幸存者只跑 G2 的几何、孔洞、端口余量与 exact power，不放 operation 商品标签，也不建 routing 搜索；
5. 记录每个变体的 LP pole lower bound、整数状态、首个可行解时间、peak RSS、冲突数与最终杆数。

建议资源编排为 4 个 CP-SAT 进程并发、每进程 6 workers、每变体 30 分钟上限；若 16 个变体进入整数门，最坏计划预算为 2 小时。【猜测】

正面结果是一张带 pole witness 的 geometry certificate。全部 UNKNOWN 不是负结果。只有可验证的整数不可行证明才允许缩小或判死该宏族。

## 八、备选路线与取舍

备选是保留同一条带和 exact power 主模型，但取消“所有商品共用一个环”，改为按商品构造若干局部有向岛。strict 允许同一商品存在多个互不连通的岛，因此可优先把生产者和消费者在相邻走廊上局部闭合。

【猜测】它有机会减少长返回段和核心 feeder 的自由格需求，但会失去“同 class 任意置换”的优势，几何模型必须提前知道 operation 身份，并重新引入 19 个商品的路由分解。除非 G1 明确显示主方案的 `|R∪H|` 使电杆上限过低，否则不应先走这条更宽、更嘈杂的路线。

## 九、需要补充的数据与实测

规则语义本身足够设计上述管线。落地仍需以下资料：

1. **authoritative checker 的布局序列化 schema、CLI 和最小样例**：用于生成 G6 真正接受的设施、端口绑定和 transport component 文件。
2. **项目认可的负证书格式**：例如 VeriPB、DRAT 或其他 PB/SAT proof checker。若没有，G2 的所有负输出只能记为未决，不能用于判死。
3. **47 GB 与 48 GB 的实际可用内存口径**：用于确定 G1/G2 的并发数；在澄清前按 47 GB。
4. **上述 32 变体探针的遥测**：尤其是 LP pole lower bound、CP-SAT peak RSS、分支/冲突增长和首解分布。它决定是否把 skeleton 变体放在外层并行，还是合并为一个带 selector 的模型，也决定整数门的实际时间上限。

最优先的工程动作不是写 commodity router，而是跑固定有向环下的 **LP 影子 + exact geometry/power 探针**。只要 G2 给出一张完整几何证书，后续端口绑定、运输组件生成和逐商品可达性都已被压缩为小规模匹配与确定性复核。
