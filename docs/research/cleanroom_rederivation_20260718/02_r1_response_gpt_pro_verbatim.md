## 结论

应采用 **"分解式求解，统一式证明"** 的双轨架构：

1. **找解轨**负责尽快获得高质量、完全合法的布局，允许使用 CP-SAT、LNS、局部搜索和各种启发式。
2. **证明轨**不直接做完整优化，而只证明一个判定命题：

"是否存在一个合法布局，含有比当前布局更好的空矩形？"

当前布局给出下界；上述判定式的可验证 UNSAT 证书给出上界。二者相等，最优性闭环完成。

证明轨内部采用一个伪布尔 PB 几何主问题，加一个带证书的传送带连通性分离器。不要把所有传送带流变量一次性塞入主模型，也不要把某个 CP/MIP 求解器打印的 `OPTIMAL` 当成最终证明。

适合的工程栈是：

* 找解：CP-SAT/LNS。CP-SAT 适合整数离散模型，可用于快速产生候选和改进布局，但其输出在本架构中只作为候选，不是信任根。
* 主证明：RoundingSat 或 Sat4j 的 proof-logging 版本，输出 VeriPB 证明，再由 CakePB 做形式化验证。2025 年的工作已经覆盖了这两类 PB 求解器的高级推理、LP/Farkas 证书和割平面，并给出了形式化验证后端。
* 精确传送带子问题的备用方案：CaDiCaL/LRAT，加 cake_lpr 验证。CaDiCaL 已有原生生成 LRAT 的实现路线，cake_lpr 是经 CakeML/HOL4 形式化验证的 LRAT/LPR 检查器。

有一个前置条件必须明确：实际证书实例还需要完整的 17 种配方表，以及对"万能口是否必须全部使用""传送带方向和单格局部结构"的规范化定义。当前文本足以设计架构，但还不足以生成唯一的最终实例哈希。

# 1. 总体架构

我会拆成六个组件。

## 1.1 规范化实例编译器

输入是一个不可含糊的 `instance.json`，包括：

* 每个配方类的数量、几何类型；
* 每种商品的精确输入和输出路数；
* 每个通用口是必用、可用还是容量上限；
* 传送带局部语义；
* 地图、塔覆盖和目标定义。

编译器确定性地生成：

* 每个设施类的全部合法姿态；
* 每个姿态的本体格集合；
* 每个物理端口及其接驳格；
* 每个塔锚点的本体格和覆盖格；
* 变量编号及其语义映射；
* PB/OPB 模型和审计清单。

同配方、同几何的机器不应逐台编号。对每个等价类 k 和姿态 p，只使用一个二元变量 x_{k,p}=1 表示该类有一台机器采用姿态 p，再加 Σ_{p∈P_k} x_{k,p} = n_k。

因为同类机器没有任何可观察身份，这不是启发式对称破除，而是对原问题的精确商模型。它把数百万个"机器编号乘摆位"变量压到大约 25 万至 35 万个姿态变量。

编译器必须附带一份逐类等价性说明。第三方需要审计的不是"求解器是否聪明"，而是"每个合法布局是否一定能映射到模型中的某个赋值"。

## 1.2 下界搜索器

职责是找到合法布局，不负责证明最优。

建议使用：

* CP-SAT 的多线程搜索；
* 固定候选空矩形后做 packing；
* LNS 反复重排矩形边缘附近的设施；
* 塔位、端口、仓储箱的局部修复；
* 与连通性检查器循环交换割。

下界搜索器输出完整候选：全部设施位置和朝向；所有使用端口及商品；塔和仓储箱；传送带格或可重建的商品路径；声称的最大空矩形。

这个候选必须经过独立的语义检查器。搜索器本身完全不进入信任边界。

## 1.3 PB 几何主问题

主问题处理：必建设施计数；辅助设施选择；本体不重叠；端口类型和精确计数；接驳格空置；供电；候选空矩形；已经发现的必要连通性割。

主问题不必从第一天起精确描述所有传送带细节。

一个重要原则是：**上界证明模型可以是原问题的松弛，只要它包含所有真正合法布局。** 设真正的更优布局集合为 V，证明模型表示的集合为 R。只需要保证 V ⊆ R。若最终证明 R=∅，自然得到 V=∅。因此，传送带可以先只加入必要的自由空间连通条件。允许模型暂时产生"假布局"只会增加求解时间，不会破坏证明可靠性。

## 1.4 连通性分离器

主问题每次给出一个整数候选，分离器检查传送带条件。

首选模式是自由格图上的连通分量检查，并生成全局有效的拓扑割。只有当这一松弛过弱、持续出现方向或局部带型不可实现的假解时，才升级到精确 SAT 路由子问题。

## 1.5 目标管理器与 cube 调度器

它不让证明求解器直接做字典序优化，而是接收一个已验证布局的分数 z*=(A*,s*) 并构造"存在更优矩形"的判定公式。

必要时把该公式按矩形宽、高、锚点区间切成若干互斥 cube，在多核上并行证明。每个 cube 独立输出 UNSAT 证书，另有一个很小的覆盖检查器验证所有 cube 恰好覆盖了全部更优矩形候选。

## 1.6 证书装配器与独立验证器

最终验证器只做以下事情：

1. 验证候选布局确实合法；
2. 独立计算该布局的最大空矩形及字典序分数；
3. 验证每条连通性割或路由 no-good；
4. 验证 cube 覆盖完整；
5. 调用 CakePB/VeriPB 检查各个 PB UNSAT 证明；
6. 如有精确路由 no-good，调用 cake_lpr 检查 LRAT 子证明。

第三方重放证明时不需要运行搜索器。

# 2. 每条规则放在哪里

| 规则 | 处理组件 | 推荐编码与理由 |
| --- | --- | --- |
| 本体不重叠、不得出界、设施数量 | 静态 PB 主问题 | 姿态在编译期保证不出界；每格一个占用等式，避免姿态两两冲突子句 |
| 类型匹配、精确端口计数 | 静态 PB 主问题 | 是局部且传播很强的约束，延后会产生大量贴脸和端口不足的垃圾候选 |
| 使用端口的接驳格空置且在图内 | 静态 PB 主问题 | 与格占用变量直接联结；图外接驳格不创建使用变量 |
| 中间商品、原料和成品连通性 | 连通性分离器 | 全局图约束，静态流编码体积大；用拓扑割按需加入 |
| 传送带方向、交叉和局部带型 | 精确候选检查器；必要时 SAT 路由子问题 | 对下界布局必须精确验证；上界证明可先用必要连通条件松弛 |
| 供电 | 静态 PB 主问题 | 塔本体影响不重叠和空矩形，不能完全推迟；覆盖关系本身是稀疏集合覆盖 |
| 空矩形与字典序目标 | 目标管理器加 PB 主问题 | 用四个边界变量和宽高表编码，不枚举数百万个矩形位置 |
| 仓储箱 | PB 主问题 | 它同时影响本体、供电、成品端点和空矩形 |
| 具体传送带布局 | 下界见证 | 上界只需证明不存在更优布局；不要求证明器为每个被排除候选都构造带网 |

## 2.1 不重叠的具体编码

设 b_g 表示格子 g 是否被任意设施本体占据。对每个格子：b_g = Σ_{p:g∈B(p)} x_p + Σ_{a:g∈B_tower(a)} t_a + Σ_{q:g∈B_box(q)} s_q。

因为 b_g 是布尔变量，右侧不能大于 1。不需要为每对相交姿态生成冲突子句。

这是本架构最重要的内存控制之一。禁止使用姿态两两 overlap clauses。

## 2.2 端口和接驳格

对姿态 p、物理端口 r、商品 c，使用变量 u_{p,r,c}。只为配方允许的商品创建变量。约束包括：u_{p,r,c} ≤ x_p；Σ_{r∈输入侧} u_{p,r,c} = d^in_{k,c} x_p；Σ_{r∈输出侧} u_{p,r,c} = d^out_{k,c} x_p；以及每个物理端口至多承接一种商品。

若端口 r 的接驳格为 g，则：u_{p,r,c} + b_g ≤ 1。

如果接驳格在图外，根本不生成相应的 u 变量。这样仍然允许设施贴边，只是朝外端口不能被使用。

可根据完整配方表在两种等价编码之间选择：端口槽位变量编码；预枚举本地端口掩码编码。掩码数量少时选后者，组合数大时选前者。

## 2.3 供电编码

使用塔变量 t_a，以及 4,900 个覆盖见证变量 z_g。z_g ≤ Σ_{a:g∈C(a)} t_a。对每个需要供电的设施姿态 p：x_p ≤ Σ_{g∈B(p)} z_g。

这里不要求所有被塔覆盖的格子都令 z_g=1。z_g 只是"这个格子被选作供电见证"。该编码比对每个设施姿态直接列出数百个可覆盖塔锚点稀疏得多。

塔的 2×2 本体仍然进入 b_g 占用等式，也必须避开目标空矩形。

## 2.4 空矩形编码

设矩形为 [L,R]×[D,U]。宽高分别为 w=R−L+1、h=U−D+1。边界坐标使用 order encoding。宽高关系使用一个有限表，不在 PB 中直接乘法。

对一个本体包围盒为 [x0,x1]×[y0,y1] 的姿态 p，加入：¬x_p ∨ (R<x0) ∨ (L>x1) ∨ (U<y0) ∨ (D>y1)。

在 order encoding 中，四个比较各自只是一个文字。因此每个姿态只需一个很短的矩形避让约束。

端口接驳格、传送带格可以位于空矩形内，因为目标只排除设施本体。

## 2.5 目标不做优化，只做一次"更优性反证"

候选布局经独立检查后得到 z*=(A*,s*)。定义：Better(w,h) ⟺ w,h≥6 ∧ [wh>A* ∨ (wh=A* ∧ min(w,h)>s*)]。

证明公式为：Φ_{>z*} = 全部必要规则 ∧ 存在一个满足 Better 的空矩形。

只要 Φ_{>z*} 被证 UNSAT，就完成上界。

由题中数据，必建设施已经占 3,544 格，所以任何空矩形面积都不可能超过 4900−3544=1356。因此只需考虑 6≤w,h≤70、wh≤1356 的 2,371 个有序宽高对。候选分数越高，实际需要考虑的对越少。

# 3. 组件之间传递什么信息

## 3.1 主问题发给连通性分离器

每个候选只需传：4,900 位本体占用位图；被选中的姿态 ID；每个已使用端口、商品、输入输出方向和接驳格；仓储箱和中枢的商品分配；可选的矩形边界，用于诊断和分支排序。

不应传求解器内部对象或不稳定的变量地址。所有信息使用编译器生成的稳定整数 ID。

## 3.2 连通性拒绝格式

不能只返回"路由失败"。必须返回一个可检查的全局有效推论。

设：I^c_g：格 g 上存在商品 c 的已用输入接驳；O^c_g：格 g 上存在商品 c 的已用输出接驳；S：当前自由格图中的一个连通分量；δS：与 S 正交相邻、但不在 S 中的地图格。

若 S 内有商品 c 的输入端点 g，但没有商品 c 的输出端点，则返回：

I^c_g ≤ Σ_{h∈S} O^c_h + Σ_{v∈δS} (1−b_v)。 (式 1)

当前候选中：I^c_g=1；S 内没有输出，第一项为 0；S 是自由格连通分量，所以所有边界格都被本体占据，第二项为 0。因此该候选违反式 (1)。

式 (1) 的语义非常清楚。未来布局要合法，至少必须发生一件事：删除或改变这个输入端点；在 S 中放入对应输出端点；释放至少一个边界格，使它有可能连接到外部。

对于"输出无法到达任何输入"，返回完全对称的割。

一条割的证书只需包含：commodity / direction / trigger_endpoint_cell / bitmap_of_S。独立割检查器根据位图重新计算 δS，验证端点方向和式 (1)。这个检查器可以控制在几百行代码内，也可以把拓扑割引理形式化一次。

这种割远强于"禁止整个当前布局"的大 no-good，并且能跨矩形 cube 和不同搜索运行复用。

## 3.3 精确路由子问题的拒绝格式

如果自由格分量条件全部满足，但精确的传送带方向或局部格型仍不可实现，则调用 SAT 路由器。

路由器把以下内容作为 assumption literals：哪些格被本体占据；哪些接驳端点存在；端点的商品和方向；必要的局部带型限制。

若 UNSAT，返回：一个最小化或近似最小化的 assumption core A；该 core 下路由 CNF 的 LRAT 证明；添加到主问题的 no-good：∨_{ℓ∈A} ¬ℓ。

第三方先用 cake_lpr 检查 LRAT，再检查 no-good 恰好是 core assumptions 的否定。这样主问题无权凭空发明路由割。

## 3.4 主问题发给目标管理器

每个 proof worker 返回：cube ID；`SAT` 候选，或者 `UNSAT`；SAT 时的完整主变量赋值；UNSAT 时的 VeriPB 证明文件；本次使用的 cuts 哈希；编译器、模型和求解器版本哈希；峰值内存、运行统计和 proof 文件摘要。

## 3.5 最终证书包

建议至少包含：instance.json / semantics.md / pose-catalog.bin / variable-map.json / candidate-layout.json / candidate-belts.json / cuts.jsonl / cubes.json / static-model.opb / proofs/cube-*.pbp / manifest.json / checker-source/ / verify.sh。

每个生成物都记录 SHA-256。审核者执行 `verify.sh` 后，只接受检查器的结果，不接受求解日志中的口头结论。

# 4. 最优性证明如何闭环

最终证明材料应明确给出下面四个可检查事实。

**事实一：下界见证**——独立布局检查器验证候选 W 满足全部规则，并自行计算 score(W)=(A*,s*)。最大空矩形要由检查器重新计算，不能相信布局文件中声明的矩形。

**事实二：所有加入的割都有效**——每条自由空间割由拓扑割检查器验证；每条精确路由 no-good 由 LRAT 子证明验证。

**事实三：所有更优矩形情况均不可行**——对每个 cube，CakePB/VeriPB 验证 Φ_{>z*} ∧ cube条件 不可满足。

**事实四：cube 完整覆盖**——一个独立的小检查器枚举所有满足 Better(w,h) 的宽高和位置，验证它们恰好落入至少一个已证明 UNSAT 的 cube。

于是可以作如下反证：假设存在分数高于 (A*,s*) 的合法布局。它必然包含一个满足 Better 的空矩形，因此落入某个 cube。该合法布局可以映射成该 cube 主模型的赋值，并满足全部已验证的必要割，这与该 cube 的已验证 UNSAT 证明矛盾。所以不存在更优布局。

# 5. 预见的前三个失败模式

## 5.1 失败模式一：证明了错误的问题

最危险的错误通常不是求解器 bug，而是语义缝隙：配方表遗漏一条路数；把可空置的万能口误当成必用；把"一个端口可服务多个输出"误写成一一匹配；把方向性带网误写成无向连通；错误删除贴边姿态；错误认为未使用端口也必须有空接驳格。

对策：把完整语义冻结为版本化实例；编译器和见证检查器由两套独立实现生成；对 5×5 到 12×12 的缩小实例做穷举交叉验证；每条约束有稳定的 origin ID；证明模型优先采用安全松弛（宁可允许假解，也不要在未证明的情况下排除真解）；证书模型不使用未经证明的地图对称性。搜索模型可以激进，证明模型必须保守。

## 5.2 失败模式二：变量、内存和 proof trace 爆炸

典型死法包括：266 台机器逐台编号，产生数百万姿态变量和巨量排列对称；对每对相交姿态生成冲突子句；为 19 种商品静态展开 4,900 层 reachability；每个设施姿态直接列举所有覆盖它的塔；一个巨大 proof 文件在结束时才发现检查器无法装入内存。

对策：按配方类聚合机器；使用每格 PB 占用等式；供电使用 z_g 覆盖见证；连通性使用按需拓扑割；端口采用 slot/mask 自适应编码；按矩形宽高和锚点做 cube 分解；每个 cube 独立 proof、独立 trim、独立压缩；proof 检查流式进行；从项目第一周就对 proof 生成和重放做小规模标定。

## 5.3 失败模式三：上下界长期不收敛

表现通常是：找解器卡在一个不错但不够好的矩形；上界模型不停产生具有巨大空矩形的假布局；连通性分离器每次只排除一个候选；路由 SAT core 包含几千个 assumptions，no-good 几乎没有泛化能力。

对策：每次候选同时加入所有有缺陷分量的割；按位图和商品对割做规范化、去重和包含关系消除；优先在矩形边界、本体边界和接驳格附近分支；把上界模型产生的假布局反向送给 LNS 尝试局部修复成真正下界；对频繁出现的路由 core 做 deletion-based core shrinking；分层升级连通模型（几何松弛 → 自由格分量割 → 桥和割点强化 → 精确方向 SAT）；若某类 cube 持续困难，固定更细的宽高或锚点区间。

# 6. 算力和内存预算

模型规模预估（配方类聚合后）：姿态变量约 25-35 万；塔变量 4,761；仓储箱姿态变量约 1.8 万；本体和供电格变量约 1 万；商品端口变量约 200-600 万；稀疏约束文字出现次数约 2,000-6,000 万。

运行分配：实例编译 1-2 核 / 1-2GB；下界 CP-SAT/LNS 12-16 核 / 14-24GB；连通分量分离器 1-2 核 / <1GB；精确路由 SAT worker 每个 1 核 / 1-4GB；PB proof worker 每个 1 核 / 约 6-10GB；proof 重放检查 1-2 核 / 6-12GB。48GB 主机上证明阶段初始并行 3-4 个 PB proof worker，cgroup 每 worker 8GB 硬上限。证明阶段是内存受限，而不是核心数受限。

总 core-hour：20-30% 寻找和加固下界；55-65% 更优性 UNSAT 证明；10-15% 证书重放与交叉检查。上下界并行推进，不要先雕刻候选再考虑证明。

磁盘：proof trace 按数百 GB 级临时空间规划；每 cube 单独落盘、立即检查和 trim、通过后压缩、记录哈希、设磁盘硬配额。

## 最终推荐

主路线：CP-SAT/LNS 找见证 + PB 几何主问题 + 带证书的连通性分离 + VeriPB/CakePB 上界证明。

最关键的三个设计选择：

1. **证明一个"存在更优矩形"的 UNSAT 判定式，而不是让证明器直接优化。**
2. **上界模型允许是安全松弛，所有额外割必须携带可检查理由。**
3. **同配方机器按类聚合，使用每格占用 PB 约束，绝不展开两两重叠和全局多商品流。**

这套架构即使最终没有用到精确传送带 SAT 子问题也成立。若几何、端口、供电和自由格拓扑割已经足以证明更优矩形不存在，那么得到的是一个更短、更容易审计、同时更强的上界证明。
