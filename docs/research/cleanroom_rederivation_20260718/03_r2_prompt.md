# R2 提示词（半开放轮，另开对话用）

> 用法（01 号实验设计）：**另开新对话**（不带 R1 上下文），先粘贴 00 号规格书全文，紧接着粘贴下面这段。两轮之间不喂我方任何答案。R2 测的是：只给"分解式"这一个方向锚点，它的切层/回传/迁移三判据是否独立收敛到 v2.2 四问的同构物。
>
> 污染自查：下文无禁词（LBBD/Benders/master/cut/ghost/front/上收/下放/lift/分层判据/九族/F1-F9 零出现）；"把下层规则改写进上层"是规格书语言（01 号设计原文措辞），不泄露判据内容。

---

基于这份规格书，我们已经拍板采用**分解式**求解架构（多组件分工协作，而非单一整体模型）。现在请你独立推导三个设计问题。每个问题都请给出**明确的判据**——不是例子清单，而是可以对任意新规则机械套用的判定标准：

1. **层怎么切**：把全部规则（不重叠 / 端口计数 / 接驳空置 / 连通 / 供电 / 空矩形目标）分配到各组件时，你用什么判据决定"这条规则放在哪一层"？请把判据表述为一个可以对任意新规则套用的判定过程，并演示它在上述六类规则上的运行结果。

2. **层间拒绝信息的形式**：当下层组件拒绝上层组件的提案时，拒绝理由回传给上层的形式该如何设计？什么样的回传形式是好的、什么样是坏的？判据是什么？

3. **规则迁移的时机**：什么情况下应该把原本放在下层的规则（或它的某种变形、某种弱化版本）改写进上层组件？什么情况下不应该？判据是什么？

请直接给出推导与判据，不需要重复架构总述。
