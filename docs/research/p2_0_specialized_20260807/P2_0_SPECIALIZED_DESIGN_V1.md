## 0. 总判（先读这段）

立项动因是这样一条命题：`production_targets` 钉死 ⇒ 每种商品的稳态速率是常数 ⇒ 流量谓词退化成「use 变量挂常数系数的线性容量账」，一般吞吐认证的难点（流量与路径皆变量）随之塌缩。

**本稿的结论是：命题的前半段成立，后半段不成立；但塌缩的方向是对的，只是塌缩到的位置和预想的不同。**

三条结论（**标签逐条拆开**，勘误二轮按 D-13 重标；原标题「三条实测结论」已撤——它用一个【实测】盖住了三层不同强度的断言）：

1. **聚合速率确实是常数，但每台机器的占空不是**。19 种商品的稳态总流量唯一确定【实测】（表 A，`rate_table_receipt.json`）；「17×17 方程组非奇异 ⇒ 解唯一」是读高斯消元代码与方程结构后的【推导】。但目标只钉死每个 operation 的**聚合**活动 `x_op`，台间怎么分是布局的自由度：219 台 recipe-backed 机器里 170 台被 `Σu = n` 钉死为满速【实测·日志】，其余 49 台构成一个 **42 维满维多胞形**【推导】。表 A/B 里的逐台占空与逐口车道分解是**均摊约定下**的取值，不是唯一解（勘误来源：`refute_round1/REJUDGE_REPORT.md` §1）。F_route = 9,135 件/分钟与 flowbound 线的 OB1 收据逐数字吻合【实测】，这条与占空分配无关。

2. **「常数系数挂 use 变量」这个建模形态不成立**，死因有两层：
   - **第一层（无条件）**【推导】：端口速率 = 满速速率 × `u[i]`，而 `u[i]` 是 42 维多胞形里的自由变量。不先把占空分配固定成约定，「某格上某商品的速率」连**在端口处**都没有定义。
   - **第二层（固定占空后才轮到）**【推导】：它需要的不是逐口纯流而是**网络级**纯流，而**速率算术本身推不出网络级纯流**。**buckwheat 与 sandleaf 在任何满足聚合等式的占空向量下都必然分支**（种子回流环的奇偶性：N 条速率 1 的产道要喂两支各需 `⌈N/2⌉` 台的下游，N=11、21 皆奇数 ⇒ 耗道 N+1 > N），各逼出一段速率 ≤ 1/2；二者是不同中间品，两段之和 ≤ 1 ⇒ **速率兼容对恒存在**。该定理的前件是**当前 mandatory counts + 每个正占空消费者必须经当前 route graph 获得正流量 + warehouse-bridge 继续被排除 + 当前端口容量与精确计数语义**（勘误二轮按外审 R-03 / 核签 ACCEPT 补全）。
   
   > **原文（已撤）**：「而网络级纯流恒不成立」「速率合法的混流窗口恒存在」。撤销依据 = 外审份4 D-05 / 核签 ACCEPT。**三个谓词必须分开**：`NS`（一条源流在网络中从不发生一对多分支）、`RC`（存在两个不同商品的正速率段且速率和 ≤ 容量）、`P1`（同一物理组件不被两个商品共同使用）。两条计数定理证明的是 `¬NS`；守恒再推出 `RC`。但 **`RC` 不构造几何共址、不构造汇流器或共同下游、不推出任何布局违反 `P1`**；`¬NS` 本身也不违反 `P1`（同商品分支后的两条带各自仍是单商品）。可保留的正确表述只有一句：**仅靠「所有不同商品段的速率和都大于容量」这一速率分离法，无法无条件推出 `P1`**。这与 §4 甲案「分流不违反 P1」是同一条一致性，本稿全篇按此贯彻。

   canonical `rate_lemma_scope` 的逐口纯流强制在**均摊约定下**成立【实测·速率算术】（本稿独立复现，反例 0），但该约定不在它声明的前件里——换一份同样合法的分配（阶梯），反例 40 对【实测·速率算术】。「阶梯是游戏合法稳态」则是【假设】。详见 `refute_round1/REJUDGE_REPORT.md` §3 定理 1/定理 2 与 §4，以及本稿 §2.5（勘误二轮已按核签改写前件 (ii) 的定性）。

3. **真正塌缩的位置是求解结构，不是约束形态**【推导】。速率兼容对的位置随占空分配而变（均摊下出现在被迫切细的细流段，阶梯下出现在端口残道），但**恒不为零**。所以特化的收益不在纯度，而在求解结构——**但这个收益带前件**：
   - 在 **P1 已把每个硬件状态分配给唯一商品**，或 **master 先给每商品固定容量预留 `y[h,k]`（`Σ_k y[h,k] ≤ cap`）** 之后，多商品流才**可条件分解**成「逐商品单商品流 + 格位打包」两层；单商品流是整数的、其不可行证书是**最小割**（组合对象），不需要 v2 §4.3 那套有理 Farkas 基建。
   - **无 P1 的上界侧仍有跨商品的共享容量耦合行 `Σ_k f[h,k] ≤ cap`，不能直接分解**。可以走「容量预留 master + 单商品子问题」的 Benders 结构，但 **master 本身仍是多商品耦合问题**。单商品 min-cut 证书也只证明「在给定商品归属 / 容量预留下不可行」，**不是 unrestricted 多商品模型的无条件证书**。
   > **原文（已撤）**：「这个收益是真的，而且比原命题更稳——它不依赖任何前件。」撤销依据 = 外审份4 D-09 / 核签 ACCEPT：该句与本稿 §3 `:232`/`:241` 自己写的「P3 的合法性依赖 P1，所以 P3 是见证侧工具」在同一份稿子里直接打架。「min-cut 省一个量级」的等级同步拆开：结构替代是【推导】，工程量级是【假设】（Q1 未闭合）。

**推荐**：走**丙案（双侧夹逼）**——上界/cut 侧用**与车道分配无关**的松弛，见证侧用受限族。理由与两个替代方案的对比见 §4。

### 1.1 什么塌缩了

设 `production_targets` 钉死（前提：canonical `production_targets`，valley_battery 3.0 条满速线 + qiaoyu_capsule 2.75 条）。则：

### 1.2 什么没塌缩

速率常数说的是**每种商品的总量**和**每个端口的量**。它**没有**说：某一格上某种商品的流量是常数。后者取决于流怎么分配——而流分配是变量。这正是一般吞吐问题的难点所在，钉死目标并没有消除它。

具体地，「use 变量挂常数系数」这个形态要成立，需要：

> **前件 L（网络级纯流）**：商品 k 的流在整条网络上只沿其**最小车道**走，任何一段的速率都等于某条最小车道的速率。

有了前件 L，「格 c 被 k 使用」就对应一个确定的速率 ρ_k，行才写得成 `Σ_k ρ_k·u[c,ℓ,k] ≤ cap`。**§2.4 证明前件 L 对本实例不可满足。**

### 1.3 与 canonical 的关系（先说清，避免误读）

canonical `semantics.rate_lemma_scope` 的断言是**逐口车道**层面的，本稿独立复现并确认成立（§2.1）。该条目自己声明 `predicate_status: "non_predicate"`、且 `usage_rule` 明确「rate arithmetic never enters a certificate」——它管的是**叙述层**怎么引用速率算术，不是模型约束。

**本稿不推翻 canonical 的任何条目。**本稿否定的是一个**外推**：从「逐口车道两两不可共道」推到「每格至多一种中间品」。这个外推没有写在 canonical 里，但它是「常数系数挂 use 变量」建模形态的隐含前提，所以必须被检验。§2.5 给出建议的措辞加固（可选，非必须）。

### 2.2 车道约定无关性（对 canonical 的一条加固）【推导】

canonical 的前件 (ii) 只规定车道**条数**最小，没有规定这些车道之间怎么分配速率。仓库里实际存在两种约定，给出不同的数字：

- **fill-first**（`docs/research/canonical_batch_20260807/rate_lemma_recompute.py:42-43`，勘误二轮行号订正：原引 `:42-44`，实际 fill-first 只占 `:42` 的 `lanes = ceil(rate)` 与 `:43` 的 `residual = rate - (lanes - 1)` 两行）：前 `L−1` 条满载、末条取残余 ⇒ 满带宽车道 **464** 条；
- **均分**（`.artifacts/p2_0_refresh_20260805/area_bound_work/ob5_slot_census.py:65`，MEMO §2.1 与其 401/453 口径的来源）：每条取 `r/L` ⇒ 满带宽 slot **401** 个。

两个数字建在同一个基数上（均分口径报的 568 = 574 − 6 个终品输出 slot，而那 6 条道速率是 11/60 与 1/5、在两种约定下都不满带宽，所以 464 与 401 可直接比）。**两个数字都对，只是约定不同。**

**引理不受影响**，理由是两行的算术：

> 设某口速率 r，最小车道数 `L = ceil(r/cap)`，车道速率 `a_1..a_L` 满足 `Σa_i = r`、`a_i ≤ cap`。则
> `min_i a_i = r − Σ_{j≠i} a_j ≥ r − (L−1)·cap` = fill-first 的残余值。
> 即 **fill-first 恰好取到任何最小车道分配下单条车道速率的下确界**，是引理的对抗最坏情形。

所以逐口纯流强制在**任何**最小车道分配下都成立，不只是在 fill-first 下。canonical 收据用 fill-first 是正确的选择（虽然条目本身没写出这个理由）。

### 2.3 「终端成品段可混流」需要一处精度修正【实测】

canonical `rate_lemma_scope` 写「the only lanes on which commodity mixing remains rate-legal are the final-product terminal segments (qiaoyu_capsule + valley_battery, 2-4 lanes into wired warehouse-line inputs)」。

实测：两条终品的**全流**车道之和 = 11/20 + 3/5 = **23/20 > 1**，**一格装不下**。可混流的是**未完全汇聚**的子段：产口侧 3 条 11/60 + 3 条 1/5，任取速率和 ≤ 1 的子集可以共道（最多 5 条：3×11/60 + 2×1/5 = 57/60）。

所以准确措辞是「终端成品段中**所载子速率之和 ≤ 带容量**的那些段」，不是整条终端段。这不影响 canonical 的任何下游结论（该条目本身是 non_predicate），只是引用时别读成「终品段随便混」。

### 2.4 网络级纯流**不成立**（本节是本稿最承重的一条）【实测】

前件 L 要求商品的流在中段不被切细。问题是：**切细是不是可以避免？**

**探针一（`split_free_probe.py`）**：逐商品判定「只合流、不分流」的车道路由是否存在。建模为每条产道**整条**指派给某条耗道（允许多条并入一条），车道速率自由但口内守恒、每条 ≤ cap；CP-SAT 整数精确。

**该探针把每台机器的占空写死成均摊（`split_free_probe.py:97`），这是未经辩护的约定**；放开台间分配后重判（`refute_round1/split_free_probe_v2.py`），六例里**四例翻案**：

| 商品 | 均摊约定下 | 放开占空后 |
|---|---|---|
| **buckwheat** | 鸽巢 11 产道 < 12 耗道 | **仍必然分流**，对任意分配成立 |
| **sandleaf** | 鸽巢 21 < 22 | **仍必然分流**，对任意分配成立 |
| steel_block | 鸽巢 17 < 18 | **翻案**：耗道降到 17，split-free 存在 |
| buckwheat_seed | CP-SAT INFEASIBLE（12 / 11） | **翻案**：产道降到 11，split-free 存在 |
| sandleaf_seed | CP-SAT INFEASIBLE（22 / 21） | **翻案**：产道降到 21，split-free 存在 |
| sandleaf_powder | CP-SAT INFEASIBLE（33 / 32） | **翻案**：产道降到 32，split-free 存在 |

必然分支的商品占路由流量因此从 3,375 / 9,135 = 37% 降到 **960 / 9,135 = 10.5%**。存在一个整网一致的**速率算术点**（阶梯式：能满速的满速、余数落最后一台），使 19 种商品里 **17 种同时 split-free**【实测·速率算术】；计数上界与该见证吻合，故 **17 是速率算术层的上确界**【推导】。

> **上表「翻案」四例的保守读法**（勘误二轮，外审 D-04 / 核签 ACCEPT，与命题 S2 的三层标签同源）：【推导】均摊前提下的四条「不可能」结论**不能外推到自由占空域**；静态速率算术存在 split-free 见证【实测·速率算术】。该见证的**游戏动力学、初态、几何与模型可表达性尚未验证**【假设】。所以四例的正确表述是「**原必然性证明已失效，且静态算术层有反例**」，**不是**「游戏合法反例已经存在」。升格所需的 M2/M3/M4/M5/M7 与 binding 审计见 §1.1 命题 S2 下的实验表。

**站住的两例有不依赖求解器的计数证明**（`REJUDGE_REPORT.md` §3 定理 1）：buckwheat 的 planter 侧 `x_op = n_op = 11` ⇒ 占空被唯一钉死为全 1 ⇒ 恰 11 条速率 1 的产道；耗侧 crusher 与 seed_collector 各需 `Σu = 11/2` ⇒ 各至少 `⌈11/2⌉ = 6` 台在跑、每台恰 1 条耗道 ⇒ 12 条。11 < 12。根因是**种子回流环的奇偶性**：采种机 1 进 2 出、种植机 1 进 1 出 ⇒ 采种支恰占产量一半，奇数 N 劈半后两支各需 `⌈N/2⌉` 台，合计 N+1 > N。sandleaf 是 21 vs 22，同构。这条与占空分配、与布局都无关。

**翻案的四例同样可手算**：例如 steel_block，若 6 台 molding_bottle 取「5 台满速 + 1 台半速」而非均摊的 6 台各 11/12，则满速台每台吃 2 件/tick = 2 条满道、半速台吃 1 件/tick = 1 条满道，共 11 条；加 parts_maker 的 6 条，耗侧恰 17 条速率 1 的道，与产侧 17 条完美匹配。**鸽巢是均摊约定制造出来的，不是实例固有的。**

**探针二（`maxmin_segment_probe.py`）**：既然分流不可避免，那被迫的细流段最厚能做到多厚？求 `m_k` = max over 路由 min over 段（端口级运输问题 + 车道数变量，对下界二分，CP-SAT 整数精确）。

| 商品 | m_k | | 商品 | m_k |
|---|---|---|---|---|
| buckwheat | 1/3 | | sandleaf_powder | 14/33 |
| buckwheat_seed | 1/3 | | sandleaf_seed | 4/11 |
| steel_block | 1/3 | | sandleaf | 7/22 |

其余 11 种中间品 m_k ∈ {5/6, 11/12, 1}。

**关键的逻辑**：`m_k` 是 max-min，所以**每一个**路由都至少有一段速率 ≤ `m_k`。于是对任意两种商品 j,k，只要 `m_j + m_k ≤ cap`，就不存在任何路由能从速率上排除它们共道。均摊约定下这样的**不同中间品对有 15 对**（另有 6 对同商品，属同商品拥塞不属混流）。

**上表同样是均摊约定下的值。**放开占空后（`REJUDGE_REPORT.md` §3）：翻案的四种商品不再有被迫细流段；站住的两种最厚的最细段都升到 **1/2**（分流点各从 13、23 个降到 1 个），而 1/2 是**任何**分配下的上界——被劈开的产道速率恰为 1，各段总和恰为 1，最细一段必 ≤ 1/2。

### 结论 A：无分支路由对两种作物不可能【推导】

在**当前 mandatory counts、当前直连运输语义与 warehouse-bridge exclusion** 下，buckwheat 与 sandleaf 对**任意满足聚合等式的占空向量**都必须发生**至少一次一对多分支**。

### 结论 B：速率分离不能无条件推出物理纯度【推导】

每种作物被分支的总流量为 1 件/tick，因此各自至少有一个正段速率不超过 1/2。所以**速率算术中恒存在一对不同商品段，其速率和不超过带容量**。

这只证明**容量算术无法排除二者共道**。它**不构造物理共址**，**不证明任何合法布局实际混流**，**也不证明 P1 族为空或 P1 约束本身错误**。P1 仍可作为**见证侧限制**；若要把它当 without-loss-of-generality 的全局限制，必须另证支配引理（§4 甲案）。

因此可保留的、唯一无条件的表述是：

> **仅靠「所有不同商品段的速率和都大于容量」这一速率分离法，无法无条件推出 P1。**

**两个端点的算术对比**（这段是数字对照，不是网络级断言）：往均摊靠，端口残道最厚（5/6）但中段细流最细（7/22）；往阶梯靠，中段细流最厚（1/2）但端口残道掉到 1/2。全网最细段在所有分配上的可达最大值恰为 1/2，而「靠速率分离排除共道」需要它严格 > 1/2。速率兼容对的数目随分配变（均摊 15 对、阶梯 10 对），但**恒不为零**。

因此**严格读法**（「车道条数处处最小」）下的前件 L 族仍然是空的，但空得比本节初稿说的少得多——只差 buckwheat 与 sandleaf 两种商品、各一个分支点、各两段 1/2，而不是六种商品。**宽松读法**（「只在端口处最小」）下中段稀释不受约束，结论不变。

> **原文（已撤，勘误二轮）**：「**结论（升格为无条件命题）**：…而网络级纯流恒不成立 / 速率合法的共道窗口恒存在 / **两个端点都破，没有第三条路**」。撤销依据 = 外审份4 D-05 / 核签 ACCEPT：传导链「被迫分支 → 各有一段 ≤ 1/2 → 两段和 ≤ 1 → **网络纯流恒假 / P1 不能用**」在最后一步越了级。本稿 `:488`（§9.3 第 3 条）自己已经写对了边界——「窗口存在只意味着速率排除不了共道，不意味着混流一定发生」——但 §0、本节与 §7.1 三处把它写成了网络级结论。删除的句式与替换：
> - 「网络级纯流恒不成立」 → 「网络级的**由速率自动推出纯度**恒不成立」
> - 「一格只准走一种中间货在任何分配下都不能当模型约束」 → 「速率兼容对恒存在；**实际共道与 P1 可行性仍是几何问题**」
> - 「速率合法的 shared-lane window always exists」 → 同上（该英文句同时出现在 `REJUDGE_REPORT.md` §4 方向 b 的 canonical 替换文本里，已随本批一并订正）
>
> 注意这与 §4 甲案的「分流不违反 P1」**是同一条一致性**：外审 R-07 正是靠它撤销甲案族空死刑，D-05 只是要求本稿把这条一致性贯彻到措辞上。

### 2.5 建议的 canonical 措辞加固（可选，非本批必做）

**本节的定位已由勘误反转**：`rate_lemma_scope` 需要的不再是「可选加固」，而是**必办的措辞修正**——该条目的残道速率集合是在均摊约定下算的（`docs/research/canonical_batch_20260807/rate_lemma_recompute.py:34` 的 `util = runs / machines` 与 `:37` 的 `per_machine_runs = runs / machines`），而这条约定不在它声明的前件 (i)(ii) 里。

**缺的前件是「占空约定」，不是「车道约定」**（勘误二轮按核签 D-06 改写）。canonical 前件 (ii) 的原文带一句消歧补充：

> (ii) minimal-lane-allocation convention - each commodity occupies the fewest belt lanes its rate admits; **a layout that deliberately spreads one commodity over more lanes to dilute per-lane rates leaves this precondition family and the lemma asserts nothing about it.**

这半句把 (ii) 定性为**反稀释条款**，不是「全网车道总数最小化」的目标。据此得到一个**完备二分，两个分支都杀掉引理**，所以结论不依赖选哪种读法：

- **分支一：均摊在族内。** 均摊的每个端口都只用 `⌈r_p⌉` 条道、没有为了稀释而刻意铺开，阶梯同样如此 ⇒ **两份都在族内**。但残道集合是 `{5/6, 19/22, 10/11, 11/12, 21/22, 1}` vs `{1/2, 1}`（0 对 vs 40 对反例）⇒ **(ii) 根本不决定残道集合，(i)+(ii) 推不出结论**。
- **分支二：均摊出族。** 若把「均摊对 5 种商品用了 12 条道去装 11 的量」也算作 spreading，则均摊落在族外——而 canonical 记的那次机器复算（`rate_lemma_recompute.py:37` 的 `per_machine_runs = runs / machines`）**正是在均摊上做的** ⇒ **该条目的支撑证据是在它自己的前件族外算出来的**。

核心是：**前件 (ii) 根本不约束占空分配，而占空分配才是决定结论成不成立的东西**。不需要先争「谁更满足 (ii)」，也不需要先定读法。

> **原文（已撤，勘误二轮）**：「前件 (ii) 的字面是『用最少车道』，而均摊对 5 种商品用了**多于**其速率所需的车道（全网 628 条 vs 阶梯 622 条 vs **下确界 616 条**）——**最满足前件 (ii) 的那份分配，恰是破掉结论的那份**。**前件与结论互斥**，不是补一条前件能了的。」

## 3. 约束族清单

先把建模底座回源钉准（**本稿逐行回源，不引用他稿的行号**，`src/models/routing_subproblem.py` 主仓 main）：

- `use_vars` 的键是 `RouteStateKey = (x, y, layer, flow_in, flow_out, commodity)`——**已经是 per-commodity**（`:770` 声明、`:1053-1058` 创建）。
- `phys_vars` 的键去掉 commodity、换 `component_type`（`:1030-1042`）；`use_var ≤ phys_var`（`:1066`）；`AddMaxEquality(phys_var, use_vars_on_it)`（`:1075-1076`）——**同一物理组件可被多商品共享**，这是当前语义。
- 容量约束 `_add_capacity_constraints`（`:1119-1122`）= `AddAtMostOne(phys_vars_on_cell_layer)`，即**每 (cell, layer) 至多一个物理状态**，纯空间互斥、无时序维度。
- 端口贴合 `_add_port_adherence`（`:1297`）：每个 active 端口 `sum(vars_for_port) == 1`（exact-one）。

这意味着：**拓扑层可以复用现有的 per-commodity `use` / `phys` 两层**，不必重建键结构。**但数值层必须新增变量**——`use`/`phys` 只表达「哪个格位被哪种商品选中」，不表达「过多少货」。

> **原文（已撤，勘误二轮）**：「**加吞吐谓词不需要新变量结构**，per-commodity use 变量与 physical/commodity 的两层已经在那里。以下四个行族都建在现有变量上。」撤销依据 = 外审份4 D-08 / 核签 ACCEPT：这句与 20 行后的 P2 段自己写的「这是诚实版本：**流是变量**…变量是**新引入的** `φ`」**在同一节里直接打架**。

### P7-S 的最小完整变量与行族（勘误二轮新增，外审 D-08 / 核签 ACCEPT，与 §6 的 T1–T6 对齐）

现有 `use` / `phys` 变量只表达拓扑选择。P7-S 仍需新增**数值层**：

- `d[i] ∈ [0,1]`：recipe-backed 机器占空（219 个，其中 170 个被钉死为 1）；
- `f[a,k] ≥ 0`：商品 `k` 在有向 route transition / terminal arc `a` 上的流量。**索引必须能重建每个 state 的入边与出边**，不能只按物理格聚合——否则守恒行写不出来。

必须至少有以下行族：

| 族 | 行 | 对应 §6 的 v2 约束 |
|---|---|---|
| **D1** | 对每台机器：`0 ≤ d[i] ≤ 1` | T4 机器耦合（域） |
| **D2** | 对每 operation：`Σ_i d[i] = x_op` | T4 留下的 7 条聚合等式 = T5 目标满足 |
| **T1** | 对每商品、每个非 terminal 路由节点：`Σ_in f = Σ_out f` | **T1 守恒（原样保留）** |
| **T2** | 对每机器端口：terminal arc 流量 = 配方满速系数 × `d[i]` | T3 端口容量 + T4 配方耦合 |
| **T3** | 对外部源与终品汇：固定总供给 / 需求与对应 terminal 流量 | T6 边界供给 |
| **C1** | 对每个稳定的物理容量组 `h`：`Σ_k through(f,h) ≤ cap · phys[h]` | **T2 组件容量** = 本稿 P2 上半 |
| **C2** | 对每 `(a,k)`：`f[a,k] ≤ cap · use[a,k]` | 本稿 P2 下半 |
| **P1** | **可选的见证侧纯度限制**，必须按**稳定 hardware key** 聚合（见 `REJUDGE_REPORT.md` §9 欠账 4 的粒度要求） | 无 v2 对应，特化新增 |

**P1 不属于无条件 P7-S；其余 D / T / C 行共同构成静态吞吐可行性。**

**为什么必须补这五族**：原 §3 只有 `Σ_k φ ≤ cap` 与 `φ ≤ cap·use` 两条，**允许凭空产生、消失或断开的数值流**——谓词 (5) 的图连通性**不能替代数值守恒**（连通只说「有路」，不说「流量对得上」）。所以原 §3 不是一个可判定 P7 的模型，只是一组容量片段。下面的 P1–P4 是这批行族在本实例上的**特化展开与工程量估计**，不是完整清单。

### P1 —— 每物理状态的商品纯度行（**受限族专用**，不可无条件加）

```
对每个 phys_key：AddAtMostOne(_phys_uses[phys_key])
```

形态上就是把 `:1075-1076` 的 `AddMaxEquality` 旁边再加一行 `AddAtMostOne`，作用于同一批 `_phys_uses[phys_key]` 列表。系数全 1，纯组合，**零有理算术**。

- 行数：每个物理状态一行 = `len(phys_vars)`；上界 = 活跃 free cell × layer × (flow_in, flow_out, component_type) 组合数。
- **soundness 警告**：由 §2.4，这一行族**不是**对全部布局有效的松弛，而是**限制**。它只能进见证侧（丙案的下界半边），**绝不可进上界/cut 侧**，否则会剪掉真可行解、破坏 lex 最优性。

### P2 —— 每物理状态的容量行（**无条件有效**）

```
对每个 phys_key：Σ_k φ[phys_key, k] ≤ cap        （φ 为有理流变量）
对每个 (phys_key, k)：φ[phys_key, k] ≤ cap · use_var[…, k]
```

这是诚实版本：**流是变量**，不是常数系数。系数是 1 与 cap，变量是新引入的 `φ`。

- 行数：容量行 = `len(phys_vars)`；耦合行 = `len(use_vars)`。
- **有理化（勘误二轮按 D-07 改写）**：`660` **仅是均摊速率表与本批实验点的公共分母**，也是 Part D / F / G 使用的**离散网格**【实测·均摊有限表】。**它不是自由占空多胞形的公共分母。** 连续静态层应使用 **exact LP / Fraction** 语义；若采用 CP-SAT 网格，**必须把「占空限制在 1/D 网格」写成显式近似，且不得由网格 `INFEASIBLE` 推出连续域 `INFEASIBLE`**。对一份**已经冻结的有理见证**，可按该见证实际分母重新计算 LCM。
  > **原文（已撤）**：「全部车道速率的公分母 = **660**【实测】；乘 660 后全部系数为整数，可直接进 CP-SAT 整数域」。撤销依据 = 外审份4 D-07 / 核签 ACCEPT，反例已复跑坐实（`external_round2/independent_handcheck.py`）：`crusher_buckwheat` 取 `13/14, 19/21, 11/12, 11/12, 11/12, 11/12` 时和恰为 `11/2`、每项都在 `(0,1]`，但前两项乘 660 得 `4290/7`、`4180/7`，**不是整数**。原文的病是搬运时丢了限定词——`rate_table_stdout.log:99` 的上下文是**均摊表**的有限速率集合，被写成了连续多胞形的整数化尺度。这与 R-05（Part F 格点被写成连续域）是**同型同源**的病。
- 这一族对**任何**布局有效，是丙案的上界半边基石。

### P3 —— 逐商品单商品流可行性（**特化的真正收益所在**）

在 P1 成立的受限族里，每个物理状态只属于一种商品 ⇒ 多商品流**分解**成 19 个独立的单商品流问题：

```
对每商品 k：在「分配给 k 的物理状态集合」上，
            从 k 的产口 terminal 到耗口 terminal 存在容量 cap 的可行流，流量 = F_k
```

- 数量：19 个子问题（扣终品则 17 个）。
- **为什么这是收益**：单商品流的容量与需求在乘公分母后全整数 ⇒ 由最大流最小割定理，LP 松弛的最优解整数，且**不可行证书就是一个最小割**——一个组合对象（一组格位 + 一条计数不等式），天然 exact-safe，不需要 v2 §4.3 的有理 Farkas 规范形、row-family manifest、`constraint_id` 重建那一整套。这是特化相对一般吞吐真正省下来的东西。
- 代价：P3 的合法性依赖 P1，而 P1 是受限族。所以 P3 是**见证侧**工具，不是上界侧工具。

### P4 —— 汇流点与箱口

- **汇流点（merger）**：canonical 的 merger 是 2-3 入 1 出的单格器件，其出边受同一条 P2 容量行约束，**不需要额外行**。owner 给的「汇流器 2s CD、双入满速竞争最坏减半」是 tick 层的仲裁语义，属 v2 的 A8/TP7-D 层，静态层用聚合容量行已经保守覆盖（聚合和 ≤ 1 件/tick 比「最坏减半」更松还是更紧，取决于仲裁模型——**列为开放问题 Q6**）。
- **协议箱口**：canonical `protocol_storage_box_wireless` 定谳箱有 3 个物理输入口、每口 30 件/分钟 ⇒ **箱的物理进料上限 90 件/分钟**；无线段是箱→仓库、每 10 秒清空 6 个缓存槽，不构成进料侧瓶颈。`slot_count_clause` 的 6 槽阻塞是**离散动力学**（槽占满即堵，与商品类型数无关），属 TP7-D 层，静态层不表达。
  - 静态层需要的箱口行：`Σ_k φ[箱输入口 p, k] ≤ port_cap`，即 P2 的端口特例。
  - **当前实例里箱口不承重**：两个终品的需求各 1 个 generic input slot（`generic_io_requirements.json`），流量 16.5 + 18 = 34.5 件/分钟，远低于 90。

### 行数量级小结（生产规模 266 实例、70×70×2 层）

| 行族 | 行数量级 | 系数 | 有效性 |
|---|---|---|---|
| P1 纯度 | `len(phys_vars)`（≤ 9,800 格-层位 × 组件形态数） | 全 1 | **仅受限族** |
| P2 容量 | `len(phys_vars)` + `len(use_vars)` | **连续有理变量**；固定见证时用**该见证专属 LCM**（勘误二轮：原「1 / cap（公分母 660）」已撤，D-07） | 无条件 |
| P3 单商品流 | 19 个子问题 | **只有在商品归属、占空及容量均冻结后**，才可按该实例分母整数化（勘误二轮：原「整数（乘 660）」已撤，D-07） | 仅受限族 |
| P4 箱口/端口 | 端口数量级（574 制造口 + 52 源口 + 2 终品汇口） | 1 | 无条件 |

`len(use_vars)` / `len(phys_vars)` 的真实规模由 `_record_state_space_stats`（`:1080` 定义、`:1099-1100` 计数）在运行期报出，本稿未跑生产规模 build，**故上表只给上界形式、不给实测数字**——列为开放问题 Q1。**注意上表只覆盖 P1–P4 四族，不覆盖本节开头补齐的 D1/D2/T1/T2/T3 五族**（勘误二轮，D-08）；完整规模要按 §10 的 Q1 实验规格（三模型 × 14 指标）测，两个长度数闭不了工程规模。

## 4. 前件缺口：三案对比与推荐（本稿核心）

问题的形式：认证要对**全部可行解**说话（lex 最优性要求「任一更优候选必不可行」），而速率引理带前件。不满足前件的解怎么办？

先把方向摆正——**两个方向的代价完全不对称**：

- 往**紧**里做（加限制）：只会漏掉真可行解 ⇒ 报出的最优值**偏小** ⇒ 见证仍然真实可行，但「这是全局最优」的断言**失效**。
- 往**松**里做（用松弛）：只会多算一些不可行解 ⇒ 报出的上界**偏大** ⇒ 上界仍然真实，但不够紧。

认证链要的是两边都有：一个真可行的见证 + 一个不小于它的上界。**只要两者相遇，最优性就闭合，前件问题自动消失。**

### 甲案：把前件写成模型约束（限制可行域）

加 P1 纯度行，强制解落在网络级纯流族内。

- **优点**：便宜到不像话——P1 是现有变量上的一行 `AddAtMostOne`，零有理算术；且它顺带把多商品流分解成 P3 的 19 个单商品流，不可行证书退化成最小割。
- **原判「该族对本实例是空的」已撤回**（勘误）。那一步是非蕴含：P1 说的是「每个物理状态只承载一种商品」= 禁止**混流**，而 §2.4 证的是「中段稀释不可避免」= 存在**细流段**。分流器下游的两条带各自仍只跑一种商品，每个物理状态仍只承载一种商品——**分流不违反 P1**。正确的蕴含方向是「网络级纯流 + 速率引理 ⇒ P1」，反过来不成立。已回源核实：`phys_key = (x, y, layer, flow_in, flow_out, component_type)`（`routing_subproblem.py:1031-1038`）不含 commodity 维度，同层两条带共格另由 `_add_capacity_constraints`（`:1119-1122`）挡住，跨层交叉 layer 不同故不触发 P1。
- **P1 族空不空是个几何问题**（19 种商品能不能在 70×70×2 层上路由到从不共用同一个物理组件），**本稿与勘误批都未测**。所以甲案不是死路，而是**欠一到三条未证支配义务、视它具体冻结了什么而定**（下，勘误二轮按 D-10 拆档；原文「欠两条」已撤）+ 族空性未知。
- **可修版本**（若族确实为空时才需要）：把 P1 放宽成「只在能承载最小车道速率的段上要求纯度」，即对每个物理状态附一个「是否细流」的判别。但那要引入流变量，就退回 P2，不再有「常数系数」的便宜。

**甲案需拆成三档，不再合并记账**（勘误二轮，外审 D-10 / 核签 ACCEPT）：

**甲-A0：仅加 P1，duty 与数值流仍自由。**
若以 A0 的族内最优代表全局最优，**只欠一条**：

> **OB-P1（物理纯度支配，未证）**：对每个完整 P7 可行布局，存在一个**不让不同商品共用同一 hardware key**、且 `max_lex(area, min_side)` 不更差的完整 P7 可行布局。
> 直觉支持：把两种商品从同一物理组件上拆开，需要额外的旁路格位，只增不减；而聚合格位账 `Σ_c Σ_k f ≤ cap·|cells|` 与混流与否无关（容量守恒），所以混用拿不到聚合上的好处。
> 直觉**不构成证明**：拆开改变的是几何可行性（哪条道能拐到哪里），不是聚合量；把一个混用布局「收拢」回纯度族需要一个保面积的重路由构造，本稿没有。

**甲-A1：A0 再固定一份 duty。**
除 OB-P1 外，还欠：

> **OB-D2（占空分配支配，未证）**：对任何合法占空分配下的可行布局，存在一个采用指定分配（如均摊或阶梯）、且 `lex(area, min_side)` 不更差的布局。
> 为什么它是独立的一条：常数系数形态要求端口速率是常数，而端口速率 = 满速速率 × `u[i]`，`u[i]` 是 42 维多胞形里的自由变量（§1.1 命题 S2）。**「选定一份占空分配」本身就是一条前件**，不是目标钉死的推论。

**甲-A2：A1 再冻结速率档、lane decomposition 或 merge pattern。**
除前两条外，还须**证明该有限编码覆盖目标受限族**，或给出相应的支配引理。（为什么 A1 不够：固定 duty 只固定**端口总速率**，不固定端口内怎么分道、同商品 lane 在哪合并、合并后下游段速率、分支重并拓扑——见 `REJUDGE_REPORT.md` §5.2 勘误二轮改写段。）

> **若 P1 / A1 / A2 仅作为丙案的「找见证启发式」，而见证最终由不带这些限制的完整 P7 verifier 复核，则三条支配引理一条都不需要。** 这与本稿 §4 丙案「下界侧的族选择是纯工程自由度，选错了不损 soundness」是同一条，只是原稿没把它贯彻到义务台账上。

> **原文（已撤，勘误二轮）**：「**义务 OB-D（最小车道支配引理，未证）**…直觉支持：**稀释**一种商品需要 splitter + 侧枝再 merger 收回…」+「**这两条是甲案的未闭合项**」。两处撤销依据 = 外审份4 D-10 / 核签 ACCEPT：
> ① **义务对象写偏了**——OB-D 的直觉段讲的是「稀释 / 分流」，而 **P1 禁的是不同商品共用物理组件**；分流**不违反** P1（这正是 R-07 撤销甲案族空死刑的依据）。所以该义务的对象应是「不同商品共用同一 hardware key」，已改名为 **OB-P1**。
> ② **「固定欠两条」不准确**——甲案 `:274-276` 的定义只是「加 P1 纯度行」，**没有固定 duty**，因此不自动欠 OB-D2；OB-D2 的真实出处是 `REJUDGE_REPORT.md` §5.2 尝试复活「固定阶梯 duty + 常数系数」时才引入的。正确记账是「**视甲案具体冻结了什么，欠一到三条；只作见证启发式则零条**」。
> **丙案三条都不需要。**

### 乙案：谓词限定在前件族内 + scope 声明

照 `semantics.port_commodity_scope` 的先例：认证命题声明在「最小车道分配」这个游戏片段上，模型可行域 ⊆ 裁定规则可行域，保守正确。

- **优点**：零新数学，有现成先例，措辞机制成熟。
- **原「问题一：会把命题声明在空集上」已撤回**（勘误，同甲案）——那条建立在「族已证为空」的错判上。
- **真正的问题**：发布口径会退成「该族内最优」。这与 owner 已定的「zmd 目标不设降级退路」（全局 `max_lex` certified 无退路）冲突，属于 owner-only 拍板项。
- **附带代价**（勘误一轮新增）：若受限族取到甲-A1 以上（即把「占空按某份指定分配」也写进 scope，见 OB-D2），这条前件在 certified 语境下 discharge 不了，声明面比原设想更宽。（勘误二轮限定：甲-A0 不冻结 duty，因此**不必然**带这条代价。）
- **定位**：乙案不是当前可用方案；它的价值是**兜底措辞模板**——若丙案的夹逼长期合不拢，乙案是诚实降级的形式。

### 丙案：双侧夹逼（**推荐**）

把 P7 拆成两个**分别 sound** 的半边，各自不需要前件：

```
上界半边（松弛，对全部布局有效）：完整 P7-S 行族（D1/D2/T1/T2/T3/C1/C2，§3）
                                  ——不含 P1，不含任何车道分配假设
下界半边（见证，充分条件）：任何能构造出真可行见证的受限族
                            ——可以用 P1+P3，也可以用别的启发式族
```

**闭合判据分两阶段**（勘误二轮，外审 D-11 / 核签 ACCEPT，且我方文档自证）：

> **阶段 A（面积）**：对**全部** P7 可行布局证明 `area ≤ U_A`；由任意受限搜索族找到候选后，**交给不含该受限族前件的完整 P7 verifier**，得到见证 `(A_w, S_w)`。只有当 `A_w = U_A` 时，**面积坐标**闭合。
>
> **阶段 S（最短边）**：在附加条件 `area = U_A` 下，对**全部** P7 可行布局证明 `min_side ≤ U_S`。只有当**同一个完整见证**满足 `S_w = U_S` 时，`max_lex(area, min_side)` 才闭合。
>
> 因此「上界 = 下界」必须指 **lex pair** `(U_A, U_S) = (A_w, S_w)`，**不能只指面积相等**。
>
> **前提（语义一致性，核签补，外审未看到）**：上下两边必须**同语义**——`OPT_P2.0 ≤ 1167` 与 `OPT_六谓词 ≤ 1188` 是**两个语义下**的上界，「上界对上界推不出最优值变化」（`docs/research/p2_0_area_bound_20260806/AREA_BOUND_THEOREM_REPORT.md:285-296` 已登记这条开放问题）。本稿 §9.3 第 4 条自己点到过这条，但原来没写进闭合判据。

> **原文（已撤，勘误二轮）**：「闭合判据：**上界 = 下界 ⇒ 全局 lex 最优性成立**，无需 OB-D 支配引理」。撤销依据 = 外审份4 D-11 / 核签 ACCEPT——**我方自己的面积上界报告 `AREA_BOUND_THEOREM_REPORT.md:296` 原文写着「`min_side 维度本文未触碰。`」**。`min_side` 上界从未立过，所以只有 `A ≤ 1167` 时，即使存在面积 1167 的见证，也只能认证**主坐标**、不能认证 lex 次坐标。**「丙案不需要支配引理」这个抽象原则仍然正确**，条件是上下两边覆盖完整 lex pair，且受限模型产出的候选由 unrestricted P7 verifier 复核。

- **为什么这是对的**：上界半边是松弛 ⇒ 它给的 `A ≤ U_A` 对全部布局成立；下界半边给的见证是真可行的（且经不含受限前件的 verifier 复核）⇒ `A* ≥ A_w`。若两阶段都取等，则该见证是全局 lex 最优，**受限族是否覆盖全部解完全不重要**——它只是找见证的手段。
- **上界半边的面积坐标已经有现役件**：flowbound 线的 `A ≤ 1167`（无条件）正是 C1 容量行的聚合特例（`docs/research/p2_0_area_bound_20260806/AREA_BOUND_THEOREM_REPORT.md` 定理 1，六轮对抗审查转正的承重档）。它的证明链只用了「每件过 ≥1 个 route state」+「每 state ≤ 30 件/分钟」+ 格位分账，**零车道分配假设**。§8 展开。
  - **但它只是 `U_A`**。`U_S`（`min_side` 上界）**从未开工**（同报告 `:296`）——阶段 S 目前**完全空白**，这是丙案闭合的头号缺口，与 Q4 并列。
  - **外审份4 D-12 在它的视角完全正确**（审查包里没有该定理报告，只能条件接受），但核签判 **DOWNGRADED-IN-REPO**：仓内是有完整承重档的结论、**不是「假设」，本稿不改它的等级标签**；该改的是**外发纪律**——下批外审必须把定理报告一起给（核签 §3.B2 / §3.C 的 C2）。
- **下界半边可以先用最便宜的族**：直接加 P1+P3 试构造——**勘误后这一步没有已知障碍**（分流不违反 P1，见甲案；族空性未测）。构造不出来再放宽到「允许分流但限制分流点数」等族。**下界侧的族选择是纯工程自由度，选错了不损 soundness，只是夹不拢。**
- **代价**：要维护两个模型；夹不拢时给不出结论（`UNKNOWN`，fail-closed，与现有纪律一致）。

**推荐理由（一句话，勘误二轮重写）**：丙案是唯一一个**零支配引理**的路线——上界半边对全部布局有效、下界半边选什么族都不损 soundness（前提是见证由不含该族前件的完整 P7 verifier 复核），因此不需要任何支配引理就能保住全局 lex 最优性；甲案便宜，但**视它冻结了什么欠一到三条**未证支配义务（OB-P1 / OB-D2 / 编码完备性）且族的空性尚未测过；乙案撞 owner 的无降级退路口径，且甲-A1 以上还要把一条 discharge 不了的占空前件写进 scope。
> 原文（已撤）：「丙案是唯一一个**零前件**的路线」「甲案…欠**两条**未证支配义务（OB-D、OB-D2）」。前者过强（丙案本身仍带**语义一致性**前提，见上闭合判据；且它要求上界侧是**完整** P7-S 模型，而 §3 原来不是）；后者按 D-10 改成一到三条。

**这条推荐不因两轮勘误而动摇，但代价栏变长了**：丙案的优点是「不需要支配引理」，两轮勘误只增加了甲乙两案的义务、没有给丙案增加**支配**义务。上界半边的五步链逐条与占空分配无关（[B] 只用聚合 `x_op`，[C] 只用聚合 `F_route`），§8 已逐条核过。**丙案新增的两条工程欠账**（勘误二轮）：①上界侧必须补齐 §3 的完整 P7-S 行族（守恒 / 终端 / 配方耦合 / duty 聚合），原 §3 的容量片段判不了 P7；②阶段 S（`min_side` 上界）从未开工。

**给 owner 的选择点**：丙案不需要 owner 拍板（它不改 scope、不降级命题）。真正需要 owner 拍板的只有一件事——**若夹逼长期合不拢，是否接受乙案式的降级发布**。建议现在不定，等丙案跑出第一轮夹逼间隙的数字再定。

### 一条重要的陷阱（写给 flowbound 线）

本稿表 D 给出一个诱人的收紧：若每格只有一种商品，则 `L ≥ Σ_k ceil(F_k / C) = 308`（扣终品 306），比现役的聚合 `L ≥ ceil(F_route/C) = 305` 更紧，单层口径可从 `A ≤ 1015` 收到 `A ≤ 1012`。

## 6. 与 fluid P7（v1/v2）的关系：T1–T6 在特化下变成什么

| v2 约束 | 一般形态 | 特化后 | 变化性质 |
|---|---|---|---|
| **T1 守恒** | 每商品每非终端节点 `Σin φ = Σout φ` | **不变**，仍是变量流的守恒 | 无变化。特化没有消掉流变量（§1.2） |

3. **未被特化触及**：v2 §2.3 的 TP7-D 离散周期层、§3 的公理组 A1–A13、v3.1 的启动三件套（bootstrap manifest + startup trace + 周期日历）**全部原样需要**。钉死目标不消解任何一条离散语义鸿沟。

## 7. 与 mixflow / U-01 / 箱口的关系

**说明**：本节只用主仓已落地的 canonical 裁定与 `.artifacts/` 里的设计摘要，**不依赖未合并分支的代码细节**；下面的结论对「聚合 use 变量」与「per-commodity 子图」两种 use 结构都成立（本稿 §3 已确认主仓当前就是 per-commodity，`:1053-1058`）。

### 7.1 共乘容量行正是速率引理场景

mixflow 线处理的是「一条带上混载多商品」的建模。canonical `mixed_commodity_flow` 允许带级混流，`terminal_clause` 把它三分：(1) 有线仓储口（core 14 个输入）无限吸收；(2) 协议箱 6 槽有界；(3) 机器输入口无选择性 ⇒ 混流终止在机器口**不安全**。

本稿的贡献是给这条裁定配上**速率侧的边界**：

- 在**主干**上（464 条满带宽车道 + 全部残道）**速率上装不下两种中间品**——这是逐口纯流强制（§2.1）。**但这条只在均摊约定下成立**（勘误一轮）：`maxmin_segment_probe.py` 复用 `split_free_probe.py` 的 `solve_duty()`，同染均摊硬编码。换一份合法分配（阶梯），半速机器的端口残道就掉到 1/2，**速率兼容对直接出现在端口上**。
- 在**细流段**上两种中间品速率兼容（均摊约定下 15 对；阶梯约定下细流段升到 1/2、10 对，但位置改在端口残道）。
  > 勘误二轮：上面两条原写「混流在主干上速率上不可能」「混流窗口直接开在端口上」「15 对窗口」。**「窗口」与「混流」这两个词把速率兼容（`RC`）说成了实际共道**，按外审 D-05 / 核签 ACCEPT 统一改称「速率兼容对」。速率算术只能说「装得下 / 装不下」，说不了「装没装」。

所以给 mixflow 线的**无条件**收窄只剩一句（勘误二轮按 D-05 重写）：

> **速率算术恒能找到一对不同中间品的正速率段，其速率之和 ≤ 带容量**（因为被劈开的产道速率恰为 1，最细一段必 ≤ 1/2，`REJUDGE_REPORT.md` §3 定理 2）。
> 这句话**既不构造物理共道，也不把这对段限定在细流段**——阶梯算术点的兼容残道出现在**端口侧**。**涉及哪些商品、出现在主干还是细流段，随占空分配而变。**

> **原文（已撤，勘误二轮）**：「**混流窗口的段速率永远 ≤ 1/2**…**窗口恒不为零这一点则是无条件的**」。撤销依据 = 外审份4 D-05 / 核签 ACCEPT：「混流窗口」这个词把速率兼容（`RC`）说成了实际共道，越了级。**恒成立的是「速率兼容对存在」，不是「混流窗口存在」**；实际共道要靠几何共址 + 汇流器语义 + 完整布局见证，本批一条都没给。原稿「混流只可能发生在分流细流段」是均摊约定下的结论，勘误一轮已撤销其无条件性，勘误二轮再撤销「窗口」这一措辞层。

de-mix 的危险性判断不变（机器口无选择性，错货进缓存槽即永久占位，kernel A9 + `terminal_clause` 类 (3)）——变的只是「需要防的场景在哪里」不再可以按均摊约定枚举。

### 7.2 U-01 准入口的速率前提如何闭合

canonical `item_admission_port_exclusion.rationale_restated` 已把准入口建模必要性裁为**零**，理由三条，其中 (a) 直接引用 `rate_lemma_scope`：「中间品在钉死满产下不能合法共道，所以中间道上没有东西可分拣」。

**本稿 §2.4 对这条理由构成一个精确的边界**：该理由在**均摊约定下的逐口车道**层面成立，在细流段层面不成立——细流段上确实可能出现两种中间品共道，也就确实可能需要分拣。**勘误进一步收窄**：换一份合法占空分配，逐口车道本身就可能只有 1/2，共道在端口处即合法，所以「逐口层面成立」也是约定相关的。

**但裁决结论不受影响**，因为它有另外两条独立支撑：(b) 唯一合法混流域（终端段）终止于无拒收的有线仓储口，不需要分拣器；(c) 分拣终端定理（kernel 推导 #21）——分拣结构只有在每条侧枝终端都吸收得下时才 sound，而有非拒收终端可用时分拣就不必要。(b)(c) 都不依赖速率算术。

**建议动作（勘误后调整）**：不改裁决，但在 P2.0 实现批里把 (a) 的措辞从「中间道上没有东西可分拣」精确到「**在均摊占空约定下**，中间品的最小车道之间没有东西可分拣」——占空条件必须写进去，因为最小车道本身在别的合法分配下就只有 1/2。并挂本稿 §2.4 与 `REJUDGE_REPORT.md` §3 作为边界注记。**这是文档级精度补丁，不是裁决翻案**（裁决靠独立的 (b)(c) 两条，不依赖速率算术）。——列为开放问题 Q7。

### 7.3 箱口

见 §3 的 P4。当前实例里箱口不承重（终品流量 34.5 件/分钟 vs 箱物理进料上限 90 件/分钟），`slot_count_clause` 的 6 槽阻塞属离散动力学、静态层不表达。**箱口成为瓶颈的唯一路径是 `production_targets` 上调**——若未来上调，箱口行（P4）会从冗余变成 gating，届时需重算。

### Q1 实验规格（勘误二轮新增，外审 D-08 / 核签 ACCEPT，可直接执行）

在**同一份 266-instance routing build** 上分别构建三个模型：

每个模型记录 **14 个指标**：

```
n_use, n_phys, n_duty, n_flow,
n_conservation, n_terminal, n_machine_coupling,
n_capacity, n_use_link, n_P1,
total_nonzeros, max_row_width, model_proto_bytes,
build_wall_seconds, peak_RSS_bytes
```

`n_use` / `n_phys` 由 `_record_state_space_stats`（`src/models/routing_subproblem.py:1080` 定义、`:1099-1100` 计数）在运行期报出；其余指标需在 P7-S 构建器里新加计数。

> **注意约束成本按 proto 项数估、不按行数估**（仓库既有教训，`memory/mutation-sentinel-geometry-and-proto-terms.md`）——所以上表要的是 `total_nonzeros` 与 `model_proto_bytes`，不只是行数。
