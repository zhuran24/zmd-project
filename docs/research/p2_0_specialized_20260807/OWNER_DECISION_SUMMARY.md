# P2.0 特化设计稿 —— 一页决策摘要（2026-08-07）

完整稿：`P2_0_SPECIALIZED_DESIGN_V1.md`（同目录）。本页只讲结论和要你定的事。

## 你提的那个想法，对了一半

你的判断是：目标钉死了，所以每种货的速度是固定的常数，流量检查就从「解一个流量分配问题」退化成「查一笔加法账」——每格上共用这格的几种货，速度加起来别超过带子的 30 件/分钟。

**前半段完全对，而且比预想的还整齐。**我把 19 种货的稳态速度全部精确算了出来（有理数、零误差），机器占空、每个端口的分道全都是常数：170 台满速、27 台跑 11/12、22 台跑 21/22；574 个端口槽里有 464 条道恰好把带子占满。总流量 9,135 件/分钟，和另一条线（flowbound）早先算的收据逐个数字对上。

**后半段不成立，我用两个探针把它证伪了。**

「速度是常数」说的是**每种货的总量**和**每个端口的量**。但「某一格上某种货的流量是多少」不是常数——它取决于这股流怎么在网络里分配，而这个分配是变量。要让它变成常数，必须保证货在半路上不被分流器切细。

我算了一下：**切细躲不掉**。有 6 种货（荞麦、荞麦种、沙叶、沙叶粉、沙叶种、钢块，占总流量的 37%）在**任何**分道方案下都必然出现分流。其中 3 种是纯数数就能看出来的矛盾——比如荞麦：11 台种植机各出满满一条道，下游 12 台机器每台吃 11/12 条道的量，11 条道盖不住 12 个口，必须切。另外 3 种由求解器证明无解，我也逐个手算复核过。

再退一步问：被迫切出来的细流最粗能有多粗？答案是 1/3、7/22、14/33、4/11 件/tick 这个量级。**细到足以让 15 对不同的货合法地挤进同一格。**所以「一格只准走一种中间货」这条规则不能当模型约束用——不是工程上难写，是算术上不成立。

**这不推翻 canonical 里刚落的速率引理条目。**那条说的是「每个端口的道两两不能共用」，我独立复算确认它成立（反例 0 条）。我否定的是把它往外推一步——推到「整张网络上每格只有一种货」。这一步没写在 canonical 里，但它正是「常数系数」这个建模形态的隐含前提，所以必须查。

## 真正的好消息

塌缩是真的，只是塌缩在别的地方：**多商品流问题可以拆成「每种货各自一个单商品流 + 格位打包」两层。**单商品流是整数问题，它证明「不可行」的证据就是一个**最小割**——一组格子加一条计数不等式，是个组合对象。这比原设计稿 v2 里那套有理数 Farkas 证书基建（规范形 + 行族清单 + constraint_id 重建）省一个量级的工程量。而且这个好处**不依赖任何前件**。

## 我推荐的路线：双侧夹逼

原任务书列了两条出路，我推荐第三条：

- **上界那半边**用**与分道方式无关**的松弛——就是 flowbound 线现成的 `A ≤ 1167`。我逐条核过它的证明链（格位分账、聚合守恒、容量计数、足迹、电杆），**五步全部与货怎么分道无关**，所以它对全部布局都成立，可以直接当 P7 的上界现役化。
- **下界那半边**用任何能造出真可行见证的受限族——族选窄了不影响正确性，只是夹不拢。
- **两边碰上就闭合**：上界是松弛所以对所有布局成立，下界见证是真可行的，两者相等就是全局最优。**前件问题自动消失，不需要补任何新引理。**

另外两条路的问题：把前件写进模型最便宜（就是现有变量上加一行），但那个族**是空的**（就是上面证的），加了直接无解，而且还欠一条没人证过的支配引理；写 scope 声明有现成先例，但会把命题声明在一个空集上，且发布口径要退成「某个族内最优」，撞你定的「不设降级退路」。

## 顺带两条小事

1. **canonical 措辞可选加固两句**（走 freeze-ritual，不改任何下游用法）：① 我证了 fill-first 那种算法恰好是最坏情形，所以引理与分道约定无关——这个理由条目里没写；② 「终端成品段可混流」要精确到「子速率和 ≤ 带容量的那些段」——两条终品全流合起来是 23/20 > 1，最后一段其实装不下。
2. **给 flowbound 线一条禁令**：我算出一条更紧的界（`L ≥ 308`，单层可从 1015 收到 1012），但它**依赖「每格一种货」这个限制**，**不能**进无条件上界链。把限制推出的界当无条件上界，等于把「我们搜的范围里没更好的」说成「不存在更好的」。
