## 1. 发生了什么（三句话）

W0 这条线在造**下界**：要拿一份合法的完整布局，第一道门叫 G1——先不管管线怎么接，
只把 266 个设施的机身、供电杆、朝向、端口前格和那个 6×7 空矩形摆出来。做法是把 70×70
的板切成 25 个 14×14 房间，每个房间**独立**枚举出一批局部摆法（catalog），再用一个小
求解器从 catalog 里给每个房间挑一个、拼成全局。

08-03 那两轮拼不起来，事后查出两笔账：**代码里的连通性判据比登记的松**（登记说「一个
房间的自由空间要连成一片」，实现却认「几片各自连着就行」），以及带孔房间的预算判据算错
口径。08-04 这一批就是去修这两笔，顺带把连通性从「先解完再过滤」搬进求解模型本身，
然后按旧协议全量重跑。

**结果是止损**：修完之后，catalog 能提供的机身面积从 3,113 掉到 **2,544**（实测），
而需求是 **3,325**（算术，冻结实例清单推出），缺 **781** 格。按任务书写死的门序，
供给不够 3,325 就停，不加预算硬闯。

## 2. 数字与对照

**主表**（同一把尺子量的；量具先在旧数据上校过刻度，旧并集复算得 3,113，与台账逐字一致）

| 口径 | 机身面积供给 | 对 3,325 的缺口 | 等级 |
|---|---|---|---|
| 旧 loose 直产（08-03 三份 catalog 并集） | 3,113 | 212 | 实测 |
| 旧 catalog 事后按 strict 重滤 | 2,749 | 576 | 实测（重滤，只删列） |
| **新 strict 直产（本批，760 签名）** | **2,544** | **781** | **实测** |
| 新 strict 计最小孔损（16 格 @ LEFT_J1）后 | 2,528 | 797 | 实测 |

三个数不是同一件事：重滤是拿旧列按新规矩筛，直产是换了模型重新找。直产更低**不等于**
实现变差——新模型是在更严的规矩下从头找，找到的少很正常。

**其他闸**：总台数的 **count supply ceiling** 241 ≥ 需求 219（实测，计孔损后 239）——
ceiling 高于需求 20，count 预门不触发。这个 20 **不是** class-feasible master 的余量：
ceiling 是逐族独立取最好摆法相乘，故意高估。

真正短的是面积，以及 6×4 那一族的**模板合并供给** 34 < 需求 38（实测；这条合并的是
6I3+6I4+6I5 三类的需求 32+3+3）。它与求解器不可行核里那条 `assume_class[6I3]` 是
**两个相关但不等同的 6×4 供给信号**（08-04 复核订正，初版写「同一件事」）：同一份
pre-gate 里 6I3 单类的 ceiling 是 63 ≥ 需求 32、并不短缺；核里只留 6I3，表达的是
另一组充分矛盾。

**求解器收据**：新 run root `.artifacts/w0_fixrerun_20260804/regen/gate_union/`，
receipt 闭合；master `INFEASIBLE`（0.27 s deterministic，实测），不可行核 = 九个非核心房间类别的
「恰选一个摆法」+「全图恰 219 台」+ 6×4 那一条，删除法证过极小（21 族 21 次求解）。
`O-FRONT-SIMULTANEITY` 这条义务保持未关闭，理由是「没有几何可核」——这是 fail-closed
的正确形态：没有解就没有可核对的对象，义务开着，PASS 结构上不可达。

## 3. 为什么这不是死刑判决

这次的读数是「**在本次预算下，这份 catalog 拼不满**」，**不是**「strict 这套规矩下
根本拼不满」。三条理由，都是实测的：

1. **没跑完的比跑完的多**。L0 那一跑里 CLEAN 房间 251 个目标只判了 58 个，**193 个超时
   没判**（实测）。而 CLEAN 恰恰是权重最大的一族（全板有 16 个这样的房间），也是被截断
   最狠的一族。
2. **同一套规矩下，别的搜索找到过更好的**。专门瞄准 CLEAN 的 strict 探测臂 480 秒就
   找到 **120** 格（找到值），而本批 catalog 里 CLEAN 最好只有 **103**（实测）。
   两者的连通性**判据同级**（08-04 复核订正，初版误写「探测臂略松」）：归档的探测臂
   代码同样把门洞桩、门前格、端口前格与孔洞格全部钉进同一片；用当前 evaluator 重读
   九份 strict 探测 witness，9/9 通过。差在搜索目标与预算——探测臂是单族定向搜索，
   catalog 那 5,400 秒要摊给十族上千个目标，CLEAN 只分到一小块，
   17 格的差指向预算分配，不是 strict 的天花板。
3. **没有坐实的「连通性独杀」案例**。本批做了配对对照：每个被 strict 证明不可行的目标，
   都用同预算、只把连通性换回旧读法再解一次。三跑合计 1,162 个证死目标里，
   **旧读法能解出来的 = 0**（实测），其中 **1,090 个旧读法也证死**——对这 1,090 个
   可以排除「连通性是唯一死因」。剩下 **72 个旧读法超时没判**（L1b 逐族 5–10 例），
   manifest 明写它「says nothing」，**既不能算进连通税、也不能算出连通税**。
   所以准确口径是：**当前没有坐实的连通性独杀案例，但「连通税严格为零」未证**。
   另外，「旧读法也证死」只排除唯一死因，**不构成**对死因是「面积/装载」的积极鉴定
   （08-04 复核订正，初版写「死因全是面积/装载驱动」，是把没做的鉴定当成了结论）。

**同时要说清楚的另一半**：把两条实测线逐族取较好的合起来，也只有 **2,841**（找到值合计，
**不是上界**），离 3,325 还差 484。所以「多跑一会儿就够了」
同样没有证据——加预算能不能补上这 484 格，今天不知道。

## 4. 摆在桌上的四条路

### ① 加深预算的定向重生成 —— **编排者默认建议**

**做什么**：不改任何规矩，只把预算花在被截断的地方——重跑那些超时没判的目标，
每目标预算从 2–5 秒提到 20 秒级。

**估时**（估计，按 manifest 里的实测目标数 × 选定的每目标预算算出来的，没跑过）：

- **①a 便宜档**：只加深 CLEAN（权重 ×16）。L0 那 193 个未判目标 × 20 s ≈ **1.1 小时**。
- **①b 全量档**：L0 的 1,260 个 + L1b 的 788 个未判目标 × 20 s ≈ **11.4 小时**求解，
  串行（一次只跑一个 solve），加配对对照与文书 ≈ **一到两天** wall。

**它能给什么**：这是**信息增益实验**，不是二分式判定，也不是预期能补满 781 格。
20 秒不是完备性阈值——加深后仍会有目标判不出来，读数仍是 `BUDGET_CENSORED`。
三种可能结果都要预先认下：①供给明显上抬 → 08-03 那句「catalog 薄」重新成立；
②供给基本不动、且未判量显著下降 → 结构性证据增强（但仍不是证明）；
③未判量仍然很大 → 什么也没判定，只是把审查删失的量级测出来。
（08-04 复核订正：初版把 ① / ② 写成了非此即彼的「判定性实验」，漏了 ③。）

**为什么排第一**：最便宜（①a 一小时级），直接攻击「审查删失」这个当前最大的不确定源，
而且不需要 owner 之外的任何新授权语义——不松规矩、不建新机器、不改登记档位。
**但**：任务书写死「止损 = 停，不加预算硬闯」，所以**加预算这件事本身要 owner 点头**。

松掉其中一条就是换一个限制档位重走，catalog 要全部重生成。

**现状**：九条的**价签**（各自扔掉了哪些解 + 撤退线）已打包发给外脑
（`.artifacts/w0_consult_packs_20260804/rstar_pricetag/`），**外发状态 = owner-reported

`R-POLE-CAP`（每房 3 根杆上限）是 08-04 才补登记的漏挂条目——现有的 3,392 / 67 格余量
等读数全部 conditional on 它。

**要 owner 定的点**：松绑是改登记档位，属于 owner 决策，不是我方能自决的。

### ③ 证明机：列生成 / Lagrangian 对偶上界

不去找解，去证「这个档位下无解」。数学已复核成立（LP 真松弛、映射方向对），
一档健全版约 700 行 / 2–4 天（估计）。

**卡在哪**：一个决定性盲区——pricing 子问题给出的界够不够紧。实测里 CP-SAT 的
`best_objective_bound` 在**无孔三族**上从未离开 packing 天花板（252–540 s 预算，实测），
而证书要求把总界压到 3,325 以下（相对 3,392 至少 68 格；相对手上最紧的组合基线 3,388
还差 64 格）。**便宜的判定实验设计已发外脑**
（`.artifacts/w0_consult_packs_20260804/pricing_exp/`），**外发状态 = owner-reported
「已发出、回复未到」**。
按 08-04 owner 拍板，这条是「重跑仍短时的下一梯级」。

**新增的一条正面信号**（本批回填）：孔洞约束是目前唯一被实测确认能让 CP-SAT 自己把
bound 压下来的结构（CLEAN 带孔 146→129、CORNER 带孔 118→85 证 OPTIMAL）。
它不改变盲区，但说明「bound 完全啃不动」这句话有作用域。

### ④ 22 号条带路线（备胎）

外脑给的另一套从头构造：交替极性条带 + 单一有向环 + live-pose 精确覆盖。它的骨架数字
**内部算术自洽**，但全程**没有 placement / routing / power witness、没跑 strict checker**，
所以一切容量数都是**带假设的条件上界**（08-04 复核订正：初版写「骨架真实、算术复核全对」
过强，且后续复核确实推翻了其中两项数字）。审计出**三处承重洞**：

- **5×5 台数零余量**：容量恰 49 = 需求 49，而且它还依赖 band14 拿满 11——band14 的
  slit 落在 `s mod 5 ∈ {0,1}` 的位置时容量只有 10，直接把总供给压到 48（08-04 二轮
  验伤新发现，逐位枚举：36 个位置得 11、22 个得 10）。
- **杆位条件上界远低于面积账**，两组要分开读：孔洞锚 `a ∈ {1,64}` 时几何上界 **≤36**、
  面积账给 **49**；其余 26 个 capacity-good `a` 上几何上界 **≤34**、面积账给 **47**。
- **首选核心宏的 14 个输入没有极性正确的走廊可接**。**补洞咨询包已发外脑**（`.artifacts/w0_consult_packs_20260804/band22_holes/`），
**外发状态 = owner-reported「已发出、回复未到」**。它的第一道门本身是分钟级 LP，试点成本不高。

## 5. 建议与它的边界

**建议**：先做 ①a（CLEAN-only 加深，一小时级），按结果再决定要不要 ①b。理由是它最便宜、
信息量最大（直接测审查删失的量级）、不消耗任何 owner-only 的授权语义；②③④ 三条的外脑
回复按 owner-reported 状态都还没到，等回复期间正好是 ① 的窗口。

**这条建议不覆盖的**：加预算这件事本身需要 owner 一句话（任务书的止损条款）；
②的松绑、③的开工、④的试点都各自要 owner 拍板，本页不代拍。

**无论选哪条都成立的一句话**：今天手上既没有「装得下」的构造，也没有「装不下」的证书。
G1 的 `INFEASIBLE` 至今只能读作「本 catalog 拼不满」，不能读作关于几何或关于限制档位的
结论。
