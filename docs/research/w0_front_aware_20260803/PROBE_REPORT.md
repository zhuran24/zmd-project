## 二、闭合算术（对机身需求 3,325 格）——2026-08-04 勘误版

- **实测找到值的合计（描述性，不承担任何不可行性推论）**：evaluator 读法不带孔
  16×138+7×126+110 = 3,200；孔放实测最优处（CORNER）= **3,175，缺 150**。
  strict 读法 16×120+805+109 = **2,834，缺 491**（未计孔洞代价）。三个数算术复核
  无误，但其中的实测值**不是上界**——它们只描述「预算内已找到的量级」。
- **唯一健全的一行（只用证到 OPTIMAL / 机器 bound 的上限）**：CLEAN 146、边界 134、
  CORNER 118 均证 OPTIMAL；CORNER 带孔 85 证 OPTIMAL、CLEAN 带孔 ≤144（算术上界）。
  三条孔洞落点分支全部 **>3,325**（最紧一支：孔放 CORNER，16×146+7×134+85 =
  **3,359 > 3,325**）——**健全口径下本档位并未被排除**。
- **勘误（2026-08-04 复核，23 号指控④坐实后逐支重查）**：本节初版的三条「矛盾」
  **全部撤回**。①「147.4 > 146」把边界**实测** 126 当上界用；换已证上限 134 后
  所需 CLEAN 均值 = (3,325−7×134−85)/16 = 143.9 ≤ 146，矛盾消失。②「孔放 CLEAN
  3,292 < 3,325」同病（三项实测值当上界用）。③「边界带孔 171−123−42−4=2 格装不下
  front 集」三重不成立：42 格孔洞对已扣 reserved 的 usable 重复扣减（该族孔洞最多
  压 4 个 reserved 格，修正后余 6 格）、front 本就允许落在 reserved 与孔洞格上
  （evaluator 的 occupied 判定不含二者）、且该族带孔健全上界 129 ≥ 123 本就不矛盾。
  原「证据显著压向松绑」的方向判断**降级**为：基于实测平台（各族找到值卡死不动）
  的倾向性证据，**无任何矛盾证书**。把它变成定理仍缺逐族健全上界，推翻它仍缺
  超过平台的构造——两者已递外脑（23 号已回：给列生成对偶界路线，复核见
  `CONSULT_VERDICT_20260804.md`）。
- **同一算术错误的代码落点（登记欠账，不热修）**：`g1_pattern_generator.py:431`
  的带孔 target 预算判据用同一错口径，把 CLEAN 带孔 target 卡在机身 ≤142——机身
  143/144 档带孔 pattern 按构造不可生成（真实候选损失）。修复=重生成级动作
  （catalog 可达集变化），挂下一批；探测臂 `area_probe.py` 无 target menu，本报告
  全部实测数不受影响。
