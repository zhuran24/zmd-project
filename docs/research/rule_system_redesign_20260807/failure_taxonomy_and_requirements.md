## 1. 第一性约束：owner 08-07 公理

### 1.1 原话与技术翻译

owner 08-07 下达（普查开跑后）：

> 我们做了守卫、孔堵住了、就放心了——不对！这个项目最关键的是不能把可行解排除掉：把所有可行的规则都放进来与堵孔同样重要，否则同样在削可行解，而我们此前几乎无视了这一侧。

技术翻译：本项目的终点是 `max_lex(area, min_side)` 的**全局最优性证明**。因此模型与游戏真语义之间的偏差，两个方向都是 unsound：

- **过严**（模型 ⊂ 游戏）：游戏里合法的能力没进模型 ⇒ 模型说「不存在更好的解」时，游戏里可能存在。**证书为假**。
- **过松**（模型 ⊃ 游戏）：游戏里非法的解进了模型 ⇒ 模型给出的见证在游戏里摆不出来。**见证为假**。

### 1.2 四象限

|  | 见证 / 正向构造 | INFEASIBLE / 上界 / 最优性证明 |
|---|---|---|
| **过严**（模型比游戏严） | 安全（过严解也是游戏合法解） | **假证书** ← 此前无人盯 |
| **过松**（模型比游戏松） | **假见证** | 安全 |

### 1.3 对本项目现有资产的具体含义

项目当前手上的承重结论，绝大多数是「证明」类而非「见证」类：

- `U=(1188,18)` conditional 上界（SMM4 detached receipt）
- P2.0 面积上界定理 `A ≤ 1167` 无条件 / `1015` 待 OB6、`P_min = 9`
- PB-03 `(1326,34)` residual-band UNSAT（VeriPB 机器可验）
- W0 G1 双 INFEASIBLE、round45 六臂 UNKNOWN、band22 三见证死刑

**这些全部暴露在过严风险下**。而项目的防线（见 §2.4）几乎全部朝向过松侧。这不是一个补充视角，是一个方向性的系统偏置，公理把它定为与堵孔同级的一等问题。

## 2. 失效模式分类学

### 2.1 两个轴，不是一个

四路普查用的是 formation / coverage / consumption / propagation 四层——这是**生命周期轴**（缺陷在规则的哪个阶段进来）。公理要求的 exclusion 是**方向轴**（缺陷把模型推向哪边）。两者正交。

本分类学的做法：**exclusion 作为第五层被完整建制**（有自己的模式编号 X-1…X-9、病例列表、防线覆盖行），同时给每条病例**额外标一个方向标签**，使得「过严侧有多少病、有多少防线」这个问题可以被机械回答。这既满足了「与纳伪孔同等地位」的要求，又不丢掉「过严可以发生在任何生命周期阶段」这个事实。

**五层定义**：

| 层 | 缺陷进来的时刻 | 一句话判据 |
|---|---|---|
| **L1 formation** | 写规则时 | 规则本身写错、欠前件、欠参数、留白由实现代答 |
| **L2 coverage** | 规则集边界 | 该有的规则整条不在册 / 枚举「所有 X」漏项 |
| **L3 consumption** | 推理者读规则时 | 规则在案，推理没把它算进来 / 消费的是压缩标签 / 证据等级混用 |
| **L4 propagation** | 规则或结论变更后 | 改了不传播：实现、缓存、下游文书、外发包、pin 链 |
| **L5 exclusion** | 任意时刻，方向为「拒真」 | 游戏合法的能力被关在模型门外；过严限制**永不报警** |

**方向标签**：`拒真`（过严）/ `纳伪`（过松）/ `双向` / `流程`（不直接偏置可行集，但毁证据质量）。

### 2.3 逐层失效模式

#### L1 — formation（规则形成期）

**F-1 前件缺失：结论写下时，它成立所需的条件没被要求写出**

- 机制：规则/引理形成时只写结论，适用条件要么隐含在散文里、要么根本没想到。canonical 全文只有 `axiom_kernel.scope_premises`（全局）和 `rate_lemma_scope.statement` 里内嵌的 `Preconditions: (i)…(ii)…` 两处写了前件，**前件不是一等字段**（S3 §2.2）⇒ 推理者不可能机械检查「前件是否成立」。
- 病例：C-14（欠最小车道分配，第五轮才抓到）、**C-15（欠台间占空均摊，六轮审查后仍漏、owner 亲手戳破）**、C-19（污染链 #1 缺物流件单槽 + 机器持续消耗两前件，却被 #8 升格成静态约束）、C-23（A8 供电被标「正交」实为使能前件）、C-43（front-state 引理漏 splitter/merger）、C-18（把 owner 的一个特定态描述读成全称安全命题）。
- 现存防线：§0b v2.3 第 3 条「**cut 必须带前件**——裸正极障碍集不得做几何 cut，前件缺失=cut 在前提变动后幽灵存活的病根」——**这条规则已经存在，但适用域只写到 cut 上**；`rate_lemma_scope.usage_rule`（全文唯一一条使用规则，要求引用者 discharge 两条前件）；三席验证制的反例席（D-7 抓到 C-14）。
- 漏洞：①「前件写在散文里」这种形态**本身**不足以保证完备——C-15 证明了：全文前件写得最显式的那一条，仍然漏；②前件的**可 discharge 性**无人核（C-25：certified 语境下最小车道前件结构上不可 discharge，模型搜的正是全部布局）；③六轮审查逐行审过同一段推理仍漏一条 ⇒ 靠「多审几轮」不收敛。

**F-2 参数不在场：分类标签把定量参数压掉了**

- 机制：条目给的是定性分类标签（class(2) 有界吸收体 / 仓库系口 / 有界混吃），而判定该标签是否成立、其判据是否可达所需的定量参数**不在同一条目、多数不在同一分区**。S3 §3 实测：判协议箱「堵不堵」需要六个量，散在 3 个顶层分区、5 个条目、4 种表达形态，其中「6 槽」「3 口」「10 s」只以**散文数字**存在（无字段、无 schema、grep 不成表），**单槽容量在文件里根本不存在**。
- 病例：**C-17（箱堵塞判据物理不可达）**、C-11（箱被归入仓库系口）、C-12（公理系最承重参数空白，靠模拟器逐设备抽取回填）、C-05（箱零实体口 / 中枢 14 进）。
- 现存防线：模拟器第一参照对账 SOP（owner 08-06 拍板）；`AXIOM_KERNEL_PROPOSAL` 的参数表（08-06 回填）。
- 漏洞：①参数表是**批次工件**，不是 canonical 条目的一部分，条目与参数之间零交叉引用（`protocol_storage_box_wireless.applies_to` 不指向 `globals.logistics`）；②C-12 已经是同一病的第三次发作，当时的修法只是补一份参数表，**没有把「条目必须带参数」做成形态要求**；③S4 实证：箱的入量参数与容量参数就写在参数表**同一行的相邻两栏**（`6 组×50` 与 `3 进 3 出 90/90 同时满速`），六轮审查全程只打磨标签措辞，没有任何一轮把它们乘起来。**参数放在一起还不够，必须有一道强制把它们乘起来的检查。**

**P-5 已发出的结论 / 外发包不回收**

- 病例：C-50（组第四轮设计包时才发现上一轮外发包里的 canonical 是严格空语义条款生效前的旧快照；08-05 band22 双回件同病，两包 canonical 均钉旧版）、C-26（memory 卡已立，被转述污染的原句仍留在文书里没订正）、C-27（过强表述已传播 4 处）。

**P-6 跨批隐性耦合无登记位**

- 病例：C-28（owner 给的特化论证用「中间品在汇流区到不了自己的 sink ⇒ 连通性排除它」免掉一族计数约束，结论成立，但支点是 routing 复验的 no-orphan——而 canonical 谓词 5 不含 no-orphan，那是明文登记在 `model_stricter_faces` 里的待放开面。将来有人做对齐游戏语义的批去松掉它，这个放开会静默失去正当性）。

- 漏洞：**canonical 里没有耦合登记位**——`model_stricter_faces` 是单向名词列表，不知道谁引用了它。

#### L5 — exclusion（合法能力被关在门外 / 过严拒真）★ 新增层

> **本层的地位**：按 owner 08-07 公理，与「纳伪孔」同等。本项目的终点是最优性证明 ⇒ 过严直接产出假证书（§1.2 四象限右上格）。

**X-1 生成 / 枚举期过剪：合法候选从未进池**

- 机制：候选池、pose 池、状态字典这类「一次生成、全局复用」的枚举，剪枝规则若比游戏严，被剪掉的东西**下游永远看不见**——没有任何求解阶段能把它找回来，也没有任何信号说它丢了。
- 病例：C-04（未启用口朝外/被堵合法这条 owner 已定谳的规则没进剪枝，少 2,064 + 1,032 个合法 pose；`68,469 → 81,797 → 82,829` 三次换钉才补齐）、C-47（剥落式过滤把拒绝转译成接受，`stripped_to_smaller` 168–238 而 `rejected_dead_body=0`，「丢弃率>70% 升级」绊线恒零）、C-01（池按错位剪枝缺角 2,064，后又发现「整侧出界即剪」对 core/box 过保守再补 1,032）。
- 现存防线：**基本无**。§0b v2.5 ⑤报警计量（拒绝率是一等指标）方向正确，但 C-47 证明它可被 fail-soft 降级清零；且它管的是「拒绝率高不高」，不是「被拒的里有多少是游戏合法的」。
- 漏洞：**没有任何机制要求剪枝规则给出「被剪掉的候选里有多少游戏合法」的估计或实测**。C-04 三次换钉全部由 owner 逐次定谳驱动。

**X-2 论证适用面被对称套用到未论证的一侧**

- 机制：一条只在输入侧成立的论证，被对称推广到输出侧（或反向），而对称性本身没被论证。
- 病例：**C-20（`routing_subproblem` 的终端豁免与置零对 `_sink_port_fronts` 与 `_source_port_fronts` 完全对称（:1233/1244-1246/1271/1282），所以全部 219 台制造机的**每一个输出口**的 front 格对外商品都是实心障碍；而 #8 的正当性（污染链 #1）只覆盖输入口——出口只往外推货，没有吞错货的机制。一块比在案残余更大的未登记过严面长期零文书背书）**、C-19（时间层论证「无限时间线上空窗必现」被升格成静态模型约束，而 A7 自己规定这类升格要先落 canonical scope 声明——同类论证没挂同一道门）。
- 现存防线：三席验证制的反例席（D-8 抓到 C-20）；`model_stricter_faces` 登记（C-20 已补登记为 confirmed over-strict）。
- 漏洞：反例席是批次临时席；对称套用没有形态上的拦截（论证不写「覆盖面 / 未覆盖面」）。

**X-3 分类标签的界不可达 ⇒ 能力被无谓关闭**

- 机制：一个「有界」「会堵」「不安全」的标签，其危险条件在物理参数下根本不可达，于是标签关掉的是纯粹的合法能力，零收益。
- 病例：**C-17**（箱被登记为 class(2) 有界吸收体 ⇒ 不能当汇流区终点；owner 十秒口算：判据物理不可达，连暂时堵门都不存在，即便发生也 ≤10 s 自愈、永不中毒。owner 裁决：箱=汇流区合法终点）。
- 现存防线：**无**（F-5 的同一空档，从 exclusion 方向看）。
- 漏洞：见 F-5。

**X-4 在案裁决失踪 ⇒ 自由度被遮蔽**

- 病例：C-22（OWN-M23「借十字过 front 格」在推导矩阵零行，被「front 格 = 外商品的实心障碍」措辞盖住；完备性席用公理系独立重推才发现失踪，并核实模型侧同样允许 L1 过境）、C-05 的中枢分支（`generic_input_slots` 从 0 改 14 = 万能收货，成品可直进中枢 ⇒ **最优解可能零协议箱，可行域此前被错误收紧**）。
- 现存防线：无常设检索；靠完备性席从公理重推。
- 漏洞：同 U-2——已定谳裁决无反向索引。

**X-5 整类合法器件 / 能力不在模型**

- 病例：C-06（物品准入口 / 管道准入口整类器件，owner 08-05 主动供出，此前从未提过；IP 上游注册表坐实完整参数 1×1、直通不可弯、`admissionRule={itemId, limit, perMinuteLimit}`）。
- 现存防线：上游对账 SOP + owner 游戏实测定谳——**方向正确但是被动的**（等 owner 想起来）。
- 漏洞：没有「游戏里有哪些器件 / 能力，模型覆盖了几个」的覆盖率账。

**X-6 投影 / 复验层比它镜像的权威层更严**

- 病例：C-36（F1/F6 master-domain 投影用 `master_scalar_coercions=False`（严格 `type is str` / `_is_strict_int`），而 live master 一律 `str()`/`int()` 强转；prod frozen `candidate_placements` 的 `boundary_storage_port.orientation` 是 int 0 ⇒ 投影 `SnapshotValidationError` ⇒ 整条 attach 在 prod 上 fail-closed 空转。fixture 手造 exact-str 值使严格与强转结果全同，单测全绿从没踩到）。
- 现存防线：**这是 exclusion 层唯一一条真正常设的防线**——「投影/复验层必须与被镜像的权威层逐字段等价、不能更严」，配对称翻转 + mutation-verified；同族补丁「验收输入若不是被验链自产字节，绿灯不算数」。
- 漏洞：卡片自承「下一同类候选 `occupied_cells` 严格/强转不对称已点名未动」；且它只覆盖「投影 vs 权威层」这一种过严形态，不覆盖「模型 vs 游戏」。

**X-7 fail-closed 静默塌向更严，零信号**

- 机制：总纪律是「一切缺口向保守方向塌」——soundness 上正确，但每一次塌陷都是一次未登记的 exclusion，且不发任何信号。
- 病例：C-24（字段缺失/未知 operation/profile 加载失败一律回退最严的机器口规则 ⇒ 真实生产口漏打标时红利静默消失）、C-47（剥落把拒绝转译成接受，报警恒零）。
- 现存防线：变异自证（证明 fail-closed 改 fail-open 会红）——它验证的是**塌陷方向正确**，不是**塌陷没发生**。
- 漏洞：**没有 fail-closed 计数器**。与 C-37（静默 skip 掩护两层欠账）完全同型：skip 比红危险，因为它同时藏「没跑」和「跑了会发现的问题」。

**X-8 过严面登记表是静态名词清单**

- 现状（S3 §5 实证）：`model_stricter_faces` 是一个字符串，登记 4 个面的名字，**无参数、无解锁条件、无对应测试、无反向索引**。对照同区的 `ruling_level_inputs`（登记两条裁决级输入，形态闭合、是全文自描述最好的一处）——同一个 kernel 里两种质量。
- 病例：C-20（登记了但没有「被排除能力有多大」的估计）、C-21（no-orphan / 有源必有汇两条**没地方登记**，因为矩阵按公理分行把整轴丢了）、C-28（登记了但没人知道谁在引用它）。
- 现存防线：登记表本身 + U-01 那条人工防雷纪律。
- 漏洞：登记 ≠ 管理。清单不带解锁前置、不带引用者、不带哨兵，等于一张便签。

**X-9 过严的对偶盲区：限制永不报警 / 触发器永不触发**

- 机制：owner 08-07 定性——**过严限制只产生缺失的答案，不产生错误的答案，因此没有报错通道**。它的对偶是触发器：设计了却从不激活，同样无声。
- 病例：C-17（限制侧）、C-34（触发器侧：cap 口径下 `binding_infeasible` 结构上到不了，framework cut 的触发分支从不有机发生，ab16 16/16 臂全 `BUDGET_CENSORED_UNKNOWN` 零有机激活）。
- 现存防线：**无**。两侧都只在被 owner 或长跑数据戳破后才发现。
- 漏洞：这是整个分类学里最纯粹的空档，也是 §3 需求 R-20 的直接来源。

##### exclusion 层的假阳性警告（必须与 X-1…X-9 同等醒目）

C-10 是本层唯一的**反向病例**：把正确的保守编码误判为保真缺口。08-06 主线据 canonical `mixed_commodity_flow`（07-03 入册，明文允许混流无终端例外）判「模型比 canonical 严 = 保真缺口 (b)」，当晚翻案为 (a)-修正——机器入口无选择权 + 缓存格类型锁 + 空窗照单全收 ⇒ 混流到机器口必吞错货，模型门口排他才是**正确保守编码**。基于错读发出的整份分析一天内作废。

所以 exclusion 席的输出规格必须是：**候选过严面 + 一个游戏合法但被模型拒的具体实例**。找不到实例 = 该面未被证明过严 = 不进候选。见 §3 R-16。

### 2.4 防线-方向不对称：这个偏置是可测的

把 39 类现存机制按「它拦的是哪个方向的错」归类：

**朝向纳伪 / 证据质量的防线（16 条）**
异源 refute 席家规、语义前提栏、证据等级标注、开工前提复查四项、收据只当索引、变异哨兵两层纪律 + 几何判据、自产字节哨兵、探针物理可实现性 + fail-closed 编码、单变量归因纪律、对抗审查也审我自己的抢先判断、三席验证制、可复现工件 + 收据纪律、skip 巡检判据、审计不靠文本搜索、freeze-ritual + pin 继承链、两条铁律边界（六谓词 + 吞吐 out-of-scope）。

**朝向拒真 / 过严的防线（2 条常设 + 2 条半成品）**

| 机制 | 强度 | 缺什么 |
|---|---|---|
| 「投影/复验层不得比被镜像的权威层更严」（C-36 后立） | **常设、有 mutation 自证** | 只覆盖框架层「投影 vs 权威层」，不覆盖「模型 vs 游戏」；下一同类候选已点名未动 |
| `model_stricter_faces` 登记表 | 常设但只是**静态名词清单** | 无参数、无解锁条件、无测试、无反向索引 |
| §0b v2.5 ⑤报警计量完整性 | 半成品 | 只管过滤器拒绝率；可被 fail-soft 清零（C-47 实证）；不问「被拒的是否游戏合法」 |
| 方向安全性分析（负结果 vs 正向见证） | 半成品 | 只在**规则改动时**当一次性分诊用（严格语义可行集 ⊂ 宽松 ⇒ 负结果更成立、正向见证受损），没有常设化成「每条结论标方向暴露」 |

**结论（三句，可核）**

1. 病例数上过严 16 : 过松 16，**一比一**；防线数上是 **2.5 : 16**。
2. 过严侧病例的**发现渠道全部是人**：owner 亲自（C-17、C-04、C-05b、C-06）、外审席（C-20、C-02）、批次临时验证席（C-22、C-21）、prod 实测炸出（C-36）。**零条来自常设自动装置。**
3. 过松侧至少有一部分能被自动装置发现（C-07 由见证摄入触发、C-02 由差分探针复现、C-42 由动态求值 allowlist）。

这个不对称就是 owner 说的「我们此前几乎无视了这一侧」的机器可测形式。**重设计的第一优先级不是发明新审查，是把这 2.5 条补成一个成套的层。**

## 4. 设计约束

### K-1 canonical 是裁决权威 + 字节钉死，形态重组必须按 freeze-ritual 且防抄录错误

- `rules/canonical_rules.json` = 40,371 字节，SHA256 `b675fb6a1cdae7920f90abf63e59aa76ea8df37ae8a8c5d5d15b10b94218c4ca`，被 `scripts/preflight_gate.py` 的 `FROZEN_ARTIFACTS` 与 `certified_artifact_contract.py` 的源码常量双钉。
- 任何形态改造 = 完整 freeze-ritual：更新 pinned hash → 重生成派生工件 → 重跑 gate → 产出 `RESEAL_MANIFEST`（文件:行号:旧→新、连锁层次、史料门名单）+ `DEPENDENCY_VERIFICATION`（派生工件字节不变的逐行验证）+ pin 真值 python 审计。08-07 canonical 批的连锁实测是 17 直接 pin + contract/checker/preflight/LOCK 四链含 antecedent 重算。
- **抄录错误风险是一等设计约束**：把 13 个条目整体重排会引入不可见的语义漂移。设计方案必须回答：①**分批 additive 优先于整体重排**（`preprocess_plan.json` 已有 additive-only fail-closed 先例）；②重排批必须带**逐条目 before/after 语义等价断言**的机器 diff，不能靠人眼校对；③reseal 铁律不变（pin sha 按 LF 字节算 `git show HEAD:<file> | sha256`，绝不用 Python `write_text`/`json.dump` 直接写 tracked 文件）。
- 已知的 pin 继承陷阱：PROJECT_LOCK 6+1 处（3 测试 pin + 3 个 D6 脚本常量 + antecedent 重算重钉），`d5578f8` 漏过一次潜伏到当晚全量门才炸。

### K-5 两类规则的权威不同，一套形态要覆盖两类必须显式标注

- **游戏语义规则**（front 语义、口岸三分法、空矩形、准入口）：权威 = owner 游戏实测 + 模拟器判例。**不可复跑**，只能对账。
- **求解器/框架层规则**（cut 触发、投影严格性、保守支代价）：权威 = 源码 + 冻结工件。**可复跑**。
- referee 卡的根因定谳正是「勤奋全落在可复跑层，复跑的踏实感掩护未查的前提」⇒ 条目必须带 `authority_kind`，且**证据等级标注必须区分这两类**（R-01 的 `authority_kind` 字段）。
- canonical 已有 `axiom_kernel.scope_premises` 写了权威序：owner 游戏内裁决 > 模拟器规则层 > canonical 文本 > 文档转述。这是现成的等级定义，直接复用。

### K-6 exclusion 侧的对称严谨性：放开必须与堵孔同样带证明

- exclusion 席的产出 = 候选过严面 + 游戏合法但被模型拒的**具体实例**。没有实例 = 不进候选。
- 放开动作仍走 owner 裁决 + freeze-ritual，exclusion 席无放开授权。
- 反例已在案：C-10（把正确的保守编码误判为保真缺口，整份分析一天内作废）。
- 推论：R-16 的席位任务书必须写明「你的任务是举实例，不是提意见」，与 refute 席「你的任务是推翻每步推导」对称。

### K-7 不得扩大认证边界
