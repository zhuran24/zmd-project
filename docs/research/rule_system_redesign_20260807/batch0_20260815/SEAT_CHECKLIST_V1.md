# 席位清单 v1

> 范围：规则系统重设计线的规则/引理、guard/限制、生成器/剪枝、规则修订、证明类结论、owner 裁决包、外发回件消化与工程/基建批。
>
> 权威边界：本清单把 `FINAL_DESIGN.md` §4.4 与 §4.9 写成可执行席位表。拒真席的默认排法来自设计推荐，仍属 `OWNER_DECISION_SUMMARY.md` 第 8 件，明确 **待 owner 裁**；本页不把它写成已批准的全项目排班制度。

## 1. 六类席位

| 席位 | 主要职责 | 必须产出的东西 | 不得代做 |
|---|---|---|---|
| Plan 席 | 判批型、圈定攻击面、选独立性与预算 | 七条件判定、触发步骤、席位分工、停止条件 | 不得用“工程批”标签替代可行集检查 |
| 立论席 | 提出规则、限制、证明、修订或工程变更 | 八步凭据中被触发的全部节、复算件、影响面名单 | 不得自己宣布 owner 裁决；不得把候选当结论 |
| refute 席 | 按五攻击面主动拆解立论 | 五种受控产出，见 §2 | 不得只写总体印象；不得用“未发现”代替覆盖声明 |
| 拒真席 | 专找“游戏合法但被模型/guard/证明挡掉”的实例 | 具体合法实例，或完整搜索面留痕与未覆盖轴 | 不得复述立论席的 soundness 论证充当拒真审查 |
| 收批席 | 汇总证据、执行失败后果、判发布等级 | PASS / PASS WITH CONDITIONALS / BLOCK，附逐步指针 | 不得修补缺失证据后直接代替原席签名 |
| owner | 回答真正只能由游戏事实、产品取舍或权威裁定决定的问题 | 事实题答案、删除/放开、优先级与待裁事项的明确裁定 | 不回答仓内可计算问题；不被迫审阅半成品材料堆 |

## 2. refute 五攻击面与固定产出形态

refute 不能只交“问题列表”。每个攻击面都要交一种可被收批席机械核对的产物。

### ⓪ 批型攻击

固定问题：这真是无科学断言的工程/基建批，还是会改变可行集、证据链、承重语义或工件字节？

固定产出：

```text
REFUTE-0-BATCH-TYPE
verdict: ACCEPT_CLASSIFICATION | RECLASSIFY
claimed_batch_type: ...
refute_batch_type: ...
changed_trigger_steps: [0, 1, ...]
evidence: [path:line or symbol]
blocking_effect: ...
```

若改判，必须同步指出八步矩阵中哪些步骤从“不适用”变为“必跑/条件触发”。

### ① 证据等级混淆攻击

固定问题：文书有没有把 owner 定谳、项目实测、模拟器读数、批次文书、记忆转述、设计分析或模型输出混成同一权威等级？

固定产出：一张“断言到证据等级”表。

| 断言 | 文书自称等级 | 实际出处形态 | refute 判定 | 最大可用等级 | 修复动作 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

发现等级上浮时，结论必须随证据等级降级；不能只改一个标签而保留原强度。

### ② 前件完整性攻击

固定问题：每一个在推导里被当成常数的量，究竟是谁钉死的？

固定产出：

| 被当常数的量 | 推导位置 | 钉死者 | 权威坐标 | 是否充分 | refute 结论 |
|---|---|---|---|---|---|
|  |  |  |  |  | PASS / BLOCK |

只要有一项答不出，攻击面 ② 的总判就是 BLOCK。不得用“通常如此”“本实例看起来固定”或一张均摊表替代钉死者。

### ③ 覆盖诚实攻击

固定问题：作者声称“考虑过全部影响”时，究竟审了哪些层，明确没审哪些层？

固定产出：六层闭合枚举与声明差分。

| 层 | 作者声明 | 实际状态：审了/明确没审/不适用+理由 | 证据 | 差分判定 |
|---|---|---|---|---|
| 几何 |  |  |  |  |
| 速率/计数 |  |  |  |  |
| 参数来源 |  |  |  |  |
| 语义锚点 |  |  |  |  |
| 实现一致 |  |  |  |  |
| 方向暴露 |  |  |  |  |

任何开放式“等”字、未枚举的“全面”、把代码审计写成游戏语义审计，都要落成具体差分。

### ④ 拒真攻击

固定问题：有没有一个游戏合法、目标域内、却被本规则/guard/模型/证明排除的实例？

优先固定产出：

```text
REFUTE-4-REJECTION-TRUTH
instance_id: ...
game_legality_basis: ...
target_scope_membership: ...
model_or_guard_rejection_point: path:symbol / rule id
reproduction: command or hand-check
verdict: CONFIRMED | PLAUSIBLE | NOT_REPRODUCED
```

给不出实例时，必须交搜索面留痕：

| 能力轴 | 探法 | 结果 | 未覆盖原因 | 下一步 |
|---|---|---|---|---|
| 实体自由度 |  |  |  |  |
| owner 裁决 |  |  |  |  |
| 模拟器判例 |  |  |  |  |
| 上游注册表 |  |  |  |  |
| 六谓词量词展开 |  |  |  |  |

只要还有未覆盖轴，总判最多是 `PARTIAL COVERAGE`，不能写“无拒真反例”。

## 3. 分席矩阵

符号：`独立` 表示不得与立论席同一推理链自审；`可兼` 表示允许同席，但须单列产出；`收批独立` 表示起草与 refute 可兼，最终接纳必须由未参与该争议段起草的人完成。

| 批型 | Plan | 立论 | refute | 拒真 | 收批 | owner |
|---|---|---|---|---|---|---|
| 规则/引理立论批 | 可兼立论 | 必设 | 可兼但五产出分栏 | 条件于方向暴露；证明类效应时独立 | **收批独立** | 仅真事实题/优先级 |
| guard/限制/准入策略批 | 可兼立论 | 必设 | **独立** | **独立，默认必设** | **独立** | 放开/删除最终签 |
| 生成器/枚举/剪枝批 | 可兼立论 | 必设 | **独立** | **独立** | **独立** | 仅游戏事实残余 |
| 规则修订批 | 可兼立论 | 必设 | **独立** | 改变可行集时独立必设 | **独立** | 待裁措辞/事实/优先级 |
| 证明类结论出厂 | 可兼立论 | 必设 | **独立** | **独立，必设** | **独立** | 不替代证明复核 |
| owner 裁决上桌 | 可兼组包 | 必设 | **独立，查可自算项** | 涉放开/删除时独立 | **独立** | 最终回答事实题 |
| 外发/回件消化批 | 可兼合稿 | 必设 | **独立核签** | 回件触及过严/过松时独立 | **独立** | 冲突裁定与优先级 |
| 工程/基建批，无科学断言 | 可兼实现 | 必设 | 条件触发 | 条件触发 | 可兼但不得自封科学结论 | 通常不需要 |

硬约束：

1. guard/限制类批与证明类结论出厂，立论、拒真、收批三者不得落在同一席。
2. refute 产出必须异质化，至少覆盖“前件攻击”和“拒真/覆盖攻击”，不能把同一套复算换三个标题。
3. 同一人兼任 Plan 与立论时，批型攻击 ⓪ 必须由另一席签。
4. 同一人兼任规则/引理的立论与 refute 时，只允许在非 guard、非证明出厂场景，且收批必须独立。
5. owner 只在仓内来源、参数账、可达性尺子、两分支解空间账已经做好后接题。

> 上述矩阵中的拒真席默认排法是 `FINAL_DESIGN.md` 的默认推荐，仍 **待 owner 裁**。owner 未裁前，本线执行时按该默认保守分席，但报告必须写“按默认推荐执行，不代表全项目排法已批准”。

## 4. 拒真席便宜通道

目标不是让便宜通道直接裁决 soundness，而是低成本产出一个具体合法实例或暴露未搜能力轴，再交独立验证。

### 4.1 默认路线

1. **最小题面**：只给目标域、被审 guard/结论、允许的游戏能力与一个明确输出格式，不喂立论席的结论性解释。
2. **本地模型候选生成**：默认用本地 Opus 级通道找一个合法被拒实例，不占稀缺 Codex 审计额度。
3. **模拟器判例补强**：能写最小判例的，先验证游戏/上游行为；模拟器只能证明其实现行为时，证据等级保持“模拟器级”。
4. **几何/算术复验**：候选实例交独立脚本、现有 verifier 或手算复核；候选模型不得兼任最终核签。
5. **找不到时交搜索面**：逐轴登记探过什么，不能把“模型没想到”写成“没有实例”。
6. **升级条件**：实例构造需要大规模几何求解、全域穷尽或 proof-producing search 时，升级专门求解席，并保留便宜通道失败记录。

### 4.2 输出纪律

- 每个实例必须同时给“游戏合法依据”和“被拒位置”；只给一半无效。
- 禁止把 canonical/立论稿中“这里应该安全”的句子作为游戏合法性的唯一依据。
- 拒真候选可以是 `PLAUSIBLE`，但只有独立复现后才能写 `CONFIRMED`。
- 便宜通道找到一个实例即可击穿全称；找不到实例不能证明全称成立。
- 本地 Opus 足够的判断本身是设计假设，仍 **待 owner 裁**；若实测显示需要几何求解，应按数据改排法而不是维护假设。
