# 消费侧三闸 v1

> 生效范围：规则系统重设计线批 0 之后新入库、外发、上桌或出厂的承重文书，以及作为前提被消费的 L2 条目。
>
> 权威边界：本页是 `FINAL_DESIGN.md` §3.8 与 §6「批 0」的执行化文本，只规定“什么不得被下游当作前提消费”。它不把任何候选规则、派生条目或 owner 待裁事项升级为已批准事实，也不建立 `rules/derived/`。

## 1. 先判什么叫“消费”

以下任一用法都算进入前提集：

- 出现在结论的推导链、算式、判据、必要条件、充分条件或排除理由中；
- 被用来支持 certified 语境下的放开、删除限制、无条件证明、证书解释或 owner 决策推荐；
- 通过标签、表格单元格、脚注、链接或“见某页”间接替代原始前提；
- 先被一份中间文书压缩，再由下游把中间文书当作已清偿前提。

仅用于说明“查过哪里、仍不知道什么”的引用不算进入前提集，但必须放进明确命名的“检索记录”或“背景引用”栏，且不能参与结论。

## 2. 闸 G1：界未核条款不得承重

### 触发

被引用条款满足任一条件：

1. `reachability.verdict = NOT_ASSESSED`；
2. `reachability.verdict = conditional`，且 `open_premise_refs` 非空。

在结构化字段尚未落地的过渡期，散文中与上述状态等价的“待核、条件于尚未清偿前件、仍缺参数、只在某未证分支下成立”也按本闸处理。执行席必须把等价判读及原文坐标写进凭据，不能只报关键词命中。

### 判定

- **BLOCK**：把该条款当作承重前提，或把它的标签当作前提的替身。
- **允许的背景引用**：逐字标注“界未核”，列出开放前件，并声明“本引用不参与本结论”。
- **解除条件**：原条款的 reachability 状态与开放前件已经在其权威载体中关闭；下游自己补一段散文不能代替上游关闭。

### 最小凭据

`条款/标签 | 原文坐标 | verdict | open_premise_refs | 本文用途（前提/背景） | 处置 | 复核席`

## 3. 闸 G2：视图、未审条目和候选面不得进前提集

### 触发

前提集出现任一对象：

1. `docs/generated/` 路径；
2. 状态为 `UNREVIEWED` 的 L2 条目；
3. `model_faces.candidates` 或等价的拒真候选条目；
4. 对本架构上线前的历史文书，出现 `LEGACY_GENERATED_EQUIVALENT`：收据、生成摘要、视图、索引或其自然语言字段并非被断言机制的机器真源，却被复制、压缩或当标签进入前提集。此兼容判读只用于识别 C-26 同型的历史消费污染，不把所有 receipt 引用一概判红。

### 判定

- **BLOCK**：上述对象直接或经标签、摘要、复制值进入前提集。
- `docs/generated/` 只允许出现在“检索记录”栏，用于指向随后回读的机器真源；最终前提必须改引真源路径与字段。
- `UNREVIEWED` 与 `candidates` 可以进入待审队列、反例搜索或研究问题清单，但不得被下游写成既定事实。
- 历史 `LEGACY_GENERATED_EQUIVALENT` 可以作为定位线索，但消费者必须回读逐字代码、冻结机器真源或相应权威载体；若只复述它的 `semantics`、summary、receipt explanation 等自然语言结论字段，仍为 BLOCK。
- 文件头写着“非权威”、正文附 usage rule、或 reviewer 声称“只作索引”，都不能抵消实际消费行为。

### 最小凭据

`被引对象 | 状态/路径类别 | 出现位置 | 是否进入推导 | 回读真源 | 处置 | 复核席`

## 4. 闸 G3：批次文书命中的参数不得直接支撑 certified 放开

### 触发

参数账的 MISSING 三级阶梯在 L1 仓内检索阶段命中“批次文书”，而不是 canonical 或其他已声明的冻结机器真源。

### 判定

- 该量的出处形态必须写为“批次文书（非冻结件）”，权威等级封顶为“批次文书”。
- **BLOCK**：用该量直接支撑 certified 语境下的放开、删除限制、无条件证明或 release/certification 强化。
- 可以用于研究假设、保守方向的临时分析或裁决包分支估算，但必须显式保留权威等级，并登记“该量应回流 canonical/冻结真源”的形态轨欠账。
- 后续仅凭另一份批次文书复述同一数字，不能升级权威等级。

### 最小凭据

`量 | 值 | 命中文书坐标 | 出处形态 | 权威等级 | 本文要支持的动作 | 形态轨欠账号 | 处置 | 复核席`

## 5. 三闸过堂表

每份承重文书入库、外发、上桌或证明类结论出厂前，必须留下一张非空表；“未触发”也要给出检索范围与一句理由。

| 闸 | 检索范围 | 命中数 | 命中坐标 | 结论 | 修复或背景化动作 | 复核席 |
|---|---|---:|---|---|---|---|
| G1 界未核条款 |  |  |  | PASS / BLOCK |  |  |
| G2 视图/未审/候选 |  |  |  | PASS / BLOCK |  |  |
| G3 批次文书参数 |  |  |  | PASS / BLOCK |  |  |

判定规则：

- 任一闸为 BLOCK，文书不得以承重身份入库、外发、上桌或出厂；历史文书可以保留为史料，但新消费者不得继承其违规前提。
- 修复必须改“消费关系”，不能只在来源文件头部再加一句免责声明。
- 三闸只证明这三类污染没有穿过消费口，不证明结论数学正确、模型与游戏等价，也不授予 owner authority。

## 6. 过渡期人工执行口径

批 0 只上线文书闸，不声称已有机器 checker。执行席按以下顺序实测：

1. 列出本文全部承重结论与其直接、间接前提；
2. 对 G1 回读 reachability 字段或等价散文状态；
3. 对 G2 检查路径、L2 状态与候选身份；
4. 对 G3 逐量回读参数账的出处形态与权威等级；
5. refute 席复核命中与零命中的理由；
6. 收批席只在三行都有证据时收批。

后续若实现机器化检查，机器规则必须保持本页的消费语义：扫描“前提集”而不是扫描全文关键词；检索记录中的合法路径不能被误杀，换一种标签包装的非法消费也不能漏过。
