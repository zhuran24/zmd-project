## 0. 这份文件是什么

它是**推理流程**的重设计规格：谁、在哪一步、检查什么、产出什么凭据、谁验收、不过怎么办。

姊妹轨（规则形态轨）改的是「规则长什么样」——canonical 条目的字段、schema、checker 规格。两轨的分界是：**形态轨让「有影响的因素」在文件里能被机械找到；流程轨让「找它」这个动作有人必须做、且做没做可查。** 任一轨单独落地都不够：形态不改，流程步只能手工重组参数（慢但可行）；流程不改，形态字段会重演 `usage_rule` 的命运——全文写得最好的一条使用规则，没有消费方，它保护的前件集仍被证不完备（`canonical_anatomy.md` §5、病例 C-15）。

本稿的七步都设计成**形态轨落地前也能跑**（降级为手工重组），落地后自动降为「引用条目字段 + 核对」。降级路径逐步写在各步的「与形态轨的接口」小节里。

**硬约束（来自 taxonomy §4 K-4）**：本项目只承认四个卡点，任何流程要求必须指名落在其中之一，否则视为未完成——

1. 设计文档 / 任务书模板（含 §0b 过堂表）
2. owner 裁决包标准
3. freeze-ritual checklist
4. 承重文书入库 / 外发前的席位清单

外加一条有界性要求：每条检查必须可枚举、可机械求值、有限步骤。「查所有前提」「多审几轮」已被 C-15 证伪（六轮逐行审过同一段推理仍漏一条）。本稿每一步都给出**有限清单**和**停机判据**。

## 2. 参数账步

> **职责**：把「引用标签」变成「重组参数」。这是 owner 08-07 第一枪在流程侧的止血。

### 2.1 触发

结论属于下列任一类，且推理链上出现分类标签或压缩结论：实体安全性、可行性、容量/堵塞、排他性、准入。判据一句话：**这个结论如果错了，错的方式是「某个量算错了」而不是「某个几何摆不下」，就必跑。**

### 2.2 谁在哪一步

- **立论席**在写下该结论的**同一份文书里**填账，不允许「另文详述」。
- **refute 席**把参数账列为第一攻击面：逐行复算，复算不一致即 BLOCK。
- **收批席**只核节名在不在、MISSING 行有没有被升级。

### 2.3 检查什么（六列，逐标签一行）

| 列 | 填什么 | 不合格的填法 |
|---|---|---|
| 标签 / 压缩结论 | 被引用的那个名词原文 + 出处（文件:条目路径） | 只写名词不写出处 |
| 判据 | 该标签成立/失效的条件原文（「6 槽全占时堵」） | 复述标签本身 |
| 判据用到的量 | 逐个列全，每个量一行子项 | 只列手边有的那几个 |
| 每个量的出处形态 | 字段路径 / 散文行号 / 派生工件字节 / **MISSING** | 写「见 canonical」 |
| 一次算完的算式 | 带单位的真实算术，结果落地 | 定性描述（「容量很大」） |
| 结论 | 可达 / 不可达 / 待核（缺 MISSING 量） | 空着或写「见上文」 |

**MISSING 规则**：任何一个量在权威源里不存在，必须显式写 MISSING，并**当场升级为裁决包步的一道事实题**（不得就近借用同名参数）。C-17 的单槽容量在 canonical 里根本不存在、最接近的是 manufacturing 的 ×50，正是「就近借用」最容易发生的位置（`canonical_anatomy.md` §3）。

### 2.4 验收判据（机械可查）

1. 文书里每个当承重前提用的标签，在账表里有且只有一行。
2. 每行「算式」栏含至少一个真实数字与单位。
3. 「结论」栏三选一，无空行。
4. 存在 MISSING 行时，裁决包步的事实题清单里有对应条目。
5. refute 席的复核行（复算一致 / 不一致 + 差异）附在表尾。

### 2.5 失败与豁免

- **不过**：文书不得入库、不得外发、不得进 owner 眼睛。
- **豁免（唯一一条）**：形态轨 R-03/R-05 落地后，该标签所在条目已带 `reachability` 与实体参数表，且参数指纹未变 ⇒ 账表填「引用 + 指纹」一行即可。指纹变了必须重算。

## 3. 可达性尺子步

> **职责**：限制与触发器的对偶盲区补线。过严限制只产生缺失的答案、不产生错误的答案，因此永不自曝——必须主动问。

### 3.1 触发

批内新增或保留任何限制（含 fail-closed 回退、准入分叉、剪枝规则、白名单），或新增任何触发器/机制（cut 族、诊断臂、绊线）。

### 3.2 谁在哪一步

- **Plan 席**在开工过堂表上加一行「限制/触发器可达性」，此时只需列清单与初判。
- **立论席**在批内实现或论证时逐条填满尺子表。
- **拒真席**（见 §7）复核判定，重点攻「判成立」的行——判成立最省事，也最容易掩盖过严。
- **收批席**核表的完整性：批内引入或保留的限制清单与尺子表逐条对上。

### 3.3 尺子表（五列，逐限制一行）

| 限制 | 危险条件 | 物理入量下可达？ | **保证方**（谁保证它不可达） | 判定 |
|---|---|---|---|---|

**判定五选一**（这是边界判别法的出厂形态，出处：`.artifacts/gpt_pro_review_batch_20260807/3_u01_warehouse_admission/DESIGN_at_c6a9f8b.md` §11.13.2）：

1. **限制成立**——危险可达。正常保留，无后续动作。
2. **限制多余**——危险不可达，**保证方 = 物理 / 冻结数据**。⇒ 该限制在描述一个不存在的东西，进删除候选（走 §3.5 三签）。
3. **守卫必留**——危险不可达，**保证方 = 这条限制自己**。⇒「不可达」正是它的职责，删了保证就没了。不得因本审计删除。
4. **非 soundness 保留**——危险本身出域（如吞吐/带宽层，`PROJECT_LOCK.md` §1A B 块 out-of-scope）。⇒ 保留可以，但必须写明真实理由（审查经济 / 实测零成本）与**摘除条件**：一旦显出成本，它是第一个该摘的，且摘掉不需要重做 soundness 论证。
5. **待核**——参数账里有 MISSING 量。⇒ 进裁决包步。

**触发器侧同表**：第 6 列「有机激活证据」——该触发器在真实生产口径下被激活过吗？给实测（长跑计数 / 日志）或「结构上到不了」的论证。零激活且无论证 = 与「限制永不报警」同型的盲区（C-34：cap 口径下 `binding_infeasible` 结构上不产生，ab16 16/16 臂零有机激活）。

**保守支代价列（承接 R-30）**：判定为「限制成立」且该限制是为稳而选的保守支时，必须补一列量化代价（迭代速率 × 空间规模 = 预计墙钟）。结构性走不完的保守支不是真选项（owner 08-06；C-35 的 7,187 轮踏车即此）。

### 3.4 豁免（有界，三条）

- **引用豁免**：条目已带 `reachability` 字段且参数指纹未变 ⇒ 填引用行。
- **守卫豁免**：判定为「守卫必留」的行免可达性核算，但必须填保证方 = 本限制，并进拒真面登记做规模估计（守卫也可能拦得比需要的宽）。
- **纯性能豁免**：该限制不改可行集，且有 exact-safe 证书指针 ⇒ 填「不改可行集 + 证书指针」。

三条之外没有豁免。「这条太显然了」不是豁免——箱案的判据也很显然。

### 3.5 删除限制的三签（防止拿本审计删掉真守卫）

判定为「限制多余」**不等于**删除授权。删除需要三个独立签名，缺一不可：

1. **可达性签**：保证方栏为物理 / 冻结数据（不是本限制自己），并附参数账指针。
2. **拒真签**：双向保真验收步给出这条限制关掉的**具体游戏合法实例**（K-6：没有实例 = 该面未被证明过严 = 不进候选）。
3. **owner 签 + freeze-ritual**：裁决包上桌，走完整 reseal 连锁。

删除落地时**必须同时补一个反向哨兵**：证明删掉这条限制后，它原本兜住的非法形态仍被别处拦住。否则删除本身就是一次纳伪（这正是 C-52「两道墙分工不明」要求算清的东西）。

### 3.6 样板回放

本尺子的首次自量已在 U-01 席完成（同上出处 §11.13.1），五行判出两条订正：箱口限制判「多余、二期删」；无环化从 soundness 义务降为审查经济保留；drain 出口「邻格必须在域外」判「守卫必留」——它挡下的正是那个不忠实探针（C-39）。**一张五行表同时产出了一条删除候选、一条降级和一条必留**，这是本步性价比的实证。

### 3.7 与形态轨的接口

尺子表的「判定 + 保证方」两列，正是形态轨 R-03 `reachability` 字段的内容。流程侧先填、形态侧后收——本步的历史表就是形态字段的首批数据。

## 4. 前件卫生步

> **职责**：让「漏前件」从「没想到」变成「表里有一行没回答」。C-15 证明了六轮逐行审查不收敛，所以本步的核心不是更努力，是**有限清单**。

### 4.1 触发

任何新立引理 / 定理 / 承重推理结论；任何被当前提复用的旧结论（复用即重新过表）。

### 4.2 前件猎取表（六问，逐承重结论跑一遍）

这六问是有限的、可机械问的，跑完即停机。

| 问 | 问法 | 漏了会怎样 | 命中样本 |
|---|---|---|---|
| **自由度问** | 结论里出现的每个量，是被前提钉死的，还是仍然自由？自由的话维数多少？**任何在推导中被当成常数的量，必须证明它被前提钉死，否则它是一条隐藏前件** | 结论只在某个未声明的取值下成立 | **C-15**：端口速率 r = 满速 × u[i]，u[i] 是 42 维自由多胞形 ⇒ 「均摊」是未声明前件 |
| **约定问** | 推导里每一次「取 X」「按 X 约定」「不失一般性设 X」，逐个列出并问：这是被迫的，还是选的？选的就是前件 | 约定被读成定理 | C-14（最小车道分配）、C-15（均摊占空） |
| **量词问** | 每个「所有 / 任意 / 存在 / 唯一」的辖域是什么？举的例子会不会被读成界？ | 例句被当全称界消费 | C-18、C-51（「6 种商品」例句当界）、C-27（「无作用域条件」过强） |
| **语境问** | 这些前件在 certified 语境下 discharge 得了吗？在 P2.0 叙述层呢？exploratory 呢？ | 用一条在本语境不可 discharge 的引理去支撑本语境的放开 | C-25（前件 (ii) 在 certified 下结构上不可 discharge） |
| **权威问** | 每条前件的权威等级是什么（owner 游戏实测 > 模拟器规则层 > canonical 文本 > 文档转述）？出处形态是逐字代码 / 冻结件字节 / 转述 / 推导？ | 转述当证据、机械推断替代实测 | C-26（收据转述）、C-01（几何推断没过实测） |
| **使能问** | 有没有被标成「正交 / 仅为完整性 / 与本条无关」的条款，其实是本结论的使能条件？ | 隐藏使能前件 | C-23（A8 供电被标正交，实为使能前件） |

**留白条款**：六问中任何一问的答案是「三处权威源都答不了」，必须登记为**留白**，并进裁决包步——不得由实现或推导代答（C-07：空矩形语义留白由崩溃修复顺手选了宽松边，在链上活了很久）。

### 4.3 前件表（凭据格式）

逐条前件一行：`id | 陈述 | 类型（物理/冻结数据/owner 裁决/约定/模型自加） | 权威等级 | 谁能违反它（布局可违反 / 冻结数据保证 / 物理保证） | discharge 语境（certified / 叙述 / exploratory）| 出处`。

「谁能违反它」这一列是本表最省事的一列，也是最值钱的：C-15 的均摊前件属于「布局可违反」——写下这三个字，方向 a（补一条布局可违反的前件）与方向 b（改成分配无关版）的取舍立刻显形。

### 4.4 覆盖层声明（凭据格式，防审查落错层）

每份审查文书首栏必填三行：**本次审查覆盖到哪一层 / 哪一层明确没审 / 没审的那层由谁负责**。

C-16 是这一栏的存在理由：P2.0 设计稿 §2.2 专门论证了「引理与车道分配约定无关」，把「口内怎么劈」审得很干净，但整段建立在给定端口速率 r 之上，「r 哪来的」没审——下层审干净被读成上层已审。有这三行，refute 席一眼能看出攻击面在哪。

### 4.5 refute 席的强化（打前件，不只打结论）

现行 refute 席家规固定第一查项是「证据等级混用」，五次复发拦下四次，机制有效。本步把它从**一条**扩到**四条固定攻击面**，并规定每条的**产出形式**——只有产出被规定，攻击才可验收：

| 攻击面 | 产出形式（必须逐条落纸） |
|---|---|
| ① 证据等级混用（现行，不动） | 逐个承重数字标：证 OPTIMAL / 实测找到值 / 算术 / 假设 / 删失（UNKNOWN、censored、incumbent） |
| ② **前件完备性**（新增） | 对每条头条断言跑一遍前件猎取表六问，产出「复核行」：该前件是否可 discharge、有没有反例取值/反例分配 |
| ③ **覆盖层**（新增） | 判定本文书的审查覆盖层声明是否诚实：有没有把下层审干净读成上层已审 |
| ④ **拒真面**（新增，见 §7） | 对每条限制/剪枝，尝试举一个游戏合法但被它拒掉的具体实例 |

②的可执行形式：**refute 席必须对每条被当常数的量给出「它被谁钉死」的答案，答不出即 BLOCK。** C-15 在这条下会当场倒——把 r 当常数，钉死它的前提不存在。

### 4.6 与形态轨的接口

前件表的字段即形态轨 R-01 `premises[]` 的字段（`{id, statement, evidence, authority_kind}`）+ R-02 的 discharge 语境标注。形态落地后，前件表对 canonical 已有条目退化为「引用 + 核对」，只对新结论手填。

## 5. 裁决包步

> **职责**：owner-only 闸 = 账算齐了再上桌，不是拿不准就上交。

### 5.1 触发

批内出现真正只有 owner 能定的残余。判据：**这个问题的答案在游戏里，不在仓库里。** 答案在仓库里（源码、冻结件、参数、既有裁决）却上交 = 违规，先跑参数账步与档案检索。

### 5.2 必备件清单（八件，缺一不成包）

1. **一句话裁决问题**，且形式必须是游戏事实题：「游戏里 X 会不会 Y」。若写不成事实题，说明推导没做完。
2. **参数账表**（参数账步产出），含 MISSING 行。
3. **可达性尺子行**（可达性尺子步产出），含判定与保证方。
4. **两分支解空间账**：判 A 扔掉什么、判 B 扔掉什么。每支要有规模（实测 / 上界估计 / 至少一个具体实例）。这条是 owner 08-07 口径的硬要求——没有它，owner 是在无信息下拍板。
5. **我方默认推荐 + 不答的默认动作**（owner 不回时批次怎么走，不许卡死）。
6. **证据等级标注**：包内每个数字标 证 OPTIMAL / 实测找到值 / 算术 / 假设 / 删失。
7. **影响面预跑**：这条裁决无论判哪边，会连锁到哪些条目、结论、代码 call site、持久化缓存、在飞外发包（连锁重写步 §6.2 的名单法先跑一遍，只出名单不改东西）。
8. **已做完的部分**：明确写「不需要 owner 的都做完了」，列出做完的清单——让 owner 能判断这包是不是熟的。

### 5.3 验收

裁决包出门前过 refute 席一遍，固定检查项一条：**这包里有没有本可以自己算的**。裁判自产文书是审查盲区（referee 家规，五次同模式复发），裁决包正是最典型的裁判自产文书。

### 5.4 反模式（明写，便于指控）

- 拿标签上交（「箱是有界吸收体，能不能当终点请 owner 定」）——先跑参数账步。
- 拿不准就上交，包里没有两分支解空间账。
- 问题不是事实题（「我们该怎么办」）。
- 影响面栏空着——owner 无法判断代价。

## 6. 连锁重写步

> **职责**：一条前提被推翻或被加了新前件后，把所有靠它站着的结论逐条重写。今日 splitfree 重判是现成范本（`docs/research/p2_0_specialized_20260807/refute_round1/REJUDGE_REPORT.md` §4–§5）。

### 6.1 触发

任何前提层变更：canonical 条款改、冻结参数改、语义翻案、引理加前件、旧结论被驳倒。工程批若改动被承重结论引用的代码语义面或工件字节，同样触发。

### 6.2 五步协议

**第一步：定位受损前提。** 写清楚被推翻的到底是哪一条、原表述与新表述的差在哪。范本：rate_lemma 不是错，是欠一条「台间占空均摊」前件；差集是「均摊分配 vs 42 维多胞形的其余点」。

**第二步：机械求出引用者名单。** 六类引用者一个都不能少：

| 引用者类 | 现在怎么找（形态轨落地前） | 落地后 |
|---|---|---|
| canonical 条目 | 全文搜条目名 + 参数值 + 结论关键词 | R-04 反向索引 |
| 仓库内承重文书 | `rg --no-ignore --hidden` 搜结论关键词与数字（注意 `.rgignore` 会藏 `docs/research/**/*.py`，见记忆卡 rgignore-hides-live-research-code） | 索引 |
| 兄弟线净输入 | 该结论被当「给某某线的收窄/放宽」交出去过吗——查本线文书里的「给 X 线」段落 | 索引 |
| 代码 call site / 持久化结论 | codegraph + 源码；持久化 nogood / cut / 证书按其 digest 判 | R-28 版本 digest 自动失效 |
| 记忆卡 | 记忆层检索 | 同 |
| **在飞的外部输入** | 外发包清单 + 外脑会话登记（C-50：上一轮外发包里的 canonical 是旧快照；band22 双回件同病） | 包登记表 |

**第三步：四态判定，逐项写新表述。** 只标状态不算完成——每一项都要写出重写后的句子。

| 态 | 含义 | 必填 |
|---|---|---|
| **作废** | 结论不再成立 | 作废理由 + 头部标记（不删史料） |
| **成立但理由换了** | 结论站得住，证明换了，强度可能变 | 新证明来源 + 强度变化（范本：splitfree ①「网络级纯流被证伪」从「均摊下 6 例实测」升格为「无条件定理」） |
| **需重验** | 不能当场判 | 重验动作 + 负责人 + 期限 |
| **不受影响** | 不受影响 | **一句话理由**，不许空着（空着的「不受影响」是本步最常见的假绿灯） |

**第四步：分层记账。** 本批文书自己改 errata；稿外下游只登记不擅改，写清谁通知、谁执行。范本：REJUDGE §5.4「本报告只登记，通知与注记由主线程负责」，逐条列出 U-01 席的叠加发现、两处叙述的均摊条件、兄弟线净输入同染。

**第五步：收口凭据。** `【连锁账】`表 + 每份下游文书的头注指针（指向本次重判报告的具体节）。冻结件变更时，连锁账并入 `RESEAL_MANIFEST`。

### 6.3 验收

- 名单六类逐类留痕（包括「本类无引用者」也要写）。
- 四态表里没有空理由的「不受影响」行。
- 在飞外发包类：一改冻结件即标包失效并通知，收口写明通知时间。

### 6.4 落卡点

freeze-ritual checklist 主干（卡点 3）；非冻结件的结论修订落文书模板的 `【连锁账】`节（卡点 1）。

## 7. 双向保真验收步

> **职责**：owner 08-07 第一条公理的流程落点。每个 guard/限制批上线时强制回答两问，并把答案登记成可管理的台账；周期性做能力盘点对账（墙审计）。

背景数字（taxonomy §2.4）：病例数上过严 16 : 过松 16，防线数上 2.5 : 16；过严侧病例的发现渠道**全部是人**，零条来自常设装置。本步就是那 2.5 条补成一层的流程半边（形态半边是 R-06/R-07 的双向登记表）。

### 7.1 两问（逐 guard / 限制 / 剪枝规则一次）

**问一：堵了哪些孔？**
- 列出被拦下的非法形态；
- 每种形态配一个变异自证（把 fail-closed 改 fail-open ⇒ 用例转红）；
- **附加一列「唯一防线吗」**：这个形态除了本 guard 还有谁拦？答「唯一」的行，是将来改动前必须先算清的（C-52 的病：两道墙分工不明，改动前才发现没人算过）。

**问二：有没有把合法能力关在门外？**
- 拒真面登记（字段见 §7.2）；
- **必须给具体实例**：一个游戏合法但被本 guard 拒掉的布局/能力/形态。给不出实例 = 该面未被证明过严 = 不进候选（K-6）。这条同时防住 C-10 那种假过严警报——把正确的保守编码误判为保真缺口，整份分析一天内作废。
- **对称套用检查**（C-20 的直接止血）：本 guard 的论证若被对称套用到另一侧（输入侧 ⇄ 输出侧、源 ⇄ 汇），必须**分别**给覆盖面与未覆盖面。source-front 那块过严面就是论证只覆盖输入口、实现对输出口同等排他，219 台每个输出口白关。

### 7.2 拒真面登记（台账字段）

| 字段 | 说明 |
|---|---|
| 面名 | 稳定标识 |
| 拒掉的合法能力 | 具体实例（必填）+ 类别 |
| 规模估计 | 实测 / 上界估计 / 「至少一个实例」三档，标明哪档 |
| 保证方 | 可达性尺子步的判定与保证方（防止将来有人拿审计删守卫） |
| 解锁前置 | 放开需要什么（哪条实测、哪次裁决、哪个 freeze-ritual） |
| **引用者反向索引** | 谁的论证押在「模型碰巧更严」上（C-28：放开押在待放开面上，将来放开时静默失去正当性，没有任何测试会红） |
| 哨兵测试 | 一个可跑的探针；探针必须物理可实现（C-39 教训） |
| 方向暴露 | 本面威胁的是证明类结论还是见证类结论（四象限） |

登记 ≠ 管理：名词清单不算登记（`model_stricter_faces` 现状是四个名字，无参数、无解锁条件、无测试、无反向索引）。上表每个字段都有对应病例，缺一格就少挡一类病。

### 7.3 fail-closed 塌陷计数（零信号 = 未建模的 exclusion）

总纪律「一切缺口向保守方向塌」在 soundness 上正确，但每次塌陷都是一次未登记的 exclusion。要求：

1. 每个 fail-closed 分支带**计数器 + 理由码**；
2. 收批时报「本批运行期塌陷次数 × 理由码分布」，**零信号不是好消息**，要判断是真没塌还是没埋点；
3. 任一理由码在生产口径下非零 ⇒ 该分支登记为拒真面候选，跑两问。

这条与静默 skip 同级对待（C-37：skip 比红危险，因为它同时藏「没跑」和「跑了会发现的问题」）；C-24 的软失败零信号、C-47 的「剥落把拒绝转译成接受致绊线恒零」都在这条下。**降级/剥落/取子集一律计入拒绝率**，不许把拒绝转译成接受（承接 §0b 操作卡⑤，补上它缺的 exclusion 侧）。

### 7.4 墙审计（能力盘点 vs 模型可表达性对账）

孔审计问「非法的进得来吗」，墙审计问「合法的进得去吗」。

**分行方式（关键设计点）**：墙审计**按能力/语义轴分行，禁止按公理分行**。C-21 是这条的实证——四方一致性矩阵按公理分行，没有对应公理的连通性整轴系统性消失，而它是认证谓词 (5) 的本体。装置的分行方式决定了哪些东西看不见。

**能力全集来源（五路，并集去重）**：
1. `facility_templates` + `globals`：每个实体的每个可调自由度（口的启用/朝向、旋转、槽、供电）；
2. owner 裁决台账：所有「允许类」裁决（如 OWN-M22 未接线口合法闲置、OWN-M23 借十字过 front 格）；
3. 模拟器规则层可执行判例（第一参照 SOP 的沉淀，判例应是累积资产而非一次性）；
4. 上游注册表（IP / endfield-calc）：器件与其 `admissionRule` 类参数（C-06 的准入口整类器件即从这一路来）；
5. 六谓词各自的量词展开：每个谓词覆盖的语义轴逐条列（这一路专治「整轴消失」）。

**每条能力三态**：可表达 / **不可表达**（⇒ 拒真面候选，须给实例）/ 未知（⇒ 给探针，或降级为待核，不许留空）。

**墙台账**（append-only）：`能力 id | 出处路 | 模型可表达性 | 证据（探针/实例/源码位置）| 不可表达时的规模估计 | 关联拒真面 | 复核日期`。

**排程与触发**：

| 触发 | 范围 | 时机 |
|---|---|---|
| 首轮全量 | 五路全集 | 本批之后第一个 canonical freeze-ritual 批同批做（那时正好要重做登记表，边际成本最低） |
| canonical 条款 / 冻结参数变更 | 受影响能力子集（增量） | 该 freeze-ritual 内，随连锁重写步一起 |
| **证明类结论出厂** | 该结论依赖的过严面子集（点式） | 出厂前，产出「本证书依赖的过严面清单」栏（R-33），墙台账供给全集 |
| 新器件 / 新 owner 裁决入册 | 单行追加 | 即时 |
| 定期兜底 | 全量重核 | 每季度或每 20 条新增承重结论，取先到者 |
| 新增拒真类病例 | 同族能力重扫 | 病例入账时 |

**首轮产出规格**：墙台账 v1 + 不可表达清单（带实例）+ 排序（按规模估计降序，给 owner 定放开优先级）。首轮预算按半天到一天估，范围以第 1、5 两路为主（实体自由度 + 谓词量词展开），第 3、4 路依赖模拟器判例与上游注册表，可分轮。

### 7.5 落卡点

任务书模板的收批验收半边（卡点 1）；席位清单里的拒真席（卡点 4）；墙审计的增量触发挂 freeze-ritual checklist（卡点 3）。

### 7.6 拒真席的位置与通道

- **任务**：为每条限制找一个游戏合法但被模型拒的**具体实例**。找不到实例，该限制才算被论证。与 refute 席对称：refute 席「推翻每步推导」，拒真席「举出被冤杀的实例」。
- **不是**放开授权：产出是候选过严面，放开仍走 owner 裁决 + freeze-ritual（K-6）。
- **通道（当前额度约束下的建议）**：codex 额度紧时，拒真席与 refute 席**合并为一次双帽任务**，但要求分节输出（refute 段 / 拒真段各自独立结论），防止两种攻击互相稀释。**证明类结论出厂时必须分席**——那正是过严直接产生假证书的场合，不能省。

## 8. 饱和扫描步

> **职责**：owner 08-07 第二条公理的流程落点。规则系统是生成式的：基础规则组合出派生规则，派生再与基础、与其它派生组合出下一级；某些组合把解空间压小到「稍微验算一下就出现新规则」。本步让这个结晶过程被系统地跑出来，而不是等有人绊倒。

### 8.1 触发

承重结论出厂前（证明类结论、canonical 修订、新定理入库）必跑；新参数/新规则入账时对受影响子空间跑。

### 8.2 谁在哪一步

- **立论席**跑第一遍——他手里有前提集，成本最低；
- **refute / 拒真席**攻**圈定**，不只攻结论。指控形式必须具体：给出一条被漏掉的账目行或一个被漏掉的邻接实体。「你圈小了」是可指控项，也是可反驳项。
- **收批席**核收据的停机判据（是否真跑到饱和，还是跑一半停了）。

### 8.3 圈定法（三层，防组合爆炸）

全组合会爆炸，所以圈定必须有结构。三层邻域：

**层 0 —— 种子集**：本结论的前提集（前件卫生步的前件表）+ 本批新入账的参数/规则。

**层 1 —— 邻域**，由两种邻接关系张成（都是有限、可枚举的）：
- **资源账邻接**：与种子共享同一本资源账的规则。账目行沿用 §0b v2.7 补记②的余量审计表：面积 / 边界周长 / 台数容纳 / 端口槽位 / 供电覆盖 / 商品源汇 / 整除模数，**外加一行本批新增的「入量 × 周期 vs 容量」账**——这正是箱案缺的那本账，把它列为常设账目行是今日事故的直接止血。
- **实体邻接**：同一实体 / 同一商品 / 同一端口 / 同一谓词的规则。

**层 2 及以上 —— 只在层 1 产出新结晶时才展开**（新结晶回灌种子集，重跑一轮）。默认深度上限 3 轮；到顶未饱和时**登记「未扫尽」**，不许假装扫完。

**组合阶数**：只做 **pairwise（两两）+ 结晶回灌**，不做全 k 元。理由：塌点几乎总是两本账相乘/相除/取奇偶产生的——箱案 = 入量账 × 容量账；5 满 1 半 = 总量账 × 两档量化账。三元以上的组合通过「回灌后再 pairwise」达到，规模是 |种子| × |层 1| 的量级，可控。

### 8.4 塌点检测（三问，逐个自由量跑）

对结论里出现的每个量 v：

1. **v 的取值集合被前提约束成什么**——连续区间 / 多胞形 / 有限档 / 单点？
2. **两本账组合后是否降维**——连续 → 有限档、有限档 → 单点、集合 → 空集？
3. **降维后是否结晶出可直接查的结构特征**——能不能翻译成一句「布局里必然有/必然没有 X」？

**②发生的地方必须显式上报**，哪怕当前用不上——它是下一级规则的原料。

**两类结晶都要报**：
- **正结晶**：新约束 / 新结构特征（5 满 1 半：「免分流布局中恰一台制瓶机只用一个进料口」）；
- **负结晶**：某危险条件 / 某分支的取值集合塌成**空集**（箱案：危险区为空 ⇒ 限制多余；也包括「某族解不存在」这类死刑）。负结晶直接喂给可达性尺子步。

### 8.5 派生规则登记册

派生结晶是一等对象，不是文书里的一段话。

**存放**：仓库内 append-only 研究台账（建议 `docs/research/derived_rules_ledger/`），**不进 canonical**。理由：canonical 是裁决权威 + 字节冻结件，每条派生结晶都触发 freeze-ritual 会把成本推到没人跑扫描。派生规则只有在被承重使用、且经 owner / freeze-ritual 时才升格入 canonical。

**字段**：

| 字段 | 说明 |
|---|---|
| id / 名称 | 自解释名（「免分流下制瓶机 5 满 1 半」，不是「D-7」） |
| 层级 | 距基础规则几步 |
| statement | 结论原文 |
| **前提集** | 指向种子规则/参数的 id 列表，**逐条**，不是「见上文」 |
| 结晶方式 | 哪两本账、怎么组合（相乘 / 相除 / 奇偶 / 鸽巢 / 计数） |
| 条件性 | 无条件 / 条件（条件榫眼只能与同前提家族叠加，判据 = 前提集之并自洽，见 §0b v2.7 补记①） |
| 验算收据 | 可复跑脚本或手算路径 |
| 方向标注 | 该结晶暴露于过严还是过松（四象限） |
| 消费者反向索引 | 谁在用它 |
| 状态 | ACTIVE / **STALE**（前提集任一条变更即自动置 STALE）/ RETIRED |

**失效追溯**：前提集里任一条变更 ⇒ 本条自动 STALE ⇒ 进连锁重写步的引用者名单。这是 C-03「结论缓存不绑规则版本」在派生规则层的对应物。

### 8.6 收据格式（`【饱和扫描收据】`）

`种子集清单 | 层 1 圈定清单 + 每条的邻接理由 | 扫描对数 | 每对判定（无关+一句理由 / 有关无新结论 / 结晶）| 结晶清单（正/负）| 塌点上报 | 停机判据（本轮零新结晶 = 饱和 / 深度到顶 = 未扫尽）| 耗时`。

**停机判据**：一轮 pairwise 零新结晶 = 饱和。这是本步为什么有界的原因——它不是「想到为止」，是「一轮空转为止」。

### 8.7 正负样板校核

设计必须能被样板测，否则只是好听。逐步演一遍：

**负样板 —— 箱案（该扫没扫）**

| 步 | 本设计会怎样 |
|---|---|
| 种子集 | 「箱=class (2) 有界吸收体」这条被当前提用 ⇒ 它的前提集入种子：槽数 6、物理口 3、单口速率、tick、冲刷周期 10 s、单槽容量(MISSING) |
| 层 1 圈定 | 资源账邻接命中新增的「入量 × 周期 vs 容量」账目行；实体邻接命中同实体 `facility_templates.protocol_storage_box` 与 `globals.logistics` |
| pairwise | 入量账 × 容量账 = 15 件/周期 vs 300 件容量 |
| 塌点三问 | 问②命中：危险条件的取值集合塌成**空集** ⇒ 负结晶 |
| 上报 | 负结晶喂可达性尺子步 ⇒ 判「限制多余」⇒ 三签流程 |

**关键点**：抓住它的不是「更仔细」，是层 1 里那一行账。这行账是本设计从今日事故里加进常设清单的——箱案之所以三周无人发现，正因为没有任何清单要求把入量和容量放进同一次运算。

**正样板 —— 5 满 1 半条件定理（owner 手动扫出）**

| 步 | 本设计会怎样 |
|---|---|
| 种子集 | 钢瓶总量账 5.5（一级派生）、带容量 1 件/tick（基础）、配方 2:1（基础）、免分流（目标性约束）、六台全开（二级派生） |
| 层 1 圈定 | 资源账邻接：商品源汇账（钢块产道 vs 耗道）+ 端口槽位账；实体邻接：同 operation `molding_bottle` 的 6 台 |
| pairwise 第一轮 | 带容量 × 配方 × 免分流 ⇒ 每台进料口数 ∈ {1, 2} ⇒ 每台占空被量化进 {1/2, 1} 两档（**塌点问②命中：连续 → 有限档**） |
| 回灌 + 第二轮 | 两档量化 × 总量账 5.5 ⇒ k·1 + (6−k)·½ = 5.5 ⇒ **k = 5 唯一**（**问②再命中：有限档 → 单点**） |
| 塌点问③ | 翻译成可直接查布局的结构特征：「免分流布局中恰一台制瓶机只用一个进料口」⇒ 正结晶 |
| 登记 | 条件性 = 条件（前提集含「钢块免分流」这条目标性约束）；**无条件下仍是 42 维自由多胞形**——同一问题两个层级两个答案，都对，登记册必须同时容得下 |
| 停机 | 第三轮无新结晶 ⇒ 饱和 |

**关键点**：两轮 pairwise + 一次回灌就够，不需要全组合。owner 是用直觉一步跳到的；本设计是把这一步拆成两轮机械运算。

**诚实边界（扫描抓不到什么）**：需要新几何洞察的（带子能不能拐到该拐的地方）、需要游戏实测才能定的语义、需要仓库外知识的。这些落回上游对账 SOP 与 owner 裁决，扫描收据里应写明「本轮扫描的层是速率/计数算术层，几何层未扫」——这本身就是覆盖层声明的一个实例。

**本轨明确挡不住的三类**（诚实边界）：
1. **规则集边界的完备性**——墙审计能查「已知能力在不在模型里」，查不出「游戏里还有我们从没听说过的能力」。这一类只能靠 owner 供出与模拟器/上游对账。
2. **几何层判断**——饱和扫描跑在算术层；带子能不能拐、格位够不够，扫描给不出。
3. **形态层的机器强制**——`semantics` 区零消费方，语义区的错误不会被任何测试发现（`canonical_anatomy.md` §5）。流程步的凭据是人写的表，checker 只能核「表在不在、栏位填没填」，核不了「算得对不对」；算得对不对靠 refute 席复算。这是本轨的天花板，也是形态轨 checker 规格必须补上的位置。

## 12. 成本与反退化

流程设计最常见的死法是变成仪式：卡片越来越多，每张都填「不适用」，然后所有人开始复制粘贴。四条反退化条款：

1. **触发矩阵是硬的**（§1.1）。不满足触发条件的步不许要求填，也不许「顺手都填一下」。
2. **每步给时间预算**，超预算说明触发条件写错了：参数账 ≈ 10 分钟/标签；可达性尺子 ≈ 5 分钟/限制；前件表 ≈ 15 分钟/承重结论；覆盖层声明 ≈ 2 分钟；饱和扫描首轮 ≈ 30–60 分钟/承重结论；连锁重写按引用者数量计。
3. **退化信号常设监测**：某步连续三批的「不适用」比例 > 70% ⇒ 触发条件回炉；同一句理由跨批复制 ⇒ 收批席抽查该行。
4. **有界性是验收项**：任何人往这套流程里加新检查，必须同时给出停机判据。加不出停机判据的检查不许进（这是 C-15 的教训：「多审几轮」不是检查，是希望）。

## 14. 未决问题

1. **拒真席通道**（编排 / owner）：codex 额度约 1%，refute 席已在紧供。默认建议 = 与 refute 席合并双帽（分节输出），证明类结论出厂时分席。是否接受、分席时用哪个座席，待定。
2. **派生规则登记册的形态**（设计 / owner）：本稿建议 append-only 研究台账、不进冻结件、不进 hash。若 owner 要求它进 hash，每条结晶都会触发 freeze-ritual，扫描步的成本模型要重算。
3. **凭据 checker 进不进 CI 硬门**（owner）：凭据的存在性（节名齐不齐、栏位空不空）可以机器核，与 `check_p1_2_proof_obligations.py` 同族。进硬门会挡住没填表的提交；不进则只在收批席人工核。本批不改 `scripts/`，只出规格。
4. **墙审计首轮范围与预算**（排期）：本稿建议首轮以第 1、5 两路（实体自由度 + 谓词量词展开）为主，第 3、4 路（模拟器判例、上游注册表）分轮。首轮挂本批之后第一个 canonical freeze-ritual 批。
5. **饱和扫描深度上限**（待实测校准）：默认 3 轮回灌是拍的，需要用几个真实结论实测「第几轮开始零产出」来校准。首批校准样本建议用 P2.0 速率层结论（种子集清楚、账目行可枚举）。
6. **合并稿的两轨排序**（合稿席）：形态轨的 R-12（`semantics` 区 schema 收紧）是所有 A 组需求的前置；流程轨的七步不依赖它。因此建议流程步先行落模板（成本低、当天可用），形态改造按 additive 分批走 freeze-ritual。
