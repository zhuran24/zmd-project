## 0. 一页读懂

owner 08-07 两枪指向同一件事：**规则的载体没有位置放「使这条规则成立的东西」，推理流程没有一步强制去找它。**本方案给出的终态是四句话：

1. **规则分四层**：求解器事实（L0，冻结）/ 裁决（L1，冻结，`semantics` 区改造对象）/ 派生闭包（L2，tracked 不冻结，自动失效）/ 投影视图（L3，可重生，非权威）。
2. **推理走八步**：批型判定 → 参数账 → 可达性尺子 → 前件卫生 → 裁决包 → 连锁重写 → 双向保真验收 → 饱和扫描。每步有凭据节名、验收判据、失败后果、停机判据。
3. **审计对象从一类变三类**：孔审计（非法的进得来吗，已有）+ 墙审计（合法的进得去吗，新建）+ **界审计（在册限制的界在物理参数下够得着吗，新建）**。第三类是今日第一枪的真正对症装置——两份对抗稿都实证了：墙审计抓不到箱案。
4. **落地分八批**：批 0（当天上线，纯模板）→ 批 1（纯工具）→ 批 2/3/4（freeze-ritual 三批）→ 批 5（埋点）→ 批 6（三类审计首轮）→ 批 7（收敛）。零 freeze-ritual 的止血排在最前，两枪的止血在批 0 与批 2 全部到位。

对抗席的 9 条 FATAL 全部修进设计；27 条 MAJOR 中 25 条修进、2 条部分采纳并给出不全采的论证（§2.3）；15 条 MINOR 台账化（§2.4）。

## 1. 设计公理章

本章两条公理是 owner 08-07 下达的，级别高于本方案的一切设计取舍。任何后续批次与本章冲突时，以本章为准。

### 1.1 公理 I — 双向保真

> **owner 原话意**：「我们做了守卫、孔堵住了、就放心了——不对！这个项目最关键的是不能把可行解排除掉：**把所有可行的规则都放进来**与堵孔同样重要，否则同样在削可行解，而我们之前几乎无视了这个。」

技术翻译：本项目认证的是 `max_lex(area, min_side)` 的**全局最优性**，证书说的是「不存在更好的解」。因此模型与游戏真语义的偏差，两个方向都是 unsound：

|  | 见证 / 正向构造 | INFEASIBLE / 上界 / 最优性证明 |
|---|---|---|
| **过严**（模型 ⊂ 游戏） | 安全 | **假证书** |
| **过松**（模型 ⊃ 游戏） | **假见证** | 安全 |

「过严 = 保守 = 安全」只在见证半边成立。而项目手上的承重结论绝大多数是证明类：`U=(1188,18)` conditional 上界、P2.0 面积上界 `A ≤ 1167`、PB-03 `(1326,34)` residual-band UNSAT、W0 G1 双 INFEASIBLE、所有 nogood 与死刑定谳——**全部暴露在过严侧**。

这个偏置是可测的，不是感觉：分类学统计 52 条病例中过严 16 : 过松 16（一比一），而防线数 **2.5 : 16**；过严侧 16 条病例的发现渠道**全部是人**（owner 亲自、外审席、批次临时席、prod 实测炸出），**零条来自常设自动装置**。

**根因是机制性的**：过严限制只产生「缺失的答案」，不产生「错误的答案」，因此**没有报错通道，永不自曝**。它的对偶是触发器——装了却从不激活，同样无声。

**本方案对公理 I 的落地**：三类审计对象（§1.5）、双向保真验收步（§4.7）、`model_faces` 双向登记表（§3.6）、拒真席常设化与其验收判据（§4.7、§4.9）、每条承重结论的方向暴露栏（§4.7）。

### 1.2 公理 I 的反向刹车（同等醒目）

**过严的判定必须与过松的判定同等严谨。**活样本 C-10：08-06 主线据 canonical `mixed_commodity_flow` 判「模型比 canonical 严 = 保真缺口」，当晚翻案——机器入口无内容选择权，模型门口排他是**正确的保守编码**，不是过严缺口，基于错读的整份分析一天内作废。

所以：

- 拒真席的产出规格是「候选过严面 + **一个游戏合法但被模型拒的具体实例**」。给不出实例 = 该面未被证明过严 = 不进候选，只能待在收件箱。
- 候选面**不得被下游当既定前提消费**。
- 放开动作仍走 owner 裁决 + freeze-ritual。拒真席没有放开授权，界审计没有删限制授权（删限制走 §4.3 的三签）。

### 1.3 公理 II — 规则派生闭包

> **owner 原话意**：「基础规则会不断推出次级规则，次级规则又与基础规则、其它次级规则组合出下一级；某些组合形成的约束把某个解空间压小，小到**稍微验算一下就会出现新规则**；新规则再与老规则组合出下一级。」

owner 当场用直觉命中一例并验算成立——**5 满 1 半条件定理**：条件于「钢块免分流」，六台制瓶机的占空分配唯一 = 5 台满速 + 1 台半速。五条来自不同派生层级的前提（钢瓶总量 5.5 / 带容量 1 件·tick⁻¹ / 配方 2:1 / 免分流目标约束 / 六台全开）把每台占空逼进 `{1/2, 1}` 两档，总量再把档位分布定死为 k=5。结晶出的新规则立刻可直接查布局：「免分流布局中恰有一台制瓶机只用一个进料口」。**无条件下仍是 42 维自由多胞形**——同一问题两个层级两个答案，都对，登记册必须同时容得下。

三条落地义务：

1. **派生规则是一等登记对象**——必带完整前提集与层级，前提变更可追溯失效；不再散在批次文书里当一段话。
2. **承重结论出厂前对其前提集跑组合扫描至饱和**——不再产出新规则为止。
3. **塌点（自由度被组合钉死）显式上报**，哪怕当前用不上；正结晶（新结构特征）与负结晶（某危险条件的取值集合塌成空集）都要报。

**为什么这是止血而不是锦上添花**：箱堵塞判据不可达 = 入量账 × 容量账两条基础规则的一次组合，三周没有任何人做这步验算；不是没人仔细，是没有任何清单要求把入量和容量放进同一次运算。

### 1.4 公理 II 的反向刹车

生成式装置会自我繁殖，两条刹车必须与公理同时立：

- **预算删失的结论不是结论**。扫描运行记录必带 `terminated_by`；`terminated_by: budget` 的扫描**不得被任何文书引用为「该子空间已饱和」**。这与「零激活不等于 cut 无用」是同一条纪律。
- **自动产出必须过闸**。扫描产出的 L2 条目一律 `UNREVIEWED`，须过一次拒真/反例席判定才转 `ACTIVE`；含 `UNREVIEWED` 前提的条目层级不递增、不可被任何文书引用。否则一条取错参数的机器结论会带着 `receipt` / `recompute_cmd` 的踏实外观自动繁殖——那正是「勤奋全落可复跑层，复跑的踏实感掩护未查的前提」在新架构里获得自动化能力。

### 1.5 两条公理合起来给出三类审计对象 ★ 本批新增

这是合稿席对两份对抗稿的综合结论，也是对 owner「完整性台账能不能更早抓到箱案」这一问的正面回答：**不能，因为缺的是第三类。**

| 审计 | 问的问题 | 抓的失效模式 | 现状 |
|---|---|---|---|
| **孔审计** | 模型放进来的解，游戏里合法吗 | 纳伪（L1/L2/L3/L4 各层的过松孔） | 已有装置（16 条防线） |
| **墙审计** | 游戏里合法的能力，模型表达得出吗 | **X-5 整类能力不在模型** | 新建（§4.7、批 6） |
| **界审计** | 在册限制的危险条件，在物理参数下够得着吗 | **X-3 分类标签的界不可达 / X-9 触发器永不触发** | 新建（§4.7、批 6） |

两份对抗稿独立指出同一件事：箱案属于 X-3，**不属于 X-5**——它不是「能力不可表达」，是「在册限制的界够不着」。墙审计按能力分行，箱案根本不占一行；更糟的是箱的收货能力本质是吞吐，而吞吐是明文 OUT-OF-SCOPE，能力册会把它正当地填成 `out_of_scope` 归档，**新装置反而提供了一个把本案合法归档的出口**。

界审计的枚举面是有界的：**所有 statement 里断言了数值界或阻塞条件的条款**（今天是十几条），每条一行 `{界的表达式, 到达侧参数, verdict, 最近核算日期, 谁在消费它}`。配套堵掉归档出口：能力册的 `out_of_scope` 取值必须附一句判定「若该能力被表达，解空间会不会变大」，答 `yes` 的照样进 `not_verified` 计数。

## 3. 规则形态（终态）

### 3.1 四层

| 层 | 内容 | 载体 | 权威 | 失效语义 |
|---|---|---|---|---|
| **L0 求解器事实** | `globals` / `facility_templates` / `recipes` / `production_targets` / `commodity_metadata` / `routing_rules` | `rules/canonical_rules.json`（本方案不动其字段集） | owner 游戏实测 > 模拟器规则层 | 不失效，只被取代 |
| **L1 裁决** | 公理 A1–A11、owner 裁决、条目化规则语句、实体参数镜像、双向面登记 | 同文件的 `semantics` 区（改造对象） | owner 裁决 / 公理 | 不自动失效，只被显式取代 |
| **L2 派生闭包** | 派生规则/定理/界/结晶点/不可达性、拒真候选面、能力册、界可达性台账 | `rules/derived/`（tracked，**不进 `FROZEN_ARTIFACTS`**，一条目一文件） | 前提集 + 推导 + 可复跑收据 | **自动失效**：前提指纹不符 ⇒ `STALE` |
| **L3 投影视图** | 实体参数表、参数反向索引、条目-谓词矩阵、三类台账投影、能力覆盖率、闭包图 | `docs/generated/`（tracked，可重生） | **无**，每个数字带 L0/L1/L2 出处路径 | currency 测试强制同步 |

L2 不进冻结件的三条理由（对抗席核实成立，保留）：节拍不匹配（高频可撤销的产出付不起固定 reseal 底价，结果是没人跑扫描）、权威等级不同（混排必然重演证据等级混用）、冻结文件表达不了条目级自动失效。

**层间接口**：L2 前提集只能指向 L0 / L1 / 更低层级的 L2；L1 引用 L2 只能通过晋级（owner 裁决或外审定谳后 additive 写进 L1，L2 原条目标 `PROMOTED`）。**禁止 L1 把活的 L2 条目当前提**——否则冻结层的正确性挂在非冻结层上。

### 3.2 L1 条目字段集

必填集按条目类分三档（D-13）：

- **`clause`**（10 条规则语句）：`id` / `statement` / `superseded_readings[]` / `scope` / `predicate_status` / `applies_to_paths[]` / `applies_to_external[]` / `applies_to_predicates[]` / `parameters[]` / `parameter_fingerprint` / `premises[]` / `allocation_choices[]` / `reachability` / `direction` / `derivation` / `provenance` / `implementation_anchors[]` / `parity_sentinel`；`usage_rule` 可选。
- **`parameter_object`**（`power_coverage_stencil`、`entities.*`）：不要求 `statement` / `premises`；要求 `source` / `missing[]` / `implementation_anchors[]` / `parity_sentinel`。
- **`kernel`**（`axiom_kernel`）：保留现有结构 + `model_faces`（§3.6）+ `_derivation_matrix`（消除 11 个悬空 `#N` 引用）。

三条相对输入稿的变更：

1. **`consumers[]` 移出 canonical**（D-03）。canonical 只留 `id`；反向引用由 L3 生成，完整性由 currency 测试保证，不由人手登记。
2. **新增 `implementation_anchors[]` 与 `parity_sentinel`**（D-08/D-14）。按 `power_coverage_stencil` 的现成先例，把「这条规则由哪几处实现承担、哪个测试钉住它们等值」抬成字段。A5 已经在散文里点名 `_port_front_cell` 是唯一转换点，把它抬成字段是纯 additive，之后 C-02 那种「某个 LEGACY_DIAGNOSTIC 面还在用 `port+DIR_DELTA`」可由 anchors 清单 + 反向扫描机械查出。
3. **新增 `parameter_fingerprint`**（M-08）：`parameters[]` 的路径 + 现场取值的 sha，逐条目。这是流程侧引用豁免（§4.2）的落点——没有它，「形态落地后账表降到一分钟」没有实现路径。

### 3.3 前件与分配选择

前件项：

```
{"id": "P-1", "statement": "…", "kind": "parameter|axiom|ruling|convention|assumption|derived",
 "authority_kind": "owner_in_game|simulator_rule_layer|canonical_text|derivation",
 "dischargeable_in": ["p2_0_flow"], "not_dischargeable_in": ["certified"],
 "discharge_evidence": "存在的路径 或 测试 nodeid 或 MISSING"}
```

两条硬判据（分别修 D-12 与 D-05）：

- **`discharge_evidence == "MISSING"` 时，schema 强制 `dischargeable_in` 不含 `certified`。**「没给证据就不能声称可 discharge」，把自由声明降为有代价声明。
- **`allocation_choices[]` 必须覆盖算术里出现的每一个分母。**

```
"allocation_choices": [
  {"被分配的量": "x_op（该 operation 的总运行次数）", "分母": "machines（台数）",
   "自由度维数": 6, "选定的约定": "台间均摊", "该约定失效时结论怎么变": "…"}
]
```

为什么不是「≥1 条 convention」：`rate_lemma_scope` 的 `(ii) minimal-lane-allocation convention` **当时已经在条目里**，存在性判据当场满足，缺的第二条照样不在。缺的从来不是「有没有约定」，是「**哪些自由变量的取值是被选的、每个选了什么**」。自由度维数是可机器求的（同一 operation 的实例数、车道数取自 L0），checker 断言覆盖每一个分母，这是有界判据。

### 3.4 可达性块

凡 `statement` 含「当且仅当 / exactly when / blocks when / triggers when / fails when」形态判据的条目必填：

```
{"condition": {"参数 refs": [...], "关系式": "arrival_per_flush >= slot_count * slot_capacity",
               "比较方向": ">="},
 "computation": "3 口 × 1 件/tick ÷ 2.0 s × 10 s = 15 件/冲刷周期 vs 6 × 50 = 300 件",
 "verdict": "unreachable|reachable|conditional|NOT_ASSESSED",
 "assessed_on": "…", "receipt": "…", "open_premise_refs": ["…待判项…"]}
```

三条相对输入稿的变更：

1. **`condition` 形式化**（D-02②）。散文 condition 无法被 checker 或扫描器消费，`verdict` 就只是一句声明。形式化后 checker 能对 `computation` 做**独立重算**。
2. **`NOT_ASSESSED` 禁令改口径**（D-02③）：不看 `scope`/`direction`，改为「**凡 statement 断言了数值界或阻塞条件的条目一律禁 `NOT_ASSESSED`**」。原口径（certified ∧ stricter）对游戏语义类条款天然不适用，而箱条款正是这一类——按原口径它可以合法写 `direction: exact` + `NOT_ASSESSED` 绿灯通过。
3. **新增 `open_premise_refs`**：判定依赖的在案待判项。箱案的正确形态是 `verdict: conditional` + `open_premise_refs: ["同种物品填槽纪律（P2 待判）"]`，不是 `unreachable`。

### 3.5 实体参数镜像与 provenance 门槛

`semantics.entities.<facility>` 一实体一条目，字段固定（几何 / 口 / buffer / cycle / `missing[]` / 每个非镜像字段的 `source`）。三条规则：

1. **`missing[]` 必填、可为空数组、不得省略。**缺项写进 `missing`，不是不写。
2. **与 L0 重叠的字段是镜像，双向等值**（多一个字段、少一个字段都红）。
3. **provenance 门槛（新增，D-16）**：**进冻结件的每个承重量必须能在仓内复验**——vendored 抽取产物 + 抽取脚本 + 收据 + 上游 commit，并配一条与 `src/adapters/industrial_planner/*.json` 同族的 currency 检查。做不到就留在 L2，不进冻结件。

第 3 条是本方案对「第四份拷贝」问题的答案。实测：`facility_templates` 只有五个键，承重参数一个都不在里面；箱的口数另存于冻结的 `preprocess_plan.json`（`box_sink.generic_input_slots = 3`，且语义还不同——generic slot ≠ 物理口）；buffer/cycle 来自未 vendored 的模拟器源码快照，仓内 vendored 的 `device_type_registry.json` 实测无 slot/capacity/flush 字段。**一个进冻结件的承重数字，在仓内无法复验**，就是把 C-12 的形态搬进了冻结件。口数与 `preprocess_plan` 建显式对照字段（含差异说明），checker 断言两者关系而非相等。

### 3.6 `model_faces` 双向登记

结构样板取 `globals.empty_rectangle.emptiness_adjudication`（对象 + `required` + `additionalProperties: false`），**不取 `ruling_level_inputs`**（实测是散文字符串，与 `model_stricter_faces` 同型，两者都是被升格对象）。

- **canonical 内**：`stricter{}` / `looser{}` 两个子表，只装 **owner 已裁定**的面。每面必带 `{statement, implementation_anchors[], why_stricter{argument_ref, covers, does_not_cover}, excluded_game_legal_instance{kind, witness, measured}, rejection_risk{could_cut_optimum, argument, probe}, unlock_path, acceptable_because, provenance, sentinel}`。
- **L2 内**：`candidates`（拒真席收件箱）+ 每面的 `consumers`（由 L3 生成）。
- `excluded_game_legal_instance.kind = "none"` 的条目不能进 `stricter`，只能待在 `candidates`；**`candidates` 里的面不得被下游当既定前提消费**。
- `rejection_risk.could_cut_optimum` 无默认值，`unknown` 合法但**会被计数**，计数进方向暴露栏。「我们不知道这个面是否砍掉了最优解」可接受，「我们没问过」不可接受。
- `sentinel` 必填，且哨兵必须选「除该守卫外全链路合法」的几何、验收输入必须是被验链自产字节、探针必须物理可实现。

登记义务按「谁最先知道」分配：实现改动者（改动合入前，兜底闸见 D-19）/ 论证作者（文书入库前，落 consumers）/ 拒真席（提交候选，无升格权）/ owner（裁决与放行）。**审查席是发现者，不是登记者**——C-20 的现状（外审发现了面、登记了名字，「被排除能力有多大」没人补）就是这个错位的产物。

### 3.7 L2 派生层

条目字段：`id` / `level` / `kind`（`theorem|bound|impossibility|unreachability|structural_feature|parameter_derivation`）/ `statement` / `scope` / `premises[]` / `premise_fingerprint` / `derivation{method, receipt, recompute_cmd}` / `crystallization{free_variable, collapsed_to, detector}` / `direction` / `status` / `sentinel`。

- **层级可机械计算**：`level = 1 + max(前提 level)`，L0/L1 记 0。给饱和扫描一个终止判据。
- **状态机**（D-11/D-10）：`UNREVIEWED`（扫描默认产出）→ 过拒真/反例席 → `ACTIVE` → 前提指纹不符自动转 `STALE` → `RETIRED` / `SUPERSEDED` / `PROMOTED`。
- **分级失效**（D-10，修反向棘轮）：①指纹不符**自动**转 `STALE`（数据更新，不红）；②只有 `STALE` 且**有 consumers** 时才阻断该批；③`UNREVIEWED` 不计入阻断集。否则 canonical 改一个 `globals` 参数，所有引用它的 ACTIVE 条目当场红，而 L2 由扫描自动增殖——canonical 批的成本会随 L2 规模线性增长，与本方案目标相反。
- **`kind: unreachability` 是 X-9 空档的正向承载位**（箱堵塞判据、cut 触发条件同归此类），也是界审计的沉淀位。
- **指纹规范化规格**（D-21）：键序、精确有理数（现场有 `11/2`、`10/17`、`21/22`）、assumption 类无值前件的处理，全部明写并复用 `src/io/strict_json.py` 的 exact-decimal 语义。批 1 验收项。
- **一条目一文件 + 运行日志走 `.artifacts/` JSONL**（D-22），避免多会话/多 worktree 并发写冲突。
- **目录头 `_authority: NON_FROZEN_DERIVED`**，打包脚本白/黑名单显式列出（D-25）。

### 3.8 L3 视图与消费红线

六张视图（V1 实体参数表含 `MISSING` 计数 / V2 参数反向索引 / V3 条目-谓词矩阵含 `axis_without_axiom` 行 / V4 三类台账投影 / V5 能力覆盖率 / V6 闭包图），必须配 currency 测试，每个数字带出处路径。

两条相对输入稿的变更：

1. **V2 只保留可现场重算的列**（D-09）：canonical 内引用、L2 前提引用、frozen 工件内引用。代码 call site 列改用 `implementation_anchors` + codegraph impact 作辅助，并在视图头部显式标该列**非完备**。理由：`authoritative_numbers` 先例的自述是「刻意不去扫散文里的过期整数，健壮的强制函数只有『核心节点值 == 现场重算』」，它只强制了一个数；而代码侧已实证拼接字符串骗过 grep、`.rgignore` 把整类活代码投影出默认结果。不完备的索引被当完备用，就是 C-27 的形态。
2. **消费侧红线机器化**（D-17）：承重文书与 L2 条目的前提集中出现 `docs/generated/` 路径 ⇒ **红**，与「ledger 永不作 cut 来源」同规格。视图路径只许出现在「检索记录」栏。理由：被当标签消费的 `terminal_clause` 是冻结的、owner 裁决的、正文里就写着 "deliberately not in commodity types" 的权威条款，`rate_lemma_scope` 甚至内嵌了 `usage_rule`——两者都没挡住。一个更短、更方便、一键可达的视图只会被更多地当标签。

**总的消费侧闸（三条，批 0 上线，本方案对第一枪的主止血）**：

1. `reachability.verdict` 为 `NOT_ASSESSED` 或 `conditional` 且 `open_premise_refs` 非空的条款，**不得作为承重前提被 L2 条目或承重文书引用**（可作为背景引用，须标「界未核」）。
2. `docs/generated/` 路径与 L2 `UNREVIEWED` / `candidates` 条目不得进任何前提集。
3. 三级阶梯里 L1（仓库内批次文书）命中的参数，权威等级封顶为「批次文书」，不得直接支撑 certified 语境的放开。

### 3.9 失效戳：八段 digest ★

持久化结论（nogood / cut / 证书 / L2 条目）的规则版本戳，**既不用 `_epoch`，也不用整文件 sha**，改用：

```
stamp = sha256( canonical 除 semantics 外的八段规范化序列 ) ⊕ sha256( preprocess_plan.json )
```

八段 = `$schema / metadata / globals / routing_rules / facility_templates / recipes / production_targets / commodity_metadata`，即 canonical 里全部 solver 可消费的顶层键。

三条理由：

- **修掉 D-01 的 unsound**：持久化结论依赖的是 L0（tick、带容量、几何、配方），`_epoch` 只在 `semantics` 变时动 ⇒ L0 一改旧 nogood 静默存活，正是 C-03 换马甲复发，而且是设计明文规定的。八段 digest 覆盖全部 L0。
- **修掉整文件 sha 的过失效**：纯语义 additive 批（本项目未来的主要 canonical 批型）不动八段 ⇒ 不会把全部持久化结论一次性作废。过失效是安全方向，但结构性走不完的保守支不是真选项。
- **零人工记账**：机器求得，不像 `_epoch` 靠人记得递增——「靠人记得更新 pin」正是 C-49 的病因。且 08-07 批已经跑过这条逐段断言，是现成载体不是新发明。

`_epoch` 若保留，降级为纯人读标记，schema 明文禁止它进任何指纹输入。条目级细粒度失效由 `parameter_fingerprint`（L1）与 `premise_fingerprint`（L2）承担。

## 4. 推理流程（终态）

八步。每步给：触发 / 谁做 / 检查什么 / 凭据节名 / 验收判据 / 失败后果 / 停机判据。**验收与失败后果不是可选项**——两份对抗稿的共同诊断是「拒真侧建的是有职责、无验收、无后果、无预算的席位」。

### 4.0 第 0 步：批型判定与档案检索

**触发**：每批开工。**谁做**：Plan 席判定并留痕，refute 席第 0 攻击面复核。

- 逐条件项（下表 ¹–⁷）写「触发 / 不触发 + 一句理由」，不许只写批型名。
- **fail-closed 兜底**：改动触及可行集、证据链、被承重结论引用的语义面或工件字节的，**一律不算工程/基建批**；判不准按更重的批型走。
- 工程/基建批必须写一行「本批不含科学断言的依据」——让「无科学断言」成为可指控的断言，而不是默认值。
- **档案检索四路**（并入本步，N-04）：记忆层 / roadmap 台账 / `docs/research/` 目录名 / 裁决索引表（批 1 产出）。四路各留一行结论。停机判据 = 四路各一行。
- **canonical 新鲜度**：`git show main:rules/canonical_rules.json` 核前提；长活分支跑 `git merge-base --is-ancestor`。

**为什么它是第 0 步而不是脚注**：整套流程是否运行完全由「这批属于哪一行」决定，而输入稿把这个判断留成无人复核的自述，还提供了一个七步全免的批型。最省事的合规路径本来是「自述为工程批」，且退化监测看不见它（自述成工程批的批连表都不填，不产生「不适用」行）。

**验收**：过堂表上七个条件项逐条有判定与理由；refute 席给出「同意 / 应改判为 X + 理由」。**失败后果**：批型未判定 ⇒ 后续凭据一律不予收批。

### 4.2 参数账步

**职责**：把「引用标签」变成「重组参数」。**凭据**：`【参数账】`。

**两级表**（M-14）：

- **标签行**（一个标签恰一行）：`标签 + 出处 | 判据原文 | 一次算完的算式 | 结论（可达/不可达/待核）| 本行用到的未声明前件 | refute 复核`
- **量子行**（每个量一行）：`量 | 出处形态（受控词表：字段路径 / 散文行号 / 派生工件字节 / 批次文书 / MISSING）| 权威等级 | 值`

**第三列的完备性靠对表，不靠「列全」**（M-03）：对余量审计表的账目行逐行过——面积 / 边界周长 / 台数容纳 / 端口槽位 / 供电覆盖 / 商品源汇 / 整除 / 模数 / **入量 × 周期 vs 容量**（新增）。每行问「本判据碰这本账吗」，答是就把该账的量拉进表，答否写一句理由。**停机判据 = 九行过完。**账目行清单 append-only 增长：饱和扫描每次结晶所用的账对若不在清单里，收批时追加一行。

**MISSING 三级处置阶梯**（M-04，替代「一律上交 owner」）：

| 级 | 动作 | 记什么 |
|---|---|---|
| L1 仓库内检索 | canonical → 批次文书（公理提案/参数表/验证附录）→ 记忆层 | 命中则填「出处形态 = 批次文书（非冻结件）+ 权威等级」，并**登记一条形态轨欠账**（该量应回流 canonical） |
| L2 模拟器判例 | 按第一参照 SOP 跑判例 | 命中则填「模拟器规则层」+ 判例路径，进累积判例集 |
| L3 owner 事实题 | 仅当 L1/L2 都答不了或两者分歧 | 进裁决包 |

L1 命中的量权威等级封顶为「批次文书」，不得直接支撑 certified 放开。

**验收**：每个承重标签恰一条标签行；标签行的算式与结论非空；每个量子行的出处形态取自受控词表；MISSING 量子行有三级处置留痕；九行账目对表过完；表尾有 refute 复核行；节尾有 `耗时 / 填表人`。
**失败后果**：文书不得入库、不得外发、不得进 owner 眼睛。
**豁免（唯一一条）**：条目已带 `reachability` 且 `parameter_fingerprint` 未变 ⇒ 填「引用 + 指纹」一行。指纹变了必须重算。

**样板（重做，箱案）**：

| 标签 | 判据 | 算式 | 结论 | 未声明前件 |
|---|---|---|---|---|
| class(2) BOUNDED mixed absorber（`semantics.mixed_commodity_flow.terminal_clause`） | 「6 槽全占时堵，**与商品种类数无关**」（`slot_count_clause`，08-06 owner 裁决明文：'six different commodities' 是例子不是界） | 件数维度：3 口 × 1 件/tick ÷ 2.0 s × 10 s = **15 件/冲刷周期** vs 容量 6×50 = **300 件**；槽数维度：**取决于填槽纪律** | **待核** | ①同种物品的后续件是填满已开槽才另开新槽，还是可直接另开新槽（`AXIOM_KERNEL_PROPOSAL_20260806.md:115` 明记「P2 待判」）；②单槽容量 50 的仓内 provenance |

量子行：物理入口 3（散文，`protocol_storage_box_wireless.statement`）/ 单口速率 1 件·tick⁻¹（字段，`globals.logistics`）/ tick 2.0 s（字段，`globals.time`）/ 冲刷周期 10 s（散文）/ 槽数 6（散文）/ 单槽容量 50（**批次文书**，`AXIOM_KERNEL_PROPOSAL_20260806.md:115`，非冻结件，L1 级命中）。

**这张表的正确结论是待核，不是「限制多余」**，因为槽数维度依赖一条在案待判项——若新件可直接另开新槽，6 件即可占满 6 槽，而每 10 s 进货可达 15 件 ⇒ 危险条件**可达**。原样板把这条待判项判成了对自己结论有利的那一边，作为负面教材保留在稿内：**参数都在手上、账也拼了，仍然可以用一条退役读法收官**——这正是参数账必须配「未声明前件」列与量词问的理由。

owner 的裁决结论（箱 = 汇流区合法终点）不受影响：它另有独立支撑——10 s flush 无条件清空 ⇒ 结构上不可毒死，即便瞬时堵门也 ≤10 s 自愈。**受影响的只是「用哪一层论证去支撑它」。**

### 4.3 可达性尺子步

**职责**：限制与触发器的对偶盲区补线。**凭据**：`【可达性尺子】`。

**判定六选一**（M-02，新增第 6 档）：

1. **限制成立**——危险可达。保留。若为「为稳而选的保守支」，必填代价列（迭代速率 × 空间规模 = 预计墙钟）。
2. **限制多余**——危险不可达，保证方 = 物理/冻结数据。进删除候选（走三签）。
3. **守卫必留**——危险不可达，保证方 = 这条限制自己。不得因本审计删除。
4. **非 soundness 保留**——危险本身出域（吞吐/带宽层）。必须写明真实理由与**摘除条件**。
5. **待核**——参数账里有 MISSING 量或在案待判项。进裁决包或欠账。
6. **联合守卫**（新增）——保证方 = 本限制 + 其他限制的合取。**不进删除候选**，改登记一条「联合防线条目」，写清参与者与各自份额，挂进双向保真步的「唯一防线吗」列。

**保证方栏改受控词表**：`物理` / `冻结数据（给路径）` / `本限制自己` / `另一条限制（给 id）` / `未知`。禁止自由文本——自由文本是这一格出错的载体。缺这一档时，两条互为保证的限制会各自独立被判成多余，两批分别删就双删了。

**触发器侧同表**（M-12）：必填「激活判据 + 观测点 + **到期日**」。无激活证据的触发器不得在本批收益论证里被当作收益。连续两批零激活 ⇒ 强制二选一：结构性不可达论证（进 L2 `kind: unreachability`）或退役提案。

**删除限制三签**（缺一不可）：可达性签（保证方为物理/冻结数据，附参数账指针）+ 拒真签（给出这条限制关掉的具体游戏合法实例）+ owner 签与 freeze-ritual。删除落地时**必须同时补一个反向哨兵，且必须是常驻回归测试**（不是一份论证，属第五卡点）。同一联合防线的成员**一批只能删一个**，删后必须重跑其余成员的尺子行（保证方已变）。

**验收**（新增，F-03②）：①批内引入/保留的限制清单与尺子行逐条对上；②每行保证方非空且取自受控词表；③判「限制成立」的行有代价列或标「非保守支」；④触发器行有激活证据或结构性论证 + 到期日。
**失败后果**：尺子表缺行 ⇒ 文书不得入库/外发；证明类结论出厂时缺行 ⇒ 证书降级 conditional。

### 4.4 前件卫生步

**职责**：让「漏前件」从「没想到」变成「表里有一行没回答」。**凭据**：`【前件表】` + `【覆盖层声明】`。

**七问**（前六问沿用，第七问新增）：

| 问 | 问法 | 命中样本 |
|---|---|---|
| 自由度问 | 结论里出现的每个量，是被前提钉死的还是仍然自由？维数多少？任何在推导中被当成常数的量必须证明它被前提钉死 | C-16 |
| 约定问 | 每一次「取 X」「按 X 约定」「不失一般性设 X」，是被迫的还是选的？选的就是前件 | C-14 |
| 量词问 | 每个「所有/任意/存在/唯一」的辖域是什么？举的例子会不会被读成界？ | C-18、C-51、C-27 |
| 语境问 | 这些前件在 certified 下 discharge 得了吗？P2.0 叙述层呢？exploratory 呢？ | C-25 |
| 权威问 | 每条前件的权威等级？出处形态是逐字代码/冻结件字节/转述/推导？ | C-26、C-01 |
| 使能问 | 有没有被标成「正交/仅为完整性/与本条无关」的条款，其实是本结论的使能条件？ | C-23 |
| **聚合问（新增）** | 本结论的每一份支撑复算（脚本/表格/手算路径），逐行列出其中每一处**把多个个体压成一个数**的操作（除以台数、取平均、取代表值、取最大/最小、按均匀分配展开、把向量当标量）。每一处都是一条前件，必须在前件表里有一行，并标「谁能违反它」 | **C-15**（`rate_lemma_recompute.py:34/37` `runs / machines`）、**C-16**（`split_free_probe.py:97` `duty[op]=x[op]/n_op`） |

**聚合问是本方案单位成本最低的一条加法**：它有界（脚本行数有限）、可机械起头（`/`、`mean`、`avg`、`/ len(`、`/ n_`、`sum(...)/`）、停机判据明确（复算工件每行赋值语句过一遍），而且一问同时命中 owner 第二枪的两个机位。前六问的六个动词（出现、取、量词、语境、权威、标注）没有一个会让人去逐行读复算脚本——而 C-15 的前件正活在那里，不带任何措辞，是一行无注释的算术。

**留白条款**：任何一问的答案是「三处权威源都答不了」，登记为留白并进裁决包，**不得由实现或推导代答**。

**覆盖层声明改为闭合枚举 + 三态勾选**（M-05）：

| 层 | 名称 | 死在这层的病例 |
|---|---|---|
| 1 | 几何层（格位、朝向、可放置性） | C-01 |
| 2 | 速率/计数算术层（本层内部算术正确性） | C-13 |
| 3 | **参数来源层**（本层用的每个数来自哪、谁钉死它） | C-15、C-16 |
| 4 | **语义锚点层**（规则文本读法、量词、例子 vs 界） | C-18、C-51 |
| 5 | 实现一致层（canonical 条款 ↔ 代码 call site） | C-08、C-02 |
| 6 | 方向暴露层（本结论过严/过松侧的暴露面） | X-1…X-9 |

每层勾「审了 / 明确没审 / 不适用 + 理由」，并写没审的层归谁。自由文本版本不可证伪：一个不知道某层存在的人，不会把它写进「没审」栏；有了闭合枚举，勾「审了」而实际没审是可指控的具体断言。清单 append-only 增长。

**refute 席五攻击面**（第 0 面新增）：⓪批型判定 / ①证据等级混用 / ②前件完备性（跑七问，产出复核行）/ ③覆盖层诚实性（对照闭合枚举）/ ④拒真面（举实例）。②的可执行形式：**对每条被当常数的量给出「它被谁钉死」的答案，答不出即 BLOCK**。

### 4.5 裁决包步

**触发**：批内出现真正只有 owner 能定的残余。判据：**答案在游戏里，不在仓库里**。答案在仓库里却上交 = 违规，先跑参数账三级阶梯。

**八件必备件**：①一句话游戏事实题；②参数账表（含 MISSING 与三级处置留痕）；③可达性尺子行（含判定与保证方）；④**两分支解空间账**（判 A 扔掉什么、判 B 扔掉什么，各带规模：实测/上界估计/至少一个实例）；⑤我方默认推荐 + 不答的默认动作；⑥证据等级标注；⑦影响面预跑（连锁重写名单法先跑一遍，只出名单不改东西）；⑧已做完的部分清单。

**验收**：出门前过 refute 席，固定检查项一条——**这包里有没有本可以自己算的**。裁决包是最典型的裁判自产文书。
**失败后果**：不成包，不上桌。
**反模式**：拿标签上交；拿不准就上交（无两分支账）；问题不是事实题；影响面栏空着。

### 4.6 连锁重写步

**五步**：①定位受损前提（原表述 vs 新表述的差在哪）；②机械求出引用者名单（六类）；③四态判定并逐项写新表述；④分层记账；⑤收口凭据。

**六类引用者**：canonical 条目 / 仓库内承重文书（`rg --no-ignore --hidden`，注意 `.rgignore` 藏 `docs/research/**/*.py`）/ 兄弟线净输入 / 代码 call site 与持久化结论（按八段 digest 判）/ 记忆卡 / **在飞的外部输入**。

**四态**：作废（理由 + 头部标记，不删史料）/ 成立但理由换了（新证明来源 + 强度变化）/ **需重验**（重验动作 + 负责人 + **到期日 + 阻断范围**）/ 不受影响（**一句话理由，不许空着**）。

**两处补装置**：

- **外发登记台账**（M-06，新建）：`包 id | 发出日期 | 收件方/会话 | 内含的冻结件快照及其 sha | 依赖的承重结论 | 状态（在飞/已回/已失效）| 失效通知日期`。首批数据用本批自己的 `.artifacts/gpt_pro_review_batch_20260807/`（4 份可发 + 1 份占位，含 canonical 快照）。第六类留痕改为「引用登记台账的行号」，不许写「无」而不给台账指针。
- **开放欠账台账**（M-07，新建，与批内连锁账分开）：`欠账号 | 到期日 | 负责人 | 阻断范围`。**阻断的牙齿**：欠账未清期间，依赖该语义面的证明类结论**不得出厂为无条件结论**，只能出 conditional 并在方向暴露栏标欠账号（与 SMM4 detached receipt 同型，本项目已验证过的形态）。收批席核逾期条数并上报（不是即阻断，避免瘫痪，但必须可见）。

理由：C-08 的名单是齐的（四个 call site 一个不少，行号都在），状态是「未修」——**C-08 从来不缺名单，缺的是把名单变成完成**。只出名单的连锁重写会重新产出一份今天已经存在的东西。

### 4.7 双向保真验收步

**职责**：公理 I 的流程落点。**凭据**：`【保真验收】` + 三张台账。

**两问（逐 guard / 限制 / 剪枝规则一次）**

- **问一：堵了哪些孔？**列出被拦下的非法形态；每种配一个变异自证（fail-closed 改 fail-open ⇒ 用例转红；文书型批转记欠账，N-07）；**附一列「唯一防线吗」**——答「唯一」的行是将来改动前必须先算清的。
- **问二：有没有把合法能力关在门外？**拒真面登记（字段见 §3.6）；**必须给具体实例**；**对称套用检查**——论证若被对称套用到另一侧（输入 ⇄ 输出、源 ⇄ 汇），必须分别给覆盖面与未覆盖面。

**搜索面留痕表**（F-03①，把空手而归变成有界断言）：

`能力轴（取自五路）| 是否探过 | 探法（探针/实例构造/判例）| 结论（无实例 / 有实例 / 未探及原因）`

「无候选」只有在全部轴标了状态时才算合法终态；有轴标「未探及」的，该批拒真结论标**部分覆盖**，未探轴写进证书的方向暴露栏。理由：现状下拒真席交白卷与认真找了一天产出同一份文书，没有任何字段区分「找过没找到」与「没找」——这正是本项目吃过的静默 skip 病。

**三类审计**（§1.5）

- **孔审计**：沿用现行 16 条防线。
- **墙审计**：按**能力/语义轴**分行，**禁止按公理分行**（按公理分行会系统性丢掉无对应公理的语义轴，连通性整轴就是这么消失的）。能力全集五路：实体自由度 / owner 裁决台账 / 模拟器判例 / 上游注册表 / 六谓词量词展开。**首轮范围显式声明为路 1 + 路 5 + 路 2（抽取后），路 3/4 标「本轮未覆盖」写进覆盖层声明**（N-03）。每条能力三态：可表达（给构造性实例）/ 不可表达（给机器证据，进拒真面候选）/ 未核（给探针，不许留空）。`out_of_scope` 必附「若该能力被表达，解空间会不会变大」，答 `yes` 的进 `not_verified` 计数。
- **界审计（新建）**：枚举面 = **所有 statement 断言了数值界或阻塞条件的条款**（今天十几条，有界可枚举）。每条一行：`界的表达式 | 到达侧参数 | verdict | 最近核算日期 | 谁在消费它 | open_premise_refs`。这是 X-3/X-9 的对症装置，也是箱案唯一能被更早抓到的路径。

**fail-closed 塌陷计数**（§7.3 + F-04）：每个 fail-closed 分支带计数器 + 理由码；收批时报「本批运行期塌陷次数 × 理由码分布」；**「零信号」判定改二选一必填**：`真零（有埋点，计数 = 0）` / `无埋点（欠账号 #N）`，禁止只写「零」。降级/剥落/取子集一律计入拒绝率，不许把拒绝转译成接受。埋点本身属第五卡点（§4.9）。

**验收**（F-03②）：①每个 guard 两问俱答；②问二有实例或有搜索面留痕表；③对称套用检查行在场；④fail-closed 计数报告在场或写明「无埋点 + 欠账号」。
**失败后果**：缺问 ⇒ 文书不得入库/外发；**证明类结论出厂时拒真侧未过 ⇒ 证书降级为 conditional 并在 ledger 标「exclusion 覆盖未建立」**。
**异源化**：拒真面登记的复核归收批席或 refute 席，不归拒真席自己。
**bootstrap 规则**（F-03b）：墙台账与界台账 v1 完成前出厂的证明类结论，其过严面栏强制写 `NOT_ESTABLISHED`（不许空、不许「无」），并进「待回溯核的证书」清单，首轮审计完成后逐条回扫。

### 4.8 饱和扫描步

**职责**：公理 II 的流程落点。**凭据**：`【饱和扫描收据】`。

**三层圈定**：层 0 种子集 = 本结论前提集 + 本批新入账的参数/规则；层 1 邻域 = 资源账邻接（九行账目行）+ 实体邻接（同实体/同商品/同端口/同谓词）；层 2 及以上只在层 1 产出新结晶时展开（回灌重跑），默认深度上限 3 轮，到顶未饱和则**登记「未扫尽」**。

**组合阶数**：只做 pairwise + 结晶回灌，不做全 k 元。塌点几乎总是两本账相乘/相除/取奇偶产生的（箱案 = 入量账 × 容量账；5 满 1 半 = 总量账 × 两档量化账），三元以上通过回灌后再 pairwise 达到。

**塌点三问**（逐自由量）：①v 的取值集合被前提约束成什么（连续区间/多胞形/有限档/单点）？②两本账组合后是否降维（连续→有限档、有限档→单点、集合→空集）？③降维后是否结晶出可直接查的结构特征？**②发生的地方必须显式上报**，哪怕当前用不上。正结晶（新结构特征）与负结晶（危险条件塌成空集）都要报，**负结晶直接喂给可达性尺子步与界审计**。

**产出登记**：一律进 L2 `rules/derived/`（单一家，M-08），状态 `UNREVIEWED`，须过拒真/反例席才转 `ACTIVE`（§1.4）。

**停机判据**：一轮 pairwise 零新结晶 = 饱和；深度到顶 = 未扫尽。`saturation_runs[]` 记 `{scope, started, rounds, new_entries[], reviewed_count, terminated_by}`；**`terminated_by: budget` 不得被引用为「已饱和」**。

**验收**：收据含层 1 全集清单；有关对逐条判定，无关对以补集形式表达（完备性由全集清单保证，不由 200 行「无关」保证，M-13②）；停机判据到没到写明；未判条数进方向暴露栏。
**诚实边界**：扫描跑在算术层，几何层（带子能不能拐、格位够不够）扫不出；需要游戏实测的语义、需要仓库外知识的同样扫不出。收据必须写明「本轮扫描的层」——这本身就是覆盖层声明的一个实例。

| 前件表（含聚合问） | ≈15–20 分钟/承重结论 |
| 覆盖层声明 | ≈2 分钟 |
| **双向保真**（补） | ≈15 分钟/guard（含实例搜寻）+ 搜索面留痕表 10 分钟/批 |
| 饱和扫描 | **按对计价** 20–40 秒/对；层 1 全集清单另计 |
| 连锁重写 | 按引用者数量 |

规则修订批（六步触发）粗算 **5–7 小时纯凭据工时**，token 侧单批新增读入 100–300K。**这两个数字是【推导】不是【实测】**，首三批实测后校准。

**轻量档**（有牌可打的降级比无牌可打的全套更可能被真的执行）：凭据只填必填格、饱和扫描只跑一轮 pairwise 不回灌、拒真侧只填搜索面留痕表不做实例构造。**轻量档批不得出厂证明类结论**，只能出叙述层结论。

**四条反退化条款**：触发矩阵是硬的（不满足触发条件的步不许要求填，也不许「顺手都填一下」）；每步给预算且节尾记 `耗时/填表人`（N-06 给了数据源）；退化信号常设监测（某步连续三批「不适用」> 70% ⇒ 触发条件回炉；同一句理由跨批复制 ⇒ 收批席抽查）；**加不出停机判据的检查不许进**。
