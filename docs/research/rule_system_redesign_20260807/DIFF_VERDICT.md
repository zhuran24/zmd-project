### 分歧 1 — `semantics` 区是否留在冻结件里　~~**推导版胜**~~〔R3：**胜负撤销**，见上表；本节以下为原文，作证据保留〕

病例驱动版把公理与全部条目留在 `rules/canonical_rules.json` 的 `semantics` 区（L1，冻结），代价是四个 freeze-ritual 批（批 2/3/4/7），每批要做八段 byte-identical 断言、17 处直接 pin 与四条连锁链。推导版 §1.8 判：机器消费的冻（参数），不可重推的记版本（公理），可重推的不冻（定理）——公理层需要的是**自己的版本号与哈希**，不是与机器输入同锁一个文件。

判据不是偏好，是病例驱动版**自己的论证的一致外推**：它用"进冻结件 ⇒ 每次改动付 ritual 底价"这条理由把 `consumers[]`（D-03）和拒真席收件箱 `candidates`（D-04）赶出了 canonical，却没有把同一条理由用在 `semantics` 区本身。更强的内证是它的**八段 digest**：持久化结论的失效戳被刻意定义为"canonical 除 `semantics` 外的八段"——即它自己认定，结论的正确性依赖的是那八段，`semantics` 不在其中。既然如此，把 `semantics` 与那八段锁在同一个字节里就没有承重作用，只有成本。

**反向权衡（诚实记录）**：拆出去意味着多一条 pin 继承链（C-49 的病），且 `semantics` 是 owner 裁决的落地处，冻结件身份有"不可悄悄改"的治理价值。推导版的答复是拆出去的文件**照样自带 sha pin**——变的不是"冻不冻"，是"改一条定理要不要连带重钉候选池那条链"。这一改动改变裁决权威的载体，属 owner 决策项。

> **〔R3 块，B4 / 核签书 §11〕本分歧的胜负撤销，且成本论证的两个前提被实测推翻。**
>
> **① 本文的理由②作废（循环论证）**：本节用"八段 digest 刻意排除 `semantics` ⇒ FINAL 自己认定结论不依赖它"当内证。**那是 FINAL 的一次设计选择，不是"结论不依赖语义"的证据**；BLOCK-12 恰好证明**该排除本身是个洞**（语义变而戳不变，旧持久化结论静默存活）。**理由①存活**：FINAL 的内部不一致是真的，仍支持"按成本考虑拆"；但内部不一致只能证明 FINAL 不自洽，**不能证明拆是安全的**。
>
> **② 上一段"改一条定理要不要连带重钉候选池那条链"这句话——那条链本来就不会被语义改动触发。**`scout_pin_chain.md` §2 项 5 实测：`mandatory_exact_instances` / `generic_io_requirements` / `candidate_placements` / `current_preprocess_context` **近两批均未变**，因为只有 `recipes` / `production_targets` / `facility_templates` / `globals` 进 preprocess。**拆分实际省下的是 17 处 pin 的重钉与 Chain B/C/D 三条连锁，不是派生工件重生成——省的量比本节描述的小一档。**
>
> **③ 拆分不减少 pin 数，它增加 pin 数。**若 `semantics` 搬出去且要保持"不可悄悄改"的治理价值，新文件必须自带 pin：进 `FROZEN_ARTIFACTS` ⇒ Chain C 再次触发；进 `certified_artifact_contract` ⇒ Chain B 再次触发；13 处文档 pin 表各加一行。**拆分本身是一次完整 ritual，且此后每次改语义仍要付"新根进证书"的代价——除非新根由机器生成的依赖根机制绑定，而不是由手工 pin 绑定。**
>
> **④ 因此有第三条路，两版与份 5 外审都没考虑**：**不拆 + 用 canonical 整文件 sha 补依赖根**。它零迁移成本、当场堵上 BLOCK-12（整文件 sha 天然含语义），代价是"对数学征税"继续存在。份 5 外审把问题做成了"拆（带原子根）还是不拆"的二分，是因为它没拿到 pin 链实测。
>
> **⑤ 核签的默认推荐（仍属 owner 决策，本文不代拍）**：**无论拆或不拆，先做传递依赖根**；否则拆分只是把 17 处手动 pin 复制成两套手动 pin，而 ritual 全程无自动化脚本。排期建议：传递依赖根 → 观察一个 canonical 批的实际成本 → owner 拿**实测**数字决定拆不拆，而不是现在拿推导数字决定。三个选项的完整对照（含各自的新增风险与 schema 逃生舱兼容性）见核签书 §11.4。

### 分歧 2 — 第三类审计审的是什么，以及它怎么被触发　~~**推导版胜**~~〔R3：**胜负撤销**，见 §2 头部重判表；可达性投影视图应标 `GENERATED_PROJECTION` 保留，不删〕

两法都叫它"界审计"，审的对象不同：

- 病例驱动版：**在册限制的数值界在物理参数下够得着吗**，枚举面 = 所有 `statement` 里含"当且仅当 / exactly when / blocks when / triggers when / fails when"形态判据的条款。
- 推导版：**命题陈述的范围限定条**（§1.7 界）。而"界够不够得着"在推导版里不是一类审计，是**正当表每一行蕴含步骤的必填栏**（补-5）。

推导版胜在两点。其一，**触发条件从词形改成角色**：按措辞触发是脆弱的，同一件事换个写法就逃逸，而病例驱动版自己在 §7.1 已经注意到原稿"三步独立命中"不成立，部分正是因为三步悬在同一个词形判定上。按角色触发（凡被用来正当化一条限制的命题）与措辞无关。其二，**范围更准**：作为表行的必填栏，它出现在且仅出现在承重的地方；作为独立台账，它既会收进没人消费因而不威胁任何结论的界，又会漏掉承重但措辞不含关键词的界。

同时推导版的"界"（命题的范围限定）在病例驱动版里没有对应的审计位——它散在 `scope` 字段、`dischargeable_in` 与 conditional 证书里。**建议：改名并合并**——可达性核算并入正当表的蕴含栏；"界审计"这个名字留给命题范围限定条的审计。

### 分歧 3 — 推理纪律的形态　~~**病例驱动版胜**~~〔R3：**胜负撤销，两边都不全对**——原判把"收有界工具"与"删无界义务"绑成了一个包；处方 = 准入四态，见两稿 R3·B3〕

推导版原本主张：纪律只有一条公理加五条推论，**推得出来的东西不必单独写下来**（现推即可）。这一条被 C-15 直接证伪——全文前件写得最显式的那条引理，六轮逐行审查仍漏掉一条前件。无界的义务（"核所有前提"）在实践中必然退化，这正是病例驱动版 K-4 有界性要求的内容。

推导版已按此修正（§1.9 现行版）：准入判据改为**两问三格**——推不出来的删；推得出来但没有停机判据的删（它只是把公理换个说法）；推得出来且有停机判据的**收**。第三格是纪律正当的增长方式。按这个判据回看病例驱动版的工具，逐条都过：聚合问（有界：脚本行数）、闭合层枚举（有界：六层）、九行账目对表（有界且 append-only）、保证方受控词表六选一、搜索面留痕表——**它们不是清单膨胀，是有界工具**。推导版原来的反清单论证会把它们全部误杀。

这是本次对勘里推导版唯一实质性落败的一点，也是最值得记的一点：**"能推出来"不等于"不用写"，因为要人现推的那一步正是人会漏的那一步。**

### 分歧 4 — 有没有一张按模型约束分行的表　~~**推导版胜**~~〔R3：**方向维持，胜负措辞撤销**；且**正当表可以先建**，行判读暂停在"未清欠账"，不必等 WLOG 组合定理〕（结构差异里最重要的一条）

病例驱动版的三张台账，**行集全部在游戏侧或条款侧**：孔审计按现行防线，墙审计按能力/语义轴（五路：实体自由度 / owner 裁决台账 / 模拟器判例 / 上游注册表 / 六谓词量词展开），界审计按带数值界的条款。`model_faces` 只登记**已经被发现并经 owner 裁定**的过严/过松面，是发现物的登记册，不是模型约束的全集索引。

于是"这条约束，谁正当化它"这个问题**在病例驱动版里没有一个常驻的行集来问**。它靠批次触发补：改动触及守卫文件集时勾选"本批新增过严面：有/无"（D-19），生成器/剪枝批必跑双向保真（§4.1）。批次触发覆盖的是**新改动**，覆盖不了**存量**——而 C-04（生成器过剪 3,096 个合法 pose）与 C-20（219 台制造机每个输出口的对称过严）都是存量，都靠人偶然发现。

推导版 §1.7 的正当表把每一条塑造可行集的决定（含候选池生成期剪枝、预处理定死的实例集与需求量、目标与 admissibility 的编码）都排成一行，判读非"等价"的行即欠账，由 §2.3 的双射检查保证行集与代码里的约束一一对应。这正是 §1.7 那条推论要的效果：**生成期剪枝不长得像约束，把它排除在行集外就等于给这一类事故留永久盲区。**

代价是唯一一项代码侧要求：约束要有**声明在施加处的稳定编号**。病例驱动版 D-09 的顾虑（"参数 → 代码 call site"不可靠机器求出，拼接字符串骗过 grep、`.rgignore` 藏活代码）在这里不适用——编号是**登记**出来的，不是扫描发现的；而它自己的 `implementation_anchors[]` 是同一个机制的另一侧写法，两者可以合并成一件事。

> **〔R3 块，B4 / 核签书 §7.2〕方向维持，但"胜"字撤，且要拆开外审列的三个条件。**外审给正当表列了三个前置条件，核签逐条判：**"约束全集可独立枚举"（BLOCK-06）与"投影关系已定义"（BLOCK-03）是真前置**；**"WLOG 可组合"（BLOCK-04）是下游**——它决定的是"逐行全绿能不能读成完整性"，不决定"要不要建这张表"。**所以正当表可以马上开工，行判读暂时全部停在"未清欠账"。**外审把三个条件并列，会把一件能马上开工的事排到三项重写之后。
>
> 另：本节说的"由 §2.3 的**双射检查**保证行集与代码里的约束一一对应"——按核签书 §4.2 对 C-31 的判读，**双射跑在两侧的声明之间，两侧共同遗漏则双射照过**，它的强度是 `DETECTS_IF_REGISTERED` 而不是结构性保证。要把它抬到无条件，靠的是**统一登记接口自动发号**（挂批 C），而**生成期剪枝那一级不可自动发号**——正是本节最看重的那一类。

### 分歧 5 — 登记一个过严面是否以"举得出实例"为前提　**各占一半**〔R3：判读维持；**外审漏读了三签里的可达性签**，见节末 R3 块〕

病例驱动版：拒真席的产出必须是"候选过严面 + 一个游戏合法但被模型拒的具体实例"，`excluded_game_legal_instance.kind = "none"` 的不得进 `stricter`，只能待在收件箱。这条防的是 C-10（把正确的保守编码误判为保真缺口，整份分析一天内作废），有效。

推导版判：**放开动作要实例——收敛；登记要实例——分歧，推导版胜。**理由：正当表的行**由约束的存在自动产生**，与有没有人找到见证无关；找不到实例只是让该行的判读停在"更严·未清欠账"。把登记本身押在见证构造的难度上，会让"见证难构造的真过严面"被归档成不存在——而见证难构造恰恰是几何类过严面的常态。病例驱动版自己用搜索面留痕表（F-03）缓解了"空手而归 = 零成本合法终态"，但缓解的是席位的诚实度，改不了"登记以实例为条件"这个门槛。

反过来，**放开（删限制、松编码）是健全性方向的动作**（§1.3：过松直接产假见证），按健全性标准立论、要求具体实例是对的。病例驱动版的三签（可达性签 + 拒真签 + owner 签与 freeze-ritual）在这一侧完全成立，推导版照单接受。

> **〔R3 块，B4 / 核签书 §8.1〕判读维持，但要订正外审对三签的读法。**份 5 外审判"一个合法被拒实例不能证明删整个 guard 是 sound"，并要求提交穷举 proof object 或精确终审 checker（P-06）。**数学点成立，但它只读了三签里的拒真签，漏读了可达性签**——"保证方为**物理/冻结数据**"按 `FINAL_DESIGN.md` §4.3 判定 2 的定义就是**危险不可达**，那是一条**从物理参数出发的全称论证**，不是实例。所以我方的三签不是"三个实例级签名"，它有一条全称腿。
>
> **真缺口比外审描述的窄**：可达性签证的是"危险条件不可达"，只有当 guard **恰好只挡该危险**时才等价于 `∀g ∈ Δ, GameLegal(g)`；guard 比危险粗时，`Δ` 里可能含与该危险无关的非法状态。**因此修法也便宜得多**（挂批 C）：把可达性签的义务从"危险不可达"改写成全称式 `∀g ∈ Δ, GameLegal(g)` 并要求写明 `Δ` 的定义；删 guard 时**强制重跑执行表里该 guard 曾出现在"强制它的约束编号集"栏的每一行**——**这个行集推导版 §1.7 已有，不需新建装置**。P-06 的"穷举 proof object"对本项目过重（几何类 `Δ` 不可穷举）。

### 分歧 6 — 派生层怎么"跑"　**互补，不判胜负**〔R3：判读保留，**补一条限制：pairwise 不是停机判据**，见节末 R3 块〕

病例驱动版给的是**搜索程序**：层 0 种子 = 本结论前提集 + 本批新入账项，层 1 = 资源账邻接（九行账目）+ 实体邻接，只做 pairwise + 结晶回灌，深度上限 3 轮，停机 = 一轮零新结晶。推导版给的是**优先序**：工作队列由两张表的非干净行生成，每条脏行就是一个精确陈述的数学任务。

两者管的是不同的东西，合起来才完整：只有优先序没有程序，"去证一条 WLOG 定理"不知从哪下手；只有程序没有优先序，扫描会自我繁殖（这一点病例驱动版自己在 §1.4 反向刹车里承认，并用 `UNREVIEWED` 状态机堵）。附带一处一致：推导版的"盯零余量的账"与病例驱动版的"塌点几乎总是两本账相乘/相除产生"是同一个观察的两种说法。

> **〔R3 块，B4 / 核签书 §5 与 §7.2〕"互补"这个判读保留，但本节漏判了一件事：pairwise 不是停机判据。**上一段照抄了病例驱动版的"停机 = 一轮零新结晶"而没有攻它。**三前提反例平凡**（`x≥0, y≥0, x+y≤−1`：任意两条的可行域都是二维非空 ⇒ 一轮零新结晶 ⇒ 按文本停机报"饱和"；三条合取为空 ⇒ 漏掉的正是最强的负结晶），**回灌也救不了**（回灌的输入是"新结晶"，反例里一对都没有 ⇒ 回灌池为空）。
>
> **加重一条**：病例驱动版自己的旗舰样板 **5 满 1 半条件定理**是**五前提塌点**——**设计的旗舰案例本身就在 pairwise 的可达范围之外，而设计却用 pairwise 当停机判据**。三前提结晶不是构造出来的病理例，它是这个项目已经发生过的类。处方见 `FINAL_DESIGN.md` §4.8 的 R3·B1 改写（状态改 `PAIRWISE_FIXED_POINT_INCOMPLETE`；承重闭包结论交对相应理论完备的求解器取 UNSAT core / proof object，**本仓现成载体 = `certside/sidecar/runner.py` 的 veripb 链**）。

### 分歧 7 — 问题层（我们在证什么）是否独立成层　**方向维持**〔R3：**八项里唯一维持的一项**；"胜"字仍撤（无独立性载体），并补 `TARGET_CLAIM` / `PROVED_CLAIM` 双对象，见节末 R3 块〕

病例驱动版的 L0 叫"求解器事实"，内容是 `globals` / `facility_templates` / `recipes` / `production_targets` / `commodity_metadata` / `routing_rules`，权威写作"owner 游戏实测 > 模拟器规则层"。这一层里混着两类完全不同的东西：

- `globals.empty_rectangle.objective` 与 `min_side_admissibility` 是**我们提的问题**，不是游戏的性质。游戏不关心你在地图上划的那个框。
- `routing_rules.layers = {ground:0, elevated:1}` 是**模型编码**——同一份文件的 `routing_cross_junction` 条目明写它是"a MODELING representation of a single-cell cross-junction"。把它冻在"求解器事实"层并标注权威为 owner 游戏实测，是一次类型错误，而且是这份文件自己写了一条条目去纠正的那次误读。

推导版把问题单列为 `PROBLEM_CLAIM`〔R3 类型名，原写"L0"〕（§1.2），把模型编码归到正当表的模型侧栏（§2.5 归位表）。这不只是整洁问题：**P2.0 要把流量纳入 Q**，届时问题变、公理不变（§1.2 推论：公理不设范围，命题才设范围）。分层正确时这是改一份文书；分层混着时要逐条款重议 scope。

### 分歧 8 — 运行期计量的地位　**框架维持，机制吸收病例驱动版**〔R3："胜"字撤；**外审后半的"连续两批零只触发调查优先级"拒收**，见节末 R3 块〕
