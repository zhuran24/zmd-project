## 0. 出发点与推导原则

推导只从两样东西出发：

1. **对象是什么**——游戏是一个形式系统。

## 1. 推导

### 1.1 对象：形式系统 = 参数 + 行为公理

游戏这个形式系统由两样东西完全确定：

- **实体集与参数**：有哪些种类的东西（机器、带、桩、核心、箱、口），每种带哪些有限个数值参数（尺寸、口数、覆盖半径、配方时长、缓存槽数）。
- **行为公理**：这些东西怎么动——机器怎么吃怎么产、带怎么运、口怎么裁决收不收、电怎么供。

这两样是**唯一的经验层**：它们不能从任何东西推出来，只能由游戏本身给定（owner 游戏内实测、上游模拟器规则层、游戏定义）。其余一切关于游戏的真命题都是这两样的推论。

这不是一个选择，是"形式系统"这个词的内容：一个形式系统 = 签名 + 公理，别的都是定理。

**〔R3 补·OBLIGATION，P-01 改造后收 / BLOCK-01〕参数表是投影，不是语义本身。**原文说这两样"完全确定"游戏，读起来像是在断言**实体参数表足以表达全部经验事实**。这一步没有依据：参数表是权威游戏语义的**一种投影**，它只承载被我们建模到的那些维度。所以：

- 引用一条参数或公理时必须带**游戏 build 版本**（哪一版游戏的语义）；不同 build 的同名参数是不同的经验输入。
- "参数表覆盖了该实体的全部相关行为"是一条**关于游戏的结论**，按 §1.5 只能由经验依据担保，具体机制见补-2 的外部枚举源与覆盖率账。参数表本身**不能**自证它足够。

> **本席对 P-01 的改造（核签书 §10 A6）**：外审原文要求"权威游戏语义以版本化的操作语义给出：签名、状态空间、初始条件、转移/观察关系、随机性或调度语义"。**这一整套不收**——本项目并不需要、也没有资源建一份可执行的游戏操作语义，把它写成前置义务等于制造一条永远不清的欠账（违反补-12：无法被执行的义务不产生依据）。收下的只有上面两条：投影关系与 game build 版本。

**第一个推论**：**关于游戏的知识只有两类——输入与推论**。任何一条声称是"游戏事实"的话，要么指得出它是哪个参数/哪条公理，要么给得出从参数和公理出发的推导。第三类不存在。

### 1.2 问题决定理论的边界，游戏不决定

我们不需要把游戏整个形式化，只需要能判定我们要问的问题。所以先把问题写清楚。

要证的命题形如：

> 在游戏规则下，满足〔266 个 mandatory 设施合法布置 + 达成产能目标〕的所有布局中，空矩形的 `max_lex(area, min_side)` 等于 `(A*, s*)`。

这里出现的每样东西都要有定义：什么叫"合法布置"、什么叫"空"、什么叫"达成产能目标"。这些定义不是游戏给的，是**我们提的问题的一部分**。例如"空矩形里不能有任何东西"（2026-08-05 owner 裁决）不是一条游戏机制——游戏不关心你划的那个框——它是我们问题里"空"这个词的定义。

**推论（问题层独立）**：问题（objective、admissibility、被问的量的定义、被要求达成的产能）是一个**独立于游戏公理的层**。它不需要游戏来裁决，需要 owner 来定义；改它不改任何游戏事实，但改掉一切结论。

**推论（公理不设范围，命题才设范围）**：因为问题会变（P2.0 要把流量纳进来），而游戏不会变，所以**公理层不应该按当前问题裁剪**。速率公理即使当前问题用不上也要在册；用不上这件事写在**命题的范围限定**里，不写在公理的取舍里。这样问题一扩大，公理层零改动。

反面：如果按"当前不需要流量"把速率从公理层砍掉，P2.0 开工时要重新找 owner 裁决一遍已经裁过的事。

### 1.3 双向保真：目标的推论，不是独立发明

模型定义了自己的合法性谓词 `ModelLegal`，游戏有 `GameLegal`。模型算出的是

  `max_lex over { m : ModelLegal(m) }`

要它等于我们真正要的

  `max_lex over { g : GameLegal(g) }`

**〔R3 改写·OBLIGATION，P-04 直接收 / BLOCK-03〕这两个 max_lex 跑在两个不同的对象空间上**：`m` 是一个**完整模型赋值**（含全部辅助变量——路由的两层表示、binding 的端口分配、所有中间量），`g` 是一个**游戏状态**。两者之间没有天然的包含关系，"集合包含"在这里**无定义**。所以第一件要写下来的东西不是包含式，是**投影**：

> 设 `G` = 权威游戏状态空间，`M` = 完整模型赋值空间，**`π: M → G`** 是一个经版本化定义的投影（把模型赋值抹去辅助变量后落到游戏状态）；`Obj_G` 与 `Obj_M` 分别是两侧的目标。

在此之上，双向保真是两条**量化义务**：

| 义务 | 形式 | 失守的后果 |
|---|---|---|
| **健全性**（模型不比游戏松） | 对任意 `m`：`ModelLegal(m) ⇒ GameLegal(π(m))` **且** `Obj_M(m) = Obj_G(π(m))` | 见证是假的 ⇒ **下界失效**（"这个值达得到"是假的） |
| **完整性**（模型不比游戏严） | 对任意 `g`：`GameLegal(g) ⇒ ∃m，ModelLegal(m) ∧ π(m) = g ∧ 目标保持` | 可能把最优解砍掉了 ⇒ **上界/最优性失效**（"不存在更好的"是假的） |

**为什么必须写成投影而不是包含——三种失败模式在包含式里根本区分不开**，而这三种在本项目里都真实存在：

| 失败模式 | 它是什么 | 在案实例 |
|---|---|---|
| **无辅助见证** | `g` 游戏合法，但**找不到任何**模型赋值 `m` 投影到它（辅助变量凑不出来） | 路由的两层表示与 binding 的端口分配都是辅助结构；某个游戏合法布局可能在这些辅助结构上无解 |
| **投影非法** | `m` 模型合法，但 `π(m)` 不是游戏合法状态 | 健全性方向的孔 |
| **目标不保真** | `π` 保持合法性但**不保持目标值**（`Obj_M(m) ≠ Obj_G(π(m))`） | `max_lex(area, min_side)` 在投影下是否不变，本文书此前从未陈述为一条义务 |

若使用 WLOG 缩约，还要另给正规化 `N: G → G`，并证明 `GameLegal(g) ⇒ GameLegal(N(g))`、`Obj_G(N(g)) ≥lex Obj_G(g)`，以及存在 `m` 投影为 `N(g)`（细则见 §1.4 处置 1 的 R3 改写）。

**所有执行表、正当表和覆盖账都是这两条量化义务的索引**，`不得`把"表已填满"或"表行全绿"写成"量化命题已证明"。表是义务索引，不是证明。

> **superseded（R3 20260807，份5外审+核签，BLOCK-03 / A1）**：本段原写"需要两个包含方向"，并用一张表列 `Legal_model ⊆ Legal_game` 与 `Legal_game ⊆ Legal_model` 两个方向，把量词统一跑在"布局"上。份 5 外审 BLOCK-03 指出这是把两个不同类型的对象空间当成同一个集合；核签书 §3.1 判**全额 ACCEPT**（数学事实），并指出同一文书 `§2.5 归位表`自认 `routing_rules.layers` 是模型编码而非游戏参数——模型赋值含辅助变量，包含关系无定义。旧表的**内容判读**（哪个方向伤哪一半结论）不变，变的是命题的**类型**。

owner 的双向保真公理是这两条量化义务的内容，不是一条外加的偏好。

**这里推出一条与工程直觉相反的结论**：**过严不是"保守安全"**。过严对见证安全，对最优性致命。而本项目的目标恰恰是最优性，且按 owner 口径不设降级退路——所以每一个"为了保险起见把模型收紧一点"的动作，都是在直接削弱要证的那个命题。

这条结论直接指认了 owner 诊断的"发布面 fail-closed 文化漏进数学面"的**具体机制**：在发布面，遇事收紧＝拒绝发布＝安全；在数学面，遇事收紧＝命题变假。同一个动作在两个面上符号相反。**这就是为什么两个面必须分开，而不只是"风格不同"**。

在案实例：`canonical_rules.json` 的 `semantics.axiom_kernel.model_stricter_faces` 把"模型比裁决语义更严"的面登记为 *all conservative, never unsound*。这句话在健全性方向上对，但它是**单方向读数**：每一处都是最优性方向上的一笔欠账，而最优性正是项目的头条命题。

> **〔R3 实测订正〕**：原文写"**三处**面"。本席逐字读该字段（类型为 `str`），实际登记**四处**：① sink-front 单商品排他、② source-front 同款排他、③ routing 复验的额外 no-orphan / selected-source-reaches-sink、④ binding slot-single-commodity。其中 ④ 已由 `port_commodity_scope` 走 §1.4 处置 2（缩范围）处理，**未清的是 ①②③ 三处**——原文的"三处"应读作"未清三处"，不是"登记三处"。这三处的 WLOG 组合欠账见 §1.4 (R3-A2) 末段。同一份文件里的 `port_commodity_scope` 条目做对了（它不说"保守"，它说"认证命题是在'每个仓储线口只走一种商品'这个游戏片段上做出的"——即缩小命题范围），`rate_lemma_scope` 的 usage_rule 也做对了（要把过严读成 without-loss-of-generality 必须引用该条并逐条兑现前提）。同一份文件里同时存在正确处理和单方向读数，且格式上看不出区别——这是格式的失败，不是作者的失败（见 §1.6）。

### 1.4 保真缺口的三值账

由 §1.3，模型与游戏每有一处不一致，就要问它伤哪个方向、怎么补。补法只有有限几种，逐个推出来：

**模型更严（伤最优性）**，三种处置：

1. **已证 WLOG（R3 改写，见下）**：证明"任何合法布局都存在一个不劣的、且满足这条更严条件的布局"。这是一条**定理**，要有证明。**但一条这样的定理只清掉这一行的账，清不掉全局**——见 (R3-A2)。
2. **已缩范围（R3 改写，见下）**：不证 WLOG，改而把要证的命题限制到满足该条件的游戏片段上。这是诚实的，但**它改的是命题本身**——所以这个限制必须出现在命题的正式陈述里，不能只写在附注里。**且它只许改 `PROVED_CLAIM`，不许改 `TARGET_CLAIM`**——见 (R3-A5)。
3. **未清欠账**：两样都没做。此时最优性命题是**有条件的**，条件就是这处更严不咬最优解，而这一点没有被证明。必须如此标注。

#### (R3-A2) 逐行 WLOG 不能自动合成为全局 WLOG　〔P-05 直接收 / BLOCK-04·OBLIGATION〕

> **superseded（R3 20260807，份5外审+核签）**：原处置 1 只写"证完之后缺口消失，最优性完好"。这句在**单行**上对，在**全局**上是假的，而正当表逐行清账正是要推出全局完整性。

反例是平凡的：约束 `M1` 只允许布局形态 `a`、约束 `M2` 只允许形态 `b`，每条**各自**都能证 WLOG（"任何合法布局都存在一个不劣的、满足 `M1` 的布局"；`M2` 同理），但两条同时启用后可行集为空。**逐条 WLOG 的合取不是 WLOG。**原因是每条 WLOG 各自给的正规化 `N₁`、`N₂` 互相破坏对方建立的性质。

于是每条 WLOG 行必须登记三个新字段，且全局清账另有一条独立义务：

| 字段 | 内容 |
|---|---|
| `wlog_bundle_id` | 该行属于哪个 WLOG 束（同时启用的 WLOG 归一束） |
| `normalizer` | 这一行用的正规化 `N` 是什么（`G → G` 的具体映射 + 目标保持证明） |
| `preservation_set` | 该 `N` 保持哪些已经建立的性质（即它不破坏束内哪些行的结论） |

**全局清账只在下列任一条件成立时允许**（三选一，`OBLIGATION`）：

1. 给出一个**联合正规化** `N`，同时满足该束内全部额外约束；或
2. 给出**有序正规化** `N₁…Nₖ`，并逐步证明 `Nᵢ` 保持所有已经建立的 `M₁…M₍ᵢ₋₁₎`；或
3. 直接证明：对每个游戏合法的 `g`，存在一个不劣的模型见证满足**全部已启用**约束。

**单行 WLOG 只能把该行标成 `LOCALLY_WLOG`，不能把全局完整性欠账清零。**正当表的"更严·已证WLOG"判读因此拆成两级：行级 `LOCALLY_WLOG`（有 `normalizer` 与目标保持证明）+ 束级 `BUNDLE_CLEARED`（三选一之一已兑现）。**只有束级清账才允许把"逐行全绿"读成完整性**（与 §1.3 R3 改写的最后一句同一条纪律）。

**在案欠账登记（本文书只登记，不改 canonical；改动挂 freeze-ritual 批）**：`rules/canonical_rules.json` 的 `semantics.axiom_kernel.model_stricter_faces` 登记了四处"模型比裁决语义更严"的面——① sink-front 单商品排他、② source-front 同款排他（owner 08-06 已确认为过严面，解锁另批）、③ routing 复验的额外 no-orphan / selected-source-reaches-sink 条件、④ binding slot-single-commodity（已由 `port_commodity_scope` 走处置 2 缩范围）。**①②③ 三处面各自的"已证 WLOG"路径上都缺组合腿**：该字段整体只写了一句 `all conservative, never unsound`，既没有 `wlog_bundle_id`，也没有任何一条陈述说明三处正规化互不破坏。**一旦三处各自补上 WLOG 定理并宣布清账，组合问题当场为真，且现行机制不会发出任何信号。**这条欠账应立刻进 `model_stricter_faces` 的台账，不必等本设计落地。（核签书 §3.2 与 §9 重写① 的"立即可做的一件"。本文书实测：该字段类型是 `str`，四处面写在同一句散文里——这也是它装不下 `wlog_bundle_id` 的物理原因。）

#### (R3-A5) 缩范围只许改 `PROVED_CLAIM`　〔P-08 直接收 / BLOCK-07·OBLIGATION〕

> **superseded（R3 20260807，份5外审+核签）**：原处置 2 只说"这个限制必须出现在命题的正式陈述里"。问题是本文书**只有一个命题对象**，所以"把限制写进命题"这个动作会**直接改掉那个命题**——未修的墙被洗成一条较弱的、当前已证的命题，原来的目标从台账上消失。这与 owner"目标不设降级退路"的口径直接冲突。

R3 起每次认证同时绑定**两个不可混淆的对象**：

| 对象 | 内容 | 谁能改 |
|---|---|---|
| **`TARGET_CLAIM`** | 项目原始要证明的命题（全局 `max_lex(area, min_side)` 最优，无范围限定） | **只有 owner 明确替换项目目标时**才可另发版本；旧目标**不得被覆盖** |
| **`PROVED_CLAIM`** | 当前模型实际证明到的命题（带全部范围限定条） | 缩范围动作改这一个 |

两者之差登记为 **`ClaimDelta = TARGET_CLAIM − PROVED_CLAIM`**：

- 每一次缩范围**生成或扩大一条 ClaimDelta 条目**，对应的墙在 `TARGET_CLAIM` 台账里继续保持 `OPEN`；
- 证书状态因此为 `PARTIAL` 或 `CONDITIONAL`，**并在首页显示 ClaimDelta**（不是脚注）；
- 处置 2 与处置 3 的差别因此变成"欠账登记在哪一栏"，而不是"命题还在不在"。

这条与 §1.4 末尾的推论（缺口台账是命题的一部分）是同一件事的两面：那条说欠账清单要与命题一起被引用，这条说**被缩掉的那部分不许从台账上消失**。

**模型更松（伤健全性）**，两种处置：

1. **已证无害**：证明多认的那些布局其实也合法（即公理层没有禁止它）。
2. **下游兜底**：由一个精确的终审复核官在链条末端把多认的挡回去。此时"多松"只是求解中间态，不进结论。

没有第三种。特别地，"更松但我们觉得不会发生"不是处置。

**推论（缺口台账是命题的一部分）**：既然未清缺口把无条件命题变成有条件命题，那么**当前所有未清缺口的清单就是命题前提的一部分**，必须与命题一起被引用。一个证书如果不带这张清单，它陈述的命题就比它实际证到的强。

### 1.5 三种依据，各自只能得出自己那侧的结论

要做 §1.4 的账，必须同时说游戏侧和模型侧的话。这两侧的知识来源不同，混用是本项目历史上最贵的错误类型之一。逐个数清楚，**依据只有三种**：

| 依据 | 形态 | 只能得出 |
|---|---|---|
| **参数/公理引用** | 指向某条在册参数或公理 | 关于**游戏**的结论 |
| **实物观察** | 亲自读源码 / 亲自跑出来的结果，收据是 `file:line` 或运行输出 | 关于**模型（我们的实现）**的结论 |
| **推导** | 从已引前提出发的推理 | 前提所允许的结论 |

三条推论直接掉出来：

- **(依据-1)** 关于游戏的话，不能用"代码里是这么写的"来支持。代码写成什么样是关于我们的事实，不是关于游戏的事实。
- **(依据-2)** 关于模型的话，必须在源头观察，**转述不算观察**。一份收据里的"该函数的语义是 X"是作者对代码的转述；引用它等于做了一步推导而前提（"转述忠实"）没有依据。
- **(依据-3)** 跨侧的话（"模型这条约束由那条公理正当化"）**必须同时带一个游戏侧依据和一个模型侧依据，外加两者之间的蕴含关系**。这类话只有一个合法住址——对应表的行（§1.7）。任何在别处出现的跨侧断言都是无依据的。

(依据-2) 顺带给出一条关于实验的推论：一次实验的结果只有在**实验装置本身是合法实例**时才是关于模型的观察；否则它观察到的是一个不存在的东西的行为。装置的合法性是该收据的前提之一，要与结果一起给。

### 1.6 由前五步推出的分层

现在把"文书该长什么样"推出来。§1.1 说游戏知识分输入与推论；§1.2 说问题是独立层；§1.4 说模型与游戏的差异要单独记账；§1.5 说模型侧事实是第三种依据。所以**要被引用的东西按逻辑类型分成五类，而不是一类**：

| 稳定类型名〔R3〕 | 本稿显示序号 | 内容 | 依据类型 | 谁能改 |
|---|---|---|---|---|
| **`PROBLEM_CLAIM`** | L0 | objective、admissibility、被问的量的定义、产能要求、范围限定；R3 起拆成 `TARGET_CLAIM` / `PROVED_CLAIM` 双对象（§1.4 R3-A5） | 定义（owner 提出） | owner |
| **`GAME_PARAMETER`** | L1 | 实体种类与数值参数表 | 经验（游戏测量） | owner / 游戏 |
| **`GAME_AXIOM`** | L2 | 行为命题 | 经验（游戏测量） | owner / 游戏 |
| **`DERIVED_THEOREM`** | L3 | 由上三类推出的命题，带前提集与证明 | 推导 | 任何人，凭证明 |
| **`MODEL_CORRESPONDENCE`** | 对应表 | 模型 ↔ 上三类的双向对照，带 §1.4 的判读（三个行集见补-10） | 跨侧（依据-3） | 任何人，凭双侧依据 |

**〔R3·A4 / CONCERN-07〕本表原来只用裸层号 `L0/L1/L2/L3`**，而 `FINAL_DESIGN.md` 用同一批裸层号表达**完全不同**的东西（其 L2 = 派生闭包 = 本稿 L3；其 L3 = 投影视图 = 本稿没有的层）。两版按裸层号合并必然错层。R3 起以左列**稳定类型名**为跨文书引用的唯一形式，层号降为本稿显示序号（映射全表见 §0.1 R3-b）。

外加一层**档案**（`OWNER_RULING_EVENT` + `HISTORICAL_SNAPSHOT`）：谁在哪天怎么定的、被推翻过的旧读法、事故经过。档案层被上述各类按编号引用，**但引用它的条目正文必须在不看档案的情况下可读**（理由见下）。**〔R3·A3〕档案层的形态在 §1.12 补-13 被改写**：它不再是"只持指针的注记"，而是**保存 owner 裁决 exact payload 的不可变事件记录**——理由见该处。

这一分层立刻解释了现行 canonical 文件的几处怪相——它们是"只有一个桶"的症状：

- **同一个格子装了不同逻辑类型的东西**，所以看不出区别。`item_admission_port_exclusion` 携带的是一条真正的 WLOG 定理（进料口在几何与连通意义上等价于一段直带，故省略它既不排除可行布局也不接纳不可行布局——这是一个模拟论证）；`warehouse_bridge_exclusion` 携带的是一条**未证的** WLOG 断言（仓库桥是真实游戏机制，理由是"按当前产能目标它不划算"，而划算与否是速率层的事，认证谓词根本不覆盖速率层）。这两条在现行格式里长得一模一样：都是 `statement` + `authority`。格式没有区分"已证"和"已断言"的位置，所以区分不出来。
- **`ruling_level_inputs` 这个字段本身是缺层的产物**：它登记"本文件有两条不能从公理推出"。在五层结构里，这两条各有自己的家（空矩形严格性 → L0 问题层的定义；仓库桥排除 → 对应表里一条未清欠账），这个字段自动消失。
- **owner 在为可推导的事拍板**。协议箱 6 槽条款被记为"2026-08-06 owner 裁决"，而同一条目自己写着这是缓存槽公理的直接推论。经验层的输入（缓存槽怎么工作）确实要 owner，但由它推出的箱子行为不要。**分层的一个可测收益：需要 owner 的条目 = 没有推导的条目，数量应当显著下降**。

**推论（正文即当前真相，修正重写而非叠加）**：法律语料里保留被推翻的原文 + 推翻它的注记，因为历史本身是权威；数学里不这样，因为读者要引用的是命题，而**引用一条需要在脑子里叠加三层修正才为真的命题是不安全的**（(依据-1) 要求引用者核对前提，而前提写在别处时核对不了）。所以：一条目 = 一条当前为真的命题，修正**改写正文**，被改掉的读法进档案层。

现行文件里 `mixed_commodity_flow` 的主 `statement` 说混流允许，其 `terminal_clause` 说主 statement 在端口层"adjudicated TOO WIDE"；`item_admission_port_exclusion` 的 `rationale_restated` 说原理由"superseded in emphasis"。读者必须自己合成当前命题。

**推论（条目名写内容，不写争议）**：判例按争议命名，定理按内容命名。`mixed_commodity_flow`（内容其实是"终端安全性三分定理"）、`item_admission_port_exclusion`（内容是"排序从不被结构性需要"）、`port_commodity_scope`（内容是命题的范围限定）都是按它们当年的争议场合命名的。名字写内容，引用时才知道自己引的是什么。

### 1.7 两张表的行索引由两条量化义务定死

§1.3 的健全性与完整性不是同一件事的两种说法，它们的**量词跑在不同的空间上**（前者跑在 `M`，后者跑在 `G`），所以表的行索引也不同。展开：

设游戏合法性 `GameLegal = ⋀ᵢ Gᵢ`（游戏条件），模型合法性 `ModelLegal = ⋀ⱼ Mⱼ`（模型约束）。

- **健全方向**：对每个 `i`，`ModelLegal(m) ⇒ Gᵢ(π(m))`。→ 按**游戏条件**索引，逐条问"谁在替我强制它"。
- **完整方向**：对每个 `j`，`GameLegal(g) ⇒ ∃m`，`π(m) = g` 且 `Mⱼ(m)` 成立（连同其余全部 `M`）。→ 按**模型约束**索引，逐条问"谁在替它正当化"。

> **superseded（R3 20260807，份5外审+核签，BLOCK-03）**：本节标题原为"两张表的行索引由两个包含方向定死"，两条方向原写作 `(⋀ⱼ Mⱼ) ⇒ Gᵢ` 与 `(⋀ᵢ Gᵢ) ⇒ Mⱼ`——后者把完整方向写成了一条**不带存在量词、不带投影**的蕴含式，因而看不出"辅助见证凑不出来"这种失败模式。**按 j 分行这个结论不变**（核签书 §2 判定"三张表 / 三个行集"是可逐步复算的推导，外审把它当走私品是误伤）；变的是每一行要证的东西的形式。

于是两张表：

**执行表（健全）**：行 = L1/L2 的每条游戏条件。列 = 强制它的模型约束集 + 判读。
判读三值：`已强制` / `更严但仍强制`（本行干净，但在正当表里留一笔欠账） / `缺口`（**模型太松 = 健全性 bug**）。

**正当表（完整）**：行 = 每条模型约束。列 = 正当化它的游戏条件 + 判读。
判读按 §1.4：`等价` / `更严·已证WLOG`（指向定理编号；**R3 起拆两级：行级 `LOCALLY_WLOG` + 束级 `BUNDLE_CLEARED`**，见 §1.4 R3-A2） / `更严·已缩范围`（指向 `PROBLEM_CLAIM` 里的范围限定，**且只许改 `PROVED_CLAIM`**，见 §1.4 R3-A5） / `更严·未清欠账` / `无正当化`（**纯人造墙**）。

**为什么必须是两张、不能合成一张双列表**：一处"模型更严"的事实，在执行表里是**干净行**（它确实强制了游戏条件，还多强制了一点），在正当表里是**脏行**（多出来那点没人正当化）。同一个事实在两张表上符号相反。合成一张表就必须选一个符号，而选哪个都会丢掉另一半——这正是 `model_stricter_faces` 那句 "all conservative, never unsound" 发生的事（§1.3）。**两张表是 §1.3 两条量化义务的机械后果，不是冗余。**

**〔R3·A1 / BLOCK-03〕表是义务索引，不是证明。**这两张表（连同补-10 的覆盖账）**索引**的是 §1.3 那两条量化义务的逐条实例，它们**本身不构成对量化命题的证明**：

- 执行表逐行"已强制"⇒ 健全性方向的每个 `Gᵢ` 都有承担者，**但每一行的蕴含步骤仍要各自成立**（补-5 的可达性核算就是这一步的必填内容）。
- 正当表逐行"等价 / 更严·已证WLOG"**推不出**完整性——按 §1.4 (R3-A2)，逐行 `LOCALLY_WLOG` 的合取不是 WLOG，**只有束级 `BUNDLE_CLEARED` 之后**才允许把逐行全绿读成完整性。
- 覆盖账逐行"可表达"⇒ 每个已知自由度有模型变量，**但"已知自由度"的完备性由补-2 的外部枚举源担保，不由这张表担保**。

凡是"表行全绿 ⇒ 保真已证"的读法，都是把索引当成了被索引物。§2.3 的检查器禁令（记账完整 ≠ 模型忠实）是这条纪律在机器面的形式；这里给的是它在文书面的形式。

**三种审计的名字由此确定**，它们不是三个独立发明，是这两张表加命题陈述的行检查：

| 名字 | 是什么 | 失效后果 |
|---|---|---|
| **孔** | 执行表的 `缺口` 行 | 模型太松 → 见证可能非法 → 下界失效 |
| **墙** | 正当表的 `无正当化` / `未清欠账` 行 | 模型太严 → 可能砍掉最优解 → 最优性失效 |
| **界** | 命题陈述里的范围限定条 | 命题比读者以为的窄；限定失效则整条结论失效 |

界审计的行不在两张表里，它审的是**命题本身**：每条范围限定要回答——它救的是正当表哪一行、它在冻结实例上是否可核、问题变了（P2.0）之后它是否还成立。

（完整方向实际需要**两个**行集而不是一个：这里的正当表管"模型多了一堵墙"，另有一个管"模型少了一个自由度"的覆盖账——理由见 §1.12 补-10。分两处推出是因为后者要先有 §1.11 补-2 的外部枚举源才立得住。）

**推论（模型约束 = 一切塑造可行集的东西）**：正当表的行索引是"模型约束"，而这个词的外延由它的作用定死——**凡是塑造可行集的决定都是模型约束**，不管它以什么形式存在：CP-SAT 的约束行、子问题的条件、**候选池生成期就被剪掉的位姿**、预处理阶段定死的实例集与需求量、目标与 admissibility 的编码。生成期剪枝尤其危险，因为它不长得像约束：被剪掉的位姿在下游任何地方都不出现，没有任何一行代码"禁止"它。2026-07-18 的 front 错位事故正是这一类——生成期按错位语义剪掉了 2,064 个合法位姿，而下游没有任何东西能发现少了东西。**把生成期剪枝排除在正当表之外，就等于给这一类事故留了永久盲区。**

### 1.8 冻结判据：机器消费的冻，可重推的不冻

冻结（byte-pin + freeze-ritual）不是纪律偏好，它有确切用途，用途决定适用范围。

**hash 只能保证一件事：字节没变。** 它对内容是否正确一无所知。所以它是**不可重现内容**的正确完整性手段（经验测量、45MB 候选池），对**可重现内容**是错误手段（可重现内容的完整性手段是重推，重推顺带查出内容错误，hash 查不出）。

由此逐层：

- **`GAME_PARAMETER`**：机器消费（候选池由它生成），且不可重推（来自游戏）。**冻。**保持现状。
- **`PROBLEM_CLAIM`**：定义了在证什么，改它改掉一切结论。**冻**（它是命题的一部分）。
- **`GAME_AXIOM`**：不被机器消费，但不可重推。它的作用是**记录命题是相对于哪套信念做出的**。所以它需要**版本与内容哈希被证书引用**，不需要和机器输入同锁一个文件。
- **`DERIVED_THEOREM`**：可重推。**不冻**。它的完整性手段是证明复核 + 前提图（§1.9）。给可重推内容上 hash，买不到正确性，只买到改动成本。
- **`MODEL_CORRESPONDENCE`（对应表）**：可重推（每行的两侧依据都可现场复核）。**不冻**，但它的**结构完整性由机器检查**（§1.9 第 1 类）。

> **〔R3 欠账登记，BLOCK-12——本轮不改，挂批 C〕**：上面对 `DERIVED_THEOREM` 的判定**只问了"可重推吗"，没有再问一次"它是否被机器消费"**——判据是二维的，应用时塌成了一维。份 5 外审 BLOCK-12 的反例（一条派生定理给出剪枝阈值 K，生成器把 K 当硬阈值消费；K 可重推但本次运行没重推，缓存的 K 来自旧公理）在本仓有同型土壤：`candidate_placements.json` 就是由参数生成并冻结的产物，一旦有一条派生定理进入**生成期剪枝**（而 §1.7 推论把生成期剪枝定义为最危险的一类模型约束），这个洞立刻真实。核签书 §6 判 **ACCEPT 为补丁**：保留"可重推的源文件不进 freeze-ritual"（这一条对，它省的是 ritual 底价），**加上**"其内容必须进入证书依赖根，或在本次认证运行中由已绑定输入重生并由已绑定 checker 验证"。落地属 R3 批 C（`artifact_root` 传递依赖 manifest），**本轮 A/B 批只登记不改**。

**在案代价**：现行 `semantics` 整块（含刚采纳的 11 条公理和全部派生条款）住在 byte-pin 的 `canonical_rules.json` 里，而这块自己声明 *NOT consumed by ... any certified solve path*。求解路径确实零消费，但**不是零消费方**：`src/tests/cuts/test_helpers_power_cover_stencil.py:100` 读 `rules["semantics"]["power_coverage_stencil"]`，把该条目与实现钉成等值（本文亲自核实；这条哨兵同时是补-1 的现成先例）。schema 侧则完全没有约束——`rules/canonical_rules.schema.json` 里 `semantics` 是 `{type: object, additionalProperties: true}`，无 required、无字段枚举（亲自核实）。

于是**改一条定理的措辞，要付一次完整 freeze-ritual**（换 pin、重推派生工件、重跑门），而这次 ritual 除了那一条哨兵覆盖的条目之外买不到任何东西。这是**对做数学本身征税**，而派生层恰恰是最该高频变动的层（新定理、更正证明、清欠账）。

**推论（改动成本要与改动的语义分量成比例）**：改一条游戏公理是真事件（它改变了我们在主张什么），成本高是对的；改一条定理是日常数学工作，成本必须低，否则派生层会停止生长——而 §1.10 说派生层的生长就是这项工作本身。

### 1.9 推理纪律：一条公理、它的推论、以及机器检查能力的四分类

数学面的纪律只有一条：

> **断言必须给出依据。**

由 §1.5 的三种依据展开，得到它的全部推论（这里是**推**出来的，不是列出来的——每条后面是它的推法）：

- **(纪-1) 引用一条派生命题时，必须同时核它的前提集在当前语境成立。**
  推法：前提不成立时，那条命题不为真，引用它就不是依据。
- **(纪-2) 经验断言必须指向在册的参数或公理条目。**
  推法：经验断言没有推导，它唯一可能的依据就是"它是输入"。指不出条目 = 没有依据。
- **(纪-3) 模型侧断言必须在源头观察，转述不是观察。**
  推法：转述是一步推导，其前提"转述忠实"本身没有依据。
- **(纪-4) 跨侧断言只能出现在对应表的行里，且必须双侧带依据。**
  推法：(依据-3)。
- **(纪-5) 三种依据都给不出的话，不许说。**
  推法：这就是那条公理本身。

**准入判据（反清单论证）**〔**来源：对勘回流 · MECHANISM**，见下方 R3 来源标注〕：新增一条检查项时，问两件事——**它推得出来吗？它有停机判据吗？**

**〔R3·B3 改写，P-02 改造后收 / BLOCK-02〕四态，不是三格**：

| # | 情形 | 处置 | 落哪个既有台账 |
|---|---|---|---|
| **A** | **推不出来**（无法从目标或经验风险推出） | **删**。没有依据，按 (纪-5) 不许进 | — |
| **B** | 必要，且**有完备停机判据** | **收**，实现为硬检查。它把一条无界的人的义务换成了有限步的操作 | 正常行 |
| **C** | 必要，但**只有半判定 / 预算内搜索 / 不完备算法** | **保留义务**，输出 `PASS` / `FAIL` / **`UNKNOWN`**；`UNKNOWN` **阻断无条件 certified 结论**（只能出 conditional） | 落既有 **`未核`** 格（覆盖账第三值、参数表 `未测` 格的同族）——**不新造开放态词表** |
| **D** | 必要，且**当前无可执行判据** | **登记为开放证明义务**，写明它阻断的命题范围；**不得因不可执行而视为不存在** | 落既有 **`未清欠账`** 格（正当表脏行）+ `ClaimDelta`（§1.4 R3-A5） |

> **superseded（R3 20260807，份5外审+核签，BLOCK-02）**：原判据是**三格**——`否/— → 删`、`是/否 → 删`、`是/是 → 收`，**没有 UNKNOWN 也没有 OPEN 态**。份 5 外审指出第二格会把"必要但当前不可判定的义务"整条删掉；核签书 §2 特别核实：外审举的错杀例（"检查当前能力册是否等于游戏全部能力"）**恰好是本设计已处理的那条**（补-2 + §2.9 覆盖账的"未核"格 + §3 的诚实边界），所以那个例子不成立——**但缺陷本身成立**：本文书全稿已有四种开放态词（`未清欠账` / `待复验` / `未测` / `未核`），唯独准入判据这一格没有。

**停机判据决定的是检查器能否给出 `PASS`，不决定证明义务是否存在。**这是 A 档与 C/D 档的分界：A 档删的是**没有依据的检查项**，C/D 档留的是**有依据但当前跑不完的义务**。原三格把这两件事压进了同一个"删"。

**C/D 两档必须并进既有词表与既有台账，不许新造第二套开放态**——新造一套会当场违反补-13（R3 改写后的四类表示：同一件事只许有一个当前权威的陈述位置）。

第 B 格仍是纪律真正的增长方式，也是它不会膨胀成清单的原因：**有界工具的数量受限于"能被推出且能被走完"这个双条件**，而不是受限于人的想象力。反过来说，"这条从公理推得出来所以不用单独写"是错的——推得出来的那一步恰恰是人会漏掉的那一步（六轮逐行审查仍漏掉一条前件，就是这个漏法）。写下来的价值不在于它是新知识，在于它把那一步变成了可以走完的操作。

> **〔R3·A6 来源标注，BLOCK-01——这是全稿最严重的一处走私品〕**
>
> **本准入判据不是从 §1.1–§1.8 推出来的**，它是**对勘回流产物**：来源是病例 **C-15**（全文前件写得最显式的那条引理，六轮逐行审查仍漏一条前件 ⇒ 证伪了"推得出来的不必写下来"）与病例驱动版的 **K-4 有界性要求**，回流路径记在 `DIFF_VERDICT.md` 分歧 3。它此前住在 §1.9 这个纯推导章的正文里、**零来源标记**，而 `DIFF_VERDICT.md` §0 自认"推导版因本次对勘做的修正已直接写回 §1.9 与 §1.12"——这违反 §0 自己立的标准（"§3 校验只能证伪推导、不能补丁式地往设计里塞东西"）。
>
> 按 §0.1 (R3-a) 的三类产物：**"无界的义务在实践中必然退化"这条经验命题 = HEURISTIC**（证据 = C-15 与六轮审查的实测，适用范围 = 需要人逐条执行的义务，失败模式 = 对可自动化的义务不适用）；**由它推出的准入四态 = MECHANISM**（实现的 OBLIGATION 是补-12"无法被执行的义务不产生依据"，替代方案是"全收 + 靠人挑"或"全不收"）。**它不是 OBLIGATION，不得标"由 §X 推出"。**

几条已知的历史教训不需要单独立法，它们是上面的实例：

- "收据里的转述不是证据" = (纪-3)。
- "探针装置得在真实几何里存在" = (纪-1) 用在实验上：收据的前提集包含"装置是合法实例"。

### 1.10 派生层怎么"运行"：工作队列由表的缺口生成

饱和扫描（从公理组合推出所有定理）不是一个新流程，它就是做数学本身。但"推出所有定理"在实践中不可枚举，所以要推出**方向**：先推什么。

由 §1.4 和 §1.7，方向是定死的——**每一条非干净的表行就是一个精确陈述的数学任务**：

| 表行状态 | 对应的数学任务 | 完成后 |
|---|---|---|
| 正当表 `更严·未清欠账` | 猜想："这条更严不咬最优解" → 证 WLOG 定理 | 欠账清零，最优性命题变强 |
| 正当表 `无正当化` | 要么找到正当化的公理，要么删掉这条约束 | 墙消失 |
| 执行表 `缺口` | 补一条模型约束，或证明该游戏条件在本问题下不可能被触发 | 孔封上 |
| 界审计条 | 尝试把范围限定升级为 WLOG 定理 | 命题从"片段上成立"升级为无条件 |

所以派生层不靠灵感驱动，**它的工作优先序是表自动生成的**。这也解释了为什么两张表必须先建全：**未登记的约束就是未登记的前提**，在此之上推出的"定理"实际上是从一个未知前提集推出来的。

> **〔R3·A6 分类标注，BLOCK-01〕**：上一段推出的是 **OBLIGATION**——"每一条非干净的表行都是一个精确陈述的数学任务，且它们之间有由 §1.4 决定的优先序"。把这批任务组织成**队列**（而不是看板、优先级堆、或干脆不组织）是 **MECHANISM**：它实现上述义务，有替代方案（看板 / 按批次分派 / 无组织），选队列的理由是它天然承载优先序且可被机器从表生成。**本节此前把"工作队列"写成推论，措辞越界**（核签书 §2 判"优先序推得出，'队列'这个装置推不出"）。

**塌点（解空间收缩为孤点）是这个队列上收益最高的一类**：当若干前提合起来把一个连续自由度压成唯一取值时，就结晶出一条"任何最优布局必具性质 P"的定理。已有样板是五满一半条件定理。它们的找法有迹可循——**盯零余量的账**：某个量的需求与其最松上界之间余量接近零时，该处几乎所有配置都被排除，剩下的就是定理。（项目既有方法论 §0b 的"预设锚点判据"从完全不同的路径独立到达同一处：被迫结构 = 零余量账。两条独立路径撞在同一点上，是这条推论可靠的旁证。）

### 1.11 补推导（病例校验回流）

§3 的 52 例校验暴露出九条**已经蕴含在 §1.1–§1.10 里、但当时没有被推出来**的结论。它们不是补丁：每条下面第一行写的就是它从前面哪一步推出来。（哪个病例暴露了哪条，见 §3。）

**(补-1) 同一条游戏条件的每个实现都要登记，实现之间的一致性是表行义务。**
推法：§1.5 (依据-3)——一条表行 = 一个游戏侧事实 + 一个**模型侧事实** + 蕴含。若代码里有 N 处各自实现同一条游戏条件（活路径、诊断面、投影层、影子面、cut 侧镜像），那就是 N 个不同的模型侧事实，于是 N 行。只登记"当前权威的那一处"，等于让另外 N−1 处的行为无依据地存在——而"当前哪处权威"是一个可以被翻转的开关。
推论：诊断面 / LEGACY 面 / 投影层不因"当前不 gate"而免登记；它们的行判读多一种取值：`与权威实现一致` / `已知不一致（登记差异与后果）`。

**(补-2) 经验层的完备性只能由外部枚举源担保。**
推法：§1.5——关于游戏的结论只能来自经验依据。"我们的公理集覆盖了游戏的全部相关行为"本身是一条关于游戏的结论，所以它也只能来自经验，不能由理论内部的自洽推出。
推论：理论必须登记它的**外部枚举源**（游戏内器件清单、上游模拟器注册表、官方数据），并给出一笔覆盖率账：源里有 N 类器件/能力，理论覆盖 M 类，未覆盖的 N−M 类逐条说明为什么不影响命题。**没有这笔账，完整性方向（§1.3）连检查都无从下手**——你无法遍历一个你没有清单的集合。

**(补-3) 被持久化的结论必须携带其前提集的版本。**
推法：§1.9 (纪-1)——引用一条命题时要核它的前提当前成立。一条持久化的 nogood / cut / 证书 / checkpoint 在后续运行里被**再次使用**，就是一次引用。它无法在使用时人工核前提，所以必须自带前提版本，规则一变即自动失效。
推论：这一条对文书与对求解工件是同一条要求，不是两套机制。

**(补-4) 机器复核收据的输入集就是该定理的前提集。**
推法：§1.9 (纪-1) + §1.5——收据脚本**就是**那条推导。一条推导的前提恰好是它的输入。因此脚本里写死的每一个常数、每一个默认约定，都是一条前提；它出现在脚本里而不出现在声明的前提集里，就是一条**未声明前提**，而声明的前提集因此是一份假声明。
推论（**R3 改写**）：这条给出了"前提漏项"的**机械可查形态**——逐行列出复算里**每一处把多个个体压成一个数的操作**（信息压缩操作清单，逐条带 `source_span` / 输入输出类型 / 所需语义前件 / 谁能违反它 / 替代分配下的结论范围）。前提漏项在纯散文形态下只能靠证明复核发现（而实践证明多审几轮不收敛）；有了这份清单，漏项就变成可逐行核对的对象。

> **superseded（R3 20260807，份5外审+核签，BLOCK-08）**：原推论写"机械可查形态——**比对脚本输入与声明前提集**……漏项就变成可核对的**差集**"。**这个形态在本条自己的旗舰病例 C-15 上恒为空**：`runs` 与 `machines` 都是已声明输入，`util = runs / machines` 的语义前件藏在**除法这个运算**里，不在输入集里。**均摊不是写死的量，它是一次运算**，所以"写死的常数即未声明前提"这句话漏掉了整个运算类。详见 §3.1b 的 C-15 专栏。上一句"脚本里写死的每一个常数、每一个默认约定都是一条前提"**本身没错**（它甚至用"默认约定"包含了均摊），错的是由它收窄出来的那个机械形态。

**(补-5) 条件装置的正当性主张隐含一条前提："触发条件可达"。**
推法：§1.3 完整方向的形式内容。一条模型约束 M 的正当性是 `Legal_game ⇒ M`。若 M 的理由是"某危险 D 可能发生"，则那些"D 不发生"的游戏合法布局不满足 M，`Legal_game ⇒ M` 直接为假。所以从"D 可能发生"到"必须禁止"之间隔着一条必须被兑现的前提：**D 在本问题的参数下真的会发生**。
对偶（同一条，方向相反）：一个只在条件 Y 下起作用的装置（触发器、哨兵、探针、报警），其"它有用"的主张同样隐含"Y 可达"。Y 不可达 ⇒ 装置恒不激活 ⇒ 主张为假。
推论：**"危险定理"不能直接当"禁止条款"的正当理由**；两者之间那一步核算是表行蕴含步骤的一部分，不是额外的谨慎。

**(补-6) 依赖运行期分支的模型侧事实，必须用运行期观察取得。**
推法：§1.9 (纪-3)——模型侧事实必须在源头观察。若某行为取决于运行期才确定的分支（分类字段、加载失败回退、剥落降级、软失败），那么"源头"就是**这次运行**，不是源码文本。静态读码得到的是"代码可能怎么走"，不是"它实际怎么走"。
推论：表行若声称"约束 M 被施加"，而实际运行中有时施加的是更严的 M′，那这一行的模型侧事实是假的。要让它可核，运行期必须**计数并上报**每一次回退/降级。**零信号的保守回退是一条无法被核对的模型侧断言**。

**(补-7) 档案层的每条裁决必须指向它产生的条目。**
推法：§1.1——裁决是经验输入，而经验输入的住址是参数层或公理层。一条裁决没有对应条目，等于一个输入被丢了。
推论：映射必须是全函数：每条裁决要么指向一个 L0–L2 条目，要么显式记为"未产生条目"并写明理由。这条同时把"已定谳裁决无反向索引"这个空档填上——反向索引不是新造的装置，它是这个映射的逆。

**(补-8) 参数表的列由公理决定；缺列必须显式登记为空缺。**
推法：§1.1 + §1.9 (纪-1)。公理是对实体的模式（"设备有口与缓存槽"、"缓存槽有容量"）。一条公理在某实体上实例化时，它引用的每个参数都必须有值——否则那次实例化不是一个命题。所以**公理集定死了参数表该有哪些列**，参数表不是想到什么写什么。
推论：某实体的某列没有值，是一条必须显式登记的事实（"未测"），不是留白。留白与"该实体没有这个属性"在读者那里不可区分，而两者的后果完全不同。

**(补-9) 审查结论必须陈述它检查了什么。**
推法：§1.9 (纪-2/纪-5)——"已审查"是一条断言，它的依据就是实际执行的那些检查。不写明检查了什么的"已审查"，断言强度超过它的依据。
推论：一次审查若落在缺口的下一层（把下层审干净），而它不声明覆盖层次，读者会把它读成上层已审——于是审查动作本身给缺口盖了绿章。

### 1.12 补推导（对勘回流）

与病例驱动版对勘（§4 / `DIFF_VERDICT.md`）以及校验期间新发生的 C-53（§3.5）又暴露四条同样是"蕴含在前面、当时没推出来"的结论。

**(补-10) 完整方向需要两个行集：多了一堵墙，和少了一个自由度。**
推法：§1.3 完整方向 `Legal_game ⊆ Legal_model` 会以两种方式失守。一种是模型多写了一条约束（正当表的脏行）；另一种是**模型里根本没有表达那件事的变量**——游戏允许的某个自由度在模型里不存在。后者不是任何一条约束造成的，所以在按约束分行的表里**永远不出现**。整类器件从未入册就是这一型。
推论：§1.7 的两张表要补成三个行集——执行表（按游戏条件，健全）、正当表（按模型约束，完整·墙）、**覆盖账（按游戏自由度，完整·缺变量）**。覆盖账的行集只能来自补-2 的外部枚举源；这也是补-2 为什么是完整方向的**前置**而不是补充。

**(补-11) 经验依据的来源必须被留存在可复验的位置。**
推法：§1.9 (纪-3) 要求在源头观察。若一个承重参数的出处是一份没有被 vendored 进仓库的外部快照（上游模拟器某次 commit 的源码、一次没留下产物的抽取），那么"在源头观察"这个动作事实上执行不了——后来的人只能读转述。
推论：进理论的每个承重量必须能在仓内复验（抽取产物 + 抽取脚本 + 收据 + 上游 commit）。做不到，它就只能以"待复验"身份存在，不能当承重前提。**引用一个复验不了的来源，与转述在依据强度上是同一档。**

**(补-12) 无法被执行的义务不产生依据。**
推法：§1.9 的全部纪律都是要人去做的动作；一条动作若成本高到实际上没人走完，它产生的依据是零，而不是"打了折的依据"。于是纪律的成本不是工程上的方便与否，**它决定纪律是否真的存在**。
推论：每条纪律必须同时给出它的**代价**与一个**明写的降级档**（降级档的产出必须自带"本结论按降级档得出"的标记，从而不被当成全档结论）。没有降级档的全套纪律，在预算紧的时候被整体跳过；有降级档的，至少跑得出一个标了强度的结论。这与"为稳而慢可能是慢性死亡"是同一条：保守支若结构性走不完，它就不是一个真选项。

**(补-13) 一条经验事实只许有一个当前权威的来源；其余位置必须是四类有类型的表示之一。**〔**R3 全面改写，P-14 直接收 / BLOCK-11**〕
推法：§1.1（经验事实是输入，不可推导）+ §1.9 (纪-3)（转述不是观察）。同一条裁决在 N 处**各自作为当前权威被陈述**，那 N−1 份就是转述冒充输入：它们没有办法自证与真本一致，而后来的人读到哪一份是随机的——**读到陈旧那份的概率随副本数增长，且不发任何信号**。这不是"文档没同步"这种卫生问题，是依据链在经验层的根部断掉。

> **superseded（R3 20260807，份5外审+核签，BLOCK-11）**：本条原写**"一条经验事实只许有一个陈述位置，其余位置只能持指针"**，并推出四条推论，其中推论 a 为"档案/注记层**不得陈述命题**……档案只持编号"。
>
> **这个结论过强，且与本设计自己的需求自相矛盾。**推得出来的是"**当前权威**只能有一个来源"；推不出"一个字符串只能出现一次"。原文与"档案不携带命题"合起来，**结构上删掉了 C-53 所需要的那个证据位**——C-53 的纠错靠的恰恰是 owner 认出**自己当时那句话的原文**，而按原文档案层只许存"08-06 owner 定的"这个指针，存不下"定成了什么"。同样，它与 `FINAL_DESIGN.md` §3.5 的 `semantics.entities` 镜像条款硬冲突（那条要求一份双向等值的副本），而本设计的对勘（`DIFF_VERDICT.md`）漏掉了这处冲突。

**允许四种有类型的表示**，每条命题的每个出现位置必须标明自己是哪一类：

| 类型 | 定义 | 必带字段 | 能不能被当前语义消费 |
|---|---|---|---|
| **`AUTHORITATIVE_CURRENT`** | 某一 semantic release 中**唯一**可作为当前游戏事实消费的命题 | 稳定 id、release | **能**——而且只有它能 |
| **`GENERATED_PROJECTION`** | 由权威源**机器生成**的表格或视图 | `source_id@release`、`source_digest`、`generator_digest` | 能，但它是投影；**不得手改**（手改即降级为无依据的转述） |
| **`IMMUTABLE_HISTORICAL_SNAPSHOT`** | 冻结批次为**复现当时判断**而保存的原始字节 | release root、批次 id | **不能**——它是历史，不是现在 |
| **`QUOTATION_FOR_EVIDENCE`** | 逐字引文 | source span、内容哈希 | **不能**——仅作证据，不作权威 |

推论 a（**改写**）：**档案层改为不可变事件记录**，它**必须**保存 owner 裁决的 **exact decision payload**——问题原文、裁决原文、证据、签名、`supersedes` 关系——而不是只留一个可变指针。当前语义（`AUTHORITATIVE_CURRENT`）由这条 ruling event log **生成**，因此它是 `GENERATED_PROJECTION`，事件记录本身是 `IMMUTABLE_HISTORICAL_SNAPSHOT`。**这样"档案携带命题"就不再是病**：病是**两份互相竞争的当前权威**，不是"命题被写了两次"。
推论 b（**改写**）：可机检的判定从"命题正文只在一个文件出现"改为——**同一 id 的 `AUTHORITATIVE_CURRENT` 只允许有一份**；其余出现必须带类型标记与上表要求的字段，缺字段即红。这仍是纯结构判定（§1.9 机器检查第 1 类）。
推论 c（保留，措辞收紧）：批次文书里的实体表与推导矩阵**不是权威**，它们必须是 `GENERATED_PROJECTION`（由真本机器生成、带三个 digest）或 `QUOTATION_FOR_EVIDENCE`（带 span 与哈希）。**手写的、无类型标记的副本**才是这条病的标准载体——C-53 漏翻的那两行正是这一型。
推论 d（保留）：补-1（同一游戏条件的多个**实现**都要登记）与本条是对偶——那边是模型侧多副本，靠"登记全部 + 断言一致"处理，因为多个实现是真实需要的；这边是游戏侧多副本，靠"**只许一份当前权威**"处理。两侧处方不同，根因同一个。
推论 e（**R3 新增**）：`FINAL_DESIGN.md` §3.5 的 `semantics.entities` 镜像条款按本条应改为 **`GENERATED_PROJECTION`**（由 `facility_templates` 生成，不手维护），而不是"手工镜像 + 双向等值校验"。该处已按 R3 同步改写（核签书 §10 C11；那是纯文书措辞项，随本条顺手落）。

| **束级状态**〔R3〕 | `LOCALLY_WLOG`（行级已证） / `BUNDLE_CLEARED`（束级三选一之一已兑现）——**只有后者允许把逐行全绿读成完整性** |

**执行表**（行 = 游戏条件）字段：条件编号 / 强制它的约束编号集 / 判读（已强制 / 更严但仍强制 / 缺口）/ 论证指针。

**约束需要稳定编号，这是本设计对代码侧的唯一要求**〔§1.7：表行要指向可识别物〕。用 `file:line` 不行——第一次重构表就烂掉，而一份**悄悄烂掉的承重台账比没有台账更危险**（它继续提供已经失效的信心）。

> **〔R3·A6 分类标注，BLOCK-01〕**：上一句的**义务**（"表行必须指向一个可识别、且不随重构漂移的物"）是 **OBLIGATION**；下面这个**落地形态是 MECHANISM**——"约束施加处用 docstring 标签声明自己的编号"只是一种实现。**已知更强的替代方案**：模型侧统一登记接口，凡塑造可行集的 API（变量域、默认值、候选枚举、过滤、预处理固定、目标编码、子问题条件）**自动发出** `constraint_id`，不靠人工标签或 grep 枚举。核签书 §10 C6 记明该替代方案要分两级：CP-SAT 侧（M/B/R 约束）可自动发号；**生成期剪枝侧（P1–P14，散在枚举器的 `range` 与 `continue` 里）不可自动**，只能人工声明 + 变异哨兵兜底，且必须在文书里如实标为两级。该项属批 C，本轮不落。

**落地形态（MECHANISM）**：约束施加处用统一标记声明自己的编号（docstring 标签即可），表行引用该编号。

**机器检查两条**〔§1.9 机器检查能力第 1 类〕，都是可判定的、不含判断：

1. **引用解析**：所有编号可解析；每条定理的前提集编号存在；无环。
2. **双射**：代码里声明的每个约束编号在正当表里恰好出现一次；正当表每行的约束编号在代码里存在；每条公理在执行表里至少出现一次。

检查器的输出必须包含一句**它不证什么**（§1.9 禁令）：记账完整 ≠ 模型忠实。

**第三条输出（不是检查，是报表）**：把当前所有非干净行打印成**欠账清单**。由 §1.4 推论，这张清单是最优性命题前提的一部分——所以它不是"待办事项列表"，它是**命题的一部分**，任何引用该命题的地方都要带上它。

**维护触发**〔§1.9 (纪-1)〕：改任何模型约束 → 改对应行；采纳新公理或修订旧公理 → 沿前提图找出全部下游条目重核（§2.4）。

### 2.4 失效传播：前提图的第二个用途

〔§1.9 (纪-1) + §2.2 前提集为编号列表〕

前提集是编号列表这一个决定，顺带把"一条新裁决会打翻什么"从一次全文重读变成一次图查询：某条公理被修订 → 所有以它为前提的定理标为待复核 → 所有引用这些定理的表行标为待复核。

这一条不是设计的装饰。2026-07-18 的 front 错位事故里，语义翻转**双向污染了全部 front 相关结论**，而当时没有任何机制能列出"哪些结论以旧 front 语义为前提"——只能靠人回忆和全仓搜索。前提图把这件事变成机械操作。

对照现行做法：现行是在旧条目上挂 `supersedes` / `clarifies` 注记，指望读者注意到。这个做法**只覆盖被推翻条目本身，不覆盖它的下游**。

### 2.6 面分离的判据

〔§1.3〕一样东西属于哪个面，判据是**它的"收紧"动作符号为正还是为负**：

- 收紧 = 更安全 → **发布面**（拒绝发布永远安全）。
- 收紧 = 命题变假 → **数学面**（过严砍掉最优解）。
- 不涉及收紧、只记录发生过什么 → **档案面**。

这条判据可以当场用在任何新提案上，且不需要记忆任何清单。

#### C-15 的机械形态订正〔R3，核签书 §4.3——外审本报告最硬的一击〕

> **superseded（R3 20260807）**：§3.1 的 C-15 行原写"能拦住它的是'**收据脚本里写死的量即未声明前提**'这条机械比对"，补-4 的推论原写"这条给出了'前提漏项'的机械可查形态——**比对脚本输入与声明前提集**"。
>
> **这两句在 C-15 上当场失效。**`runs` 与 `machines` **都是已声明输入**，`util = runs / machines` 的语义前件（台间均匀分配）藏在**除法这个运算里**，不在输入集里——**输入差集恒为空**。均摊不是写死的量，它是一次运算。**我方对自己旗舰病例的机械形态描述是错的**，而 C-15 正是本次重设计的出生病例之一。

**正式机械形态改为「信息压缩操作清单」**（`FINAL_DESIGN.md` §4.4 聚合问抬为补-4 的正式形态，加 `source_span`）：

> 逐行列出该结论的每一份支撑复算里**每一处把多个个体压成一个数**的操作——除以台数、取平均、取代表值、取最大/最小、按均匀分配展开、取整、排序后取位次、把向量当标量、默认分配、缺失值填充、按同质性合并。**每一处都是一条前件**，必须在前件表里有一行，并标 `source_span`、输入类型、输出类型、所需语义前件、**谁能违反它**、替代分配下的结论范围。**仅有输入集合相等，不得把前件完备性标为 `PASS`。**

**强度**：`DETECTS_IF_REGISTERED`——它有界（脚本行数有限）、可机械起头（`/`、`mean`、`avg`、`/ len(`、`/ n_`、`sum(...)/`）、停机判据明确（复算工件每行赋值过一遍），**但前件是"该支撑复算以脚本形态存在且在册"**：若某次聚合发生在 SQL、表格或口算里，这条停机判据够不着。

### 3.3 校验暴露的三处推导缺陷（已回填）

九条补推导里，有三条不只是"没想到"，而是原推导有实质缺陷：

1. **模型侧事实的时间维度被漏掉了**（补-6）。§1.5 说模型侧依据是"亲自读源码"，这句话默认了模型是静态的。凡行为取决于运行期分支的地方，读源码得到的是可能性不是事实。C-24 / C-47 / C-37 三条同型病例证明这个漏洞是高频的。
2. **"多个实现"这个可能性被漏掉了**（补-1）。§1.7 谈"模型约束"时默认一条约束对应一处实现。真实代码里同一条游戏条件有活路径、诊断面、投影层、cut 侧镜像多份。C-02 / C-08 / C-36 / C-48 四条全是这一类，且其中两条至今未修。
3. **前提漏项被当成了"只能靠证明复核"**（补-4）。原推导 §1.9 把"证明对不对"整体划给人，因此对 C-15 束手无策。收据的存在改变了这个判断：**收据把一条推导变成了一个有确定文本的对象**，于是"实际用到的前提"可以逐行清点。这条把机器能管的边界往前推了一格——但只推了这一格：收据的**语义**是否正确仍然只能靠人。
   > **〔R3 订正〕**原文把这一格写成"'声明的前提集 ⊊ 实际用到的前提集'成为可比对的**差集**"。**差集形态在 C-15 上恒为空**（见补-4 的 R3 改写与 §3.1b 的 C-15 专栏）；正确形态是**信息压缩操作清单**。这一条本身是本节承认的三处推导缺陷之一，R3 发现它的**修法**当时也写错了——**同一处连错两层**，是本轮最值得记的一笔。

### 3.4 病例校验对设计的净效果

52 例里过严侧（拒真）16 条、过松侧（纳伪）16 条。本设计对两侧的处理是同一套装置的两个方向（§1.3 **两条量化义务** → §1.7 两张表 → §1.4 三值账），因此不存在"某一侧防线薄"的结构性偏置——**偏置在旧结构里来自只有一张按公理分行的表**（C-21 的根因），而不是来自审查者不努力。

至今**未修的 7 条**（C-08、C-15、C-24、C-25、C-34、C-35、C-48）在本设计下的落点：C-35 不管辖；其余 6 条全部落在正当表/执行表的脏行或前提图的待复核集里，即它们会以**已登记欠账**的形态持续可见，而不是靠人记得。

### 3.5 C-53：校验进行期间新发生的一条，以及它对本设计的追问

事故经过：协议箱的 P2 项（同种货填满已开槽才另开新槽）由 owner 于 08-06 晚定谳。该裁决有**三个登记处**——记忆卡、canonical `slot_count_clause` 的 `adjudicated` 字段、`AXIOM_KERNEL_PROPOSAL.md` 的实体表与推导矩阵 #2 两行。前两处更新了，第三处漏翻，仍挂"待判"。病例驱动版的机器复核恰好读了第三处，于是把**已判**报成**待判**，结论再经转述上到 owner，把一条已经生效的裁决降级成开放问题。owner 当场抓获；箱堵塞判据的"物理不可达"判决随之恢复。

这条追问的是本设计的一个具体承诺：**"裁决出处是注记层"这句话，怎么才能让"同一条裁决在 N 个文件里有 N 份状态"结构上不可能。**答案是补-13，它比"派生规则的前提集失效"更靠根部——那是派生层的传播问题，这是**经验层自己的多副本失步**，前提图救不了它（三份副本各自都"自洽"，图上没有任何一条边是错的）。

补-13 给的三件事，逐件对上这次事故：

1. **命题只许有一个陈述位置**。P2 的真本应当只在 L2 公理层的一条目里（缓存槽公理的箱实例化），另外两处只留编号。漏翻在结构上不可能发生，因为没有第二份正文可漏。
2. **注记层不持命题**。`adjudicated` 字段记"谁哪天定的"，不记"定成什么"——这次两处更新里有一处正是 `adjudicated` 字段，说明当前形态下**连注记都在复述命题**。
3. **批次文书里的实体表与推导矩阵是副本，必须机器生成**。这次漏翻的恰恰是这两样，而它们是手写的。

附带一条不能不说的：这次的错误结论**进了本设计的上一版**——`DIFF_VERDICT.md` 曾把"箱案判读应为待核"当作要照单吸收的机器复核事实。它被更正，靠的不是任何机制，是 owner 认出了自己的裁决。**一个把"读到陈旧副本"当作随机事件的体系，其纠错通道就是 owner 的记忆**，而这正是本设计要取代的东西。
