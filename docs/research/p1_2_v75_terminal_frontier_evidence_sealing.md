# P1.2 V75 Terminal Frontier Evidence Sealing

V74 made the public `CERTIFIED` surface verifier authoritative over disk state,
strict JSON, and exact-artifact hashes.  The next review pass found that this
outer verifier was not the weak point anymore.  The remaining false-negative seam
was inside the terminal campaign proof object itself: a terminal checkpoint could
still treat `last_stop_reason.reason == "search_exhausted_all_candidates"` plus a
best certified candidate as enough evidence that the whole outer frontier had
really been exhausted.

## Finding

The old terminal predicate was too much like a wax seal stamped on a blank map.
It checked that the final candidate was internally certified and no recorded
certified candidate was better, but it did not carry a replayable account of the
candidate domain that had been generated by `outer_search`.

That left three sibling false-negative shapes:

1. A checkpoint could contain terminal stop metadata without a sealed list of the
   candidate-generation parameters used to define the full search domain.
2. A missing, `UNKNOWN`, or otherwise unresolved candidate that was still better
   than the final result could disappear from the terminal proof if it was not
   represented in a recomputable frontier projection.
3. A sliced generation domain, for example one created with `start_area` or a
   smaller caller-selected area cap, could masquerade as full-domain exhaustion.

V73/V74 remain sound as public-surface architecture: inspector, delivery
manifest, and B5A now go through the centralized verifier.  The issue was the
object that verifier was asked to trust.

## Fix

V75 introduces `src/search/certified_frontier.py` as the replayable terminal
frontier evidence kernel.  A terminal `CERTIFIED` campaign now carries
`terminal_frontier_evidence` with:

- a schema/source tag and exhausted-search reason;
- candidate-generation parameters for `max_w`, `max_h`, `min_side`,
  `max_aspect_ratio`, `area_upper_bound`, and `start_area`;
- `domain_authority = "outer_search_static_area_bound_v1"`;
- `safe_area_upper_bound`, recomputed from canonical rules, mandatory exact
  instances, generic IO requirements, and certified optional lower bounds;
- candidate-domain size, status counts, and a SHA-256 status digest;
- recomputed potential-domain and frontier keys;
- the best certified candidate key and the final result candidate key.

`ExactCampaign` schema version is bumped to 5 and resume validation now rejects
terminal certified state when this evidence is missing, stale, sliced, or
inconsistent with the current canonical grid and safe static area bound.
`outer_search` builds the evidence at the same commit point that writes the
terminal final result, and it refuses to save/export terminal certified evidence
unless the verifier can replay the candidate domain and prove the projected
frontier is empty.

The important architectural change is that terminal frontier exhaustion is no
longer a prose stop reason.  It is a replayable, digest-sealed projection over
the same candidate generator used by the outer search.

## Regression coverage

New V75 tests cover the reopened seam directly:

- `test_v75_resume_rejects_terminal_certified_without_replayable_frontier_evidence`
- `test_v75_resume_rejects_terminal_evidence_with_unexhausted_frontier`
- `test_v75_resume_rejects_terminal_evidence_from_start_area_slice`

The proof-obligation gate now anchors these tests and structurally requires the
frontier evidence kernel, authoritative domain tag, safe area bound, and status
digest fields.

Validation command used for this patch:

```bash
python3.13 scripts/check_p1_2_proof_obligations.py
python3.13 scripts/check_phase_review_gate.py
python3.13 -m pytest -p no:randomly \
  src/tests/test_delivery_manifest.py \
  src/tests/test_exact_campaign_inspector.py \
  src/tests/test_v62_candidate_frontier_contract.py \
  src/tests/test_v63_terminal_evidence_contract.py \
  src/tests/phase3b/b5a/test_b5_anchor_sprint.py -q
```

`pytest-randomly` is disabled in the targeted run because this sandbox dependency
set has a third-party NumPy seeding issue outside the P1.2 code under review.
With that environment noise removed, the targeted security regression set is the
release-relevant check for this patch.
