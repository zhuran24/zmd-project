# P1.2 V82 oriented candidate domain and persisted-cut replay sealing

Date: 2026-06-11

Review anchor: `v82_oriented_domain_and_cut_replay_sealing`

## Result

V82 was the second independent external review round of the overnight loop. It
found two algorithmic/soundness findings, both reproduced locally end-to-end
before patching. The owner clean-streak count remains 0.

## Findings

### F-1 (algorithmic/soundness): candidate domain enumerated only h <= w while masters treat (w, h) as oriented

`generate_candidate_sizes` canonicalized shapes by `h <= w`, but the exact
masters enumerate ghost anchors with `dx in range(ghost_w)`, `dy in
range(ghost_h)` — `(3,1)` and `(1,3)` are different spatial candidates. The
objective `max_lex(area, min_side)` is transpose-invariant, but feasibility is
not: a mandatory-facility layout can block every horizontal `3x1` placement
while a vertical `1x3` remains feasible. Every full-frontier terminal proof
since V75 was therefore computed over half the real domain, and the terminal
evidence verifier replayed the same incomplete domain, so builder and verifier
agreed on the missing-half map and the certified surface published the result.

Local reproduction (3x3 toy, mandatory column blocking the middle): the domain
contained `3x1` but not `1x3`; direct solves returned `3x1=INFEASIBLE`,
`1x3=CERTIFIED`; outer search published terminal CERTIFIED `1x1` while the true
optimum `1x3` (area 3) was never enumerated — a certified false negative
escalating to a wrong published optimum.

Patch: enumerate all oriented pairs (`h` ranges over the full grid height).
The geometric-dominance prune in the terminal projection
(`certified_frontier.py`) was audited and is already oriented
(`ghost_w <= cert_w and ghost_h <= cert_h`), as are the frontier dominance and
infeasible-prune comparisons in `outer_search.py`; the objective-dominance
component of the scheduling prune gain is transpose-insensitive by design and
remains sound for search scheduling. `TERMINAL_FRONTIER_DOMAIN_AUTHORITY` is
bumped to `outer_search_static_area_bound_oriented_v2` so terminal evidence
produced over the old half-domain is rejected explicitly
(`terminal_frontier_domain_authority_invalid`), not just via digest drift.

Production impact: the 70x70 certified candidate domain roughly doubles, which
lengthens full campaigns; soundness takes precedence and no compensating
shortcut is taken in this round.

### F-2 (algorithmic/soundness): persisted exact_safe_cuts replayed into the master after shape-only validation

Checkpoint resume and worker-preload paths replayed `exact_safe_cuts` into the
certified master after structural validation only (`BendersCut.from_dict`,
`exact_safe=True`, `source_mode`, artifact-hash match). None of those checks
rebuild the family-specific proof obligation, so a forged JSON cut with a real
conflict set and real artifact hashes is structurally perfect. Local
reproduction (2x1 toy): baseline `1x1=CERTIFIED`; with a forged
`routing_exhausted_nogood` banning the only feasible pose, both the
preloaded-cut path and the checkpoint-resume path returned `INFEASIBLE`, and
resume validation raised nothing.

Patch (conservative fail-closed): `certified_exact` no longer consumes
persisted exact-safe cuts across checkpoint/IPC boundaries. They are counted
(`persisted_exact_safe_cut_replay_input_count`) and explicitly flagged
(`persisted_exact_safe_cut_replay_enabled=False`) in run metadata, but never
enter the master; fresh cuts generated by the current process are unaffected.
Restoring persisted replay requires proof-carrying cut validators (per-family
obligation rebuild), recorded as future work, not a config knob.

Both findings sealed fail-closed. Production defaults are unaffected except
that certified campaigns now enumerate the full oriented domain (correctness
over speed) and regenerate cuts instead of replaying persisted ones. Residuals
carried forward: proof-carrying cut validators for persisted replay (future
work), `EXACT_SUBPROBLEM_PARAMS` on watch, v1 terminal evidence stays
fail-closed.

safety patch and audit anchor update only. It does not claim owner clean-review
