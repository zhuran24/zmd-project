Read order
----------

  1. research_lab/STATE.txt

  4. research_lab/ARCHITECTURE.txt — file-flow, role, or architecture work
  5. research_lab/ATTENTION_AND_REFLECTION.txt — full read for architecture work;
     §3-4 only when the runtime pause reflex fires

shared-Git repair, or a specific operational contract.

Session orientation
-------------------
Before reasoning, state in one sentence:

  "RESEARCH mode: I am producing candidate knowledge for <active campaign>;
   this session cannot grant certification or update U/L."

Then identify one live question. A session may explore several ideas, but it
should have one question whose answer can change the next problem or decision.

Runtime pause
-------------
The methodology is loaded at entry, then ordinary work should focus on the
object. Do not reread doctrine after every step. When the memory reflex
`REFLEX:RESEARCH-PAUSE` fires, read ATTENTION_AND_REFLECTION.txt §3-4 and perform
the one-screen pulse before opening the next experiment. Only a changed direction
or live question needs a durable STATE update. Every durable file/link still gets
the lightweight placement check in §5; that does not trigger a pause by itself.

Where work goes
---------------
  tracked experiment source / small fixtures:
      research_lab/campaigns/<campaign>/experiments/

  durable campaign conclusions and their effect on the next question:
      research_lab/campaigns/<campaign>/RESULTS.txt

  reusable method that has survived more than one campaign:
      research_lab/methods/  (create only when earned)

  logs, solver dumps, caches, temporary models, raw notebooks, large output:
      research_lab/local/

  candidate ready for independent certification review:
      research_lab/promotion/<packet-id>/

Before committing
-----------------
  * Re-read the active campaign success object and truth boundary when the claim
    could affect campaign scope or completion.
  * For every durable file/link, apply the lightweight attention placement check:
    audience, frequency, half-life, induced behavior, link intent/depth, one truth source.
  * Keep the commit to one coherent research change.
  * Use exact pathspecs; do not stage local output.
  * Update STATE only when the current question or campaign position changed.
  * Update RESULTS only when a conclusion changed the next problem or decision.
