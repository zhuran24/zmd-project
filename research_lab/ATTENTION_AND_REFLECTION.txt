ZMD RESEARCH ATTENTION AND REFLECTION
=====================================

Status
------
This file is the canonical runtime-attention contract for the research tree. It
is not another methodology, charter, approval gate, or research report.

Three major direction corrections occurred only after the owner stopped the
line, even though the relevant principles already existed in the methodology.
The missing object was not another reason. It was a concrete trigger telling the
agent when ordinary continuation must pause and the reasons must be brought back
into working attention.

1. The three entry surfaces have different jobs
------------------------------------------------

AGENTS.md / CLAUDE.md
  Always-on router. They establish role, read order, default attention, hard
  truth boundaries, and short pointers to runtime reflexes. They must remain
  compact. They do not carry changing campaign facts or the full methodology.

Claude Code MEMORY.md and cards
  Always-light reflex layer. It carries stable events that must interrupt work
  while a line is already running. It answers "when must I stop?" Dynamic state,
  experiment counts, and current thresholds do not belong here.

Skill index: /zmd-method and /research-charter
  Deep doctrine layer. It explains why the project works this way, how to reason
  about layers, cuts, evidence, frontier, and research economics. Load it at cold
  start and after context compression; reopen the relevant section when a pause
  exposes a real method dispute. Do not reread the whole doctrine after every
  experiment.

Division rule:
  why and distinctions live in skills;
  when-to-interrupt lives in memory;
  mode and routing live in AGENTS/CLAUDE;
  the complete operational statement lives here.

A fact has one truth source. Higher-frequency entry surfaces point to it instead
of copying it in full.

2. Attention map for the rest of the tree
-----------------------------------------

The three entry surfaces are only the top of the graph. Every durable file and
link below them also changes what a later agent notices, in what order, and with
what apparent authority. File placement is therefore part of the research
method, but not a reason to turn every edit into governance paperwork.

README.md
  Human landmark and repository-role summary. For agents it points to the entry
  command; its directory inventory is not a read order.

.zmd-worktree-mode
  Machine routing contract. It names canonical surfaces and paths; it must not
  carry changing narrative or research conclusions.

research_lab/START.txt
  Cold-start procedure and write destinations. Read on first entry or when the
  route is unclear, not as current state.

research_lab/STATE.txt
  The only current-orientation surface. It carries the endpoint, deepest positive
  witness, one live question, current reflection checkpoint, inflight recovery,
  and a few immediate guards. It is reread every session and is not a ledger.

campaigns/<id>/CAMPAIGN.txt
  Stable campaign contract: success object, scope, standing tension, close
  condition, and truth boundary. Read when entering or changing campaign, when
  completion is disputed, or when the current experiment may have changed the
  campaign's scope. It does not own the live question or current evidence list.

research_lab/PROGRAM.txt
  Stable three-level mission and research principles. Read on first entry,
  changed mission, or dispute about what the tree ultimately serves.

research_lab/ARCHITECTURE.txt
  Stable repository, file-flow, attention, and promotion design. Read for
  architecture work, not to decide an ordinary experiment.

research_lab/ATTENTION_AND_REFLECTION.txt
  Canonical low-frequency attention contract. Read in full for architecture
  work; at runtime read only the pause-trigger and pulse sections when the memory
  reflex fires.

research_lab/CHECKS.txt
  Claim-proportional validation menu. Follow when choosing how strongly to check
  an effect; it is not the research rhythm and does not decide what to study.

research_lab/BASELINE.txt
  Baseline identity and refresh decisions. Read only when importing or comparing
  inherited code/data, not for ordinary campaign orientation.

campaigns/<id>/INPUTS.txt
  Frozen external evidence identities and roles. Read when a claim consumes an
  input or its identity must be checked; a listed input is not automatically an
  active premise.

campaigns/<id>/RESULTS.txt
  Append-only consequential-result ledger. It is queried by result ID, experiment
  ID, topic, or a pointer from STATE; it is never a default front-to-back read.
  Each record's "effect on next problem" is historical after a later result
  supersedes it. Only STATE owns the current next problem.

campaigns/<id>/experiments/<id>/
  One experiment's tracked question, source, checker, compact result, and local
  effect. Its "next problem" records what that experiment caused at the time; it
  does not remain current merely because the file is opened later.

campaign journals
  Reasoning archaeology and chronology. Read when reconstructing how a choice was
  made, auditing inertia, or recovering lost rationale; do not use them as current
  status or as stronger evidence than machine artifacts.

campaign-level direction, collision, review, and identity-audit files
  Frozen arguments or audits for a named dispute. Read when that representation,
  premise, or evidence identity is challenged. They may explain why a route was
  chosen, but they do not become current merely by sitting near CAMPAIGN.txt.

research_lab/methods/
  Reusable methods that survived materially different contexts. Load only when a
  current question matches the method's trigger; a method file is not an
  instruction to apply the method everywhere.

METHOD_ORIGIN.txt and STANCE_ORIGIN.txt
  Owner-origin and stance archaeology. Read when returning to the original feel,
  resolving interpretation drift, or revising doctrine; not on every session.

HISTORICAL_REFERENCE_REGISTER.txt
  Question-routed pointer index into the read-only material tree. It is a lookup
  surface, not a default reading list and not a truth source.

promotion/
  Frozen interface objects for certification. Read or write only when a selected
  result is crossing the research/certification boundary.

src/, rules/, specs/, docs/, and tracked historical artifacts
  Code and library material reached from a concrete question, CodeGraph, an
  evidence pointer, or an authority lookup. Their inherited prominence in the
  repository does not make them default attention.

research_lab/local/
  Raw runs, caches, dumps, temporary models, large receipts, and one-off reviews.
  Presence here does not make a conclusion durable and no default-read file may
  cite a local path as its sole truth source.

2A. Links are load instructions
-------------------------------

A link is not neutral bibliography. On a high-frequency surface it is an
instruction to spend attention, and its wording determines whether a later agent
reads now, reads only on a trigger, treats the target as evidence, or merely knows
where output belongs.

Use these link intents in prose rather than inventing a metadata bureaucracy:

  READ NOW
    Required to orient the present session. Keep this set tiny; normally STATE is
    the only research file in it.

  READ WHEN
    Follow only on a named event: campaign entry, method dispute, pause trigger,
    baseline refresh, recovery, promotion, or a specific evidence question.

  LOOKUP / EVIDENCE
    The target supports a claim or identity. Read the smallest relevant section;
    do not absorb its old narrative as current state.

  SOURCE OF TRUTH
    Names where a fact is authoritative. Authority does not imply default-load.

  RECOVERY
    Follow only when an inflight handle, failed run, or handoff requires it.

  WRITE TARGET
    Says where a new artifact belongs. It is not a reading recommendation.

High-frequency files must not contain naked links to long cumulative documents.
They name the trigger, purpose, and preferably the section, result ID, experiment
ID, or query. Critical runtime information should be reachable in at most two
hops from an entry surface. Evidence files may link widely because they are
queried after the question is already known.

Links also have direction. Current surfaces may point downward to stable scope or
frozen evidence. Old experiment records and journals may describe the next
problem they caused at the time, but they never point upward with authority to
replace STATE. A generated index must not become a second truth source merely
because more agents see it.

3. Mandatory pause triggers
---------------------------

The pause happens before opening the next experiment or abstraction, not after a
long report has already rationalized the continuation.

P1. Same-language third step
  Before a third consecutive consequential experiment that preserves the same
  frozen skeleton/context, consumer depth, and primary success signal, when the
  previous two did not advance the deepest positive witness.

P2. Two account-only results
  After two consecutive consequential results that moved only the knowledge-
  leverage or research-machine account, before spending a third result without
  named frontier or deeper-witness movement.

P3. UNKNOWN continuation
  Immediately when the proposed response to UNKNOWN is only more time, another
  seed, solver profile, threshold, cut batch, atlas, or representation layer,
  without a new semantic variable, direct consumer, or orthogonal control.

P4. Unconsumed positive object
  Before building another abstraction above a positive geometry, witness,
  finite basis, atlas, or interface object that has not yet been sent to the
  next real consumer it was meant to serve.

P5. Interface inflation
  Before compiling another interface layer when the current cut/atlas/signature
  store is growing while cross-context reuse, transfer, or discrimination stays
  weak. A smaller state count alone is not deeper progress.

P6. Skeleton monopoly
  After three consequential experiments inherit the same skeleton or local
  basin without an orthogonal constructor/control, even if the metric or local
  representation changed between them.

P7. Stop or contradiction signal
  Immediately when a preregistered stop condition fires, an owner asks to look
  back, a new result contradicts the current narrative, or an evidence identity
  changes under the line.

P8. High-attention file change
  Before creating a new default-read file or editing AGENTS.md, CLAUDE.md,
  MEMORY.md/core memory cards, a skill description/body, START.txt, the STATE
  schema, .zmd-worktree-mode, or this attention architecture.

These are event triggers, not a per-step self-review ritual. Normal research
continues at full speed until one fires.

4. The reflection pulse
-----------------------

The pulse fits on one screen and should usually take less time than starting the
next experiment. Answer only these questions:

  1. What is the deepest positive witness/consumer layer now, and what was it at
     the last checkpoint?
  2. Did the last results change the problem or consumer, or only the instrument,
     representation, evidence store, or explanation?
  3. Which of the three accounts moved: frontier, knowledge leverage, research
     machine?
  4. What assumption, skeleton, metric, or interface has silently become
     furniture rather than a tested choice?
  5. What is the cheapest direct-consumer attempt or orthogonal control now?
  6. Decision: CONTINUE, BRANCH/CONTROL, or STOP/SWITCH, with one sentence why.

Do not create an experiment number, dossier, or long reflection report merely to
perform the pulse. Do not reread both full skills unless the answers reveal a
method conflict.

Recording rule:
  unchanged CONTINUE
    Continue immediately. No durable file is required.

  changed direction, live question, stop condition, or tested assumption
    Update STATE.txt's Reflection checkpoint and Live question. Put supporting
    evidence in the campaign result/experiment that earned the change.

  architecture or entry-surface change
    Update this file and ARCHITECTURE.txt; keep high-frequency pointers short.

5. Attention effect of every durable file change
------------------------------------------------

Before creating or modifying any durable file or durable link, consider six
things. This is a mental placement check, not a form to fill out:

  audience
    Which agent/role is expected to encounter it?

  load frequency
    Every prompt/session, every campaign entry, only on a matching trigger, or
    only as evidence lookup?

  half-life
    Stable doctrine, stable reflex, live state, consequential result, historical
    reasoning, or raw run?

  induced behavior
    What will a future agent do earlier, later, more often, or stop doing because
    this file or link is visible?

  link intent and depth
    Is the pointer READ NOW, READ WHEN, LOOKUP, SOURCE, RECOVERY, or WRITE TARGET?
    Does it send the reader through unnecessary intermediate indexes or into a
    long file without a section/query?

  identity and duplication
    Where is the one truth source, and which higher-frequency files should only
    point to it? Could this new summary silently become a competing current state?

Placement defaults:
  role/mode/read order                 -> AGENTS/CLAUDE
  stable runtime interrupt             -> memory card + pointer here
  method/charter reasoning             -> skill
  current endpoint/question/checkpoint -> STATE
  campaign scope/success object        -> CAMPAIGN
  consequential conclusion             -> RESULTS + experiment record
  raw/reproducible runtime output       -> local
  file-flow architecture               -> ARCHITECTURE

High-frequency files must be shorter and more pointer-rich than low-frequency
evidence files. A new idea should enter at the lowest-frequency layer that still
reaches the agent at the moment it matters.

6. Anti-goal
------------

The purpose is to make methodology fire at the right moment, not to keep the
agent staring at methodology. Respecting the charter means doing research with
its distinctions present in the background, then surfacing them when an event
trigger says the current continuation may have become automatic.
