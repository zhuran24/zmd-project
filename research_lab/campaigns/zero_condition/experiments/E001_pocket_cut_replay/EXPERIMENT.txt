EXPERIMENT E001: pocket judgment replay through the repartitioned interface
=========================================================================

Question
--------
After explicitly transporting the proved four-pose blue-iron pocket judgment
from instance-labelled evidence into the pose-bool master's group-occupancy
language, does one sound cut produce a replacement zero-condition geometry, and
which interface family is then the first to reject or admit it?

This is one causal experiment.  The only change to placement plus power is the
single proved pocket nogood.  The later interface ladder diagnoses the resulting
geometry; it does not add further feedback to the master in this run.

Competing readings
------------------
A. The point cut has almost no leverage: it only permutes symmetric instance
   labels or makes a tiny local move, and the replacement returns to the same
   source-trap family.

B. The cut changes real group-level geometry, but the replacement still dies
   before exact routing.  The first rejecting family tells us whether the next
   language should be static port domains, terminal uniqueness, or free-space
   component support.

C. The replacement survives the cheap interface families and reaches exact
   simultaneous routing.  In that case the wall has moved from coarse topology
   to path coexistence, and the next cut language must be derived from the exact
   routing failure rather than from more front-blocked events.

Cheapest faithful test
----------------------
Build the unchanged no-ghost pose-bool placement-plus-power master, add exactly
one constraint corresponding to the independently checked pocket judgment, use
the old A1 assignment only as a non-feasible hint, and solve for a replacement.

For a replacement, rebuild binding three times on the same fixed occupancy:

  1. static port-domain filtering only;
  2. the same model plus duplicate terminal-key constraints;
  3. the same model plus duplicate keys and commodity component support.

Only a candidate surviving stage 3 is sent to ordinary routing precheck and the
exact routing solver.  This ordered ladder answers where the new geometry first
dies instead of bundling all interface logic into one opaque rejection.

Truth boundary
--------------
The run can measure the leverage of one checked judgment, identify the first
rejecting interface family for its replacement, and expose mismatches between
proof object space and consumer literal space.  It cannot certify a lower bound,
prove the no-ghost problem infeasible from UNKNOWN, authorize a production cut,
or establish that one observed death family is globally complete.

Decision effect
---------------
* A named-instance/group-literal transport failure blocks the cut and becomes an
  outer-loop object-space defect, not a solver result.
* A static-port rejection directs the next family toward domain compilation and
  minimal blocker explanations.
* A terminal-key rejection requires auditing that rule's exact semantics before
  any placement feedback.
* A component rejection justifies commodity/core localization and a placement
  obstacle explanation, not more point binding nogoods.
* Exact routing entry moves the research seam downstream to simultaneous path
  coexistence and its own rejection language.
* A complete routing witness immediately takes priority over architecture work
  so the remaining flow, strict, and game-side obligations can be closed.
