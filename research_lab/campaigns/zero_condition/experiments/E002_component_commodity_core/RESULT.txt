Interpretation
--------------
The E001 replacement is not being killed by one exceptional commodity. Every
routed production relation separately lacks a component-compatible binding in
this fixed geometry. This is strong evidence for a global fragmentation regime,
not evidence that 19 unrelated local cuts should be emitted.

The result still leaves one important alternative open: the component compiler
could be stronger than the production routing precheck over unobserved binding
assignments. The next experiment must use a differently shaped formulation and
compare its optimal witness directly with run_exact_routing_precheck before the
19/19 result is used to redesign placement.

Hidden tool defect
------------------
OR-Tools 9.15 / Python 3.13 returned a stale literal from
SufficientAssumptionsForInfeasibility() after assumptions were changed and the
same CpModel was re-solved. The behaviour was reproduced on a two-guard toy model
and in E002.

Accordingly:

* the sufficient-core API was queried only on the first all-true infeasible solve;
* subsequent status classifications did not consume that API;
* every singleton status was confirmed by a fresh model rebuild.

The stale-core defect does not invalidate the fresh INFEASIBLE statuses. It does
invalidate repeated-solve sufficient-core extraction as a trustworthy research
or certification surface in this runtime.

Truth boundary
--------------
This result concerns the fixed E001 replacement occupancy and the frozen
front-domain, terminal-uniqueness, and component-support binding model. It is not
a whole-layout infeasibility proof, a placement cut, an exact-routing result, or
a proof that one global backbone topology is necessary.

Decision effect
---------------
Do not continue commodity-by-commodity cut mining from this layout. First verify
the component rule by an independent mismatch-minimization formulation. If every
commodity still has a strictly positive minimum mismatch, measure the scale and
shared geometry of the unavoidable orphan components. Small repeated boundaries
support a family compiler; broad shared boundaries support an explicit
permeability resource or constructive backbone representation.
