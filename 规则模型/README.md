# 规则模型

把《明日方舟：终末地》游戏规则.txt（仓库根目录，下称规则文件）写成 Lean 4 代码。代码就是规则要表达的那个模型：规则文件的每个名词在这里有一条定义，规则没写清的地方在这里写不下去，写不下去的地方记在 [边界清单.md](边界清单.md)。

状态：框架立起来了，判定还没写。已经有的：配方、时间单位、两种轮询；不带格子坐标的通道、元件、运输带、终点、终点的时刻、次序；游戏记着的每样东西（状态，13 样）、会改变它的每种事（操作，13 种）、每种事发生以后每样东西怎样变（作用，除走一步外 156 格，每格都写了着落，见 [格子表.md](格子表.md)）。还没有的：一步里的五条判定（现在只定了先后和各自拿什么、给什么）、组和级别、格子和端口。哪些名词有了定义，用 `python3 查名词.py -v` 看。

## 怎么跑

Lean 4 经 elan 装在 `~/.elan`，版本由 `lean-toolchain` 定（v4.35.0），不依赖 Mathlib。

```
cd 规则模型
lake build              # 编译全部模块；定理在这一步检查，回放里的 #guard 对不上就编译失败
python3 查名词.py -v     # 每条声明和规则文件对得上吗；还有哪些名词没写
python3 查格子.py        # 「每样东西 × 每种事」每一格有没有着落；重新生成 格子表.md
```

## 做法

1. **只存游戏里原本就有的东西，其余都算出来。** 存的是：建了什么、建在哪、建的先后、各项设定；每个物品格里的物品和它停了多久；轮询记着什么；制造进度；物品准入口的计数。通道、接通先后、元件、运输带、终点、次序、组、级别都写成从这些算出来的函数。规则里最容易藏东西的就是这些算出来的量，直接存一份就把它们藏回去了。
2. **每个函数对所有输入都要有结果，不留逃生口。** 不用 `partial`、`sorry`、`panic!`、`get!`，不拿默认值顶替「不会发生」。写到哪一步写不下去，那里就是一条边界，归到四类之一，记进边界清单：
   - 规则推得出：写成定理，证出来；
   - 本题不管：写进「合法基地」的条件（成环、断头带这些），在条件之外不要求有结果；
   - 没人知道：做实测；
   - 游戏有确定做法、只是我们不知道（蓝图内部的建成先后、离线重建的先后）：写成显式的参数，结论要对参数的每种取值都成立。
3. **表的先后只用规则定下的先后**（建成先后、接通先后、物品格编号）。规则没定先后的地方不许靠表里碰巧的顺序选一个，否则等于悄悄补了一条规则。
4. **实测和现象清单写成回放**（`Endfield/回放/`），编译时核对。被实测排除的说法也写成函数留着，核对它确实对不上。
5. **规则文件和代码逐行对应。** 每条声明的文档注释第一行，写它对应规则文件的哪一行，六种写法见 `查名词.py` 开头。规则文件改了字，`查名词.py` 会报出引它的声明。

名字用规则文件里的名词。Lean 不认裸的中文标识符，所以都写在 «» 里；局部变量用英文字母。

## 接下来的顺序

框架先行：先把「记着什么 × 什么事会改它」的格子摆全，再往格子里填。

1. （已有）状态、操作、作用：除走一步外的每一格都有着落。
2. 把 `待写` 里的五条判定一条一条换成真的定义。每换一条，写明它读状态的哪几样、改哪几样，「走一步」那一列也就展开了。次序：
   - 组、组的时刻、级别（只用历史，不等别的）；
   - 元件各组的移动判定、非运输单位各组的移动判定、输入判定（要物品格的上限、滞留、物品准入口收不收）；
   - 结束制造判定、开始制造判定（等「缓存格」那一行定下来）；传输。
   打通以后，分流器出口变动的八组、现象清单第 1、3、4、19、20、24 条都改成直接用 `作用` 回放。
3. 规则文件里的「一直」「同时」「随时」各落在判定顺序的哪一条，逐个写明（「物品一直在尝试移动」「所有单位同时进行」「设定随时更改」）。
4. 每一处「从一堆里选一个」，证明不会并列（终点的时刻、组的时刻、级别、接通先后）。
5. 接上格子：单位的位置和朝向、端口、「正对紧贴」形成通道、接通的先后；「建一个单位」合成一个操作；供电。
6. 顶层定理：合法基地上，每种操作都有结果，而且结果不依赖规则没定的先后。
