# 规则模型

把《明日方舟：终末地》游戏规则.txt（仓库根目录，下称规则文件）写成 Lean 4 代码。代码就是规则要表达的那个模型：规则文件的每个名词在这里有一条定义，规则没写清的地方在这里写不下去，写不下去的地方记在 [边界清单.md](边界清单.md)。

状态：一整步能走，要证的定理都证了，格子层接上了。模型分两层：

- 里层不带位置：配方、时间单位、两种轮询；通道、元件、运输带、终点、终点的时刻、次序、组、组的时刻、级别；游戏记着的每样东西（状态，13 样）、会改变它的每种事（走一步里的 6 种事和两步之间的 13 种操作），每种事发生以后每样东西怎样变，一共 247 格，每格都写了着落，见 [格子表.md](格子表.md)；判定顺序的六条和传输；18 条定理（见下面「定理」）。这一层里一条通道就是「从哪个单位到哪个单位」，建成、接通、拆除是一件件给进来的事。
- 外层是格子（`Endfield/格子/`）：摆件的位置和朝向、端口、「正对紧贴」形成通道、一个摆件建成时几条通道接通的先后、供电、蓝图、离线重建。它只负责从位置算出建成、接通、拆除这些事，交给里层去做。

早先的回放不带位置，接通先后是照规则手排的；`回放/格子*.lean` 带位置，接通先后是算出来的。还没有的：由格子层证出里层定理的前提（端口数合）。哪些名词有了定义，用 `python3 查名词.py -v` 看。

## 怎么跑

Lean 4 经 elan 装在 `~/.elan`，版本由 `lean-toolchain` 定（v4.35.0），不依赖 Mathlib。

```
cd 规则模型
lake build              # 编译全部模块；定理在这一步检查，回放里的 #guard 对不上就编译失败（两份走步的回放要算一两分钟）
python3 查名词.py -v     # 每条声明和规则文件对得上吗；还有哪些名词没写
python3 查格子.py        # 「每样东西 × 每种事」每一格有没有着落；重新生成 格子表.md
python3 查证明.py        # 命题.lean 里的每一条都证完了吗、有没有留空（要先 lake build）
```

## 做法

1. **只存游戏里原本就有的东西，其余都算出来。** 存的是：建了什么、建在哪、建的先后、各项设定；每个物品格里的物品和它停了多久；轮询记着什么；制造进度；物品准入口的计数。通道、接通先后、元件、运输带、终点、次序、组、级别都写成从这些算出来的函数。规则里最容易藏东西的就是这些算出来的量，直接存一份就把它们藏回去了。
2. **每个函数对所有输入都要有结果，不留逃生口。** 不用 `partial`、`sorry`、`panic!`、`get!`，不拿默认值顶替「不会发生」。写到哪一步写不下去，那里就是一条边界，归到四类之一，记进边界清单：
   - 规则推得出：写成定理，证出来；
   - 本题不管：写进「合法基地」的条件（成环、断头带这些），在条件之外不要求有结果；
   - 没人知道：做实测；
   - 游戏有确定做法、只是我们不知道（蓝图内部的建成先后、离线重建的先后）：写成显式的参数，结论要对参数的每种取值都成立。
3. **表的先后只用规则定下的先后**（建成先后、接通先后、物品格编号）。规则没定先后的地方不许靠表里碰巧的顺序选一个，否则等于悄悄补了一条规则。
4. **实测和现象清单写成回放**（`Endfield/回放/`），编译时核对。被实测排除的说法也写成函数留着，核对它确实对不上。
5. **规则文件和代码逐行对应。** 每条声明的文档注释第一行，写它对应规则文件的哪一行，六种写法见 `查名词.py` 开头。规则文件改了字，`查名词.py` 会报出引它的声明。

## 定理

规则写成代码以后，有两种地方编译器拦不住：

1. 规则说「一直」「同时」，代码只能排出一个先后（一段带子里两件货都能前移，规则没说谁先，代码只能挨个挪）；
2. 规则说「取最早的」「按级别从高到低」，代码得从几个里挑一个（两个组级别一样时，排序不报错，悄悄让排在前面的先走）。

这两种地方不处理，代码就替规则做了决定，等于又藏了一条规则。所以每一处都立一条命题、证出来：第一种证「换个先后结果一样」，第二种证「不会并列」。

- `Endfield/命题.lean`：17 条命题，每条只有一句陈述。改它的一个字，就是改了要证的东西。
- `Endfield/合法基地.lean`：命题拿来当前提的几样（合规、端口数合、走得通、合法、有电只看历史），都写成能算的判断，回放里的布局可以直接拿来验。
- `Endfield/证明/`：证明，每条命题（或相关的几条）一个文件；`总.lean` 把它们收成 17 条定理，类型就是命题本身。
- 顶层的一条：合法基地上，游戏让做的操作都有结果，走步时没有哪个组被跳过，走一步的结果不看规则没定的先后。

每条定理说的是什么、用了哪些前提、还有什么没证，见 [边界清单.md](边界清单.md) 的「已证的定理」「还没证的」。

加一条定理的步骤：

1. 在 `Endfield/命题.lean` 写陈述（`def «名» : Prop := …`）。先拿回放里的布局用 `#eval` 试算，试出反例就是一条边界，不用证了。
2. 证明写在 `Endfield/证明/<名>.lean`：`import Endfield.«证明».«基础»`，主定理 `theorem «名» : «命题».«名»` 放在 `namespace Endfield.«证明»` 里，辅助引理一律 `private`。证明要用到另一条还没证的命题时，把那条命题写成主定理的参数。
3. 在 `Endfield/证明/总.lean` 加一条 `theorem «定理».«名» : «命题».«名»`，把参数用已证的定理填上。
4. `lake build`，再 `python3 查证明.py`。

名字用规则文件里的名词。Lean 不认裸的中文标识符，所以都写在 «» 里；局部变量用英文字母。

## 接下来的顺序

框架先行：先把「记着什么 × 什么事会改它」的格子摆全，再往格子里填。

1. （已有）状态、操作、作用、走一步里的六种事：每一格都有着落。判定顺序的六条和传输也写了。
2. （已有）实测和现象清单的回放：现象清单 29 条里，第 3、4 条在例子里走过，第 5、10、21 条要等格子（要靠端口位置定同时接上的先后），其余 24 条都有回放；实测-2026-10-08 到 2026-11-10 各节也都有回放。没摆的只有要格子位置才能表达的部分（桥接器面板上读到的是哪一格、带上各件的位置）和断头线路。回放对不上的地方就是规则或模型的问题；现在剩下的都列在边界清单「还没定的」里。
3. （已有）证明：规则说「同时」「一直」的三处换个先后结果一样；每一处「从一堆里选一个」不会并列（终点的时刻、组的时刻、级别）；同组各起点元件次序相同；顶层定理（合法基地上，每种操作都有结果，而且结果不依赖规则没定的先后）。顶层定理的前提里，「端口数合」现在是假设。
4. （已有）接上格子：摆件的位置和朝向、端口、「正对紧贴」形成通道、接通的先后；「建一个摆件」是一个操作；供电；`待写` 里的三样；蓝图、离线重建。现象清单第 5、10、21 条有了带位置的回放。
5. 由格子兑现顶层定理的前提：从位置算出来的历史合规、端口数合；场上的通道正好是正对紧贴的那些。
