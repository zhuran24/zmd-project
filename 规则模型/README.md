# 规则模型（Lean 4 状态机与形式化证明）

本目录把上一级目录的《明日方舟：终末地》游戏规则.txt（下称规则文件）写成 **Lean 4 状态机模型**（Lean `v4.35.0`，不依赖 Mathlib），服务于整座基地的精确求解目标：在仓库能同时接收两种成品时，调试后每个可达循环态须平均每 tick 至少向仓库交付 0.6 个高容谷地电池与 0.55 个精选荞愈胶囊（2026-11-27 owner 确认维持该目标不变），在此前提下最大化短边至少 6 格的空矩形面积（同面积时取短边较长者）。

工程目标是让规则文件中的每个名词都有可追溯的形式化定义（`python3 查名词.py -v` 列出已有逐字对应定义行的名词，以及尚缺这种定义行的名词；有些机制由辅助声明或组合规则表达，具体实现可查源码）；写代码时发现规则原文没写清、与模型存在差异或需要实测/裁定的地方，统一记在 [边界清单.md](边界清单.md) 中。

## 模型结构与当前状态

目前模型已实现完整的单步推进与外层网格几何，`Endfield/命题.lean` 中立下的命题已全部证明完毕（零 `sorry`，用 `python3 查证明.py` 核验），全量编译时自动核对 `Endfield/回放/` 下各回放模块的 `#guard` 断言（涵盖游戏实测读数、社区现象清单、模型预计和模型自检；另有 `Endfield/回放/工具.lean`、`Endfield/回放/格子工具.lean` 两份回放辅助文件）。模型分为两层：

- **里层（不带网格位置的拓扑与状态转移层）**：
  - 包含配方、时间单位、两种轮询，以及从历史算出来的通道、元件、运输带、终点、终点的时刻、次序、组、组的时刻和级别；
  - 把游戏运行中记着的 **13 项状态字段**与会改变它的 **20 种事**（走一步里的 6 种内部动作 ＋ 两步之间的 14 种外部操作）逐项对照共 **260 格**——具体的状态更新表达式写在 Lean 源码中，自动生成的 [格子表.md](格子表.md) 展示每一格所属的七类着落标记及当前各项统计（据、实测、没测、未定、待写、约定、无关，其中「无关」在表中显示为空）；
  - **单步判定顺序与传输**：规则正文「判定顺序」第 **1～6** 条依次规定第一次汇流器输入判定、元件各组移动判定、第二次汇流器输入判定、非运输单位各组移动判定、结束制造判定、开始制造判定；现行模型（`Endfield/判定.lean` 的 `一步于`）在第 1 条前先做整理（带内物品前移等），随后依次执行元件各组移动判定、非运输单位各组移动判定（采用正文的 `每步判两次` 时，Lean 在两段移动中遍历到非分流器通往汇流器的通道时，分别用步初整理后的 `s1`、元件移动结束后的 `s3` 现算第 1、3 条的输入判定，供第 2、4 条使用；每次移动判定成功移走一件货后，也立即调用整理把带内物品前移到不能再移为止，然后才判下一条通道；协议储存箱满足无线传输条件时，在该箱被选取时按参数位置插入传输）、结束制造判定、开始制造判定，最后在第 6 条后推进计时（本步结束制造才转入取货物品格的成品，最早在下一步的移动判定中送出）；正文有意略去或模型未检查的其余边界见 `../不写进规则的.txt` 与 [边界清单.md](边界清单.md)；
  - 在这一层里，一条通道只记「从哪个单位连到哪个单位」：建、收与放蓝图逐件传入**建成、接通、重接、拆除**四种拓扑事件；离线重建则一次传入整段重建历史，保留货物与 `来处`、已停步数、轮询、制造进度、协议储存箱冷却和物品准入口的 `拍`，准入口的累计已收及各名额剩余步数由 `未定.离线后的计数` 给定。

- **外层（`Endfield/格子/`，70×70 网格与端口几何层）**：
  - 定义 70×70 基地网格、各种摆件的占地大小与朝向、端口位置、**成通道条件（不同单位的取货端口与存货端口正对紧贴，且至少一方是运输单位时，自动形成通道）**、同一摆件建成时各端口接通的先后（其中桥接器各边先后按 2026-11-12 实测随朝向旋转，部分跨轴取货朝向由旋转换算，正文「桥接器」按顺时针给四边编号，「接通」第 3 条规定存货端口依第 1、3、4、2 边接通，取货端口依第 3、1、2、4 边接通；协议核心先存货后取货，同类端口按 `接通先后` 参数给定的排序号排列，同号时按上、右、下、左方向编号再按边上格号递增破同，该并列破同属模型约定）、供电桩 12×12 覆盖判定、蓝图批量建造与离线重建（题面要求全部单位由蓝图建成，可分多张，单张范围不超过 50×50 格，见限制句台账 `S18`；模型 `放蓝图` 逐张检查摆放和图内建成先后，50×50 尺寸上限、同时开启每 5 tick 上限的准入口 50 个上限及孤立准入口禁放由题面验收另查）；
  - 同时具体实现了里层 `待写` 接口留出的三项钩子（玩家放货放进哪一格、供电状态判定，以及协议核心和仓库取货口的取货端口编号——格子层对这两类单位的可达出货通道保证能找到对应编号）；
  - 外层在建、收和放蓝图时从网格坐标算出**建成、接通、重接、拆除**事件逐件交给里层执行（同一次建、收或放蓝图是一个外层操作，其事件连续执行，中间不能走步或插入其他操作），离线时按给定先后算出整段重建历史再一次调用里层的 `离线` 操作（建、收一格传送带时，格子层会沿受影响的连续带段查找仍然存在的原有带端通道，对找到的通道各发一次「重接」将其接通时刻更新并排到末尾；复现已送过货的非运输单位新接多格出口带时，回放从远端往单位方向建带，避免逐格接长触发额外重接清空该组的「已移动」）。

早先不带位置的回放（如 `Endfield/回放/配件机和带子.lean`）通道接通先后是照规则手排的，供电直接用工具函数赋予，不验几何贴合；带网格位置的回放按坐标摆放：`Endfield/回放/格子.lean` 同时核对从位置算出的接通先后与走步结果，其他文件各核各自断言的量（如 `Endfield/回放/供电范围.lean` 只核供电布尔值）。

## 常用编译与核查命令

Lean 4 经 `elan` 装在 `~/.elan`，版本由 `lean-toolchain` 锁定（`v4.35.0`），不依赖 Mathlib。在 `规则模型/` 目录下运行：

```bash
lake build                   # 编译默认目标 Endfield 导入链中的全部模块、检查定理证明，并执行回放 #guard 断言（其中两份走步回放要算一两分钟）
python3 查名词.py -v          # 检查代码声明注释与 ../《明日方舟：终末地》游戏规则.txt 的对应情况，列出尚缺逐字定义行的名词
python3 查格子.py             # 检查「13 项状态 × 20 种事件」共 260 格是否均标有合法着落标记，并重写 格子表.md（只读检查加 --check）
python3 查证明.py             # 检查 命题.lean 中的全部命题是否均已证完且只用到 Lean 自带标准公理（需先 lake build）
```

## 五条建模准则

1. **只存原始状态，派生量由历史与状态算出**：
   - 里层状态只保存：供当前布局使用的拓扑事件历史（平时逐件追加，离线时用从空场地生成的重建历史整体替换；当前布局与建成先后由它算出）、各项设定与各物品格里的物品；有货的运输格另记已停步数（其余格计时归零）与可空的 `来处`（从另一物品格移入时记该格，从仓库移入时记为空，记录的来源单位拆除时也清空）；按物品种类记录的仓库件数；轮询记忆（其中汇流器的 `进货上次` 保存上次通过非分流器进口收货时该通道在当时进货表中的下标，分流器直接送货不更新它）；制造进度；无线传输冷却；物品准入口的计数与建成后走过的步数（`拍`）。外层另存场地上各摆件的坐标与朝向。
   - 通道、接通先后、元件、运输带、终点、次序、组、级别都不单独存为可变状态，而是写成从历史算出的函数（规则最容易藏歧义的地方就在这些派生量里；在历史不变的连续多步推进中，可预先算好一张 `判定表` 供各步复用，见 `Endfield/判定.lean` 与 `Endfield/回放/工具.lean`）。
2. **全函数无逃生口，边界分四类归档**：
   - 不用 `partial`、`sorry`、`panic!`、`get!`，不拿随意默认值顶替“不会发生”。写代码卡住的地方归入 [边界清单.md](边界清单.md) 的四类之一：
     1. 规则本身推得出 → 立成命题证出来；
     2. 本题通过合法基地前提排除的情形（如纯传送带环，以及连着通道却到不了末端元件的断头线路） → 写进 `Endfield/合法基地.lean` 的前置条件，在条件之外不要求有结果；
     3. 游戏真实行为未知 → 做实测（协议核心端口先后等目前无法实测的在清单里标明）；
     4. 涉及规则条文改写或本题口径取舍 → 登记待 owner 裁定（自行核查或派席位核对规则条文依据、排查假禁令或盘点未测项时，须先查 `../求解器/规则修订/2026-11-26-限制句核对/README.md`——第一节的核对规矩必读，逐条依据查第三节，快照之外的补充事实查第四节；派工时须写进任务书，已有记录的确认事项不再重复问）。
   - 尚未掌握的机制分两种处理：有的先照一个自然做法实现并在 `边界清单.md` 登记未测范围（如几条带进箱或进制造单位时的 `进货上次`）；有的显式做成参数——蓝图先建全部非普通传送带摆件（含物品准入口）、再建普通传送带，两类各自内部的先后由外层 `放蓝图` 接收的有序摆件表给定，离线 `重建` 则接收原场地所有摆件的排列而无此两类分组限制；协议核心同类端口的排序号由外层 `接通先后` 给定；里层其余参数放在 `Endfield/框架.lean` 的 `未定` 结构中（共四项：改设定后的计数、离线后的计数、传输排在几组之后，以及专供回放已排除旧说法的 `输入判定都没货时`）。各定理覆盖的参数范围以 `Endfield/命题.lean` 陈述的前提为准；依赖未知机制的求解结论须覆盖其所有容许取值（尤其是蓝图两类各自内部的建成先后及所有可能的离线重建先后；已被实测排除、仅供反例回放的旧说法除外）。
3. **禁止靠列表碰巧的存储顺序偷排先后**：排序使用有出处的次序或显式参数（如建成先后、接通先后、物品格编号、组的级别、非运输单位已移动通道最近一次移动物品的先后、桥接器实测边序、协议核心端口排序号参数）；无线传输按物品格编号送、制造单位优先用编号较小的空存货格均属未测取法（见 `边界清单.md` 的传输条目与「还没证的」空格互换条目），协议核心同类端口排序号相同时按方向和边上格号破同（见 `Endfield/格子/几何与端口.lean` 的 `排端口`）。规则未指定先后且结果应当相同时，证明换序不变；纯读取等已由写法保证的情形（如各汇流器输入判定互不相干）在说明中交代依据，尚未立命题证明的情形（如两个空存货格互换）记在 `边界清单.md`。
4. **实测与现象写成 `#guard` 回放断言（认清覆盖范围）**：
   - 新增回放模块后，须将其导入 `Endfield.lean`（或确认已由根模块间接导入），`lake build` 才会检查其中的 `#guard` 断言；保留被实测排除的说法，用回放断言核对它在哪些读数上失败（具体实现可见回放中的对照函数，或主模型供回放选用的参数分支）。注意回放只盯各文件实际断言到的情形，未覆盖的分支改坏了不会报警（例如准入口名额曾误写为至少占 38 步，直到补入 11-26 新回放前旧回放全部照常通过）。
   - 现象清单（规律版，回放按它的条号对齐）在 `../求解器/规则修订/2026-10-10-交给GPT/现象.md`，带原始出处的记录在 `../求解器/规则修订/2026-10-08-现象整理/现象.md`：其中 `Endfield/例子/走步.lean` 演算第 3 条的三出口样例并展示第 4 条三路畅通时的一轮均分（未演算满料支路恢复或多级分流）；11-25、11-26 改带实验中使用游戏「移动」操作的几轮（注：11-09 缓存格组五已用移回后产生的连接核对货序）、11-12 桥接器存货端口同轴两头的两组、11-25 桥接器朝向试验的原样放置／放蓝图／移动／复制，以及 11-25 拆除协议储存箱的货物去向（模型在拆除时只清掉箱内货并保留仓库计数）尚未建回放断言；`Endfield/回放/前提.lean` 核出七格双线和蛇形布局整体走不通，`Endfield/回放/桥接器.lean` 仍逐步核对两者可通支路的送货结果及无出口断头布置的全空断言（属合法范围外的模型结果）；11-26 第二节改用末端准入口当闸核对轮询；第 27 条与第 28 条起步头两件在并入新判定顺序时未回真机重测。
5. **声明注释按 `查名词.py` 的七种格式双向溯源**：
   - 除 `Endfield/证明/` 下的 `private` 辅助声明豁免外，每条 `def`、`abbrev`、`structure`、`inductive`、`class`、`theorem` 前都必须有 `/-- … -/` 文档注释，且首行属于 `查名词.py` 开头规定的七种格式之一：规则原文的完整定义行（去掉缩进后逐字相同，例如 `时间单位：tick`）、`据：`、`规则里没有：`（须在 `边界清单.md` 登记）、`工具：`、`回放：`、`例子：`、`框架：`。
   - 注意：`查名词.py` 对规则原文完整定义行做逐字比对，对 `据：` 只检查所引名称是否存在；规则正文改字后，按 `据：` 引用该名词的代码仍须人工复核语义；同理，`查格子.py` 只检查 260 格着落标记齐全合规，不自动验证更新表达式本身写得对不对。

## 定理体系与新增证明规程

把文字规则写成顺序执行的代码时，有两类隐患单靠类型检查拦不住：
1. **规则写「同时」「一直」，代码只能排个先后挨个算**（如带内多件物品前移、各单位同时结束或开始制造、汇流器非分流器进口组遍历）——立命题证在相应前提下**换任何先后结果完全一样**（`有电只看历史` 时各单位制造判定可换序；`带内整齐` 且整理遍数不少于带内通道数时带内通道可换序；汇流器两条命题以 `输入判定都没货时 = 每步判两次` 为前提）；
2. **规则写「取最早的」「按级别从高到低」，代码排序怕遇到并列**——立命题证明：历史合规时，不同组已定义的组时刻和级别**不会并列**；历史还满足每一刻端口数合时，不同终点已定义的终点时刻也**不会并列**；此外证明端口数合时非分流器末端唯一出口、当前布局端口数合时元件的一个组内各条通道起点所在元件次序相同、非运输单位轮询等价于队列。

此外还证明了物品格规矩与两层衔接定理（引用时须注意各自前提）：
- **物品格规矩与配方唯一性**：起始状态历史合规且 `货合规矩` 时，走一步保持 `货合规矩`；里层操作保持性同样要求起始状态历史合规且 `货合规矩`，并要求玩家放货实现守规矩、操作成功（外层格子层的放货实现已证守规矩）（其中缓存格无物品种类与容量上限，但须与制造进度一致）。从空基地经格子层操作可达的状态均满足 `货合规矩`，其上任一制造单位的存货物品格至多符合规则文件现有 18 条配方中的一条。
- **里层与格子层两条顶层定理（注意 `布局.走得通` 条件）**：
  - 里层顶层定理以 `历史.合法`（含历史合规、每刻端口数合、当前布局走得通）与 `有电只看历史` 为前提；
  - 格子层在从空基地按位置操作可达的状态上，分别由具名命题 `格子层的单位和通道`、`格子层的历史合规`、`格子层的历史端口数合` 证出通道对应关系及前两条里层前提；在此基础上，`格子层的顶层` 证明四项合取结论：货合规矩、位置上操作有结果的充要条件、单步结果不依赖未定枚举先后，以及在 `布局.走得通` 成立时每个组都有级别。**唯有 `布局.走得通` 不能单由几何位置推出**（照位置能建出断头带），候选布局须参照 `Endfield/回放/前提.lean` 逐个检验 `布局.走得通`。
- 登记在 `Endfield/命题.lean` 中的全部命题由 `Endfield/证明/总.lean` 统一导出（其中里层与格子层各有 1 条顶层定理）；另有两条早先证好的结果——「走一步不改历史，只有改布局和离线改历史」（`Endfield/走步不改历史.lean`、`Endfield/作用.lean`）及「操作做得了当且仅当作用有结果」（`Endfield/作用.lean`）——逐条白话说明见 [边界清单.md](边界清单.md)「已证的定理」与「不在命题文件里、早先证的两条」。

**命题复核、派发分工与命名规矩**：
- `Endfield/命题.lean` 每条只有一句陈述，改一个字就是改了所证命题，绝不能为了迁就证明去改它。由于命题陈述由单人起草，每批新命题都另派独立模型审视（前提是否可满足、结论是否为空话、中文说明与公式是否一致、对照规则逐行查漏），审出的意见再交另一家模型交叉核对。
- **主会话与受派证明席位的分工**：
  1. 主会话在 `Endfield/命题.lean` 按行首 `def «名» : Prop := …` 格式写下陈述（先在回放布局上用 `#eval` 试算，试出反例就是一条新边界，不必去证）；
  2. 可派给其他席位证明：主会话在任务书中给出 [派证明的说明.md](派证明的说明.md) 的路径、命题名、证明文件名、获准作为假设引用的命题及一段思路；受派方只在指定的 `Endfield/证明/<名>.lean` 中（`import Endfield.«证明».«基础»`，在 `namespace Endfield.«证明»` 内写 `theorem «名» : «命题».«名» := …`，把实际用到的获准假设写在冒号前作显式参数，本文件内部辅助引理写 `private`）证明原命题，只用 `lake env lean Endfield/证明/<名>.lean` 单文件检查，正常完成时交回完成情况、文件路径、含所用假设的主定理完整签名及末次检查输出（通过写「无输出」）；若发现命题不成立或缺前提，交回具体反例或缺的前提而不改 `Endfield/命题.lean`；模型定义修改导致旧证明失效时同样派回修订；
  3. 主会话收回后在 `Endfield/证明/总.lean` 导入证明文件，并在已有的 `namespace Endfield.«定理»` 内写 `theorem «名» : «命题».«名» := …` 用已证定理填齐参数，亲自重跑 `lake build` 与 `python3 查证明.py` 验收。
- **命名规矩**：声明名沿用规则文件里的名词；Lean 不认裸中文标识符，中文标识符一律写在 `«…»` 里；局部变量用英文字母。
