# 规则模型对拍格式 v1

运行目录为 `规则模型/`（本文件在其下的 `对拍/` 里）。输入是 UTF-8 JSON，标准输出是 UTF-8 JSON Lines。一个输出行对应一个已经结束的单步或外部操作。同一段内的顺序就是模型的执行顺序。段首有完整历史和初态，段首本身产生零行。

## 运行

```bash
cd 规则模型
lake build 对拍库 对拍
lake exe 对拍 对拍/黄金/格子边界.json
python3 对拍/核黄金.py
lake env lean --run 对拍/核两序.lean 对拍/黄金/*.json
python3 对拍/核接口.py
```

`python3 对拍/导出.py` 重新生成全部黄金文件。`python3 对拍/导出.py 传输周期` 只生成这一份。`-j 2` 指定同时运行的 Lean 进程数，默认是 2。`lake build` 的默认目标为 `Endfield`。

最小的仓库示例可存成 `示例.json` 交给 `lake exe 对拍 示例.json`。

```json
{
  "版本": 1,
  "段": [{
    "历史": [], "供电": [], "端口": [],
    "未定": {
      "传输排在几组之后": [],
      "离线后的计数": ["保留","保留"],
      "改设定后的计数": ["保留","保留"],
      "输入判定都没货时": "每步判两次"
    },
    "状态": {},
    "操作": [["入库","源矿",3],["走",1],["出库","源矿",3]]
  }]
}
```

该输入的标准输出为

```jsonl
{"仓库":[["源矿",3]]}
{"仓库":[["源矿",3]]}
{}
```

## 段与历史

顶层有两个必填键。`版本` 是数字 1，`段` 是按运行顺序排列的数组。各段独立装入。表内的单位号、端口号、格号、数量、步数和时长都是非负 JSON 整数。对象键唯一。可空值用 `null`，布尔值用 `true`、`false`。

| 段键 | 内容 |
|---|---|
| 历史 | 从空布局开始的有序事件数组。历史是状态的第 1 个字段。 |
| 供电 | 按号递增列出有电单位，未列为无电。开关另存在状态里。带位置的回放按场地求值；手排回放沿用原来的供电函数。 |
| 端口 | `[[[起,止],口号],…]`。列全从协议核心、仓库取货口出发的现有通道，按起、止的数值递增。核心口号 0–5，仓库取货口口号 0。空表写 `[]`。 |
| 未定 | 下表四个键均必填。 |
| 状态 | 段首十二项有限表。空对象使用各项默认值。 |
| 操作 | 操作数组，允许空数组。 |
| 期望 | 可选。每项是一个与标准输出同形的规范状态对象。给出时，执行器逐项检查内容与行数。 |
| 备注 | 可选的字符串。黄金文件记源断言的行号、所取窗口和适用的次序规则。 |

事件写作 `["建成",号,种类]`、`["接通",[起,止]]`、`["重接",[起,止]]`、`["拆除",号]`。先后完全取数组顺序。建成要求编号空闲，协议核心至多一个。接通要求两端存在、不同号、至少一端为运输单位、该通道当前尚未接通。重接要求当前已有该通道，会把它排到接通表末尾。拆除要求该单位存在，同时去掉它的通道。判定表由 `历史.立表` 计算。

种类字符串有 `传送带`、`分流器`、`汇流器`、`物品准入口`、`桥接器格`、`协议储存箱`、`协议核心`、`仓库取货口`，以及九个机名 `粉碎机`、`精炼炉`、`配件机`、`塑形机`、`采种机`、`种植机`、`研磨机`、`封装机`、`灌装机`。桥接器的各格分别占单位号。供电桩的效果由供电表表达。

| 未定参数 | 取值与作用 |
|---|---|
| 传输排在几组之后 | `[[箱号,n],…]`，每个现有协议储存箱恰一项，按号递增。0 表示先传输，再做该箱各组移动。n 不小于组数时在全部组后传输。中间值为传输之前已做的组数。 |
| 离线后的计数 | `[累计已收策略,名额策略]`，两项各自取 `"保留"` 或 `"清空"`。清空分别写回 0 或空列表；保留名额时也保留次序及剩余步数。 |
| 改设定后的计数 | 同样的二元数组。当放行物品相同、每 5 tick 上限改变时，第 1 项决定累计已收。当放行物品改变时，累计已收按模型归零，第 2 项决定名额。放行物品相同时名额保留。 |
| 输入判定都没货时 | `"每步判两次"` 为现行模型取法。另可取 `"不收"`、`"轮到的那条"`、`"都收"`、`"再判一次"`，对应回放保留的四种已排除说法。 |

原回放黄金段的计数策略均为 `["保留","保留"]`，取值来自原回放的 `取一种`。传输位置与汇流器说法按各回放实际采用的 `未定` 写出。

## 状态的完整写法与比较

历史由当前段首确定，成功执行离线时改为操作携带的历史。输出行只携带以下十二项。每项是一张 `[[键,值],…]` 表。规范输出略去默认行及由此成为空表的字段。输入可以显式写默认值。格位为 `[单位号,格名]`，通道为 `[起,止]`，一堆货为 `[物品名,件数]`。

| 字段 | 键 | 值及默认值 |
|---|---|---|
| 货 | 格位 | 原顺序的货堆数组，默认 `[]`。 |
| 已停 | 当前有货的运输物品格 | 步数，默认 0。取 `min(原数,8)`。 |
| 来处 | 当前有货的运输物品格 | 上一个格位，默认 `null`。 |
| 分流器上次 | 分流器号 | 一条通道，默认 `null`。 |
| 进货上次 | 单位号 | 按现布局的进货表长取余，长度 0 或 1 时取 0。默认 0。 |
| 出货已移动 | 非运输单位号 | 通道数组，默认 `[]`，保留模型记录的最近一次移动先后。 |
| 制造中 | 制造单位号 | `[配方对象,还差几步]`，默认 `null`。还差 0 步的制造仍可出现在这张表中。 |
| 准入口 | 物品准入口号 | 含下述六键的对象，默认各子字段均取默认值。拍取 `原数 % 4`。 |
| 储存箱 | 协议储存箱号 | `{"仓储模式":false,"冷却还剩":0}` 是默认。仓储模式为真时采用仓储模式，冷却单位为步。 |
| 开关 | 制造单位号或协议储存箱号 | 布尔值，默认 `true`。 |
| 取货指向 | `[单位号,口号]` | 该取货端口指向的物品名，默认 `null`。包括当前没有接通道的有效端口。 |
| 仓库 | 物品名 | 件数，默认 0，上限 80000。 |

准入口六个子字段的默认对象为

```json
{"放行":null,"累计上限":null,"每5tick上限":null,"累计已收":0,"名额":[],"拍":0}
```

`放行` 是物品名或 `null`。两个上限分别为 1–5000、0–5，也可以为 `null`。放行物品为 `null` 时两个上限均须为 `null`。`累计已收` 是件数。`名额` 为各个已占名额的剩余步数数组，保留原先后。`拍` 的规范值为 0–3。段首输入的准入口、储存箱对象均可省略取默认值的子字段。

每个字段只枚举表内指定种类的现有键。非运输单位包括九种制造单位、协议储存箱、协议核心和仓库取货口。开关的键域取决于种类，断电时也保留开关。以单位号为键的表若给了域外编号，即使值是默认值也报格式错误。已停和来处在现有的非运输格或空运输格上允许显式给 0 或 null（各自的默认值），给非默认值报格式错误。两表的键是货物当前所在的格，来处的值仍可指向非运输格。

段首的进货下标必须已经规范化。汇流器的进货表按接通先后列出所有非分流器进口；其他单位取“进同一个的”组。货物移入时模型写入通道的 `idxOf`，建成和拆除该单位时归零，拆除使进货表变空时也归零。拆除后表长缩短但非空时，旧数可能超界。段内离线保持种类及通道集合，因此表长不变，同一下标按新历史选带。建造、拆除、接通通过新段首给出，须从该段实际布局和原状态重新规范化。

箱冷却、制造进度和准入口计时在模型里可以按种类域外的编号求值。域外的这些读数只在计时、状态复制或回放观测中出现，不参与段内货流和操作条件。`{}` 按每项默认值装入。

在 `Endfield/` 中核到的读取处如下。行号对应本次核对的模型副本。

| 字段 | 参与走步、操作或段首校验的地方 |
|---|---|
| 已停 | `物品格.lean` 56–60 行只在运输格有货时用已停判可移动，144–145 行移动时将两端归零。`框架.lean` 269–271 行只给有货运输格加一，其余写零。`作用.lean` 101、159 行在建成或拆除时清零。 |
| 来处 | `物品格.lean` 124–131 行对所有格到格的移动读源格来处以防回移，源格可为箱格或制造单位的取货格。146–152 行只在从格进入运输格时写入来源，货离开时清源格，从仓库进货时目的格也写空。非运输源格在可达状态中始终读到 `none`。建成清来处，拆除还清掉指向被拆单位的来处（`作用.lean` 102、160–164 行）。 |
| 储存箱 | `判定.lean` 201、212–213 行在传输及其判定中读取。第 212 行先检查箱种类。`作用.lean` 60、238–240 行限制操作对象并在切模式时保留冷却。`框架.lean` 283–285 行的计时只改本号箱字段。 |
| 开关 | `框架.lean` 248–249 行的“运行”读取开关。它的调用点为该文件 278、285 行的两项计时，以及 `判定.lean` 212、357、371 行的箱传输、结束制造、开始制造。`作用.lean` 的“拨开关”只接受需电单位。 |
| 制造中 | `判定.lean` 307、356、371 行分别用于缓存进取货格、结束制造和开始制造，调用方按制造种类分支。`物品格的规矩.lean` 47 行在制造分支核对配方。`框架.lean` 276–279 行的计时只更新本号制造进度。 |
| 分流器上次 | `判定.lean` 164 行只在“分流器的”组中读取。`拓扑与级别.lean` 200 行按起点种类建这个组。`物品格.lean` 153–155 行在分流器出货时记通道。 |
| 出货已移动 | `判定.lean` 234 行在非运输单位的“出货的”组排先后。`物品格.lean` 158–161 行在“算出货”时读旧队列并追加。`作用.lean` 127–128 行在箱子新接出口时读取旧队列。分组见 `拓扑与级别.lean` 198–205 行。 |
| 进货上次 | `判定.lean` 118、139、167 行分别在输入判定、无货时选轮到的通道、元件移动判定中读取，都经过“位置上的通道”。汇流器用完整进货表；其他单位用“进同一个的”组，与 `框架.lean` 180–184 行的进货表一致。`物品格.lean` 156–157 行在移动成功时写下标。建成、拆除和重排的处理见 `作用.lean` 104、125、144、170–173、341 行。 |

回放的 `工具.lean`（压平）和 `前提.lean`（状态读数）还会逐号抄取字段。显式复制、原值透传、证明和回放断言的读数均不会把删去的值带入后续货流判定。

单位键按数值递增。单位内的格名按模型 `单位种类.物品格` 排列：运输格 `["格",0]`；协议储存箱 `["格",0]` 至 `["格",5]`；制造单位先列 `["存货",i]`（i 从 0 递增），再列 `"取货"`、`"缓存"`。研磨机、封装机、灌装机各有两个存货格，其他机型各有一个。有效取货端口按口号递增。段首各表的键须存在且按顺序唯一，单位种类和格位上的值须符合上述各项限制。货堆、配方原料、名额、出货已移动等作为**值**的数组保留原序。

仓库按以下 19 种物品的顺序列行，各处物品字符串共用这份枚举。

```text
源矿、源石粉末、致密源石粉末、蓝铁矿、蓝铁块、蓝铁粉末、致密蓝铁粉末、钢块、钢质瓶、钢制零件、荞花种子、荞花、荞花粉末、细磨荞花粉末、砂叶种子、砂叶、砂叶粉末、高容谷地电池、精选荞愈胶囊
```

配方以完整对象表示。举例为 `{"单位":"粉碎机","原料":[["砂叶",1]],"产物":["砂叶粉末",3],"时长":1}`。`时长` 用 tick，1 tick 等于 8 步。制造单位采用模型的 18 条配方，段首的制造中记录、缓存格与其他货格按 `状态.各格合规矩` 校验。

## 段内操作

| JSON 数组 | 结果 |
|---|---|
| `["走",n]` | 调用 `一步于` n 次，每次完成各输出一行。0 步输出零行。 |
| `["设准入口",u,物品或null,累计上限或null,每5tick上限或null]` | 给 u 写入这一整套设定。 |
| `["重置计数",u]` | 在已设累计上限的准入口点重置。 |
| `["设储存箱模式",u,仓储]` | 真为仓储，假为无线传输。 |
| `["设取货指向",u,口号,物品或null]` | 设定或清除一个有效端口的指向。 |
| `["拨开关",[单位号,…],开]` | 为所列制造单位或协议储存箱设置开关。 |
| `["放货",u,物品,n]` | n 大于 0，放进协议储存箱或制造单位。调用格子层 `放进单位`，按其容量放下能放入的件数。 |
| `["收货",[u,格名]]` | 整格取走模型允许收取的非运输格中的货。该格须有货且格名不能是缓存。 |
| `["入库",物品,n]` | 仓库增加 n 件，结果须在容量内。 |
| `["出库",物品,n]` | 从仓库取出 n 件，须有足够库存。 |
| `["离线",新事件数组]` | 新历史须合规且重建出相同的单位号、种类及通道集合。按 `作用` 更换历史、处理计数，下一步使用新历史的判定表。段内的供电、端口映射和未定参数继续使用。 |

建造、拆除、重接通过新段首提供。段内包括离线在内的每项非走步操作成功后输出一行。输入错误或 `作用` 返回 `none` 时，程序把错误写到标准错误并以非零状态退出；此前已成功的操作可能已经输出。状态行和黄金期望中的对象键按照 Lean JSON 打印器的字符串序排列，行内无多余空白。对象键序不参与 JSON 的语义相等。

## 黄金文件的来源

`对拍/导出.py` 选取原回放的断言及其依赖的布局、状态、剧本和读数定义，在临时命名空间执行。观察器 `对拍/取样.lean` 包住原模型的一步和操作，记录真实输入、前态与后态。供电和端口在原回放的 `待写` 上按单位、通道求值。`蓝图里的准入口` 的三组蓝图各取原函数列出的第一个相容放货偏移，并收录短窗口断言。原文件的全部 `#guard` 仍在默认目标中。

连续布局事件取最后一个事件后的状态。回放直接装货、回到较早状态试另一支、供电或其他参数变化等造成段首不同，也各从实际取得的快照开始。沿用原黄金的取样间隔，保留原轨迹的首尾、等距连续窗口和非走步操作。相邻窗口合并。每个窗口另起一段，每个保留步都有完整期望。段内备注的 `a–b/N` 指所选原轨迹的操作后读数位置，走 n 步在这里计 n 个位置。纯供电文件的表值在段首，操作与期望均为空。

备注「待接箱的次序」标出存在该布局分支的段。其基例是分流器已有进口且无出口，或唯一出口通往无出口的桥接器格。模型在该分支给分流器取次序 1，并按已有规则向上游计算。静态段也可能带此标记。

接口黄金的输入在 `对拍/接口样例.py` 中手写。导出器逐段交给对拍可执行程序，将标准输出按行读回为期望。两份离线换序黄金各含原历史对照段。
